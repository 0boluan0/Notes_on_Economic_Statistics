## 2.1–2.3 From text to IDs
<!-- bilingual-en:end -->

*一段文字如何交给模型*

<!-- bilingual-en:start -->
The tokenizer converts a string into a sequence of integer token IDs. Its vocabulary fixes the mapping between each token and its ID. A token can be a word, a fragment, punctuation or a byte sequence. The tokenizer’s `encode` method maps text to IDs, and its `decode` method reconstructs text according to that encoding. The Transformer encoder and decoder are names for neural network components. Once the IDs are ready, the embedding layer can look up vectors for them.
<!-- bilingual-en:end -->

分词器（tokenizer）把字符串表示为一串整数。每个词元（token）在这套词表（vocabulary）中有自己的编号（token ID）。一个词元可以是整词、词片、标点或一串字节。这里的 `encode` 是分词器输出编号的方法，`decode` 是由编号还原文本的方法。论文里的 Transformer 编码器（encoder）和解码器（decoder）则是神经网络组件。实际流程是先由分词器得到 ID，然后嵌入层（embedding layer）按 ID 查向量。

<!-- bilingual-en:start -->
An ID has meaning inside its own vocabulary. The learning exercise uses both GPT-2 tokenization and a different tokenizer for Chinese. A model must use an embedding table indexed consistently with its tokenizer. Numeric size or proximity of IDs says nothing about word meaning. See [[00_Knowledge/词元编号|token IDs]].
<!-- bilingual-en:end -->

编号要连同词表一起读。同一句中文交给 GPT-2 和另一种分词器，可以有不同的切法、长度和编号。模型使用的嵌入表必须和输入编号的含义匹配。编号相差一位，只代表两个表项，语义相似度需要从表示与训练中得到。见[[00_Knowledge/词元编号|词元编号]]。

<!-- bilingual-en:start -->
## 2.4–2.5 Keeping unfamiliar words distinguishable
<!-- bilingual-en:end -->

*陌生词怎样保留原来的差别*

<!-- bilingual-en:start -->
Special tokens give the tokenizer explicit markers for a convention. In the book’s simple tokenizer, `<|unk|>` is the fallback for an unrecognized item, while `<|endoftext|>` can mark a boundary between texts. Their meanings and IDs belong to the particular tokenizer and training setup.
<!-- bilingual-en:end -->

特殊词元（special token）用于表示训练约定。教材先写的简单分词器以 `<|unk|>` 代替未收录的项目，`<|endoftext|>` 则可以作为两段文本的边界标记。它们具体的含义和编号取决于分词器及训练设置。

<!-- bilingual-en:start -->
With a whole-word vocabulary, two unseen words can both map to one unknown token (UNK). The next layer then receives the same ID in each case. Enlarging the embedding from 3 to 300 coordinates still retrieves one shared row. A representation that retains smaller units can preserve the difference before lookup.
<!-- bilingual-en:end -->

若按整词建词表，两个训练时没遇过的词可能都映射成同一个未知词元（unknown token，UNK）。这叫词表外问题（out of vocabulary，OOV）。下一层只收到同一个编号，即使把嵌入维度从 3 加到 300，两次拿的依旧是同一行。要保住两个词的差别，要在分词时把各自的拼写表示出来。

<!-- bilingual-en:start -->
A character alphabet can spell any word made from its characters, at the cost of longer sequences. Byte-pair encoding (BPE) repeatedly counts adjacent token pairs during tokenizer training, merges a frequent pair into one token, and records the order of the merges. At use time the fixed rules segment new text. Frequent fragments can take fewer positions while smaller units remain available. See [[00_Knowledge/字节对编码|byte-pair encoding]].
<!-- bilingual-en:end -->

字符级分词（character-level tokenization）能拼出字母表所覆盖的任意词，代价是序列变长。字节对编码（byte-pair encoding, BPE）在训练分词器时统计相邻词元对，合并当前高频的一对，记录合并次序，再基于新边界继续统计。日常编码使用这套已学好的规则。常见片段占用的位置变少，较小单位仍能拼出生词。见[[00_Knowledge/字节对编码]]。

<!-- bilingual-en:start -->
For the character-initialized hand calculation, the corpus contains `hug` five times, `pug` three times, `pun` twice and `sun` once. The pair `u g` occurs eight times, so the first rule creates `ug`. The updated corpus contains `h ug` five times, so the next rule creates `hug`. With these two rules, `pughug` becomes `p / ug / hug`. This calculation exposes how the merge rules are learned.
<!-- bilingual-en:end -->

手算合并规则的语料按字符起步。其中 `hug` 出现 5 次、`pug` 3 次、`pun` 2 次、`sun` 1 次。第一轮 `u g` 的频数是 5+3=8，合并成 `ug`。第二轮在新边界上数出 `h ug` 共 5 次，合并成 `hug`。应用已经固定的两条规则，`pughug` 切成 `p / ug / hug`。这段手算只解释合并机制。实际 GPT-2 的起始单位由字节给出。

<!-- bilingual-en:start -->
In the same hand calculation, an alphabet of 26 letters maps `coffee` to six positions. Adding `ug` as entry 27 changes `buggy` to `b / ug / g / y`. With width 4, the resulting table has shape (27,4), but that one input needs only (4,4) after lookup. Table size counts available entries, while input length counts the tokens actually selected.
<!-- bilingual-en:end -->

在这组手算里，26 个字母可以把 `coffee` 编成 6 格。新增词元 `ug` 后，`buggy` 切为 `b / ug / g / y`，共 4 格。若宽度是 4，词元表形状为 (27,4)，这条输入查表后则为 (4,4)。词表大小数可用条目，序列长度数这次实际使用的位置。

## 2.5 Characters, bytes and tokens
<!-- bilingual-en:end -->

*字符数、字节数和词元数分别在数什么*

<!-- bilingual-en:start -->
UTF-8 represents a Unicode character with one or more bytes. Each byte takes one of 256 values. A byte-level BPE tokenizer with all 256 base values can represent valid UTF-8 text even if a whole character or word has no merged entry. A learned token may contain only part of a character. Decoding the complete sequence reassembles the bytes before interpreting them as text. See [[00_Knowledge/字节级分词覆盖|byte-level coverage]].
<!-- bilingual-en:end -->

UTF-8 把 Unicode 字符编码为字节（bytes）。一个字节有 256 种取值。字节级 BPE（byte-level BPE）把全部 256 种字节都纳入基础单位后，一个生僻字即使没有整字表项，也能用若干词元表示。一个词元可能刚好止于一个汉字的中间。还原完整序列时，先拼好字节，才能读出字符。见[[00_Knowledge/字节级分词覆盖]]。

| 输入 / Text | UTF-8 字节 / Bytes | GPT-2 token IDs |
|---|---|---|
| `a` | `[97]` | `[64]` |
| 茶 | `[232, 140, 182]` | `[164, 234, 114]` |
| `hello` | `[104, 101, 108, 108, 111]` | `[31373]` |

<!-- bilingual-en:start -->
The table is a reproducible GPT-2 encoding. Five bytes can share one token, and one character can span three tokens. In the Chinese round-trip experiment, `get_encoding("gpt2")` gave 95 tokens and `encoding_for_model("gpt-4o-mini")` selected `o200k_base` and gave 32 for the same string. Both decoded back to the original. Token count here describes this string and this pair of encodings.
<!-- bilingual-en:end -->

表中数值来自 GPT-2 的真实编码。五个字节可以合成一个词元，一个汉字也可以跨三个词元。对下方同一串文字，`get_encoding("gpt2")` 得到 95 个词元，`encoding_for_model("gpt-4o-mini")` 选到 `o200k_base` 并得到 32 个词元。两者都完整还原了原文。这个长度比较只对应这段文字。

```text
编辑器里：你已经写了代码，但还没保存 磁盘文件：还是空的运行按钮：执行了磁盘上的空文件
```

<!-- bilingual-en:start -->
In that second encoding, IDs `3637, 96, 223` supply bytes `[32,231]`, `[163]` and `[129]`. Together these decode to a space followed by U+78C1. A replacement character printed by decoding a lone incomplete token is a cue to inspect `decode_single_token_bytes` or decode the complete sequence.
<!-- bilingual-en:end -->

第二套编码中，`3637、96、223` 三个 ID 的字节分别是 `[32,231]`、`[163]`、`[129]`，拼起来才是“空格＋磁”。单独打印某个词元时出现 `�`，可以用 `decode_single_token_bytes` 看字节，再用完整 ID 序列解码验证往返（round trip）。

## 2.6 One window, one pair of sequences
<!-- bilingual-en:end -->

*先确定一条样本的输入和答案，再移动窗口*

<!-- bilingual-en:start -->
Write the tokenized document as $u_0,\ldots,u_{N-1}$. A window starting at position $i$ provides $T$ inputs and one next-token target for each input. At local position $t$ the correct answer lies exactly one source position farther on. The causal model can use the prefix from the beginning of this sample through its current position. See [[00_Knowledge/下一词元滑窗取样|window construction]].
<!-- bilingual-en:end -->

令 $u_0,\ldots,u_{N-1}$ 为整篇原文的词元编号。以原文位置 $i$ 为起点，取 $T$ 个输入。样本内部第 $t$ 格对照的是原文中紧接着的下一个词元。做这一格的预测时，模型可用本样本开头一直到当前格的前缀（prefix），包括 $x_t$ 本身。见[[00_Knowledge/下一词元滑窗取样]]。

$$
x_t=u_{i+t},\qquad y_t=u_{i+t+1},\qquad 0\le t<T.
$$

<!-- bilingual-en:start -->
For the window starting at source position 2, one observed prefix ends at source position 11. The next position is 12. The two lines below align the final input and its observed target for the 10-token version of this window. The model’s prediction is computed later. The text already supplies the label.
<!-- bilingual-en:end -->

在起点为 2、输入长为 10 的实际窗口里，最后一格取原文位置 11，对应“龙”（ID 3866）。目标取原文位置 12 的“时代”（ID 6888）。这一格完整可见的前缀是“一切的开端，是混沌未开的古龙”。`y` 是来自原文的标签（label）。模型运行后才产生预测（prediction）。

```text
x = 一切的开端，是混沌未开的古龙
y = 的开端，是混沌未开的古龙时代
```

<!-- bilingual-en:start -->
A complete pair uses $T+1$ consecutive source IDs. Its last target is at $i+T$, and the highest source index is $N-1$. Thus $i+T<N$. The stride $s$ is the gap between successive starts. Python’s exclusive stop $N-T$ enforces the boundary exactly. Inner label offset and outer window stride control different choices.
<!-- bilingual-en:end -->

一组完整配对需要原文中连续的 $T+1$ 个词元。最后一个目标的索引是 $i+T$，全文最后一个索引是 $N-1$，所以需要 $i+T<N$。滑动窗口（sliding window）的步长（stride）$s$ 决定下一组起点移动几格。样本内部的标签偏移始终为 1，因为任务是预测下一词元。下面直接遍历分词器给出的整篇编号。

```python
for start in range(0, len(tokens) - max_length, stride):
    x = tokens[start : start + max_length]
    y = tokens[start + 1 : start + max_length + 1]
    samples.append((torch.tensor(x), torch.tensor(y)))
```

## 2.6 When a batch and an epoch finish
<!-- bilingual-en:end -->

*一轮训练里究竟有多少批*

<!-- bilingual-en:start -->
One pair $(x,y)$ is one sample. The data loader stacks the inputs of $B$ samples and separately stacks their corresponding targets, producing two aligned ID tensors of shape $(B,T)$. In this fixed, sequential dataset, an epoch is one complete training pass through all samples. In the author’s simple loop the optimizer applies one parameter update per training batch. Iterating a loader to inspect a tensor only reads the data.
<!-- bilingual-en:end -->

一个输入与目标对 $(x,y)$ 算一条样本（sample）。数据加载器（data loader）一次取 $B$ 条样本，分别按行堆叠各条输入和各条目标，得到同一个批次（batch）里的两份 $(B,T)$ 张量。批大小（batch size）数每批的样本条数。对这里顺序读取的有限训练集，一个训练轮次（epoch）是完整用于训练一遍。书里的基础训练循环每批调用一次优化器更新参数。在练习中打印批次只是在读取数据。见[[00_Knowledge/训练轮次与小批量]]。

<!-- bilingual-en:start -->
The following two configurations use the same full 469-token corpus, stride 2, batch size 2, and keep the final partial batch. The first reproduces the earlier window exercise. The second matches the 100-position configuration in the code. Each last complete window reaches target index 468.
<!-- bilingual-en:end -->

两组配置都使用同一篇完整的 469 个词元，步长为 2、每批 2 条，`drop_last=False`。第一行对应先前的短窗口练习，第二行对应代码中的 100 位窗口。两种情况的最后一个有效目标都在原文位置 468。

| 每样本输入长度 $T$ | 窗口起点（含两端） | 样本数 | 一遍的批数 | 末批编号形状 |
|---:|---|---:|---:|---|
| 10 | 0, 2, …, 458 | 230 | 115 | `(2, 10)` |
| 100 | 0, 2, …, 368 | 185 | 93 | `(1, 100)` |

<!-- bilingual-en:start -->
In the first row, three completed training batches account for 6 samples and 0 completed epochs. In the second row, 92 full batches account for 184 samples, and the last sample supplies batch 93. Keeping or discarding a partial batch is a loader policy. Keeping only windows with sufficient targets is an earlier sampling policy.
<!-- bilingual-en:end -->

第一行里，处理完第三批就是用了 6 条样本、结束 0 个完整 epoch。第二行里，92 个满批装了 184 条，最后 1 条单独成为第 93 批。窗口够不够 $T+1$ 个原文词元，由取样规则决定。末批样本条数够不够 $B$ 条，由加载器的 `drop_last` 决定。

<!-- bilingual-en:start -->
## 2.7–2.8 Looking up tokens and positions
<!-- bilingual-en:end -->

*一个编号怎样得到一个带位置的向量*

<!-- bilingual-en:start -->
An embedding table has one trainable row per addressable vocabulary entry. If the model width is $d$, each row has $d$ coordinates. Gathering rows for an entire batch adds a final vector axis. In the GPT-style model in this book, a separate table indexes learned absolute positions within each sample. Position and token vectors have the same width and are added coordinate by coordinate.
<!-- bilingual-en:end -->

词元嵌入表（token embedding table）每个可寻址的词元编号对应一行可训练参数，设嵌入维度（embedding dimension）为 $d$，每行就有 $d$ 个坐标。按整批编号查表后，新添的最后一维装这些坐标。本书的 GPT 模型还单独学习一张绝对位置嵌入表（learned absolute position embeddings），用样本内部的位置编号查行，两张表取出的向量按坐标相加。见[[00_Knowledge/Token嵌入]]和[[00_Knowledge/可学习位置嵌入]]。

$$
E\in\mathbb R^{V\times d},\quad P\in\mathbb R^{L\times d},\qquad
h_{b,t}=E[x_{b,t}]+P[t],\quad T\le L .
$$

<!-- bilingual-en:start -->
A short row lookup explains the matrix operation. In the previously used vocabulary, `.` is 0, `I` is 1, `coffee` is 2, `like` is 3 and `tea` is 4. The sequence `tea like tea` therefore retrieves rows 4, 3 and 4, in that order. A one-hot row for `tea` has a single 1 at index 4. Multiplying it by the table selects row 4. Stacking such rows for an entire sequence gives the identity below.
<!-- bilingual-en:end -->

沿用课堂词表，`.`、`I`、`coffee`、`like`、`tea` 的编号依次是 0 至 4。`tea like tea` 的编号就是 `[4,3,4]`，查表结果按顺序取 $E[4],E[3],E[4]$。若把 `tea` 写成独热向量（one-hot vector），只有索引 4 的位置为 1。它乘整个嵌入表时，只有第 4 号行被保留。把各位置的独热行叠成矩阵 $O$，就得到下面的等价写法。实际实现直接按编号取行。

$$O_{T\times V}\,E_{V\times d}=X_{T\times d}.$$

<!-- bilingual-en:start -->
In this notation $V$ is the token table capacity, $L$ the position table capacity, $T$ the positions actually used per sample, $B$ the number of samples in this batch and $d$ the coordinates per vector. For $T=100$, $L=1024$ and $d=91$, a full batch has the shapes below. The same 100 position vectors are added to every row by broadcasting.
<!-- bilingual-en:end -->

这里的 $V$ 是词元表的行数，$L$ 是位置表的容量，$T$ 是本样本实际使用的位置数，$B$ 是当前批次的样本数，$d$ 是每个向量的宽度。取当前配置 $T=100,L=1024,d=91$，满批的形状如下。两条样本使用相同的位置号 0 到 99，所以加法时同一份位置向量会自动匹配到两条样本，这叫广播（broadcasting）。

```text

token vectors    (2, 100, 91)
```
