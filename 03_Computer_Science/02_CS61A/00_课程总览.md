函数与环境模型先说明每次调用怎样建立 frame、解析名称并保存闭包；递归随后利用同一调用机制，让一个问题引用更小的同类问题。
<!-- bilingual-en:start -->
Functions and the environment model first explain how each call creates a frame, resolves names, and preserves closures. Recursion then uses the same call mechanism to express a problem in terms of smaller instances of itself.
<!-- bilingual-en:end -->

先打开 [[递归与递归数据.canvas|递归与递归数据总图]] 看清“定义、正确性、运行时与性能”四层关系。先从递归规格开始：基本情况给出直接答案，递归步骤必须说明怎样由较小同类实例构造当前答案。
<!-- bilingual-en:start -->
Open the [[递归与递归数据.canvas|Recursion and Recursive Data map]] to separate definition, correctness, execution, and performance. Begin with the recursive specification: base cases give direct answers, while recursive cases must explain how smaller instances construct the current answer.
<!-- bilingual-en:end -->

![[递归的基本与递归步骤]]

写出基本情况仍不够；下一步要逐一证明所有递归调用都沿同一个良基关系下降，不能让某个隐藏分支绕开基本情况。
<!-- bilingual-en:start -->
Writing a base case is not sufficient. Every recursive call must descend along one well-founded relation; no hidden branch may bypass the base cases.
<!-- bilingual-en:end -->

![[递归终止]]

终止说明调用会回来，环境模型则说明回来时从哪里继续：每次调用有自己的 frame，最近暂停的调用最先恢复。
<!-- bilingual-en:start -->
Termination explains that calls return; the environment model explains where execution resumes. Each call has its own frame, and the most recently suspended call resumes first.
<!-- bilingual-en:end -->

![[递归调用栈]]

当输入本身由递归构造器生成时，算法可直接镜像数据定义；相应的正确性证明再复用[[结构归纳法|结构归纳]]，不要把计算过程与证明过程混成一句话。
<!-- bilingual-en:start -->
When the input itself is recursively generated, the algorithm can mirror the data definition. Correctness can then reuse [[结构归纳法|structural induction]]; computation and proof remain distinct obligations.
<!-- bilingual-en:end -->

![[结构递归]]

程序正确之后才分析成本。递归深度只描述最长等待链；总时间必须把整棵调用树上每个节点的工作相加。
<!-- bilingual-en:start -->
Analyse cost after the procedure is correct. Recursion depth describes only the longest suspended chain; total time sums the work at every node of the call tree.
<!-- bilingual-en:end -->

![[递归调用树成本]]

如果缓存有效期内反复请求由同一状态决定的结果，记忆化可以复用首次计算；重复请求既可能来自一棵调用树，也可能来自多次顶层调用。若缓存键漏掉会改变答案的上下文，提速会同时制造错误。
<!-- bilingual-en:start -->
When a cache repeatedly receives a key that denotes the same state, memoization can reuse the first result; those requests may come from one call tree or from separate top-level calls. If the key omits context that changes the answer, the optimisation also creates a correctness bug.
<!-- bilingual-en:end -->

![[记忆化的适用条件]]

若问题拆成若干近独立子问题，则进入分治：复杂度取决于子问题的数量和规模，也取决于本层分解与组合的真实成本。[[归并排序复杂度|归并排序]]是具体实例。
<!-- bilingual-en:start -->
When a problem splits into nearly independent subproblems, divide and conquer applies. Its complexity depends on the number and sizes of the subproblems and on the real splitting and combining costs. [[归并排序复杂度|Merge sort]] is the concrete example.
<!-- bilingual-en:end -->

![[分治成本模型]]

当外部输入可能非常深时，可把 frame 隐含保存的节点、阶段和局部结果改成显式栈，避免依赖 Python 的解释器递归深度。
<!-- bilingual-en:start -->
When external input may be extremely deep, move the node, phase, and partial result implicit in each frame into an explicit stack, avoiding dependence on Python's interpreter recursion depth.
<!-- bilingual-en:end -->

![[递归的显式栈改写]]

最后看分支搜索。不同 frame 可以共享同一个可变对象，因此回溯若原地修改状态，就必须在探索下一候选前撤销本分支的改动。
<!-- bilingual-en:start -->
Finally consider branching search. Distinct frames can share one mutable object, so in-place backtracking must undo a branch's changes before exploring the next candidate.
<!-- bilingual-en:end -->

![[回溯状态恢复]]

### 2. 对象抽象、类与多态
<!-- bilingual-en:start -->
*2. Object Abstraction, Classes, and Polymorphism*
<!-- bilingual-en:end -->

函数和闭包已经能保存局部状态；对象系统进一步给状态命名属性、把行为绑定到接口，并让不同表示通过继承或共同协议参与统一调用。先打开 [[Python 面向对象、类与继承.canvas|Python 面向对象、类与继承总图]]，再沿执行、状态、协议、继承和设计边界阅读。
<!-- bilingual-en:start -->
Functions and closures can already preserve local state. The object system names that state with attributes, binds behaviour to interfaces, and lets different representations participate in shared calls through inheritance or common protocols. Open the [[Python 面向对象、类与继承.canvas|Python OOP map]], then follow execution, state, protocol, inheritance, and design boundaries.
