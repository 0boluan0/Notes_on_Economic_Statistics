#### 控制流怎样保持正确
<!-- bilingual-en:start -->
*How control flow remains correct*
<!-- bilingual-en:end -->

条件先把标量解释成真或假；`switch` 与三种循环形式决定控制转移。语法只说明“接下来执行哪里”；对设计为最终结束的循环，不变量与终止度量共同说明“结果为什么正确且为什么会停”。
<!-- bilingual-en:start -->
A condition first interprets a scalar as true or false; `switch` and the three loop forms then determine control transfer. Syntax says where execution goes next. For a loop designed to finish, an invariant and termination measure together explain why the result is correct and why the loop stops.

#### 对象、声明与间接访问
<!-- bilingual-en:start -->
*Objects, declarations, and indirection*
<!-- bilingual-en:end -->

先把对象、指针对象和指针值分开，再解析声明中的每一层 `*`。只有在指针状态满足前提时，表达式中的 `*` 才能真正访问对象；要修改调用者的指针对象，还要再多一层地址。
<!-- bilingual-en:start -->
Separate objects, pointer objects, and pointer values before parsing every `*` layer in a declaration. Expression-level indirection requires a valid pointer state, and changing a caller's pointer object requires one additional address level.
<!-- bilingual-en:end -->

#### 数组转换、下标与边界
<!-- bilingual-en:start -->
*Array conversion, subscripting, and bounds*
<!-- bilingual-en:end -->

数组拥有完整对象身份，只有在规定的表达式语境中才转换为首元素指针。下标建立在指针加法和间接访问上，因此同一数组与 one-past 规则才是真正的合法区域。
<!-- bilingual-en:start -->
An array retains its own object identity and converts to a first-element pointer only in specified expression contexts. Subscripting builds on pointer addition and indirection, so the same-array and one-past rules define the real valid region.
<!-- bilingual-en:end -->

#### 字符数组怎样成为字符串
<!-- bilingual-en:start -->
*How a character array becomes a string*
<!-- bilingual-en:end -->

字符序列只有在可访问容量内出现首个 `\0` 才是 C 字符串；字符串字面量会建立静态数组，却不允许修改。把长度、容量和字面量寿命混在一起，会让看似简单的复制立刻越界或失效。
<!-- bilingual-en:start -->
A character sequence is a C string only when its first `\0` lies within the accessible capacity. A string literal creates a static array but may not be modified. Confusing length, capacity, and literal lifetime makes even a simple copy overflow or expire.
<!-- bilingual-en:end -->

#### 分配对象的大小、替换与释放
<!-- bilingual-en:start -->
*Sizing, replacing, and releasing allocated objects*
<!-- bilingual-en:end -->

分配成功只开始对象生命周期，不自动建立业务值或释放责任。请求大小先防整数回绕，`realloc` 再按成功与失败两条路径提交，最后由明确所有者恰好释放一次。
<!-- bilingual-en:start -->
Successful allocation begins an object lifetime but does not automatically establish application values or release responsibility. Check size arithmetic first, commit `realloc` along its success or failure path, and let one explicit owner release exactly once.
<!-- bilingual-en:end -->

#### 把规则组合成可工作的结构
<!-- bilingual-en:start -->
*Combining the rules into working structures*
<!-- bilingual-en:end -->

深拷贝把“独立存储、完整终止符、所有权转移”组合成一个接口；错误分类帮助定位到底坏了边界还是生命周期；动态数组则用指针、长度和容量三元不变量把全部规则长期维持住。
<!-- bilingual-en:start -->
A deep copy combines independent storage, the complete terminator, and ownership transfer. Error classification locates whether bounds or lifetime failed. A dynamic array keeps all rules live through its pointer-length-capacity invariant.
<!-- bilingual-en:end -->
