### 6. 递归与递归数据
<!-- bilingual-en:start -->
*6. Recursion and Recursive Data*
<!-- bilingual-en:end -->

递归把问题还原为更小的同类问题，并用调用栈把抽象定义变成执行过程。
<!-- bilingual-en:start -->
Recursion reduces a problem to a smaller instance of the same kind and uses the call stack to turn an abstract definition into an execution process.
<!-- bilingual-en:end -->

先打开 [[递归与递归数据.canvas|递归与递归数据总图]]。Lecture 15–16 的例子可以统一成四个问题：递归怎样定义、为什么会结束、调用怎样执行、成本怎样增长。
<!-- bilingual-en:start -->
Open the [[递归与递归数据.canvas|Recursion and Recursive Data map]] first. The examples in Lectures 15–16 can be organised around four questions: how recursion is specified, why it terminates, how calls execute, and how cost grows.
<!-- bilingual-en:end -->

![[递归的基本与递归步骤]]

有基本情况不等于一定到达它。对每条递归调用边给出共同的下降关系，才把课堂中的“toward the base case”变成可检查的终止证明。
<!-- bilingual-en:start -->
Having a base case does not mean that execution reaches it. A common descending relation for every recursive edge turns “toward the base case” into an auditable termination proof.
<!-- bilingual-en:end -->

![[递归终止]]

随后再 trace 调用：各层参数和局部名称属于不同 frame，父调用暂停等待子结果，并按后进先出次序恢复。
<!-- bilingual-en:start -->
Then trace execution. Parameters and local names belong to distinct frames; parent calls wait for child results and resume in last-in, first-out order.
<!-- bilingual-en:end -->

![[递归调用栈]]

Lecture 16 从数字转向列表与嵌套结构，关键不是换了一批例题，而是算法开始镜像数据自身的递归构造。正确性证明可进一步连接到[[结构归纳法|结构归纳]]。
<!-- bilingual-en:start -->
Lecture 16 moves from numbers to lists and nested structures. The deeper change is that the algorithm now mirrors the recursive construction of the data. Its correctness proof can then connect to [[结构归纳法|structural induction]].
<!-- bilingual-en:end -->

![[结构递归]]

递归的执行形状还决定成本。最大深度控制同时等待的调用链，总时间则要汇总整棵调用树；两者不能互相代替。
<!-- bilingual-en:start -->
The shape of recursive execution also determines cost. Maximum depth controls the suspended call chain, while total time aggregates the whole call tree; neither measure substitutes for the other.
<!-- bilingual-en:end -->

![[递归调用树成本]]

Fibonacci 的问题是单次调用树反复请求相同子问题，不是“递归天生慢”。一般而言，缓存只有在相同键于有效期内代表同一可复用结果时才正确；收益则要求同一有效键真的再次被请求，不限于递归内部。
<!-- bilingual-en:start -->
Fibonacci repeatedly requests the same subproblems within one call tree; recursion itself is not inherently slow. More generally, caching is correct only when a key denotes the same reusable result throughout its validity period, and useful only when that valid key is actually requested again, whether recursively or across top-level calls.
<!-- bilingual-en:end -->

![[记忆化的适用条件]]

分治处理的是另一种形状：把问题拆成较小子问题再组合。完整递推必须同时记录子问题规模与本层成本；[[归并排序复杂度|归并排序]]在后面的算法部分给出具体展开。
<!-- bilingual-en:start -->
Divide and conquer addresses another shape: split into smaller subproblems and combine their results. A complete recurrence records both subproblem sizes and current-level costs; [[归并排序复杂度|merge sort]] is developed in the later algorithms section.
<!-- bilingual-en:end -->

![[分治成本模型]]

如果输入深度没有可信上界，把待处理节点和返回阶段放进显式栈，可避免依赖 Python 的解释器递归深度；这不会消除算法本身的空间需求。
<!-- bilingual-en:start -->
If input depth has no trustworthy bound, an explicit stack can store pending nodes and return phases without relying on Python's interpreter recursion depth. This does not eliminate the algorithm's own space requirement.
<!-- bilingual-en:end -->

![[递归的显式栈改写]]

分支搜索再多一个状态问题：若各层共享同一个可变容器，当前选择必须在下一分支前撤销；独立 frame 不会自动复制容器。
<!-- bilingual-en:start -->
Branching search adds a state problem. If calls share one mutable container, the current choice must be undone before the next branch; distinct frames do not copy the container.
<!-- bilingual-en:end -->

![[回溯状态恢复]]
