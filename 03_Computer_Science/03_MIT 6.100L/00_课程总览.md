### 2. 浮点数、近似算法与搜索
<!-- bilingual-en:start -->
*2. Floating-Point Numbers, Approximation Algorithms, and Search*
<!-- bilingual-en:end -->

基本表达式和控制流先建立可执行程序；浮点误差和搜索说明计算机如何近似数学对象。
<!-- bilingual-en:start -->
Basic expressions and control flow first establish an executable program. Floating-point error and search then show how a computer approximates mathematical objects.
<!-- bilingual-en:end -->

![[浮点数与数值误差]]

先承认机器数只有有限精度，才能为近似相等和误差设置正确标准；求根算法随后用这些标准决定如何推进与何时停止。
<!-- bilingual-en:start -->
Finite machine precision must be acknowledged before approximate equality and error tolerances can be defined correctly. Root-finding algorithms then use those standards to decide how to advance and when to stop.
<!-- bilingual-en:end -->

![[数值求根：二分法与 Newton–Raphson]]

数值方法正确收敛之后，还要问达到给定误差需要多少步；渐近分析把这种资源增长与输入规模或精度要求联系起来。
<!-- bilingual-en:start -->
After a numerical method is known to converge correctly, the next question is how many steps are required to reach a specified error. Asymptotic analysis relates that resource growth to input size or demanded precision.
<!-- bilingual-en:end -->

![[渐近记号与算法复杂度]]

### 3. Python 函数、抽象与高阶函数
<!-- bilingual-en:start -->
*3. Python Functions, Abstraction, and Higher-Order Functions*
<!-- bilingual-en:end -->

近似算法写得越长越难验证；函数与高阶函数把步骤封装成有规格的可复用单元。
<!-- bilingual-en:start -->
Long approximation algorithms become difficult to verify. Functions and higher-order functions package their steps into reusable units with explicit contracts.
<!-- bilingual-en:end -->

![[Python 函数、作用域、闭包与高阶函数]]

### 4. Python 序列、可变性与别名
<!-- bilingual-en:start -->
*4. Python Sequences, Mutability, and Aliasing*
<!-- bilingual-en:end -->

函数处理对象；序列、可变性和别名决定多个名字共享数据时程序状态如何变化。
<!-- bilingual-en:start -->
Functions operate on objects. Sequences, mutability, and aliasing determine how program state changes when several names share data.
<!-- bilingual-en:end -->

![[Python 序列、可变性与别名]]

### 5. 测试、调试、异常与断言
<!-- bilingual-en:start -->
*5. Testing, Debugging, Exceptions, and Assertions*
<!-- bilingual-en:end -->

状态与分支增加失败路径，因此需要测试、断言、异常和有证据的调试循环。
<!-- bilingual-en:start -->
State and branching create additional failure paths, which require testing, assertions, exceptions, and an evidence-based debugging loop.
<!-- bilingual-en:end -->

![[测试、调试、异常与断言]]

### 6. 递归与递归数据
<!-- bilingual-en:start -->
*6. Recursion and Recursive Data*
<!-- bilingual-en:end -->

递归把问题还原为更小的同类问题，并用调用栈把抽象定义变成执行过程。
<!-- bilingual-en:start -->
Recursion reduces a problem to a smaller instance of the same kind and uses the call stack to turn an abstract definition into an execution process.
<!-- bilingual-en:end -->

![[递归与递归数据]]

### 7. Python 面向对象、类与继承
<!-- bilingual-en:start -->
*7. Python Object-Oriented Programming, Classes, and Inheritance*
<!-- bilingual-en:end -->

递归数据和函数仍分散状态；类与继承把数据、不变量和行为组织成抽象数据类型。
<!-- bilingual-en:start -->
Recursive data and functions can still leave state dispersed. Classes and inheritance organise data, invariants, and behaviour into abstract data types.
<!-- bilingual-en:end -->

![[Python 面向对象、类与继承]]

### 8. 算法复杂度、排序与哈希
<!-- bilingual-en:start -->
*8. Algorithmic Complexity, Sorting, and Hashing*
<!-- bilingual-en:end -->

正确程序还要知道规模增大时是否可用，因此用复杂度比较算法并理解排序与哈希。
<!-- bilingual-en:start -->
A correct program must also remain usable as the input grows, so complexity is used to compare algorithms and to understand sorting and hashing.
<!-- bilingual-en:end -->

![[渐近记号与算法复杂度]]

复杂度记号先提供比较增长率的共同尺度；排序算法再让同一个任务中的时间、空间、稳定性和数据假设可以具体对照。
<!-- bilingual-en:start -->
Complexity notation first provides a common scale for comparing growth rates. Sorting then makes time, space, stability, and data assumptions concrete within one shared task.
<!-- bilingual-en:end -->

![[排序算法]]

排序通过建立全局次序支持搜索和遍历；哈希表改用键到位置的映射换取平均常数时间访问，但承担冲突和最坏退化风险。
<!-- bilingual-en:start -->
Sorting establishes a global order that supports search and traversal. A hash table instead maps keys directly to locations for average constant-time access, at the cost of collisions and possible worst-case degradation.
<!-- bilingual-en:end -->

![[哈希表]]

### 9. 随机模拟与数据可视化
<!-- bilingual-en:start -->
*9. Stochastic Simulation and Data Visualisation*
<!-- bilingual-en:end -->

复杂度预测资源增长；随机模拟和可视化把算法用于无法解析求解的实验，并呈现不确定性。
<!-- bilingual-en:start -->
Complexity predicts resource growth. Stochastic simulation and visualisation apply algorithms to experiments that lack analytic solutions and communicate their uncertainty.
<!-- bilingual-en:end -->

![[Monte Carlo 模拟]]

Monte Carlo 产生的是一整个模拟分布而不只是一个答案；可视化随后用于检查模拟是否合理，并把离散程度、尾部和比较结果准确传达出来。
<!-- bilingual-en:start -->
Monte Carlo produces an entire simulated distribution rather than a single answer. Visualisation then checks whether the simulation behaves plausibly and communicates its spread, tails, and comparisons accurately.
<!-- bilingual-en:end -->

![[数据可视化与不确定性表达]]
