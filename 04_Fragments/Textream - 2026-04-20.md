# Textream

## 一句话总结

Textream 是一个免费、开源的 macOS 提词器应用，把脚本以 Dynamic Island 风格提示层、浮窗、全屏或 Sidecar iPad 的形式放在说话者视线附近，并通过实时语音跟踪、经典自动滚动、语音触发滚动来减少直播、访谈、演讲、播客录制时的视线偏移和流程中断。

## 核心问题

- 直播、访谈、演讲和录制时，如何在不明显低头看稿、不频繁切窗口的情况下保持脚本可见？
- 一个提词器如果要真正融入线上表达工作流，需要具备哪些能力：位置、可见性、控制方式、隐私、多人协作、输入输出格式？
- Textream 的价值是“自动滚动文本”，还是“低摩擦、低干扰、只对自己可见的提示层”？
- 哪些场景适合使用 Textream，哪些场景仍然需要传统讲稿、PPT 备注或专业提词器？

## 详细梳理

### 1. 它解决的不是“没有地方放稿子”，而是“稿子会破坏表达现场”

在直播、面试、远程演示、播客录制、课堂讲授这类场景里，讲稿、提纲、广告口播、访谈问题通常已经存在，真正的问题是它们和镜头、会议窗口、演示窗口之间发生冲突。普通备忘录或文档窗口虽然能显示文字，但会带来几个摩擦：

- 说话者需要把视线移到屏幕一侧或低头看另一台设备，眼神会脱离镜头或嘉宾。
- 切换窗口会打断注意力，尤其是在屏幕共享、直播推流或讲解 demo 时。
- 脚本滚动需要鼠标或触控板介入，手动操作会和表达节奏竞争。
- 如果脚本出现在共享画面里，观众可能也会看到本来只属于讲者的提示。

Textream 的产品定位正好围绕这些摩擦展开：它把文本放到屏幕顶部的 Dynamic Island 风格提示层、可拖动浮窗、全屏提示器，或者外接显示器/Sidecar iPad 上，让脚本保持在讲者可见的位置，同时尽量不打断正在进行的表达任务。

### 2. 三种引导模式对应三类读稿节奏

Textream 把“跟稿”拆成三种模式，而不是只提供一种匀速滚动：

- Word Tracking：默认模式。通过 macOS 本地语音识别监听你的发言，并在你说到相应位置时高亮词语。它适合完整脚本、需要逐字贴合的口播、演讲稿或课程稿。
- Classic：经典自动滚动。文本按照固定速度前进，不需要麦克风。它适合不想开启语音识别、环境噪音较大、或者只需要粗略跟随提纲的场景。
- Voice-Activated：语音触发滚动。说话时滚动，沉默或静音时暂停。它介于前两者之间，更适合自然节奏下的讲述，因为人停顿时稿子也不会继续跑远。

这三个模式说明 Textream 的设计重点不是“把文本滚起来”，而是承认不同表达场景对节奏控制的要求不同：逐词追踪适合脚本化表达，恒速滚动适合确定节奏的录制，语音触发适合更自然的半即兴表达。

### 3. 提示层形态：Dynamic Island、浮窗、全屏与 Sidecar

Textream 的显示方式也被拆成多种形态：

- Dynamic Island overlay：贴近 MacBook 顶部刘海区域的提示层，位于所有应用之上。这个形态强调“靠近视线中心但不占用主内容区”。
- Floating Window：可拖动的浮窗，可设置毛玻璃效果和透明度，也可以跟随鼠标。这个形态适合没有刘海屏、外接屏、多窗口工作或想自己决定提示位置的用户。
- Fullscreen Mode：在任意显示器上全屏显示提词内容，适合正式演讲、外接提词屏、远距离阅读。
- External Display 与 Sidecar：可以把 iPad 或外接显示器作为提示器，也支持镜像翻转，面向更接近专业提词器设备的使用方式。

这些形态构成了一个核心产品判断：提示内容应该尽量进入“周边注意力”，而不是变成另一个需要管理的主窗口。对于创作者来说，这种周边提示层比普通文档更接近真实表达现场的需求。

### 4. “只让自己看见”是关键功能，不是附加功能

官方页面强调 Textream 可以把 overlay 隐藏于屏幕录制和视频通话之外，让只有讲者能看到提词器。这一点对使用场景很关键：

- 面试或访谈中，讲者可以看到问题列表、追问方向和嘉宾信息，但不希望对方看到。
- 直播或录屏中，观众看到的是自然表达，而不是提词工具本身。
- 教学或演示中，讲者能保留讲解顺序、重点和提醒，不影响屏幕共享内容。

这里的设计价值不是“隐蔽作弊”，而是把讲者的操作层和观众的展示层分离。好的表达工具应该允许讲者有自己的 backstage，不把所有准备过程暴露到 frontstage。

### 5. 本地优先与隐私边界

Textream 的语音识别使用 macOS 本地 speech recognition，官方说明强调无云端、无账号、无追踪、数据不离开 Mac。对提词器来说，这不是小卖点，因为脚本里可能包含：

- 未发布的演讲内容、课程内容、产品发布信息。
- 访谈问题、客户信息、会议提示。
- 赞助商口播、商业合作、播客大纲。
- 个人表达草稿或敏感话题。

因此 Textream 的隐私承诺可以理解为它的采用门槛之一：如果提词器需要持续监听声音、读取完整脚本、与视频会议同时运行，那么本地处理和无账号模式能显著降低用户的心理成本。

### 6. Accessibility 与可读性设置

Textream 提供字体、字号、颜色和 OpenDyslexic 等设置，并支持多语言和 CJK 文本。它把提词器当作阅读辅助工具来设计，而不是只当作一个文本播放器。

这对实际使用很重要。提词器失败常常不是功能缺失，而是阅读压力过高：字太小、对比度不合适、高亮不明显、滚动速度和阅读速度不匹配、CJK 换行不舒服。Textream 把这些可读性参数暴露出来，说明它关注的是长时间阅读时的稳定性。

### 7. Remote Connection 与 Director Mode 把它从个人工具扩展为现场协作工具

Textream 不只支持本机读稿，还提供远程连接和 Director Mode：

- Remote Connection：手机、平板或另一台电脑可以通过本地网络浏览器查看提词器状态，不需要安装额外应用。
- Director Mode：另一个人可以在浏览器里写入和推送脚本，讲者端开始跟读，已读文本会锁定，未读文本仍可编辑。
- Director API：README 说明了 HTTP 与 WebSocket 端口、客户端命令和状态帧，说明这个模式不仅是界面功能，也有可扩展的协议层。

这让 Textream 的边界从“我自己看稿”扩展到“现场有人帮我控稿”。对直播、访谈、课程和发布会来说，这个能力很重要：讲者不一定能同时管理内容、节奏、嘉宾和技术细节，导演或助理可以在后台更新未读部分。

### 8. 文件、导入和启动入口决定它能否进入日常流程

Textream 支持几类工作流入口：

- PowerPoint notes import：可以从 `.pptx` 中提取 presenter notes；Keynote 和 Google Slides 需要先导出成 PowerPoint。
- `.textream` 文件：保存脚本以便复用，支持多页内容。
- URL scheme：通过 `textream://read?text=...` 启动读稿。
- macOS Service：可在其他应用中选中文本后通过服务菜单发送到 Textream。
- Auto update checker：启动时或菜单中检查 GitHub Releases。

这些功能说明它不只是一个“打开后粘贴文本”的小工具，而是试图嵌入内容生产链路：从幻灯片备注、文档选中文本、自动化链接、远程控制，到最终读稿。

### 9. 安装与使用边界

Textream 的门槛和限制也很明确：

- 系统要求是 macOS 15 Sequoia 或更高版本，因此旧系统用户不能直接使用。
- 它是独立分发的应用，不通过 Mac App Store；官方给出首次启动时清除 quarantine 属性的命令。这意味着普通用户可能会遇到 macOS 安全提示。
- 本笔记没有验证它在 Zoom、Google Meet、OBS、Teams、ScreenFlow、QuickTime、Keynote 等软件中的 overlay 可见性和隐藏效果。
- 语音识别虽然本地处理，但实际体验仍可能受麦克风权限、环境噪声、语言识别质量、口音、语速影响。
- Director Mode 和 Remote Connection 依赖本地网络；在公司网络、校园网、VPN 或防火墙环境下可能需要额外测试。

因此，Textream 值得放入工具箱，但真正进入正式工作流前，需要针对自己的会议软件、录屏软件、直播软件做一次完整彩排。

## 关键论点与依据

- Textream 的核心定位是 macOS 提词器，而不是普通笔记窗口；依据是官方页面和 README 都把它描述为面向 streamers、interviewers、presenters、podcasters 的 teleprompter。
- 它的核心差异来自三种引导模式：实时词语跟踪、经典自动滚动、语音触发滚动；依据是官方功能说明和 README 的 Guidance Modes。
- 它强调“提示层”而非“文档编辑器”：Dynamic Island overlay、Floating Window、Fullscreen、External Display/Sidecar 都围绕显示位置和不干扰主任务展开。
- 隐私是产品可信度的一部分；依据是官方说明强调本地语音识别、无云端、无账号、无 tracking、数据不离开 Mac。
- 它具备从个人工具走向现场协作的可能性；依据是 Remote Connection、Director Mode、Director Mode API、WebSocket 状态同步和浏览器端控制说明。
- 它的采用限制包括 macOS 15+、独立分发带来的首次启动阻拦、以及不同会议/录屏软件中的实际表现需要测试；这些限制来自官方系统要求和安装说明，实际兼容性判断需要本地验证。

## 可复用框架

### 低摩擦提示层框架

一个适合直播、演讲、访谈的提示工具，至少要回答六个问题：

1. 可见性：提示是否位于讲者自然视线附近，而不是迫使讲者明显转头或低头？
2. 非干扰：提示是否能覆盖在当前工作界面上，同时不阻挡主要交互？
3. 节奏控制：提示是否能跟随人的说话速度，而不是要求人迁就机器滚动速度？
4. 观众隔离：提示是否只对讲者可见，不被会议、直播、录屏捕获？
5. 输入整合：它是否能接入已有材料，如 PPT 备注、脚本文件、选中文本、URL scheme？
6. 现场协作：当讲者不能自己控稿时，是否允许导演、助理或远程设备参与控制？

### 提词器选型检查表

- 是否支持我的系统版本和芯片架构？
- 是否能在我常用的软件组合中隐藏于观众视角之外？
- 是否支持我的语言、字体、字号和高亮偏好？
- 是否需要云端语音识别或账号登录？
- 是否可以在没有麦克风权限时继续使用基本滚动？
- 是否能从我已有的写作工具或幻灯片流程导入内容？
- 是否支持彩排、暂停、跳转、回退和现场改稿？
- 失败时是否有低技术备份方案，例如纸质提纲或第二屏静态备注？

## 对我的启发

- 这类工具的本质不是“更懒地读稿”，而是把表达现场中的认知负担外包给一个低存在感的提示层。
- 做演讲、课程、播客、录屏时，可以把正文稿、关键转场句、易忘数据、引用来源、广告口播放进 Textream，而不是只依赖临场记忆。
- 如果用于学习或讲题，可以把“定义、结论、下一步推导、易错点”做成提词文本，帮助自己录制更连贯的讲解。
- 产品设计上值得注意的是：Textream 没有只做一个文档窗口，而是围绕真实场景拆出显示形态、节奏控制、隐藏机制、远程协作和输入入口；这比单点功能更接近工作流产品。
- 使用前应该做一次完整测试：打开会议软件、屏幕共享、录屏、外接显示器、麦克风权限和隐藏开关，确认“我能看到、观众看不到、录制结果正常”。
