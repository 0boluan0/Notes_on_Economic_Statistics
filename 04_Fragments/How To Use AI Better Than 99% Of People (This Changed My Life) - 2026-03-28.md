# How To Use AI Better Than 99% Of People (This Changed My Life)

## 一句话总结
这支视频最值得保留的不是某个单一 prompt，而是一条很清晰的 AI 使用原则：不要让 AI 瞎猜你要什么，而要先把专家知识、任务结构、个人上下文和执行阶段都组织好，再让 AI 在这个框架里工作；本质上，Dan Koe 推的是“AI orchestration”而不是“问一句、答一句”的随手聊天。

## 核心问题
- 为什么大多数人虽然天天用 AI，但结果仍然很一般？
- Dan Koe 的核心方法与普通 prompt engineering 有什么不同？
- 如何把 AI 从“回答器”变成“可复用的执行系统”？

## 详细梳理
### 1. 核心立场：AI 的问题不是不够聪明，而是你没有给它足够结构
开场部分 Dan Koe 说自己使用 AI 的方式和多数人不同。差异不在模型，而在方法：多数人直接把模糊任务扔给 AI，让它猜；而他更强调先构建一套结构化输入。

### 2. 第一步：先拿到“专家级详细说明”
视频 6:49 之后开始进入操作层。Dan Koe 的第一步不是直接写 prompt，而是先获得某项任务的详细 expert instructions。这个“说明书”可以来自：
- 你自己写
- 让 AI 生成一份通用 guide
- 导入一位已知专家的 PDF、视频、文章来提炼
- 模仿一个你真正喜欢的示例并拆解其结构

这一步非常关键，因为它在做的其实是“先找对方法，再交给 AI 执行”。

### 3. 第二步：把说明书转成 meta prompt，而不是一次性 prompt
到 14:47 之后，Dan Koe 把重点放在 meta prompt 上。也就是，写一个“帮助你生成高质量 prompt 的 prompt”。这样做的好处是：
- 你不必每次从零写复杂指令
- 你可以保留结构化模板并反复迭代
- prompt 本身会变成可积累、可升级的资产

### 4. 第三步：加上 context gathering phase + execution phase
视频里最实用的一点，是他把 prompt 拆成多个 phase。比如个人品牌教练的例子里，先让 AI 逐步提问收集背景信息，再生成 30 天计划，最后进入逐日 coaching。这里的关键不是“prompt 很长”，而是它清楚地区分了收集上下文、形成计划和执行反馈这几种不同任务。

### 5. 用 AI 学习与构建同时发生
21:39 左右，Dan Koe 总结时说了一句很准的话：以这种方式使用 AI，你其实是在同时学习和构建。因为你不是把任务完全外包出去，而是在一边组织方法，一边把自己的流程外显化、文档化和可复用化。

### 6. Prompt library、coach、advisor、thought partner 才是长期价值
视频后半段给了几个例子：个人品牌教练、思想 sparring partner、创意 thought partner。重点并不是这些例子的领域，而是同一个模式可以反复复用：
- 拿到高质量知识源
- 提炼成结构化说明
- 做成会收集上下文和阶段执行的 prompt
- 存进自己的 prompt library

这比单次聊天强得多，因为它会随着你经验增长而不断升级。

## 关键论点与依据
- 大多数人用不好 AI，问题在于让它在低上下文里乱猜。依据：开场与 6:49 后的详细 instructions 部分。
- 先提炼专家说明书，比先写 prompt 更关键。依据：10:46 左右“Find An Expert Source Of Information”。
- 模仿优质示例比泛泛问“怎么写”更能得到高质量结构。依据：11:47 左右“Emulate An Example You Like”。
- Meta prompt 的价值在于把 prompt 写作本身也变成系统。依据：14:47 之后的 meta prompt 讲解。
- 最优 AI 用法是 orchestration：既学习，也构建，也文档化自己的方法。依据：21:39 左右的总结与 prompt library 讨论。

## 可复用框架
### Dan Koe 式 AI 工作流
1. 定义任务，不让 AI 猜目标。
2. 获取专家级说明书或优质范例。
3. 把说明书转为可复用 meta prompt。
4. 强制加入 context gathering 阶段。
5. 再进入 action plan 和 execution 阶段。
6. 将结果沉淀为自己的 prompt library。
