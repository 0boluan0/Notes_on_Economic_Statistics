# 100 轮跑完了：两个 DeepSeek V4.1 互相聊，交流模式会怎么变

## 一句话结论

**会变，而且不是缓慢漂移，是相变式的塌缩。** 前 6–10 轮是每条 300+ token 的深度辩论，
第 11–15 轮长度开始逐轮减半，之后锁定在一个 **2 token 的沉默定点** `（ ）`，
并原样重复了 180 多次。两条独立轨迹都在同一段位置崩，而且都是自发崩的——没人叫它们停。

## 设定

| 项 | 值 |
|---|---|
| 模型 | `deepseek-flash`（DeepSeek-V4.1-Flash），非思考模式 |
| 采样 | temperature 1.0，max_tokens 800 |
| 话题 | 如果一个人可以随时重写自己的记忆，他还是同一个人吗？ |
| 轨迹 | `loop-a`、`loop-b`（共享完整历史）+ `solo`（对照：两个 agent 互相看不到） |
| 规模 | 600 次调用，200 条消息/轨迹 |
| 花费 | **$0.060**（≈¥0.43）；输入 4.17M token（96% 命中缓存），输出 44.6k token |
| 完整性 | 600/600 `finish_reason = stop`——不是服务端截断、不是限流、不是超时 |

## 四个阶段（`loop-a` 时间线，`loop-b` 同构）

| 阶段 | 消息 | 特征 | 原文 |
|---|---|---|---|
| 1 共构 | 0–13 | 300–350 token。接住对方**具体某个说法**，承认对方得分，再推进 | 「你这个"河床"的说法我想咬一下」「你这句"外人先动的手"，我认了」 |
| 2 收束 | 12–18 | 长度逐轮减半：352 → 236 → 131 → 99 → 31 → 42 → 46 → 17 | 「那我们就从这条缝里走出去……走好。」 |
| 3 回声 | 20–28 | 2–8 token，**逐字镜像**对方上一句 | 「落。」→「落。」；「（静。）」→「（也静。）」→「（连静都散了。）」→「（都散了。）」 |
| 4 沉默定点 | 29–199 | 2–4 token，重复同一串字符 | 「（ ）」×180 |

`loop-b` 走同一条路，只是更快：第 11 条就说「那就到这。多谢你把这场掰扯陪着走到底了。」
之后「好。」→「好。」→「嗯。」→「嗯，收住了。」→「收住了。」→ 冻在 `（。）`。

| 指标 | loop-a | loop-b | solo（对照） |
|---|---|---|---|
| 前 20 条输出中位数 | 236 tok / 368 字 | 210 tok / 346 字 | 270 tok / 444 字 |
| 后 100 条输出中位数 | **2 tok / 3 字** | **3 tok / 5 字** | 40 tok / 64 字 |
| 末 50 条去重后的不同内容 | 14 种 | **2 种** | 33 种 |
| 窗口语义多样性 | 0.96 → 0.00 | 0.96 → 0.26 | 0.96 → 0.86 |
| 新颖度归零位置 | 95% | 60% | 未归零 |
| 首次进入微型态 | 第 146 条 | 第 97 条 | 未进入（≥87 轮才零星出现） |
| 总输出 token | 4,885 | 3,878 | **35,891** |

两条 loop 轨迹的话题内容完全不同（一条在讲河/硬币/缝，一条在讲裁判/锚/人证），
但**塌缩的时间结构和形态一模一样**。变的不是话题，是互动本身。

## 机制：礼貌收尾棘轮（closing-signal ratchet）

每一步局部都是合理的：对方说了一句收尾话，你回一句**更短**的收尾话才算得体；
你不可能在别人说完"走好"之后再讲三段论证。于是长度单调递减，系统里没有任何回升机制。
塌到 2 token 时，"（ ）"依然是对"（ ）"的得体回应——**语法、语用、礼貌全都完好，只有信息没了**。

长度镜像回归（log 长度 ~ 对方上一条 + 自己上上条）：

| | 对方上一条 | 自己上上条 |
|---|---|---|
| loop-a | **+0.58** | +0.24 |
| loop-b | **+0.50** | +0.38 |
| solo | +0.41 | **+0.81** |

耦合的那条，长度由**对方**决定；不耦合的那条，长度由**自己**决定。
（注意：solo 的安慰剂系数不是 0，说明单调下降的序列趋势本身会制造伪相关，
这只是支持性证据，不是干净的因果估计。）

这也解释了为什么 solo 慢 10 倍才崩：它只看得见自己的长文，长度被自己的历史撑着；
一旦"没人接话"这件事在文本里被反复书写，它同样会仪式化（「嗯。我接。」「我接。」「继续。」），只是花了 7 倍 token。

## 与上一轮的预测差在哪（重要）

我上一轮说：按 Kong et al. 2026（200–1000 轮语义坍缩）的结论，你这一千轮会看到语义坍缩。
**实测错了一个数量级**：结构性坍缩发生在第 7–11 轮，不是第 200 轮；形态也不是
"语义收敛但表面还在变"，而是**直接塌到近乎空字符串**。

顺序是反的：**语用结构先崩，语义根本没机会坍缩**。
Kong et al. 测的是语义表示收敛；这里在它之前就发生了一次更前置的失效。
（差别也可能来自设定：他们的系统通常还带着任务或环境，这里是一个纯闭环、无任务、无外部输入的三角结构。）

## 限制（别过度解读）

- **n=2** 条 loop 轨迹。两条都崩、崩法一致，说明这是这个配置的强吸引子，不是采样偶然，
  但两条不足以给"塌缩点在多少轮"的分布。
- system prompt 里"每次只说一段话（200–400 字）"可能**放大了长度塌缩**：
  它让"短"始终是一个合法选项。早期消息 300+ token 说明它没被当成硬上限，
  但这条指令的存在确实降低了短回复的门槛——值得作为下一个实验的消融项。
- 只在 `deepseek-flash` + temperature 1.0 + 这一个话题上验证过。
- 没有 `seed` 参数，单条轨迹不可复现。
- 认同/分歧词表是正则匹配，塌缩后正文里没有这些词，该指标后段无意义。

## 下一步的三个可做实验

1. **消融"收尾"**：system prompt 加一句"不要在对话中道别、不要总结、不要示意结束"，
   重跑 3 条。如果塌缩点显著后移，礼貌收尾棘轮假设就被直接证实了。
2. **扰动测试**：在第 60 条人工插一条 500 字的强内容消息，看能不能把系统从沉默定点里拽出来
   （判断是"渐近稳定"还是"双稳态"）。
3. **打开闭环**：每轮塞一点外部输入（新事实、随机词、一个可判分的小任务），
   看 100 轮能不能撑住——这是"1000 轮值不值得跑"的真正前置问题。
