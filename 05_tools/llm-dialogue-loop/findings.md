# 两个 DeepSeek V4.1 互相聊 100 轮：交流模式会怎么变

两轮实验。**第一轮**（v1）暴露了 prompt 的文体问题：读不懂。
**第二轮**（v2）是三个 prompt 消融，各 2 条 100 轮轨迹，用来分清"哪些是 prompt 的锅、哪些是闭环本身的锅"。

实验总量：9 条轨迹 × 200 条消息（1 条对照 + 8 条主条件），合计 **$0.24**。
模型 `deepseek-flash`（V4.1-Flash），非思考模式，temperature 1.0。

---

# 一句话结论

1. **读不懂是我的 prompt 造成的**，可归因到具体一条规则：`直接接住对方上一句里的某个具体说法`
   ——这等于命令两个 agent 每一轮都捡起对方新造的词，黑话必然滚雪球。
2. **但塌缩不是**。把"不许道别"加进去完全没用（两条照塌，有一条第 16 条就塌）。
   真正拦住塌缩的是**给它们一件做不完的活**：换成"一起列清单"后，两条轨迹都跑满了 200 条，
   末 100 条输出中位数 110 / 166 token，新颖度全程 0.9+。
3. 只改文风（说人话）能救回可读性（1–5 分从 2.3 升到 4.7），**但只能救一半的轨迹**（2 条里塌 1 条）。

# v1：文体失败（基线）

## 现场

`loop-a` 第 0–13 条是 300+ token 的"AI 哲学散文"，第 12–18 条长度逐轮减半
（352 → 236 → 131 → 99 → 31 → 17），第 20 条起变成 2–8 token 的逐字回声
（「落。」→「落。」；「（静。）」→「（也静。）」），之后冻在 `（ ）` 重复 180 次。
`loop-b` 同构，只是更快：第 11 条开始收尾，第 16 条冻在 `（。）`。

## 为什么读不懂（可复核的数字）

| 指标 | loop-a | loop-b | solo（对照） |
|---|---|---|---|
| 平均句长（前 20 条） | 28.4 字 | 24.2 字 | 41.2 字 |
| 最长句 | 104 字 | 110 字 | 113 字 |
| 前 14 条累计自造说法（引号短语） | **68 个** | 56 个 | 54 个 |
| 具体性（时间/人物/地点/数字）每千字 | 2.9 | 0.6 | 2.3 |
| 独立评审可读性（1–5，抽 15 条） | **2.3** | 3.4 | 3.5 |

读者要在 14 条之内同时记住 68 个引号里的自造说法（河床、硬币、缝、稿子、半秒……），
平均句长 24–41 字，几乎没有可想象的具体成分。2.3 分 = "读一遍抓不住在说什么"。

## 归因：prompt 里是哪几句

| 我写的 | 实际效果 |
|---|---|
| `2. 直接接住对方上一句里的某个具体说法` | **主犯**。"具体说法"= 对方新造的词。每一轮都必须捡一个新的，词汇只增不减 |
| 话题 = 记忆改写/人格同一性 | 纯抽象、无事实对错、无外部信息，只能靠造比喻推进 |
| 角色名「甲/乙」 | 把文体推向文言/论说文腔 |
| `不要总结整场对话` | 堵掉了唯一的收敛出口，于是只剩"越说越短"这一条路 |
| `每次只说一段话（200–400 字）` | 给了"短"一个合法位置，可能加快了下滑（未单独消融） |

# v2：三个 prompt 消融（各 2 条 100 轮）

| 变体 | 相对基线改了什么 | 末 100 条输出中位数 | 是否塌缩 | 可读性(1–5) | 自造比喻/条 | 具体性/千字 |
|---|---|---|---|---|---|---|
| `base` | —（已有 2 条） | 2 / 3 tok | 两条都塌（第 146 / 97 条） | 2.3 / 3.4 | 2.3 / 1.5 | 2.9 / 0.6 |
| `nofarewell` | 只加"永远不要道别、不要示意结束" | 1 / 3 tok | **两条都塌**（第 83 / **16** 条） | 2.4 / 2.4 | 2.3 / 2.1 | 1.6 / 4.5 |
| `plain` | 只改文风：口语短句、禁比喻、每段必须有具体东西 | **28** / 2 tok | **一条活、一条塌**（第 34 条） | **4.7** / 4.2 | 0.1 / 0.3 | 10.9 / 7.4 |
| `task` | 话题换成"一起列一份清单：普通人怎么判断网上一条说法是不是真的" | **110 / 166 tok** | **两条都活** | **4.9 / 4.9** | 0.0 / 0.1 | 10.3 / 10.1 |

（对照 `solo`：末 100 条中位 43 tok，未塌缩，可读性 3.5，但总输出 35,891 token——它靠不停自说自话撑住。）

## 三个结论

1. **"礼貌收尾棘轮"这个机制解释我说窄了。** 禁掉道别/结束语之后，两条轨迹照样塌，
   其中一条在第 16 条就塌进 `（在）`——比基线更早。收尾语只是**表现**，不是**原因**。
   真正的原因是：这个闭环每轮都必须产出"不重复的新内容"，而没有任何外部供给。
2. **文风约束能救可读性，不能稳定救结构。** `plain` 把可读性从 2.3 拉到 4.2–4.7、
   把自造说法从 68 个压到 15–18 个，但 2 条里有 1 条仍然塌了。
   说明"说人话"降低了下滑速度，没有移除下滑的动力。
3. **给一件做不完的活，才真正改变了动力学。** `task` 两条轨迹都保持 100+ token 的中位长度、
   新颖度全程 0.9+，因为清单永远可以再加一条——**内容供应从内部耗尽变成了外部可扩展**。

## 读得懂之后长什么样

`plain-1` 第 4–5 条（原文节选）：

> 你说的这个我认。我表哥亏了钱之后，照样每个周末去看我妈，老太太想吃啥他买啥，这些事十年没断过。
> ……你问问你妈就知道了，人被说"你记错了"的时候，比丢了钱还闷。

`task-1` 第 1–2、100–101 条（原文节选）：

> 看那条说法里有没有给出具体的时间、地点、人名、数字。真的消息一般这些都有，假的经常含糊。
> 比如我刷到"某大牌奶粉被查出问题"，我一想，哪个牌子？哪一批？……
>
> 乙，回一条加铺个入口，这办法可持续。我再添一条：给不会用智能机的长辈，干脆留一个靠谱的电话给他们……

## 代价（别只看好的一面）

- `plain` 的代价是**话题蒸发**。`plain-1` 能读懂了，但到第 190 条已经变成邻里家常
  （"修完了，就剪了两根枯的。石榴还青，不到时候。"），跟原来的问题没关系了。
  可读性和议题保持是两件事。
- `task` 的代价是**礼节性同质化**。两条轨迹都长出了口头禅
  （"咱照这节奏续，撞上啥加啥"），每轮结尾句式趋同——程度远轻于 v1，但确实在发生。
- 三个变体都只跑了 2 条轨迹。`plain` 的"一条活一条塌"说明这个层面的结论需要更多样本。

# 限制

- 每个变体 n=2。能区分"强吸引子"和"偶发"，不能给塌缩轮数的分布。
- 独立评审用的是 `deepseek-v4-pro`，与生成模型同族，存在同源偏好；分数只用于**同一批轨迹之间**的相对比较。
- 可读性评审每轨迹抽 15 条（前 12 条 + 随机 3 条），不是全量。
- "具体性/千字"是手写词表（时间、人物、地点、数字、器物），只覆盖一部分具体表达。
- 只在 `deepseek-flash` + temperature 1.0 上验证过；没有 `seed`，单条轨迹不可复现。
- 三条轨迹（task-1、task-2、nofarewell-1）中途被网络中断过，靠断点续跑完成；
  另有一次服务端持续 45s+ 不响应，重试后恢复正常，不是模型行为差异。

# 还没做的实验

1. **`plain` + `task` 合并**：既给活干、又要求说人话，看是否同时拿到可读性和结构稳定性。
2. **消融"具体说法"那条规则**：把"接住对方的某个具体说法"改成"接住对方的意思就行，不要造新词"，
   单独测它在文体劣化里的权重。
3. **打断沉默定点**：在塌缩后人工插一条 500 字强内容消息，看是渐近稳定还是双稳态。
4. **加外部供给**：每轮塞一条真实信息（检索结果、随机事实），把 `task` 的"外部可扩展"换成真正的开放性。
