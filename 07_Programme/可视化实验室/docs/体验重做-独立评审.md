# 体验重做：独立评审

这次应重做教学场景，而不是继续增加图或文字。现有计算可以支持学习，但界面主要呈现“模型的全部输出”，没有把学习者带过“我改变什么 → 哪条依赖受影响 → 为什么得到这个结果”。精美也需要这个主次关系：每个屏幕有一个值得看的主体，其余元素帮助读懂它。

## 审查范围与证据边界

本轮直接阅读 `assets/app.js`、`assets/style.css`、`assets/content.js`、`assets/math.js`、`assets/dl-content.js`、`assets/dl-math.js`，结合当前逐图记录作设计复审。以下结构、数据、样式问题有源码依据；有关初学者理解和屏幕感受的判断是待真实交互验收的设计判断。本轮没有重新操作当前界面，不把“已渲染、能读数”当作“用户已经理解”。

## 首要问题

| 优先级 | 现有事实 | 对学习的影响 | 应改变什么 |
|---|---|---|---|
| 1 | `render()` 先输出指标、全部动态说明、全部图和公式，最后才是“观察与操作”。 | 操作指导来得太晚。“先只看原函数”与已经完整展开的页面矛盾。 | 把当前一步的动作放到主图旁；每次只强调一个问题。完整推导和条件仍可展开。 |
| 1 | Backprop 计算图只有连续五节点；梯度柱状图只列 ŷ、h、z、w。数据中实际已有 b、v 梯度。 | 参数在图外，局部导数在图外，梯度又在另一图。读者必须自己拼回链式法则；v=0 情境尤其容易误读为全部参数都无梯度。 | 参数接入实际依赖节点；把反向数值直接放回相应边和分支。 |
| 1 | Attention 的全部 Value 与输出随共同尺度同比变化，向量图却每次自动取坐标范围。 | 缩放后图形可几乎保持相同屏幕位置，只剩刻度变化。主问题“权重不变，输出会变吗”被呈现方式掩盖。 | 比较时锁定坐标范围，保留 1 倍基准位置，直接显示当前输出的位移和数值差。 |
| 1 | 参数只有通用更新事件；预设会一次恢复并改变多项参数，没有列出变化。 | 用户看见许多东西一起变，却不知道哪项导致哪项。 | 主动作只改一个变量；多参数情境切换说明这是新情境，并提示关键条件。 |
| 2 | 所有图同样式、所有指标同权重，保存 SVG 重复出现在每幅图标题旁。 | 视觉上没有“这张图就是本页答案”的中心。数值核验图与概念机制争夺注意力。 | 一张主场景承载机制；辅助比较、验证和导出降低层级。 |
| 2 | 所有数值参数几乎同样呈现；≤980px 控件整体移到结果前，≤420px 又全部竖排。 | 小屏学习者先穿过一长列不知道为何要动的控件，才见到图。 | 当前一步只展开一至两个相关控件，放在场景上缘或紧邻场景；更多参数折叠。 |
| 2 | 图依赖分离的图例、通用坐标提示及系列顺序配色。 | 色彩是绘图顺序，不是概念身份；悬停只报坐标也不能补足推导关系。 | 关键对象直接标名，颜色在一次实验内保持语义；必要关系不依赖悬停。 |

现有 NN 文案也需要负责：首问常直接进入“梯度为何中断”等第二层问题；与此同时把模型边界、梯度核验、挑战答案都准备得很完整，却没有给首次接触者一个短而可完成的入口。删减首屏负担不会牺牲严谨性，前提是把关键条件放在相应现象旁，并保留可查的完整层。

## 三项共享的编排规则

- 首屏是“一个问题、一幅主场景、一个建议动作”。不以一排指标和一整块条件说明开场。
- 按“看见变化 → 算出变化 → 检查边界”推进。步骤切换改变强调与说明，计算仍使用当前真实参数。
- 只把当前有用的量放大。变量名、数值、运算符各有稳定位置；保留合理小数位，精度详情另查。
- 主体使用大面积留白和少量分隔线，减少相同的嵌套卡片。图形线条、公式和控件使用一致的对象名称；强调色服务于当前因果路径。
- 一步操作后给出具体反馈，例如“v 从 1 变为 0，传给 h 的梯度变为 0”；不要只写“结果已更新”。
- 需要比较大小和移动时保持坐标基准。主动放大可以保留，但必须明确正在改变视窗。
- 桌面先保证图有足够空间，导航可收起；窄屏先呈现场景与一个动作，再给展开项。字号和触控目标不能靠压缩到不可读来保住横排。
- 保留公式、来源和导出能力，放入可展开的“怎么算 / 条件与来源 / 更多”区域。关键假设仍留在当前步骤中，例如 Attention 是手工二维向量。

## Tangent：让斜率有一段看得见的几何

### 主场景

入口改成：“把右边的点移近，割线斜率会怎样？”先解决有限距离与局部变化率，再进入误差阶数。

主图只强调固定点 P=(x,f(x))、移动点 Q=(x+h,f(x+h))、前向割线和切线。P、Q 直接标名；Q 到 P 的横向与纵向差用直角折线表示，并写出 Δx=h、Δy=f(x+h)−f(x)。图右侧或窄屏下方是一条与图同步的读数：

> 割线斜率 = 竖着变化多少 ÷ 横着变化多少

下面立即代入当前数值，再用小一号文字给出切线斜率。函数细线、割线强调色、切线另一稳定色；不让三种线只靠下方图例区分。图旁只保留 h 主控件，提供 0.5、0.1、0.01 快捷值，细调可用对数映射。x 与函数切换放入“换一个位置或函数”。

固定 x 比较 h 时锁住视窗；小 h 使三角形难辨时，数值标注仍可读，可主动选择“放大附近”。不随着每次 h 更新悄悄追着点缩放。

### 三步编排

1. **先算一条割线。** 用 x³−x、x=1、h=0.5，直接看到 Δx=0.5、Δy=1.875，因此斜率 3.75，而切线斜率是 2。
2. **只把 Q 移近。** 把 h 改为 0.1，P 保持不动，Δy=0.231，差商变成 2.31。显示“差商 3.75 → 2.31；离 2 更近”。保留前一次 Q 的淡轮廓只作短暂比较，随后可以清除。
3. **为什么左右取点更准？** 用户选择“加入左侧点”后再出现 P₋、中心割线和中心差商。h=0.1 时中心差商为 2.01。下面展开误差图，讨论 3xh+h² 与 h²，以及 x=0 的特殊抵消。

误差双对数图属于第三步的解释，不与最初几何图争主位。前向与中心两种方法在公式、几何和误差图中使用同一名称与颜色。

### 理解验收

- 不打开原理面板，学习者能指出 Δx、Δy 分别是哪两段，并用它们解释 3.75 的来源。
- h 改变时能指出 P 不动、Q 移动、比较基准不动；不能只有数字变而图上关系无法辨认。
- h=0.1 时能区别“真实斜率 2”“前向 2.31”“中心 2.01”，不会把中心差商当成另一个函数的导数。
- 对 x=0 的重合，能说出这是当前函数和位置的特殊抵消；界面不暗示所有位置都如此。
- 窄屏无需水平滚动即可同时看到主图、当前差商和 h 的主要动作；标签不覆盖 P、Q 或核心线段。

## Backprop：在同一张依赖图上把梯度送回来

### 主场景

入口先问：“损失怎样告诉 w 应该往哪边动？”目前的“活跃但没梯度”保留为第三步中的对照情境。

用一个有分支的真实计算图取代“前向链图 + 分离梯度柱状图”：

```text
 x ──┐            v ──┐             目标 t ──┐
 w ──┼→ z=wx+b → h=tanh(z) → ŷ=vh → L=½(ŷ−t)²
 b ──┘
```

上行显示真实前向值，青绿表示当前前向依赖；反向梯度用橙色回到同一节点。w、b、v 是可见的参数分支，目标 t 是固定目标输入，不能把它画成正在训练的参数。桌面横向主体，手机纵向主体，参数贴在自己接入的运算旁，避免五张大卡片把关系拉开。

初次示例可使用现有参数范围内的 x=1、w=0、b=0、v=2、t=1：前向是 0、0、0、0.5，反向乘数简单，学习者能手算出 ∂L/∂w=−2。普通非零值和饱和情境仍保留。

### 四步编排

1. **从输入算到预测。** 依次强调 z、h、ŷ；在运算内部显示代入，不先显示全部梯度。
2. **预测与目标的距离。** 高亮 ŷ、t、L，先显示残差 ŷ−t，再显示平方损失及 ∂L/∂ŷ=ŷ−t。说明损失非负，梯度可以带符号。
3. **沿依赖反向相乘。** 从 L 返回，边上写局部乘数：v、1−h²，以及到 w 的 x、到 b 的 1、到 v 的 h。节点上写累积梯度，区分“局部乘数”和“已累计的 ∂L/∂·”。允许单步突出当前一段，完整链始终可查。
4. **用一次小改动核对。** 先读 ∂L/∂w 的符号，预测增加 w 后损失增减；再点击小幅改变 w，显示真实的前后损失。线性预测 ΔL≈(∂L/∂w)Δw 标为局部近似，不承诺大步长也成立。有限差分精度曲线放入“进一步核验”。

第三步有两个非常有用的现成对照：v=0 时，h 可以非零，但 ∂L/∂h 和 ∂L/∂w 为 0；同时 ∂L/∂v=−tanh(1)≈−0.7616。x=0 时，到 w 的分支为 0，而到 b 的分支仍可非零。必须让分支真的出现在画面上，不能只靠段落解释。

### 理解验收

- 学习者能沿同一张图从损失找到 w，口头说出“上游梯度 × 当前局部导数”，并指出至少两个乘数来自哪个运算。
- 使用简洁初始示例时能在画面上复原 (−1)×2×1×1=−2；不会把激活值 h 当成 ∂L/∂h。
- 切换 v=0 后，能指向梯度停止传向 h 的位置，也能指出 v 自己仍有非零梯度；不能呈现“整张网络全部熄灭”。
- 切换 x=0 后，w 与 b 两个分支的区别无需打开文字面板便可读出。
- 小幅改变 w 后，实际损失前后值、变化量、局部预测具有明确标签；不能把近似预测标作重新计算的结果。
- 320px 宽度仍可读出主节点、参数分支和乘数；无需依赖悬停才能知道某个梯度对谁求导。

## Attention：把一行读取过程摊开

### 主场景

先让用户完成一个 Query 的读取，再展开所有 Query 的矩阵。入口为：“C 怎样把 A、B、C、D 的内容混合成一个输出？”权重与内容的区别随后通过一个动作回答。

顶部用 A、B、C、D 按钮选择 Query，取代整数索引滑块。中间四列固定对应四个 Key / Value，依次显示：

```text
所选 Query 的匹配分数 → 允许读取？ → 权重 → 权重 × Value → 相加得到输出
```

同一列从上到下保持身份，直接标 A/B/C/D。权重用共享 0–1 尺度的单色条和数值表示；被屏蔽项用灰色“不可读”并明确权重 0，不让一个鲜艳的有限原始分数先吸引注意再靠 × 撤销。需要原始分数时可以展开。Q、K、V 的具体二维数值必须可查，否则初学者仍只能观察黑箱。

右侧放 Value 与输出向量图；手机放在四列过程下方。固定坐标轴用于尺度对照，保留基准输出轮廓。重点输出采用一个稳定强调色；每一项的加权贡献可点击查看，并与该列对应。完整 4×4 分数与权重矩阵归入“同时看全部 Query”。

### 三步编排

1. **均匀读取容易手算。** 用 Query C、因果掩码、α=0：A/B/C 各占 1/3，D 为 0。显示三项贡献 (1/3,0)、(0,1/3)、(1/3,1/3)，相加为 (2/3,2/3)。原始 Value 与“乘权重后的贡献”不要共用模糊名称。
2. **改变读取比例。** 切换到有分数差异的情境，再只调温度 T，画面显示哪些条变大、哪些变小。α 与 T 在当前模型中通过 α/T 起作用；α 作为进阶参数，避免两个等价的主控件让人误以为控制不同机制。
3. **只改内容，比例不变。** 将 Value 共同尺度由 1 调为 3；四个权重条保持，Value 与输出在同一坐标系中伸长。固定基准输出与当前输出同时可见，并写“权重保持；输出坐标各乘 3”。

图旁保持一句范围说明：“四个 token 是手工二维向量，本页演示一次读取运算。”因果掩码在这里表示序列可见性约束，不用于声称注意力权重是最终预测的因果解释。

### 理解验收

- 学习者可直接从四列指出权重来自哪一行、沿什么方向归一化、为什么 D 的贡献为 0。
- 均匀读取示例能看着贡献项算出 (2/3,2/3)，而不是只读到最终指标。
- Query A 且因果掩码开启时，画面只保留 A 的有效贡献，输出与 V_A 重合；调温度不会制造不存在的变化。
- Value 尺度 1→3 时，权重条确实不变，输出相对固定基准明显移动。若图形仅刻度变而位置不变，本项不通过。
- 说明“温度改变比例、Value 尺度改变内容”时，用户能指向各自变化的具体部分；无需先阅读完整公式段。
- 窄屏仍能追踪选定 Query 与四列身份，屏蔽状态、权重、贡献不依赖颜色或鼠标悬停独立传达。

## 如何判定这一轮做成了

先只重做这三项，用实际场景验证编排。每项选择一位首次看此页的使用者或由验收者按首次访问顺序操作：不预先讲解、不先打开来源、不替页面解释。让其完成一项预测、一次改变、一次说明，再按上面的理解标准判断。

审美复核看主次与秩序：视线先落在主场景；当前动作紧邻其结果；重要名称和数值不用来回查图例；相同对象跨步骤不变身份；窄屏没有长控件墙和被挤小的公式。交互复核看参数变化有没有可定位的原因与结果。数学复核保留对关键条件和结果的核对，但更多断言数量不能替代这三项验收。

实现上先为三项增加专用场景，复用已有 `result.data` 和参数更新接口即可。不需要先抽象一个覆盖全部实验的新框架。等三项确实读得懂，再提炼可复用的布局和交互。

## 本轮后续修订记录

上述审查针对重做前的通用页面。随后已新增 `assets/story-backprop.js` 与样式：前向值、参数分支、局部乘数和累计梯度放回同一张图；小幅改变 w 后，保留改动前梯度、局部预测与重新计算的损失；旧比较在其他条件改变后失效。

主代理的首轮真实交互反馈指出：1280×720 窗口中，场景内部只有约 683px，720px 断点错误地把整张图排成纵向，首屏几乎只有输入节点。第二轮因此把横向阈值改为 600px，压缩参数行与节点间距，移除重复标题，把分支对照按钮移到图前，四因子展开式默认折叠。这个发现说明，单张 SVG 可读仍不足以验收整页。

其余十项神经网络与六项序列/推断实验已在 `assets/guides-dl.js` 各写三步具体路径，逐项选择当前要看的图、指标和参数。它们是阅读顺序的改进，不能据此宣称已经具有与专用场景相同的教学质量。第二轮页面与窄屏的真实复看仍由主代理执行，完成情况以其交互记录为准。
