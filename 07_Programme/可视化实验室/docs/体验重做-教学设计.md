# 体验重做：先做好三个教学范式

当前版本的教学体验不合格。此前主要验证了覆盖范围、数值和图形能否显示，用户仍须自己决定先看什么、哪个数对应哪条线、改变参数为什么会得到这个结果。这些工作应由实验本身完成。下面先重做 `tangent`、`backprop`、`attention`，逐个取得真实体验反馈，再推广。

本设计依据当前 `app.js`、基础及深度学习 content/math 文件；没有把代码阅读说成新一轮视觉验收。文中的例子均调用现有数学内核复算过。这份文件只提出设计，尚未修改页面与内容代码。

## 现在哪里妨碍理解

| 当前结构 | 对初次使用的影响 | 本轮要改变的行为 |
|---|---|---|
| 指标和动态说明出现在主图前，所有结果同时显示 | 尚不知道在问什么，就要解读多个术语和数字 | 问题 → 一张主场景 → 一个动作 → 就地结果 |
| `renderPlots()` 一次铺开全部图，真正的操作路线在图后面 | 读者在多图间寻找对应关系，还要上下滚动回看步骤 | 每一步只激活一个因果关系；下一步在原场景上增加信息 |
| 所有控件和预设同时出现；窄屏先排整块控件 | 不清楚哪个参数是本步要改变的，也可能同时改变多个原因 | 当前步骤只露出一个主控件，其余放入“自由探索” |
| `tangent` 初始就比较前向、中心和双对数误差 | 学习导数之前，要先理解数值分析的比较口径 | 先建立“测一段时间”和“这一刻”的区别 |
| `backprop` 前向计算图、反向柱图彼此分离 | 看见梯度变小，却看不见是哪条边、哪个乘数造成的 | 前向值与反向敏感度使用同一张计算图 |
| `attention` 从两张 4×4 矩阵开始，再展示多个 Value 箭头 | 同时要理解矩阵轴、Q/K/V、Softmax 与加权和 | 先跟踪一个 Query 的一次完整读取，再扩展为矩阵 |

公式实际位于图后，但当前指标、轴名和开场问题已经要求读者预先掌握公式。调整公式位置还不够，第一句和第一步也要改变。

## 三个页面共用的阅读节奏

首屏固定为：**一句具体问题，一块主场景，一个动作，一句观察结论。** 显示“第 1/4 步”和“下一步”，支持返回与重播，不自动翻页。直接拖动和按钮选择都可用键盘操作。

主场景占页面主要面积。当前对象清楚，其余对象降低对比但仍可辨认；名称贴着对象，少让用户往返查图例。变化前的关键位置或数值保留淡色参照，避免整图重绘后丢失比较对象。颜色之外同时使用实虚线、箭头、标签或轮廓。

每一步正文控制在一至两句短话；解释出现于对应对象旁。完整推导、边界、来源及诊断图进入“为什么”和“进一步检查”，仍可随时打开。导出、来源、自由探索都保留，但不争夺第一眼注意力。这里的 30 秒目标是理解情境并看见第一个因果关系，不承诺 30 秒掌握整个主题。

## 范式一：tangent——从两次测量到这一刻的速度

**30 秒情境文案**：

> 小车在第 1 秒经过这里。再过半秒，它前进了 1.875 米。我们算出这半秒平均每秒走 3.75 米——但第 1 秒这一刻，它也是这个速度吗？

引导例固定 `function=cubic, x=1`。把函数解释为这一小段时间里的合成位置模型 `s(t)=t³−t`，只在本情境使用秒、米和米/秒。函数表达式放在可展开的“位置从哪里来”；自由更换函数后恢复一般 x/y 语境。

| 步骤与屏上短句 | 用户做什么 | 主场景画什么、突出什么 | 要建立的因果关系 |
|---|---|---|---|
| 1. “先测两个时刻。” | 点“再测一次” | 一个固定点 P：1 秒、0 米；再出现 Q：1.5 秒、1.875 米。横轴时间、纵轴位置。先不给切线和导数数值。 | 两次位置测量才给出这一段的变化。 |
| 2. “1.875 米 ÷ 0.5 秒，是这段时间的平均速度。” | 点“连起来” | P、Q 之间加割线和小直角三角形；横边标 0.5 秒，竖边标 1.875 米；旁边只出现 3.75 米/秒。 | 割线斜率对应一段时间的平均变化率。 |
| 3. “把第二次测量靠近第一秒。” | 依次选“0.5 秒后 / 0.1 秒后 / 0.01 秒后”，也可拖 h | P 始终固定，Q 沿曲线靠近，割线围绕 P 转动；就地显示 3.75 → 2.31 → 2.0301。保留上一条割线的淡影。 | 缩短间隔改变的是所测时间段；平均速度逐渐靠近同一个局部值。 |
| 4. “这些平均速度正在接近 2 米/秒。” | 点“显示这一刻” | 在 P 处出现切线，直接标“这一刻：2 米/秒”；当前割线仍在，可看见两者的微小区别。此时才给导数的极限表达。 | 导数描述这一刻的变化率；有限 h 的平均值仍是近似。 |

**画面关键**：本引导过程中固定坐标范围，建议时间 0.95–1.55、位置 −0.15–2.25；不随 h 自动缩放。否则画面斜率会随坐标尺度变化，用户难以判断线是否靠近。需要局部放大时，由明确的“放大这里”动作开启并标出范围。屏幕倾角不直接等于以米/秒计的数值斜率。

**留到第二层**：中心差分、对数误差图、误差阶、浮点舍入。只在用户已经理解割线与切线后，用“如果两侧都测一次呢？”引出中心差分。保留现有高级内容，不放进四步主线。

**无提示检验**：隐藏数值，让用户指出缩小 h 时哪个点不动、哪个点移动；再问“h=0.01 算出的 2.0301，是这一刻的精确速度吗？”答案必须能回指两次测量，而不只是背“导数是极限”。

## 范式二：backprop——改哪个旋钮，能让预测靠近目标

**30 秒情境文案**：

> 这台小预测器收到 1，应该输出 1，现在却输出 0。我们只动第一个旋钮 w：往上调一点，误差会变大还是变小？

引导起点用 `x=1,w=0,bias=0,v=2,target=1`。保留真实的 tanh 单元，先将节点说明写成“压缩数值（tanh）”。采用这个起点是为了让第一轮局部乘数容易检查，不把此处的导数 1 推广到其他位置。

| 步骤与屏上短句 | 用户做什么 | 主场景画什么、突出什么 | 要建立的因果关系 |
|---|---|---|---|
| 1. “先看它怎么算出 0。” | 点“算一次” | 在同一张计算图依次点亮输入1 → 加权值0 → 压缩后0 → 预测0；目标1放在预测旁，最后出现损失0.5。w是可见的旋钮，其余参数暂时固定。 | 前向过程产生预测，中间值是实际计算结果。 |
| 2. “预测稍微变大，损失会变小。” | 先选“w往上 / w往下 / 还不确定”，再点“从误差往回看” | 预测与目标之间的缺口保持可见；损失到预测处出现反向箭头和局部标记 −1。点开标记才解释为“预测增加一点，损失的一阶变化为负”。 | 损失对预测的敏感度给出这条链的起点。 |
| 3. “每退过一个环节，就乘它的局部变化率。” | 点“再往前一层”，按边逐段展开 | 仍使用这张图，反向路径依次标 ×2、×1、×1；经过的边旁累计显示 −1 → −2 → −2 → −2，最后到达 w。前向节点值保持淡色，反向数值使用明确的“损失梯度”标签。 | 对 w 的敏感度由沿路径的局部导数相乘得到；倒传的数不是激活值。 |
| 4. “梯度为负，先把 w 增加一小点试试。” | 点“w 增加 0.01” | 同图重算，w=0.01、预测≈0.0200、损失≈0.4802；0.5000 的旧值留作参照。显示“损失下降约0.0198”。完整链式法则在此时展开。 | 反向传播计算梯度；随后的小幅参数更新由另一动作完成，并实际重算验证。 |

**画面关键**：不用第二张梯度柱状图代替反向计算关系。参数 w 要真的连接到 `w×x+b`，目标连接到损失；倒传到 w 的路径必须可追踪。选中某条边时，只突出其局部乘数与上下游两个数，不把所有偏导符号一起塞入节点。反向箭头改变方向和样式，不能仅靠颜色区别。

**留到第二层**：有限差分误差曲线、饱和区、偏置梯度和其他参数梯度。完成主线后再用“有误差，w 却收不到梯度”引出 `x=1,w=1,b=0,v=0,t=1`：此时 w 梯度为0，但 v 梯度约 −0.7616。不要沿用主线 w=0 的状态展示这个区别，因为那时 h=0，v 梯度也为0。

**无提示检验**：先隐藏最终梯度，让用户指出路径上某个乘数变成0后会影响哪条梯度；再问“算出梯度后，参数已经更新了吗？”主图必须能直接支持这两个判断。

## 范式三：attention——先决定从哪里读，再组合读出的内容

**30 秒情境文案**：

> 有四张存储卡。每张卡都有一个查找标签和一份内容。现在发出一次查询：先比较标签，决定各读多少，再把实际内容组合起来。

卡片始终叫 A、B、C、D，不套用自然语言词义。小字说明这是四个手工二维向量。首轮固定观察 Query C，只跟踪这一行；“查找标签 Key”和“内容 Value”在卡片上分区，不能共用一个数冒充两者。

| 步骤与屏上短句 | 用户做什么 | 主场景画什么、突出什么 | 要建立的因果关系 |
|---|---|---|---|
| 1. “先比较查询和四张卡的标签。” | 点“计算匹配” | Query C=[1,1] 指向四张卡的 Key，Value 暂时收起；出现一行匹配分数 0.71、0.71、1.41、0.00。选中 C 可展开它的点积计算。 | Query 与 Key 决定分数；此时还没有读取 Value。 |
| 2. “把分数变成合计100%的读取份额。” | 点“分配份额” | 原位置的分数下面转出一条有 A/B/C/D 标签的份额条，约22%、22%、45%、11%；显示“合计100%”。先不放温度滑块和熵指标。 | Softmax 将相对分数变成非负、和为1的权重；份额不等于正确率。 |
| 3. “按这些份额，组合卡片的实际内容。” | 点“读取内容”；点任一卡查看它的贡献 | 同四张卡揭开 Value：(1,0)、(0,1)、(1,1)、(−1,2)，连到一个输出框 (0.561,0.888)。只对选中卡显示乘法，例如 C 贡献约(0.449,0.449)，其余仍保留份额标签。 | 权重决定各份内容怎样参与加权和；不能只看最大权重就丢弃其他内容。 |
| 4. “标签不动，只把内容翻倍。” | 先预测份额是否会变，再点“内容×2” | Key 与份额条保持原位和原数值；Value 的两坐标翻倍，输出变为(1.121,1.776)，旧输出淡显。“份额不变，读取结果翻倍”贴在输出旁。 | Q/K 决定怎么读，V 决定读到什么；相同权重可以得到不同结果。 |

**画面关键**：四张卡在整个故事中保持相同顺序和身份，份额标签跟随卡片，不从卡片跳到陌生的矩阵行列。选中贡献才显示局部乘法，首屏不显示四个完整向量乘积。需要几何解释时，另开“看加权平均的位置”，再展示 Value 端点、凸包和输出点。

**留到第二层**：“只能读已经出现的卡”引出因果掩码。固定 Query C，划去 D，再让其余三项重新分配至合计100%；被屏蔽位置必须明确为0。随后才提供“展开全部查询”显示 4×4 矩阵，并高亮刚才的 C 行。温度与强度从一个参数开始开放，因为当前公式只通过 α/T 影响分数；同时露出二者会制造两套独立机制的错觉。

**无提示检验**：分别改变标签匹配和 Value，用户应能指出哪种改变可能影响份额、哪种只改变读取结果；再要求解释为何屏蔽 D 后，其他份额要重算。不要把“找到了最大权重卡片”当作理解注意力。

## 实现优先顺序与通过条件

1. **先给 tangent 做完整四步页面。** 加一个逐步展示层，复用现有计算结果；冻结非当前控件、隐藏次要指标和诊断图，补 P/Q、变化三角形、固定轴和就地文字。先解决第一分钟的阅读顺序，再调字体、留白和线条。没有动机的入场动画不列入优先项。
2. **再做 backprop 的同图前算/倒传。** 增加逐边高亮、局部乘数、参数分支和一次小更新。状态变化必须来自实际重算，不能只播放已写好的数字。先检验用户能否追踪一条梯度，再开放所有参数。
3. **再做 attention 的单行卡片读取。** 复用现有 Q/K/V、分数和权重；把完整矩阵放在展开层。先验证“分数、份额、内容”的区分，再加掩码与多 Query。
4. **三个样例分别实际观看和操作后再归纳共用组件。** 可以共用步骤导航、前后参照、局部说明和高级展开；主场景仍按机制设计。不要先给其余57项机械套四步或批量改文案。

每个样例至少做三轮有记录的审阅：第一轮看打开后能否立即找到问题与动作；第二轮实际操作，检查视觉变化与计算是否对应；第三轮隐藏结论，做上述迁移问题并检查窄宽布局。审阅者要指出具体卡住的位置，不只给“清楚”“好看”的总评。用户再次反馈后据实修订，不能用测试通过替代体验认可。

实施时保留自由探索入口和全部原有数值接口，逐步揭示是显示状态，不另造一套数学结果。教学步骤中的数字、按钮参数、变化前后值和边界情境都应直接取自当前计算结果。这个文档的数值核对如下：

| 情境 | 已用现有内核核对的值 |
|---|---|
| 三次函数，x=1，h=0.5/0.1/0.01 | 前向差商3.75 / 2.31 / 2.0301；真实导数2 |
| 反传起点 w=0，其他参数如上 | 预测0，损失0.5，w梯度−2 |
| 同一预测器只将 w 改为0.01 | 预测0.0199993334，损失0.4802006533 |
| Query C、全部可见、α=T=1、Value尺度1 | 权重约(0.221181,0.221181,0.448581,0.109057)，输出(0.560704,0.887876) |
| 仅将 Value 尺度改为2 | 权重不变；输出(1.121408,1.775753) |
