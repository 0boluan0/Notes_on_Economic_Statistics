# Bash进程替换把命令的输入或输出暴露为可访问的路径

Bash 进程替换用 `<(command)` 或 `>(command)` 生成可作为参数传入的路径，并把该路径连接到另一个命令的输出或输入。它依赖系统提供 FIFO 或 `/dev/fd` 等设施；路径不必对应普通临时文件，也不能保证像普通文件一样可随机定位。
<!-- bilingual-en:start -->
Bash process substitution, `<(command)` or `>(command)`, produces a pathname that can be passed as an argument and connects it to another command's output or input. It relies on facilities such as FIFOs or `/dev/fd`. The pathname need not name a regular temporary file, nor support seeking like one.
<!-- bilingual-en:end -->

```bash
diff <(printf '%s\n' same) <(printf '%s\n' same)
```

`diff` 接收两个路径参数，并从中读取相同内容，因此通常无输出且状态为 0。`<( … )` 供外层命令读取；`>( … )` 接收外层写入的数据。注意 `<(` 中间不能插入空格；本语法不是任意 `sh` 都提供的功能。
<!-- bilingual-en:start -->
`diff` receives two pathname arguments and reads identical content, so it normally produces no output and exits with status 0. `<( … )` supplies data for the outer command to read; `>( … )` receives data written by it. No space may separate `<` and `(`. This syntax is not supplied by every `sh` implementation.
<!-- bilingual-en:end -->

这与[[命令替换]]把 stdout 变成文本不同。替换中的命令不是外层普通管道的一个阶段；外层命令成功或启用 `pipefail`，都不能单独证明替换中的命令成功。例如 Bash 中 `cat <(false)` 可以返回 0，因为 `cat` 成功读到了空输入。
<!-- bilingual-en:start -->
Unlike [[命令替换|command substitution]], this does not insert standard output as text. A substitution command is not a stage of the outer ordinary pipeline. Outer-command success, even with `pipefail`, does not establish substitution success: in Bash, `cat <(false)` can return 0 because `cat` successfully reads empty input.
<!-- bilingual-en:end -->

## 来源与核验

- GNU Bash 3.2 本机 `bash(1)`，`Process Substitution` 与 `Pipelines`；[官方进程替换章节](https://www.gnu.org/software/bash/manual/html_node/Process-Substitution.html)：支持路径接口、FIFO 或 `/dev/fd`、读写方向与管道状态的适用范围。
- [Missing Semester 2020：Shell Tools and Scripting](https://missing.csail.mit.edu/2020/shell-tools/)，Process substitution：支持 `diff` 接收路径的课程用途；“普通临时文件”不是这里承诺的实现。
<!-- bilingual-en:start -->
The local Bash manual supports the pathname interface, backing facilities, directions, and scope of pipeline status. The course motivates supplying paths to `diff`; a regular temporary file is not the guaranteed implementation. The `cat <(false)` example tests the status boundary directly.
<!-- bilingual-en:end -->
