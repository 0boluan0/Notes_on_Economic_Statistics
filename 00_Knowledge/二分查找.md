# 二分查找在有序离散候选上保持半开区间不变量，并用比较反馈每步排除约一半候选
<!-- bilingual-en:start -->
*Binary search maintains a half-open interval over ordered discrete candidates and uses comparison feedback to discard about half at each step*
<!-- bilingual-en:end -->

> [!summary] 减半成立，因为比较结果能够安全排除一侧
> 对按升序排列的离散序列，二分查找维护一个仍可能含有目标的半开索引区间 $[lo,hi)$。检查中点后，`小于`、`等于` 或 `大于` 的比较反馈能证明其中一侧不可能含有目标，于是每轮把候选数缩小约一半。
> <!-- bilingual-en:start -->
> On an ascending discrete sequence, binary search maintains a half-open index interval $[lo,hi)$ that can still contain the target. Comparing the midpoint with the target proves that one side is impossible, reducing the number of remaining candidates by about half on every iteration.
> <!-- bilingual-en:end -->

## 半开区间不变量决定更新方向

设数组满足

$$
a_0\le a_1\le\cdots\le a_{n-1},
$$

目标值为 $t$。初始化 $lo=0,hi=n$，并保持不变量：

> 若 $t$ 出现在原数组中，则至少有一个满足 $a_i=t$ 的索引仍位于 $[lo,hi)$；区间外的位置已经被比较结果安全排除。

令

$$
mid=lo+\left\lfloor\frac{hi-lo}{2}\right\rfloor.
$$

- 若 $a_{mid}<t$，由升序性知 $i\le mid$ 的位置都不可能等于 $t$，所以更新 $lo=mid+1$。
- 若 $a_{mid}>t$，由升序性知 $i\ge mid$ 的位置都不可能等于 $t$，所以更新 $hi=mid$。
- 若 $a_{mid}=t$，则已经找到一个匹配位置。

<!-- bilingual-en:start -->
For an ascending array, initialize $[lo,hi)=[0,n)$. The invariant is that if the target occurs in the original array, at least one matching index remains inside this half-open interval; comparisons have safely eliminated the positions outside it. At the midpoint, $a_{mid}<t$ eliminates indices through `mid`, while $a_{mid}>t$ eliminates `mid` and everything to its right. Equality supplies a match.
<!-- bilingual-en:end -->

半开区间让空搜索空间自然表示为 $lo=hi$。每次未命中的更新都严格缩短 $hi-lo$，所以循环会终止。若序列允许重复值，上述版本只承诺找到某一个匹配；寻找第一个匹配位置需要改用 lower-bound 不变量，不能把“任意命中”和“最左命中”当成同一个规格。

<!-- bilingual-en:start -->
The half-open convention represents an empty search space by $lo=hi$, and every unsuccessful update strictly decreases $hi-lo$, proving termination. With duplicates, this version finds some match only. Finding the first match requires a lower-bound invariant and is a different specification.
<!-- bilingual-en:end -->

## 对数复杂度针对剩余候选数

若初始候选数为 $n$，经过 $k$ 轮减半后，剩余候选数至多约为

$$
m_k\le \left\lceil\frac{n}{2^k}\right\rceil.
$$

要把候选缩到常数个，只需 $k=O(\log_2 n)$ 轮；在随机访问数组、一次取中点和比较均为常数成本的模型下，最坏比较次数为 $\Theta(\log n)$。

<!-- bilingual-en:start -->
After $k$ halving steps, at most about $\lceil n/2^k\rceil$ candidates remain. Reducing the search to constant size therefore takes $O(\log_2 n)$ iterations. With random-access array indexing and constant-cost comparisons, the worst-case comparison count is $\Theta(\log n)$.
<!-- bilingual-en:end -->

这个结论是关于候选数和[[算法成本模型|成本模型]]的。若数据尚未排序，预先排序的成本不属于一次二分查找本身；若容器不能常数时间访问中点，实际运行时间也未必是 $\Theta(\log n)$。[[切片二分成本]]具体说明“比较次数对数级，但复制成本更高”的实现差异；多次查询时如何分摊预处理成本，见[[03_Computer_Science/03_MIT 6.100L/21_算法成本与渐近分析#7. 回到真实程序，选择一个值得比较的工作负载|课程路径中的查询总成本比较]]。

<!-- bilingual-en:start -->
This bound concerns candidate count under a stated [[算法成本模型|cost model]]. Sorting an unsorted input is preprocessing rather than part of one binary-search query, and a structure without constant-time midpoint access need not achieve $\Theta(\log n)$ elapsed time. [[切片二分成本|Slicing binary-search costs]] explains how logarithmically many comparisons can coexist with more expensive copying. The [[03_Computer_Science/03_MIT 6.100L/21_算法成本与渐近分析#7. 回到真实程序，选择一个值得比较的工作负载|course path's query-cost comparison]] accounts for preprocessing across multiple queries.
<!-- bilingual-en:end -->

## 没有顺序或方向反馈就不能安全减半

若序列未排序，中点值与目标的大小关系不能排除某一侧。例如在 `[1, 100, 2, 3]` 中查找 `100`，把它当成升序数组会错误地丢弃可能含有答案的一半。

即使候选有编号，若每次反馈只有“对/错”，也无法知道目标落在中点哪一侧；猜四位 PIN 时通常不能根据一次失败排除前半或后半。二分查找需要的是有序候选以及能给出方向的比较反馈，而不只是“选择了一个中点”。

<!-- bilingual-en:start -->
Without sorted order, the midpoint comparison cannot justify discarding a side; treating `[1, 100, 2, 3]` as sorted can eliminate the half containing `100`. Likewise, equality-only feedback on a PIN does not reveal which side contains the target. Binary search requires both ordered candidates and directional comparison feedback, not merely a midpoint guess.
<!-- bilingual-en:end -->

[[二分求根]]也会反复缩小区间，但它处理连续变量。标准括区间论证依赖函数连续且端点异号；某些单调反演问题还可用单调性提供更新方向。离散数组的索引不变量不能直接替代这些连续问题条件。

<!-- bilingual-en:start -->
[[二分求根|Bisection root-finding]] also shrinks an interval, but it concerns a continuous variable. The standard bracketing argument requires continuity and opposite endpoint signs; some monotone inversion problems additionally use monotonicity to determine the update direction. The discrete array invariant does not replace these conditions for a continuous problem.
<!-- bilingual-en:end -->

> [!question]- 自检
> 一个列表虽然有固定索引，但元素没有排序。为什么仍不能根据中点元素小于目标，就删除中点左侧的全部元素？
>
> **答案：** 索引顺序没有传递到元素值；左侧仍可能出现任意大于、等于或小于目标的值，因此比较结果没有提供安全排除一半的证据。
>
> <!-- bilingual-en:start -->
> A list has fixed indices but its values are unsorted. Why can a midpoint value below the target not justify deleting the entire left side?
>
> **Answer:** Index order carries no information about value order. The left side may still contain values below, equal to, or above the target, so the comparison supplies no valid elimination certificate.
> <!-- bilingual-en:end -->
