# 命令退出状态是供Shell判断执行结果的数值状态

退出状态是命令完成后交给 Shell 的数值结果，与 stdout 或 stderr 的文字分开。在 Bash 条件判断中，0 视为真，非零视为假；某个非零值究竟表示“未匹配”“输入错误”还是其他情况，必须查命令的契约。
<!-- bilingual-en:start -->
An exit status is the numerical result made available to the shell when a command completes, separate from standard-output or standard-error text. Bash conditions treat zero as true and nonzero as false. Whether a particular nonzero value means no match, invalid input, or another outcome depends on the command's contract.
<!-- bilingual-en:end -->

```bash
false
printf 'status=%s\n' "$?"
```

这里显示 `status=1`；`false` 的职责就是返回假，不代表程序发生了异常。`$?` 提供最近执行的前台管道状态；应立即读取或保存，因为下一条命令也会改变它。上述 `printf` 完成后，`$?` 通常已经是 `printf` 的 0。
<!-- bilingual-en:start -->
This prints `status=1`. Returning false is the purpose of `false`, not evidence of a runtime error. `$?` reports the most recently executed foreground pipeline's status; read or save it immediately because the next command changes it. After the displayed `printf` succeeds, `$?` is normally its zero status.
<!-- bilingual-en:end -->

例如 [[grep退出状态|grep 的 1]] 表示没有选中行，不等同于读取失败。反过来，命令把提示写入 stderr 也不必返回非零。Bash 自身还用 127 表示找不到命令、126 表示找到但不能执行；不要只靠屏幕上有没有文字判断执行结果。
<!-- bilingual-en:start -->
For example, [[grep退出状态|grep status 1]] means no selected lines rather than a read failure. Conversely, writing a notice to standard error need not imply a nonzero status. Bash also uses 127 for command not found and 126 for a command found but not executable. Visible text alone does not establish execution outcome.
<!-- bilingual-en:end -->

## 来源与核验

- GNU Bash 3.2 本机 `bash(1)`，`EXIT STATUS`、`Special Parameters` 与内建 `false`；[官方退出状态章节](https://www.gnu.org/software/bash/manual/html_node/Exit-Status.html)：支持零与非零的 Shell 判定、`$?`、126 和 127。
- 本机 `grep(1)`，`EXIT STATUS`；[GNU grep 的退出状态](https://www.gnu.org/software/grep/manual/html_node/Exit-Status.html)：支持“无匹配”与“错误”不能混为一类。
<!-- bilingual-en:start -->
The local Bash manual supports the shell's zero/nonzero interpretation, `$?`, and statuses 126 and 127. The local grep manual and its corresponding official status documentation distinguish no match from an error.
<!-- bilingual-en:end -->
