# 通常算术转换先决定共同类型再执行混合类型运算
<!-- bilingual-en:start -->
*The usual arithmetic conversions choose a common type before a mixed-type operation is performed*
<!-- bilingual-en:end -->

> [!summary] 原子过程
> 对许多二元算术与比较运算，C 不是“各算各的再装进结果变量”，而是先对等级不高于 `int` 的整数类型和规定的位域做**整数提升**：若 `int` 能表示原类型全部值就提升为 `int`，否则提升为 `unsigned int`。随后再按等级、有无符号与可表示范围规则把双方转换为共同类型，最后才执行运算。共同类型改变，数值含义也可能改变。
> <!-- bilingual-en:start -->
>
> &nbsp;
> For many binary arithmetic and comparison operators, C does not evaluate each operand independently and then fit the answer into the destination. It first applies the **integer promotions** to integer types of rank no greater than `int` and to specified bit-fields: the value becomes `int` if that type can represent every original value, and `unsigned int` otherwise. It then converts both operands to a common type according to rank, signedness, and representable range, and only then performs the operation. A changed common type can change the numeric meaning.
> <!-- bilingual-en:end -->

```c
int debt = -1;
unsigned int balance = 1;

if (debt < balance) {
    /* 在常见且符合标准的 int/unsigned int 范围下，这里不会进入 */
}
```

当 `int` 与同等级的 `unsigned int` 比较，而 `int` 不能表示全部 `unsigned int` 值时，`debt` 会先转为 `unsigned int`。`-1` 因而变成一个很大的无符号值，比较结果与直觉中的整数轴不同。这不是比较运算坏了，而是比较前双方已经不再是原来的数学值表示。
<!-- bilingual-en:start -->
When `int` is compared with `unsigned int` of the same rank and cannot represent every unsigned value, `debt` is converted to `unsigned int` first. The `-1` therefore becomes a large unsigned value, producing a result unlike an ordinary comparison on the mathematical integers. The comparison did not malfunction; its operands had already been converted.
<!-- bilingual-en:end -->

## 实用判断顺序

1. 写下每个操作数在表达式中的实际类型，而不是只看最终变量。
2. 对 `_Bool`、`char`、`short`、枚举和规定的位域先考虑整数提升；不要仅凭源代码拼写假定提升结果一定是 `int`。
3. 再判断是否进入浮点类型，或在整数类型中如何按等级和可表示范围统一。
4. 在转换发生前验证负值和上界；不要用强制转换只为压掉编译器警告。
<!-- bilingual-en:start -->
1. Write down each operand's actual expression type rather than looking only at the destination variable.
2. Consider integer promotions first for `_Bool`, `char`, `short`, enumerations, and specified bit-fields; do not infer that the result must be `int` from the source spelling alone.
3. Then determine whether floating types dominate or how integer rank, signedness, and representability select the common type.
4. Validate negative values and upper bounds before conversion; do not cast merely to silence a diagnostic.
<!-- bilingual-en:end -->

## 边界

显式转换能说明意图，却不能让超范围值变得安全。把负整数转成无符号类型会按模转换；把有限浮点值转成整数时，若截断后的整数部分不可表示，行为未定义。好的接口尽量让同一数量使用一致类型，并在信任边界显式验证。
<!-- bilingual-en:start -->
An explicit cast can state intent, but it cannot make an out-of-range value safe. Converting a negative integer to unsigned uses modular conversion; converting a finite floating value to an integer has undefined behaviour if its truncated integral part is not representable. Good interfaces use consistent types for the same quantity and validate explicitly at trust boundaries.
<!-- bilingual-en:end -->

> [!question]- 自检
> 为什么看到 `-Wsign-compare` 时，不应第一反应就是给有符号值加 `(unsigned)`？
>
> **答案：** 强转可能把负数变成巨大无符号值并掩盖真实边界错误。应先确定这个量是否允许为负，以及双方应共享哪一种语义类型。
