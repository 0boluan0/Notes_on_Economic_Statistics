# 缩小失败复现时应保留同一故障及必要条件并去除无关输入与步骤
<!-- bilingual-en:start -->
*Minimize a failure reproduction by removing irrelevant inputs and steps while preserving the same fault and its necessary conditions.*
<!-- bilingual-en:end -->

先记录输入、初始状态、执行方式、期望与实际差异，再逐步删除数据或步骤，每次重跑确认原来的失败仍在。这里的“最小”是尽量小、足以定位的复现，不宣称已经找到所有可能程序与输入中的全局最小例子。
<!-- bilingual-en:start -->
Record inputs, initial state, execution procedure, and the expected-versus-actual difference. Remove data or steps incrementally, rerunning after each reduction to confirm that the original failure persists. “Minimal” here means a small useful reproduction, not a proven global minimum over all possible programs and inputs.
<!-- bilingual-en:end -->

例如，长列表被错误判断为回文，可以先尝试 `['a', 'b']`：它仍是合法非回文，若仍错误返回 `True`，就保留了这个失败。缩成 `[]` 或单元素列表后按通常回文契约应返回 `True`，所以“仍返回 `True`”已不再复现同一错误。
<!-- bilingual-en:start -->
If a long non-palindromic list is wrongly accepted, try `['a', 'b']`: it is still a valid non-palindrome, so an erroneous `True` preserves the failure. An empty or singleton list is normally a palindrome; merely still obtaining `True` after that reduction no longer reproduces the same error.
<!-- bilingual-en:end -->

保留相似报错也未必保留同一原因。若缩小过程把合法输入变成非法类型，或移除了触发故障的对象共享关系，就需要重新判断复现是否仍有解释力。涉及伪随机流时，按[[伪随机复现]]保留生成器与调用协议，而不只记录一个 seed。
<!-- bilingual-en:start -->
A similar error message need not preserve the same cause. Changing a valid input to an invalid type or removing the relevant aliasing can invalidate the reproduction. For pseudorandom behavior, preserve the generator and call protocol described in [[伪随机复现|pseudorandom reproducibility]], not merely a seed.
<!-- bilingual-en:end -->
