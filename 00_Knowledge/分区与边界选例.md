# 测试选例应按预期行为分区并补查边界而不只取普通输入
<!-- bilingual-en:start -->
*Select tests from behavioral partitions and their boundaries rather than only ordinary inputs.*
<!-- bilingual-en:end -->

先依据规格把输入分成预期处理方式不同的区域，再从各区选代表；在区域交界、空输入、单元素和极端规模处补例。分区是寻找缺陷的启发式：同一区域的一个例子通过，不证明该区所有输入都等价地正确。
<!-- bilingual-en:start -->
Partition inputs according to differences in the specified behavior, select representatives, and add cases at transitions, empty and singleton inputs, and extremes. This is a defect-finding heuristic: one passing representative does not prove every input in its partition behaves correctly.
<!-- bilingual-en:end -->

例如，整数 `score` 的契约是：`0 <= score <= 100`，其中 `score >= 60` 返回及格。可先测不及格区和及格区的普通值，再补 `0`、`59`、`60`、`100`。只有规格承诺拒绝越界输入时，才把 `-1`、`101` 加为有明确拒绝判据的用例。
<!-- bilingual-en:start -->
Suppose integer `score` must lie in `0 <= score <= 100`, with passing defined by `score >= 60`. Test ordinary failing and passing values, then add `0`, `59`, `60`, and `100`. Add rejection checks for `-1` and `101` only if the specification promises rejection outside the domain.
<!-- bilingual-en:end -->

边界也可能是对象关系而不是数值：两个列表参数指向同一对象，与两个独立列表可能触发不同副作用。若接口允许两参数相同，需把这种[[对象别名]]情形纳入考虑。
<!-- bilingual-en:start -->
A boundary may concern object relationships rather than numbers: two parameters sharing one list can behave differently from two independent lists. If the interface allows this, include the [[对象别名|aliasing]] case.
<!-- bilingual-en:end -->
