# Bipartite pairing models
<!-- bilingual-en:end -->

*二分图配对关系*

<!-- bilingual-en:start -->
A **bipartite pairing model** records which pairs are allowed before choosing an assignment. Put students on one side and projects on the other. An edge means that the student is eligible for that project. Several edges may touch one student or one project: the graph is listing possibilities, not assigning all of them at once.
<!-- bilingual-en:end -->

**二分图配对模型**先记录哪些配对允许，再从中选择分配。把学生放在一侧、项目放在另一侧，一条边表示这名学生具备参加这个项目的资格。同一学生或项目可以接触多条边：图在列出可能性，并非把它们同时全部分配。

> [!example] Candidates and a choice · 候选关系与实际选择
> <!-- bilingual-en:start -->
> Let students be $L=\{a,b\}$ and projects be $R=\{1,2,3\}$. Suppose the allowed pairs are $a1,a2,b2$, where $a1$ abbreviates the edge joining $a$ to $1$. Student $a$ has two options, $b$ has one, and project $3$ has no eligible student. Selecting $a1$ and $b2$ assigns different projects to the two students. Selecting $a2$ and $b2$ would reuse project $2$: both pairs are individually allowed, but they cannot both be selected in a one-to-one assignment.
> <!-- bilingual-en:end -->
>
> 设学生为 $L=\{a,b\}$，项目为 $R=\{1,2,3\}$，允许配对为 $a1,a2,b2$，其中 $a1$ 简写连接 $a$ 与 $1$ 的边。学生 $a$ 有两个选择，$b$ 有一个；项目 $3$ 没有合适学生。选取 $a1,b2$，两名学生得到不同项目；若选 $a2,b2$，项目 $2$ 就被重复使用。两对分别允许，不代表能够同时进入一对一分配。

## Fixed roles and a single edge meaning
<!-- bilingual-en:end -->

*固定角色与统一的边语义*

<!-- bilingual-en:start -->
Use a finite [[图类型的建模边界|simple undirected graph]] $G=(L\cup R,E)$. The sets $L$ and $R$ are the two roles; $L\cap R=\varnothing$, and every edge has one endpoint on each side. Thus $L,R$ form a [[二分图|bipartition]]. In the example, the roles are students and projects. Their sizes need not be equal, and not every cross-side pair has to be an edge.
<!-- bilingual-en:end -->

采用有限[[图类型的建模边界|简单无向图]] $G=(L\cup R,E)$。$L,R$ 是两类角色，满足 $L\cap R=\varnothing$，每条边恰有一端在每侧，因此构成一种[[二分图|二分划分]]。上例的角色是学生与项目；两侧大小不必相等，也不要求每一对跨侧顶点都连边。

<!-- bilingual-en:start -->
Formally an edge is the unordered pair $\{\ell,r\}$, with $\ell\in L$ and $r\in R$. Writing it as $(\ell,r)$ is a convenient role-based notation here, not an arrow from $\ell$ to $r$. Decide one eligibility rule and use it for every edge. For example, “the student meets the project's entry requirements” is a Boolean condition: it is either satisfied or not. An undirected edge representing this condition does not assert that the two roles are interchangeable or that both parties have the same preferences.
<!-- bilingual-en:end -->

严格地说，边是无序对 $\{\ell,r\}$，其中 $\ell\in L$、$r\in R$。把它写成 $(\ell,r)$ 只是按角色排序的方便记号，不是从 $\ell$ 指向 $r$ 的箭头。应先确定一种资格规则，再让全部边表达这同一种规则。例如“学生符合项目的准入条件”只问条件成立与否；用无向边表示它，并不意味着两类角色可互换，也不意味着双方的偏好相同。

<!-- bilingual-en:start -->
The abstract property of being [[二分图|bipartite]] says that some suitable split exists. This application supplies a particular split and a meaning for each side. Swapping columns in a drawing does not change the graph, but changing which objects count as students or projects changes the model. An isolated vertex is allowed and means that the corresponding object has no permitted partner. Empty sides are also allowed; if either side is empty, there are no edges.
<!-- bilingual-en:end -->

抽象的[[二分图|二分性质]]只断言存在某种合适划分；这里的应用还指定了划分及每侧的含义。交换图画上的两列不会改变图，但改变哪些对象算学生、哪些算项目，就改变了模型。允许孤立顶点，它表示相应对象没有允许的伙伴；也允许空侧，只要有一侧为空，就没有边。

## From allowed edges to an assignment
<!-- bilingual-en:end -->

*从允许边到实际分配*

<!-- bilingual-en:start -->
The full edge set $E$ answers “Which pairs are allowed?” A [[匹配定义|matching]] is a subset $M\subseteq E$ whose selected edges have no shared endpoint. It adds the requirement that each object participate in at most one chosen pair. In the example, $E=\{a1,a2,b2\}$ is not itself a matching, while $M=\{a1,b2\}$ is. Leaving project $3$ unused does not violate the matching definition.
<!-- bilingual-en:end -->

全部边集 $E$ 回答“哪些配对允许”；[[匹配定义|匹配]]则是选出的子集 $M\subseteq E$，其边之间没有公共端点。它额外要求每个对象至多参与一个已选配对。上例中 $E=\{a1,a2,b2\}$ 本身不是匹配，$M=\{a1,b2\}$ 却是；项目 $3$ 闲置并不违反匹配定义。

<!-- bilingual-en:start -->
The application must then state its goal. Must every student receive a project? Must every project be used? These are [[左侧覆盖与完美匹配|coverage requirements]]. Should the number of pairs be as large as possible? That is the [[极大与最大匹配|maximum-cardinality question]]. If a project can accept several students, the ordinary matching rule no longer describes that capacity directly; the capacity has to be modeled explicitly.
<!-- bilingual-en:end -->

接着还要说明应用目标：每名学生都必须有项目吗？每个项目都必须用完吗？这些属于[[左侧覆盖与完美匹配|覆盖要求]]。是否要让配对数尽量多？这是[[极大与最大匹配|最大基数问题]]。若一个项目能够接收多名学生，普通匹配规则就不能直接表达这一容量，必须另外建模。

<!-- bilingual-en:start -->
Weights or preference lists add information beyond a yes/no eligibility graph. A weight may record a cost or benefit of an allowed pair; preference lists rank alternatives for individual participants. A [[稳定匹配与普通匹配|stability condition]] asks a different question from merely avoiding repeated endpoints. The permitted edges alone do not specify either ranking or optimization criterion.
<!-- bilingual-en:end -->

权重或偏好列表在“允许／不允许”的图之外增加信息：权重可以记录某个允许配对的成本或收益，偏好列表则为各参与者排列备选对象。[[稳定匹配与普通匹配|稳定性条件]]所问的问题，也不同于单纯避免端点重复。只有允许边，还没有指定排序或优化准则。

## Recognizing a bipartition is a separate task
<!-- bilingual-en:end -->

*识别二分划分是另一个任务*

<!-- bilingual-en:start -->
If the roles are already supplied, checking that every edge crosses them verifies this part of the model. If a graph arrives without a split, [[二着色与奇环证书|two-coloring search]] can find one or return an odd-cycle certificate. BFS or recursive DFS colors by parent-tree-depth parity, restarting on every unvisited component. BFS depth is also unweighted distance from its component root; DFS depth need not be. A same-color edge identifies a conflict from which the parent paths produce an odd cycle. This search determines whether a bipartition exists; it does not select a matching.
<!-- bilingual-en:end -->

若角色已给定，检查每条边是否跨越两侧，就能核对这一部分模型。若图尚无划分，[[二着色与奇环证书|二着色搜索]]可以找出一种划分，或返回奇环证书。BFS 或递归 DFS 按父树深度的奇偶性着色，并在每个尚未访问的分量重启。BFS 深度还是到该分量根的无权距离，DFS 深度则未必是。同色边暴露冲突，可以结合父路径恢复奇环。这项搜索判断二分划分是否存在，并未选择匹配。

> [!question]- Does an edge identify a favorite project? · 一条边能说明最喜欢哪个项目吗？
> <!-- bilingual-en:start -->
> Not in the eligibility model stated here. Both $a1$ and $a2$ are allowed, but the graph does not rank them. A preference order or benefit must be supplied separately. The edge rule itself could be defined using a stated preference threshold; that still records only whether the threshold is met, not a full ranking.
> <!-- bilingual-en:end -->
>
> 在本卡规定的资格模型中不能。$a1,a2$ 都允许，但图并未给它们排序；偏好顺序或收益要另外提供。也可以明确把某个偏好门槛用作连边规则，但那仍只记录是否达到门槛，并非完整排名。
