# 黑盒测试依据外部规格设计检查而不依赖被测实现的内部结构
<!-- bilingual-en:start -->
*Black-box testing designs checks from the external specification rather than the implementation's internal structure.*
<!-- bilingual-en:end -->

把函数看作提供承诺的接口：根据合法输入、返回行为、异常和副作用选例，不先沿着它当前的 `if` 或循环照抄测试。规格保持不变时，这些检查通常可以跨实现复用。
<!-- bilingual-en:start -->
Treat a function as an interface with commitments. Select cases from allowed inputs, results, exceptions, and side effects rather than copying its current branches or loops into the tests. When the contract is unchanged, these checks can usually be reused across implementations.
<!-- bilingual-en:end -->

例如，规格说 `larger(x, y)` 对整数返回 `x > y`，无需看代码就能选择 `(2, 1)`、`(1, 2)`、`(2, 2)`，分别检查 `True`、`False`、`False`。相等情形直接来自规格的严格比较，不依赖实现是否碰巧有单独的相等分支。
<!-- bilingual-en:start -->
If `larger(x, y)` returns whether integer `x > y`, choose `(2, 1)`, `(1, 2)`, and `(2, 2)` and expect `True`, `False`, and `False` without inspecting the code. Equality matters because the specified comparison is strict, whether or not the implementation contains a separate equality branch.
<!-- bilingual-en:end -->

黑盒不等于随便试，也不保证规格完整；错误类型等非法输入只有在接口承诺处理它们时，才有据可查的预期行为。它与[[白盒测试]]互补：一个检查外部承诺，一个利用内部结构寻找遗漏。
<!-- bilingual-en:start -->
Black-box testing is not arbitrary trial and does not make an incomplete specification complete. Invalid inputs have a prescribed expected response only where the interface promises one. It complements [[白盒测试|white-box testing]]: external commitments and internal structure supply different evidence for selecting cases.
<!-- bilingual-en:end -->
