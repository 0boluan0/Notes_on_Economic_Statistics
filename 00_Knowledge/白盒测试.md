# 白盒测试利用被测代码的内部结构来选择测试用例
<!-- bilingual-en:start -->
*White-box testing uses the internal structure of the code to select test cases.*
<!-- bilingual-en:end -->

白盒测试也称玻璃盒测试（glass-box testing）。它查看分支、循环、递归和异常处理结构，寻找尚未执行的行为；预期结果仍应由[[测试判据]]决定，不能因为当前代码这样返回，就认定这个返回值正确。
<!-- bilingual-en:start -->
White-box testing, also called glass-box testing, examines branches, loops, recursion, and handlers to identify behavior not yet exercised. The [[测试判据|oracle]] must still determine expected behavior; the current implementation's result is not correct merely because the code produced it.
<!-- bilingual-en:end -->

常用选例包括：让条件判断的两种结果都出现；让允许为空的循环执行零次、一次和多次；让递归直接到达基例，也经过递归调用。每一种选择都必须是程序规格和控制流允许的情形，不应为了凑覆盖而制造不可达状态。
<!-- bilingual-en:start -->
Useful cases exercise both outcomes of a condition, zero/one/multiple loop iterations where allowed, and both immediate recursive base cases and recursive calls. Each choice must be feasible under the specification and control flow; coverage is not a reason to invent unreachable states.
<!-- bilingual-en:end -->

例如，列表扫描有 `if item == target: return True` 和循环后的 `return False`，可用“找到”和“未找到”两类输入分别执行这两种出口。但走到所有出口仍不保证每个输入处理正确，见[[覆盖率不能证明正确]]。
<!-- bilingual-en:start -->
For a scan containing `if item == target: return True` and a final `return False`, successful and unsuccessful searches exercise the two exits. Exercising every exit still does not establish correctness for every input; see [[覆盖率不能证明正确|the limits of coverage]].
<!-- bilingual-en:end -->
