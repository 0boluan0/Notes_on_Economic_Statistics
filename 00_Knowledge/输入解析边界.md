# input 返回字符串而数值语义需要显式解析并处理失败
<!-- bilingual-en:start -->
*`input` returns a string, while numeric meaning requires explicit parsing and failure handling*
<!-- bilingual-en:end -->

> [!summary] 原子信任边界
> `input()` 读取一行并返回 `str`；用户键入 `10` 不会自动产生整数。若程序需要数值语义，必须显式调用 `int`、`float` 等解析操作，并处理输入不符合目标格式时的异常。解析成功只说明格式可转换，不保证数值满足业务范围。
> <!-- bilingual-en:start -->
> `input()` reads a line and returns a `str`; typing `10` does not produce an integer automatically. Numeric meaning requires explicit parsing such as `int` or `float`, with failure handling. Successful parsing establishes representability, not that the value satisfies the required range.
> <!-- bilingual-en:end -->

```python
raw = input("Score: ")
try:
    score = int(raw)
except ValueError:
    print("Please enter an integer.")
else:
    if not 0 <= score <= 100:
        print("Score must be between 0 and 100.")
```

字符串比较遵循字符串的字典序规则，所以 `"10" < "2"` 为真；它不等价于数值比较 $10<2$。应在共同输入边界先完成“读取 → 解析 → 范围/格式验证”，再让后续分支依赖已经建立的前提。把转换散落在多个业务分支中，容易出现某条路径漏检或采用不同规则。
<!-- bilingual-en:start -->
String comparison follows lexicographic ordering, so `"10" < "2"` is true and is not the numerical comparison $10<2$. Parse and validate once at the shared input boundary before downstream branches rely on the result.
<!-- bilingual-en:end -->

`input()` 并不提供一般安全验证：路径、日期、金额或结构化数据仍需各自的解析规则与约束。捕获异常时也应只覆盖预期的转换错误，不能用宽泛 `except` 把程序自身的其他错误一起吞掉。

> [!question]- 回忆与应用
> `int(raw)` 成功后，为什么仍要单独检查 `0 <= score <= 100`？
>
> **答案：** `int` 只证明字符串能表示一个整数；例如 `-5` 与 `500` 都能转换，却不满足分数的业务范围。
