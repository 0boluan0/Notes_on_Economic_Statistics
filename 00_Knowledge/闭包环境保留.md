# 闭包让返回的嵌套函数继续访问其定义环境中的自由变量
<!-- bilingual-en:start -->
*A closure lets a returned nested function continue to access free variables from its defining environment*
<!-- bilingual-en:end -->

> [!summary] 原子环境保留
> 嵌套函数引用外层函数局部名称时，函数对象会携带解析这些自由名称所需的定义环境。即使外层调用已经返回，只要内层函数仍可达，它之后的调用仍能沿该环境找到相应绑定。闭包不是把外层 frame 的所有内容复制进代码，也不是自动冻结变量的当前值。
> <!-- bilingual-en:start -->
> When a nested function refers to local names of an enclosing function, the function object carries the defining environment needed to resolve those free names. Even after the outer call returns, a reachable inner function can still follow that environment to the bindings. A closure neither copies the whole outer frame into the code nor automatically freezes current values.
> <!-- bilingual-en:end -->

```python
def make_scaler(factor):
    def scale(value):
        return factor * value
    return scale

triple = make_scaler(3)
triple(10)  # 30
```

闭包保留绑定和其引用对象的可达性，因此可能延长对象生命周期，也可能让多个闭包共享同一个可变对象。用 `nonlocal` 还能重绑定外层名称，形成有状态闭包；这属于显式设计的隐藏状态，应写进契约，而不能从“闭包”一词推出线程安全、不可变或私有安全边界。

> [!question]- 自检
> `make_scaler(3)` 返回后，为什么 `factor` 仍能被读取？这是否说明数字 `3` 被复制进 `scale` 的源代码？
>
> **答案：** `scale` 保留了定义环境，使自由名称 `factor` 仍可解析；这不是把值改写进函数代码。
