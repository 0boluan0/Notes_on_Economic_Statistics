# Python 名称赋值先求右侧再把名称绑定到对象
<!-- bilingual-en:start -->
*Python name assignment evaluates the right side before binding the name to an object*
<!-- bilingual-en:end -->

> [!summary] 原子执行规则
> 对普通名称赋值 `name = expression`，Python 先求右侧表达式，再把名称绑定或改绑到所得对象。`=` 是一次改变环境的动作，不是要求等式两边永远相等；值相等测试写作 `==`。名称改绑不会自动重算先前由它计算出的其他名称。
> <!-- bilingual-en:start -->
> For an ordinary name assignment `name = expression`, Python evaluates the right-hand expression and then binds or rebinds the name to the resulting object. `=` changes the environment; it is not a claim that both sides remain mathematically equal. Value equality is tested with `==`. Rebinding one name does not automatically recompute other names whose values were calculated earlier.
> <!-- bilingual-en:end -->

```python
radius = 2
area = 3.14 * radius ** 2
radius = 3

# area is still 12.56; only radius was rebound
```

元组赋值也先把右侧结果准备好，因此 `x, y = y, x` 可以交换两个绑定。这个规则不等于“所有赋值都只改名称”：若左侧是 `obj.attr` 或 `items[i]`，赋值请求对象修改属性或元素；`x += y` 还可能调用原地运算，不能在可变对象上无条件当作 `x = x + y` 的完全同义写法。
<!-- bilingual-en:start -->
Tuple assignment prepares the right-hand results first, so `x, y = y, x` can swap two bindings. This does not mean every assignment merely rebinds a name. A target such as `obj.attr` or `items[i]` asks an object to update an attribute or item, and `x += y` may perform an in-place operation, so it is not unconditionally identical to `x = x + y` for mutable objects.
<!-- bilingual-en:end -->

> [!question]- 回忆与应用
> 执行 `x = 4; y = x + 1; x = 10` 后，为什么 `y` 仍是 `5`？
>
> **答案：** `y = x + 1` 当时已把右侧求值为整数对象 `5` 并绑定给 `y`；后来改绑 `x` 不会建立或更新代数依赖。
