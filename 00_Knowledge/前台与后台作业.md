# 前台与后台区分作业对控制终端的关系而不区分是否正在运行
<!-- bilingual-en:start -->
*Foreground and background describe a job's relationship to its controlling terminal, not whether it is running.*
<!-- bilingual-en:end -->

在启用交互式作业控制的通常情形下，前台进程组拥有终端交互位置，shell 通常等待前台作业；后台作业让提示符返回，但仍可继续运算。运行／暂停与前台／后台是不同状态轴，暂停不等于已经终止。
<!-- bilingual-en:start -->
Under normal interactive job control, the foreground process group occupies the terminal's interactive position and the shell normally waits for its job. A background job returns the prompt while it can continue computing. Running versus stopped is a different distinction from foreground versus background; stopping is not termination.
<!-- bilingual-en:end -->

终端通常把 `Ctrl-C` 产生的 `SIGINT` 发给前台进程组。后台作业仍可能输出到终端，但读取控制终端通常触发 `SIGTTIN`；开启 `tostop` 时后台写入还可能触发 `SIGTTOU`。因此“放后台”不等于自动取得独立输入输出。
<!-- bilingual-en:start -->
The terminal normally sends keyboard-generated `SIGINT` to the foreground process group. Background jobs can still print to the terminal, but reading the controlling terminal normally triggers `SIGTTIN`; background writing can trigger `SIGTTOU` when `tostop` is enabled. Background execution does not automatically provide separate input and output.
<!-- bilingual-en:end -->

控制方法见[[作业状态切换]]。不带交互式作业控制的脚本有不同的终端与默认输入处理，不能把交互窗口中的全部行为直接套入脚本；断连存活另见[[后台作业断连边界]]。
<!-- bilingual-en:start -->
See [[作业状态切换|job-state transitions]] for control procedures. Scripts without interactive job control differ in terminal and default-input handling, so interactive behavior cannot be transferred unconditionally. Disconnection survival is addressed by [[后台作业断连边界|background-job lifetime boundaries]].
<!-- bilingual-en:end -->

## 来源与核验

[GNU Bash Manual §7.1](https://www.gnu.org/software/bash/manual/html_node/Job-Control-Basics.html)：支持前台进程组、键盘信号和 `tostop` 条件；本机旧 `bash(1)` 的写终端描述较简略，以现行手册条件为准。
<!-- bilingual-en:start -->
[GNU Bash Manual §7.1](https://www.gnu.org/software/bash/manual/html_node/Job-Control-Basics.html) supports foreground groups, keyboard signals, and the `tostop` qualification, which is more precise than the installed older `bash(1)` wording.
<!-- bilingual-en:end -->

[OpenBSD termios(4), Terminal Access Control 与 Special Characters](https://man.openbsd.org/termios.4)：核对终端驱动与前台进程组信号，不把信号来源简化为 shell 向单个进程发消息。
<!-- bilingual-en:start -->
[OpenBSD termios(4): Terminal Access Control and Special Characters](https://man.openbsd.org/termios.4) supports terminal-driver signaling of foreground process groups rather than a shell message to one process.
<!-- bilingual-en:end -->
