# 权重、激活与键值缓存的量化针对不同存储对象

<!-- bilingual-en:start -->
*Quantizing weights, activations, and the key-value cache targets different stored objects*
<!-- bilingual-en:end -->

评估一种推理量化配置时，应先辨认它作用于哪个对象：**权重**是在固定模型推理时重复使用的参数；**激活**是随当前输入产生的中间数值；**[[KV cache]]** 是为了后续注意力读取而跨步保留的历史键和值。K/V 本身也由激活计算产生，但缓存的保存周期与用途使其精度需要单独说明。

<!-- bilingual-en:start -->
An inference quantization configuration must identify its target: **weights** are model parameters reused during fixed-model inference; **activations** are intermediate values produced from the current input; and the **[[KV cache|KV cache]]** retains historical keys and values across steps for later attention reads. K/V is also computed from activations, but its persistence and purpose require cache precision to be specified separately.
<!-- bilingual-en:end -->

## 怎样读 W4A16

<!-- bilingual-en:start -->
*Reading W4A16*
<!-- bilingual-en:end -->

W4A16 通常描述指定层的权重采用 4-bit 表示、激活采用 16-bit 表示；W8A8 描述两者均为 8-bit。位宽标签还需要实际数值格式、覆盖层范围和[[量化粒度]]，也不会自动确定 KV cache 或累加器的格式。

<!-- bilingual-en:start -->
W4A16 typically describes four-bit weights and sixteen-bit activations for the specified layers; W8A8 describes eight-bit weights and activations. These labels still require the numerical format, covered layers, and [[量化粒度|quantization granularity]] to be stated. They do not automatically determine KV-cache or accumulator formats.
<!-- bilingual-en:end -->

例如，本文构造一个明确配置：线性层权重为 INT4、输入激活为 FP16，保存的 K/V 为 INT8，可简写为 `W4A16, KV8`，并保留上述格式说明。它没有指定 Softmax、归一化、输出 logits 或累加器全部采用哪种格式；这些必须根据实际实现分别确认。

<!-- bilingual-en:start -->
For a constructed example, explicitly choose INT4 linear-layer weights, FP16 input activations, and INT8 stored K/V. This can be abbreviated as `W4A16, KV8` while retaining those format specifications. It does not specify the formats of every Softmax, normalization, output-logit, or accumulator operation; those must be checked in the implementation.
<!-- bilingual-en:end -->

## 只降低权重位宽，会少掉哪部分空间

<!-- bilingual-en:start -->
*Which storage shrinks when only weight precision changes*
<!-- bilingual-en:end -->

取一组包含 $1{,}000{,}000$ 个参数的权重。忽略量化参数、打包对齐和其他对象，16-bit 与 4-bit 的有效参数负载分别是

<!-- bilingual-en:start -->
Take a weight tensor with $1{,}000{,}000$ parameters. Ignoring quantization parameters, packing alignment, and other objects, its effective parameter payload is
<!-- bilingual-en:end -->

$$
M_{W16}=1{,}000{,}000\times\frac{16}{8}
=2{,}000{,}000\ \mathrm{bytes}=2\ \mathrm{MB},
$$
$$
M_{W4}=1{,}000{,}000\times\frac{4}{8}
=500{,}000\ \mathrm{bytes}=0.5\ \mathrm{MB}.
$$

这里 MB 使用十进制 $10^6$ bytes。权重有效负载缩为四分之一，但若 K/V 的元素数和格式未改，缓存负载就不会因此缩为四分之一。量化元数据、临时空间和缓存要继续计入完整[[推理显存预算]]。

<!-- bilingual-en:start -->
MB here means $10^6$ bytes. The effective weight payload falls to one quarter, but an unchanged K/V element count and format do not produce the same cache reduction. Quantization metadata, temporary storage, and cache still belong in the full [[推理显存预算|inference memory budget]].
<!-- bilingual-en:end -->

存储类型也不直接等于计算类型。例如 W4A16 实现可在 kernel 内先把权重反量化为 FP16 再相乘；整数矩阵乘也常使用比输入更宽的累加器。实际加速要检查[[量化加速条件]]，不能从下载文件或权重位宽推出。

<!-- bilingual-en:start -->
Storage type does not directly determine computation type. A W4A16 kernel can dequantize weights to FP16 before multiplication, while integer matrix products can use accumulators wider than their inputs. Actual acceleration depends on [[量化加速条件|the conditions for quantization speedup]], not merely the downloaded file or weight bit width.
<!-- bilingual-en:end -->

  <!-- bilingual-en:start -->
