# 原地排序限制辅助空间而不等于修改原对象

<!-- bilingual-en:start -->
*In-place sorting limits auxiliary space rather than merely mutating the input*
<!-- bilingual-en:end -->

> [!summary] 原子区别
> 在本图采用的算法分析约定中，原地排序是指除输入存储外只用 $O(1)$ 辅助空间；递归栈要单独报告。API “修改原列表”只描述结果写到哪里，不能单独证明算法使用常数辅助空间。
>
> <!-- bilingual-en:start -->
> Under the analysis convention used in this map, an in-place sort uses only $O(1)$ auxiliary space beyond the input storage; recursion-stack space is reported separately. An API that “modifies the original list” states where the result is written, but does not by itself prove constant auxiliary-space use.
> <!-- bilingual-en:end -->

## 自然解释

经典数组 insertion sort 和 selection sort 可用少量索引与一个临时项目完成，因此符合常数辅助空间约定。普通数组 merge sort 即使把最终结果写回原数组，归并时仍通常需要线性临时存储。

<!-- bilingual-en:start -->
Classic array insertion sort and selection sort can operate with a few indices and one temporary item, satisfying the constant-auxiliary-space convention. Ordinary array merge sort normally needs linear temporary storage during merging even if the final result is written back into the original array.
<!-- bilingual-en:end -->

> [!warning] 边界
> 文献对“原地”有时允许 $O(\log n)$ 栈空间，有时不允许。遇到术语差异时，不争标签，直接写峰值辅助空间、递归栈和是否修改输入。Python 文档把 `list.sort()` 称为 in-place 是接口语义；`sorted()` 返回新列表，这两点都不等价于算法空间证明。
>
> <!-- bilingual-en:start -->
> Some sources allow an $O(\log n)$ stack under “in-place,” while others do not. When conventions differ, report peak auxiliary space, recursion-stack use, and input mutation directly. Python calls `list.sort()` in-place at the API level and `sorted()` returns a new list; neither statement alone proves an algorithmic space bound.
> <!-- bilingual-en:end -->

> [!question]- 回忆与应用
> 一个排序函数修改原数组，但内部先复制了整个数组。按本图约定它是原地排序吗？
>
> **答案：** 不是。修改原数组是接口行为，完整副本带来 $\Theta(n)$ 辅助空间。
