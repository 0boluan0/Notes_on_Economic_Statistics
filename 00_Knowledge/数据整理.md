# 数据整理是按目标数据契约转换、筛选和汇总输入表示的过程

<!-- bilingual-en:start -->
*Data wrangling transforms, filters, and summarizes input representations according to a target data contract*
<!-- bilingual-en:end -->

数据整理（data wrangling）是把原始输入变成任务所需表示的过程，例如从日志选择有关记录、提取状态码，再统计各状态码的出现次数。目标数据契约要说明一条记录是什么、字段如何编码、哪些输入有效，以及输出每一行代表什么；命令运行成功并不单独证明这些含义正确。

<!-- bilingual-en:start -->
Data wrangling converts raw input into the representation a task needs: for example, selecting relevant log records, extracting status codes, and counting their occurrences. The target data contract identifies records, field encoding, valid inputs, and the meaning of each output row. Successful command execution alone does not establish that these meanings are correct.
<!-- bilingual-en:end -->

把处理过程拆成可检查的小步：先检查输入及格式，再筛选、转换，最后汇总。每一步都应保留下一步需要的信息，并检查中间输出。例如“用户名出现次数”必须保留完整用户名；若先用空白切分再只取第二字段，含空格的名字可能已经被截断，后面的正确计数也无法修复。

<!-- bilingual-en:start -->
Use inspectable stages: establish the input format, select and transform records, then aggregate. Each stage must preserve the information required by the next. Counting usernames requires complete usernames; whitespace splitting followed by extraction of only the second field may already truncate names containing spaces, and correct counting later cannot repair that loss.
<!-- bilingual-en:end -->

查看少量样本能帮助发现格式假设，却不能证明全体记录都符合它。需要全量保证时，应在处理过程中验证契约，并明确拒绝、隔离或按约定处理坏记录；复杂格式应使用对应解析器，见[[字段切分不等于格式解析]]。

<!-- bilingual-en:start -->
A small sample helps uncover format assumptions but does not prove that every record satisfies them. A full-data guarantee requires validation during processing and an explicit policy for rejecting, isolating, or otherwise handling malformed records. Use a format-aware parser for complex formats; see [[字段切分不等于格式解析|field splitting versus format parsing]].
<!-- bilingual-en:end -->
