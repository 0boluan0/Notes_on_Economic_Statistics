# 数组对象不是指针而数组表达式通常转换为首元素指针
<!-- bilingual-en:start -->
*An array object is not a pointer, although an array expression usually converts to a pointer to its first element*
<!-- bilingual-en:end -->

> [!summary] 核心区别
> 数组对象包含固定数量、连续存放的元素；指针对象只保存一个指针值。数组表达式在多数表达式语境中会发生 **array-to-pointer conversion（数组到指针转换）**，变成指向首元素的指针值，但这项转换既没有把数组对象变成指针，也不会把元素个数附在结果上。
> <!-- bilingual-en:start -->
> An array object contains a fixed number of contiguously allocated elements. A pointer object stores a pointer value. In most expression contexts, an array expression undergoes array-to-pointer conversion to a pointer to its first element; the array itself does not become a pointer, and its element count is not carried by the result.
> <!-- bilingual-en:end -->

```c
#include <stddef.h>

int a[4] = {10, 20, 30, 40};
int *p = a;               // a 转换为 &a[0]
size_t bytes_a = sizeof a;
size_t bytes_p = sizeof p;
int (*whole)[4] = &a;     // &a 指向整个数组
```

`sizeof a` 的操作数仍有 `int[4]` 类型，所以结果是整个数组的字节数；`sizeof p` 只回答指针对象自身的大小。`&a` 的类型是 `int (*)[4]`，而普通转换得到的 `a` 是 `int *`。这两个指针的数值地址常看起来相同，所指类型和后续算术步长却不同。
<!-- bilingual-en:start -->
`sizeof a` sees the array type and yields the total array size, whereas `sizeof p` yields only the pointer object's size. `&a` has type `int (*)[4]`; the usual conversion of `a` yields `int *`. They may display the same address while retaining different pointed-to types and arithmetic steps.
<!-- bilingual-en:end -->

N1570 明列四类不发生这项转换的情况：数组表达式是 `sizeof`、`_Alignof` 或一元 `&` 的操作数，以及字符串字面量直接初始化字符数组。C11 的 `_Alignof` 语法接收类型名而不是任意表达式，所以实际会写 `_Alignof(int[4])`，不能由标准的例外列表误推出 `_Alignof a` 是合法语法。字符串初始化 `char s[] = "hi";` 则按元素复制字面量的 `h`、`i`、`\0` 到新数组。
<!-- bilingual-en:start -->
N1570 lists four conversion exceptions: an array expression used with `sizeof`, `_Alignof`, or unary `&`, and a string literal used to initialise an array. In C11 syntax `_Alignof` takes a type name, so the list does not make `_Alignof a` a valid expression. `char s[] = "hi";` instead copies the literal's elements, including the terminator, into a new array.
<!-- bilingual-en:end -->

`register` 数组还有一个少见但重要的边界：若数组对象以 `register` 存储类声明，触发普通数组到指针转换的行为未定义。`sizeof r` 不触发这项转换；一元 `&r` 虽也列在转换例外中，却因取地址运算符本身禁止作用于 `register` 对象而违反约束。不能把“例外中出现 `&`”误读成任何数组都可取地址。
<!-- bilingual-en:start -->
There is a rare but important `register` boundary. Ordinary array-to-pointer conversion of an array object declared with the `register` storage class has undefined behaviour. `sizeof r` avoids that conversion; unary `&r` is also a conversion exception, but separately violates the address-of constraint for a `register` object. A conversion exception does not make every array addressable.
<!-- bilingual-en:end -->

`sizeof` 保留数组类型，但结果不一定在编译期固定。普通非 VLA 操作数不求值；若操作数类型是 **variable length array（VLA，可变长数组）**，大小可能在运行时确定，标准规定其操作数会被求值。另有一个窄例外：如果改变某个大小表达式也不可能影响 `sizeof` 的结果，标准允许该大小表达式求值或不求值。因此，既不要把数组转换成指针后再猜长度，也不要把所有 `sizeof` 一概说成“永远不求值”。
<!-- bilingual-en:start -->
`sizeof` preserves the array type, but its result need not be a compile-time constant. An ordinary non-VLA operand is not evaluated; when the operand has variable length array type, its size may be determined at run time and the operand is evaluated. A narrow exception permits a size expression to be evaluated or not when changing its value could not affect the `sizeof` result. Neither array decay nor the slogan “`sizeof` never evaluates its operand” is a safe universal rule.
<!-- bilingual-en:end -->

数组名也不能像指针变量那样重新赋值：`a = p;` 不合法，而 `p = a;` 可以让 `p` 接收转换结果。在函数参数声明中，`int a[10]` 调整为 `int *a` 是另一条专门规则，详见[[形参数组退化与边界|数组形参调整]]；不能把函数形参的表现反推成“所有数组都是指针”。
<!-- bilingual-en:start -->
An array name is not assignable like a pointer variable: `a = p` is invalid, while `p = a` may receive the converted value. Array-parameter adjustment is a separate rule and must not be generalised into “all arrays are pointers.”
<!-- bilingual-en:end -->

> [!question]- 最小自检
> 为什么 `sizeof a / sizeof a[0]` 在 `a` 的声明作用域可能得到 4，而把 `a` 传入函数后对形参做同样运算不能恢复 4？
>
> **答案：** 前者的 `a` 仍是数组对象；数组形参已调整为指针，函数内 `sizeof` 看到的是指针类型。
