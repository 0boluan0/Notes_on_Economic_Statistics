# 鸭子类型让任何满足所需行为契约的对象参与同一多态调用而不要求共同继承
<!-- bilingual-en:start -->
*Duck typing lets any object satisfying the required behavioral contract participate in one polymorphic call without shared inheritance*
<!-- bilingual-en:end -->

> [!summary] 原子接口多态
> Python 调用点可以只依赖一组属性名称及其行为条件，而不先要求对象属于某个共同基类。只要不同对象都以兼容语义提供所需操作，同一函数就能多态地使用它们；这通常称为 duck typing。关键是“名字 + 契约”，不是碰巧存在同名方法。
> <!-- bilingual-en:start -->
> A Python call site can depend only on a set of attribute names and their behavioral conditions rather than first requiring a shared base class. If different objects provide the required operations with compatible semantics, one function can use them polymorphically; this is commonly called duck typing. The requirement is “names plus contract,” not a coincidental same-named method.
> <!-- bilingual-en:end -->

```python
def deposit_all(accounts, amount):
    for account in accounts:
        account.deposit(amount)
```

`deposit_all` 不关心对象是否继承 `Account`；它关心每个对象的 `deposit` 是否接受该金额并履行约定语义。继承可以提供这种共同接口，特殊方法协议也能提供统一调用，但二者都不是 duck typing 的必要条件。运行时若对象缺少属性，通常在走到该操作时才失败。

> [!question]- 回忆与应用
> 一个日志类也有 `deposit(x)` 方法，是否仅凭名字就能安全传给 `deposit_all`？
>
> **答案：** 不能；还要满足账户 `deposit` 的输入、结果与状态更新契约，同名不代表同语义。
