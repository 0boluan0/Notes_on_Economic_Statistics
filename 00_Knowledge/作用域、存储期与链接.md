# 作用域、存储期与链接分别回答名字可见、对象存活和跨文件身份
<!-- bilingual-en:start -->
*Scope, storage duration, and linkage answer name visibility, object lifetime, and cross-file identity respectively*
<!-- bilingual-en:end -->

> [!summary] 原子区别
> **作用域**决定源代码中哪里能用某个标识符；**存储期**决定对象的存储从何时保证存在到何时；**链接**决定不同作用域或翻译单元中的同名声明是否指向同一个实体。这三个维度相关，却不能互相替代。
> <!-- bilingual-en:start -->
>
> &nbsp;
> **Scope** determines where an identifier can be used in source code. **Storage duration** determines when an object's storage is guaranteed to exist. **Linkage** determines whether same-spelled declarations in different scopes or translation units denote the same entity. The three dimensions interact but are not substitutes for one another.
> <!-- bilingual-en:end -->

```c
static int calls;       // 文件作用域、静态存储期、内部链接

void record(void) {
    static int local;   // 块作用域、静态存储期、无链接
    int current = 0;    // 块作用域、自动存储期、无链接
    calls++;
    local++;
}
```

`local` 只在函数块内可见，却从程序开始到结束一直拥有存储；可见范围短不等于寿命短。`calls` 的文件作用域 `static` 使它在当前翻译单元内部保持同一身份；另一个源文件里同名的内部链接对象不是它。`current` 每次进入相应块时获得一次自动存储期实例，离开后该实例生命周期结束。
<!-- bilingual-en:start -->
`local` is visible only inside the function block, yet its storage lasts for the program's execution; short visibility does not imply short lifetime. File-scope `static` gives `calls` one identity inside the current translation unit; an internal-linkage object of the same name in another source file is distinct. `current` receives an automatic-duration instance on each entry to its block, and that instance ends on leaving it.
<!-- bilingual-en:end -->

## `static` 必须结合位置阅读

文件作用域对象上的 `static` 主要改变链接：把名字限制在当前翻译单元。块作用域对象上的 `static` 主要改变存储期：对象在多次函数调用之间保留值，但名字仍只有块作用域。只背“static 会保留变量”无法解释这两个用法。
<!-- bilingual-en:start -->
For a file-scope object, `static` chiefly changes linkage by keeping the name within the translation unit. For a block-scope object, `static` chiefly changes storage duration so the object retains its value across calls, while the name remains block-scoped. Memorising only that “static preserves a variable” cannot explain both uses.
<!-- bilingual-en:end -->

## 边界

存储期只描述对象；函数有作用域与链接，却没有对象存储期。链接描述的是标识符声明所指实体的身份，也不是“所有同名文本自动相连”。线程存储期和分配存储期还会增加更多生命周期规则；动态分配得到的对象没有自己的 C 标识符作用域，其可达性取决于仍保存地址的指针。判断悬空指针时要看对象生命周期，而不是看某个指针变量是否还在作用域中。
<!-- bilingual-en:start -->
Storage duration applies only to objects; a function has scope and linkage but no object storage duration. Linkage concerns the identity denoted by identifier declarations, not an automatic connection between every identical spelling. Thread and allocated storage durations add further lifetime rules. An allocated object has no C identifier scope of its own; reachability depends on pointers that still hold its address. A dangling-pointer analysis must follow the object's lifetime rather than merely ask whether a pointer variable remains in scope.
<!-- bilingual-en:end -->

> [!question]- 自检
> 函数内的 `static int count` 为什么既不是普通局部变量，也不是可从其他文件直接引用的全局名字？
>
> **答案：** 它有块作用域和无链接，所以名字只在该块可用；但有静态存储期，所以同一对象跨调用继续存在。
