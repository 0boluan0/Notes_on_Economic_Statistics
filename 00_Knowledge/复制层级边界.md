# 浅拷贝保留嵌套对象引用而深拷贝按复制协议递归处理对象图
<!-- bilingual-en:start -->
*A shallow copy retains references to nested objects, while a deep copy recursively follows the copying protocol across an object graph*
<!-- bilingual-en:end -->

> [!summary] 原子边界
> 浅拷贝创建新的外层复合对象，再把原对象中的元素引用放进去；深拷贝尝试递归复制其中的对象。两者解决的共享层级不同，深拷贝也不等于“无条件复制一切”。

对列表，**a[:]**、**list(a)**、**a.copy()** 与 **copy.copy(a)** 都可创建新的外层列表。若元素本身是列表，原件和副本仍指向同一个内层对象。

~~~python
original = [[1, 2], [3, 4]]
shallow = original[:]

assert shallow is not original
assert shallow[0] is original[0]

shallow.append([5, 6])     # 只改变副本的外层
shallow[0].append(99)      # 改变共享的内层列表

assert original == [[1, 2, 99], [3, 4]]
assert shallow == [[1, 2, 99], [3, 4], [5, 6]]
~~~

## 深拷贝遵守对象图与复制协议

**copy.deepcopy** 会维护一个已复制对象的 **memo**，用来避开递归环，并让同一源对象在副本图中复用同一副本。类还可以用 **__copy__** 与 **__deepcopy__** 定义自身语义。因此，深拷贝是“按协议递归处理”，不是机械地为每条引用都造一个互不相干的对象。

模块、栈帧、文件、套接字等运行期资源通常无法靠通用复制得到一个语义等价的独立资源；函数和类等对象也可能原样返回。深拷贝还可能复制本来应该共享的配置、缓存或身份对象，使程序含义发生变化。

选择复制层级时先问契约需要隔离哪一种修改：

- 只会增删外层元素：浅拷贝通常足够；
- 嵌套可变对象也必须隔离：考虑定向重建或深拷贝；
- 对象含资源、缓存或自定义不变量：优先调用它公开的构造、序列化或克隆接口。

“复制得越深越安全”并不成立。最小而明确的隔离边界通常更便宜，也更容易验证。

> [!question]- 自检
> 浅拷贝后 **outer_copy is not outer**，为什么仍不能推出两边完全独立？
>
> **答案：** 这个判断只证明外层对象身份不同；还要逐层检查嵌套元素是否仍指向同一对象。
