# 只有用实际备份完成恢复演练，才能验证恢复能力
<!-- bilingual-en:start -->
*Recoverability is established only by exercises that restore from real backups*
<!-- bilingual-en:end -->

> [!summary] 原子边界
> “备份任务成功”只是一条任务状态记录。在没有独立检查前，它甚至不能证明预期范围已完整写入，更不证明版本相容、依赖齐全或服务能在目标时间内恢复。恢复能力要用实际备份在受控演练中重建所需数据或服务来验证。
> <!-- bilingual-en:start -->
> “Backup job succeeded” is only a job-status record. Without an independent check, it does not even establish that the intended scope was written completely, much less version compatibility, complete dependencies, or restoration within the target time. Recoverability must be tested by rebuilding the required data or service from real backups in a controlled exercise.
> <!-- bilingual-en:end -->

演练范围应由 RPO 与 RTO 决定，并覆盖数据、配置、依赖版本、权限、操作说明和必要密钥。只抽查一个文件不等于验证整个服务；只确认数据可读也不等于业务能在新环境启动；在原系统仍可用时复制缺失配置，更不是一次独立恢复。
<!-- bilingual-en:start -->
The exercise scope should be set by the RPO and RTO and cover data, configuration, dependency versions, permissions, runbooks, and required keys. Restoring one sample file is not the same as rebuilding a service. Readable data do not prove that an application will start in a new environment, and copying missing configuration from a still-running original system is not an independent restoration.
<!-- bilingual-en:end -->

演练结果要记录恢复点、实际耗时、缺失依赖和人工绕过步骤，再反向修正备份范围与恢复流程。只有可重复完成且满足目标的演练，才把“我们有备份”变成“我们有已验证的恢复路径”。
<!-- bilingual-en:start -->
The exercise should record the restored point, elapsed time, missing dependencies, and manual workarounds, then feed those findings back into backup scope and restoration procedures. Only a repeatable exercise that meets its objectives turns “we have backups” into “we have a validated recovery path.”
<!-- bilingual-en:end -->

> [!question]- 自检
> 备份平台连续三个月显示绿色，为什么仍不能说系统满足 4 小时 RTO？
>
> **答案：** 绿色只说明备份任务报告成功；只有从真实备份完成端到端恢复并计时，才能检验服务是否能在 4 小时内重建。

## 来源与核验

- [NIST, *Protecting Data from Ransomware and Other Data Loss Events*](https://csrc.nist.gov/pubs/other/2020/04/24/protecting-data-from-ransomware-and-other-data-los/final)：核对备份应被实施、维护并测试，且规划要检查副本在需要时是否有用、可用；任务状态不能代替恢复证据。
- [NIST SP 1339, *OT Backup Quick Start Guide*](https://csrc.nist.gov/pubs/sp/1339/final)：交叉核对备份要纳入变更管理、定期测试并在恢复演练中复查；本卡采用其恢复验证原则，不移植 OT 特有配置。
- [NIST SP 800-34 Rev. 1](https://csrc.nist.gov/pubs/sp/800/34/r1/upd1/final)：核对演练、恢复程序和目标时间共同构成可验证的应急恢复能力。
