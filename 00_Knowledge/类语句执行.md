# 执行 class 语句会先运行类体再创建类对象并绑定类名
<!-- bilingual-en:start -->
*Executing a `class` statement runs its body before creating and binding the class object*
<!-- bilingual-en:end -->

> [!summary] 原子执行规则
> `class C(...): suite` 是可执行语句。Python 先解析基类项、确定元类，并由元类的 `__prepare__`（若提供）准备类命名空间；随后才在这个命名空间中立即执行类体。类体结束后，Python 调用元类创建类对象，应用类装饰器，并把最终结果绑定到当前外层命名空间中的名称 `C`。类体里的 `def` 会在此时创建函数对象，但方法函数体仍等到调用才运行。
> <!-- bilingual-en:start -->
> `class C(...): suite` is an executable statement. Python first resolves base entries, determines the metaclass, and lets its `__prepare__` hook, when present, prepare the class namespace. It then immediately executes the class body in that namespace. After the body finishes, Python calls the metaclass to create the class object, applies class decorators, and binds the final result to `C` in the surrounding namespace. A `def` in the body creates a function object at this point, but the method body still waits for a later call.
> <!-- bilingual-en:end -->

```python
events = []

class Ticket:
    events.append("class body")

    def validate(self):
        events.append("method body")

events                    # ["class body"]
Ticket().validate()
events                    # ["class body", "method body"]
```

因此，类体中的普通表达式可能在导入模块时产生副作用或抛出异常；“只是写蓝图”是有用直觉，却不能理解成类体被延迟执行。这里的时点边界是“类体先于类对象创建”，不是“类体先于所有创建机制”：元类选择和命名空间准备发生在类体之前。

> [!question]- 回忆与应用
> 为什么模块导入时可能在尚未创建任何实例前就因类体中的表达式报错？
>
> **答案：** 类体在执行 `class` 语句时立即运行；只有方法函数体通常延迟到方法调用。
