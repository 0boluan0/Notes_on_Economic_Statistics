# 困惑度只有在评测分布、tokenizer、规范化与条件格式匹配时才能直接比较
<!-- bilingual-en:start -->
*Perplexity is directly comparable only under matched evaluation distributions, tokenizers, normalization, and conditioning formats*
<!-- bilingual-en:end -->

> [!summary] 测量边界
> raw [[困惑度|PPL]] 是“每个有效 token”的平均损失取指数。直接比较两个数值，要求同一文本分布与版本、同一 [[Token口径|tokenizer 和词表]]、同一规范化、文档边界与可见条件历史，以及同一 loss mask 和聚合方式。tokenizer 不同时，可在完全相同的 UTF-8 文本上报告 bits per byte（BPB）作为部分替代，但它不能消除其余协议差异。
>
> <!-- bilingual-en:start -->
> Raw PPL exponentiates loss averaged per valid token. Direct comparison requires the same text distribution, tokenizer and vocabulary, normalization, document boundaries and visible history, loss mask, and aggregation. With different tokenizers, bits per byte on identical UTF-8 text is a partial alternative, not a remedy for the remaining protocol differences.
> <!-- bilingual-en:end -->

## 为什么同一序列概率也能产生不同 raw PPL
<!-- bilingual-en:start -->
*Why the same sequence probability can yield different raw PPL*
<!-- bilingual-en:end -->

假设两个 tokenizer 对同一段规范化文本都给出整段概率 $0.01$。Tokenizer A 把它编码成 1 个有效 token，则 $\mathrm{PPL}_A=100$；Tokenizer B 把它编码成 2 个有效 token，两个条件概率的乘积仍为 $0.01$，则 $\mathrm{PPL}_B=10$。文本与整段概率相同，raw PPL 却相差十倍，因为 token 分母变了。跨 tokenizer 直接排名是在比较不同单位。

<!-- bilingual-en:start -->
Suppose two tokenizers assign probability $0.01$ to the same normalized text. With one valid token, raw PPL is $100$; with two valid tokens whose probabilities still multiply to $0.01$, raw PPL is $10$. The text and sequence probability are unchanged, but the denominator changed. A direct ranking compares different units.
<!-- bilingual-en:end -->

## 直接比较前的最小匹配协议
<!-- bilingual-en:start -->
*Minimum matching protocol before direct comparison*
<!-- bilingual-en:end -->

1. **文本与分布：** 同一文档集合、版本、语言与领域权重、时间切分和 [[基准去污染|去污染规则]]。
2. **tokenizer 与词表：** 同一版本、词表和 special-token 处理。
3. **规范化：** 同一 Unicode、空白、标点、换行与编码处理。
4. **切分与上下文：** 同一文档边界、最大上下文、截断或滑窗方案，以及 overlap 计分方式。
5. **条件格式：** packing 后实际可见的历史相同；不能让一个模型跨文档 attention，另一个每篇从 BOS 开始。
6. **计分与聚合：** 同一 loss mask、token 加权或文档加权方式，并同时报告领域级结果。

<!-- bilingual-en:start -->
Match the documents and domain weights; tokenizer, vocabulary, and special tokens; normalization; document boundaries and context windows; history actually visible under packing; and the loss mask and aggregation. Report domain-level results alongside any mixed average.
<!-- bilingual-en:end -->

PALOMA 逐文档评测，避免直接串接文档并允许跨文档 attention，因为后一做法改变条件概率任务。若 packing 用 block-diagonal 或 segment-aware mask 隔离文档，关键就不是“是否 packing”，而是模型实际能看见什么。

<!-- bilingual-en:start -->
PALOMA evaluates documents separately rather than concatenating them with cross-document attention, which changes the conditional-probability task. With document-isolating masks, the key is actual visibility rather than the label “packing.”
<!-- bilingual-en:end -->

## Tokenizer 不同时用 BPB，但保留剩余边界
<!-- bilingual-en:start -->
*Use BPB across tokenizers, while retaining its remaining boundaries*
<!-- bilingual-en:end -->

对规范化文本及 tokenizer 选出的序列 $\tau(\text{text})$，bits per byte 定义为
$$
\mathrm{BPB}=-\frac{\log_2 p_\theta(\tau(\text{text}))}{B_{\mathrm{UTF\text{-}8}}}.
$$
BPB 用 UTF-8 byte 数替代 token 数作分母，因此比 raw PPL 更适合比较不同 tokenizer。它仍要求同一文本、编码、文档边界、条件历史与聚合，也不能控制不同评测分布或 [[训练评测污染]]。

<!-- bilingual-en:start -->
BPB replaces the token denominator with UTF-8 bytes, making it more suitable than raw PPL across tokenizers. It still requires identical text, encoding, document boundaries, conditioning history, and aggregation, and it does not control distribution differences or contamination.
<!-- bilingual-en:end -->

常规 BPB 只计算 tokenizer 实际选出的那一条 tokenization 路径，不会对所有能解码成同一文本的合法 token 序列做边缘化。因此 BPB 只是部分解决方案；能固定词表时，同一 tokenizer 仍是更严格的直接比较条件。

<!-- bilingual-en:start -->
Ordinary BPB scores only the tokenization path selected by the tokenizer rather than marginalizing over every valid path that decodes to the same text. It is therefore a partial remedy; a shared tokenizer remains the stricter condition when available.
<!-- bilingual-en:end -->

协议匹配后，较低 PPL 或 BPB 只支持“模型对该评测分布文本给出更高平均概率”。它不自动证明事实性、推理、指令遵循、安全或用户效用更好。

> [!question]- 自检
> 模型 A 用 tokenizer A 得到 PPL 8.0，模型 B 用 tokenizer B 得到 PPL 8.4。能否直接判定 A 更好？
>
> **答案：** 不能。先匹配文本、分布、切分、条件历史和聚合；能统一 tokenizer 时重评 raw PPL，不能统一时在同一 UTF-8 文本上报告 BPB，并保留 BPB 的剩余限制。
