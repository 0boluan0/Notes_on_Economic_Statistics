# raise 可显式报告异常而裸 raise 重新抛出当前正在处理的异常

<!-- bilingual-en:start -->
*raise explicitly reports an exception, while bare raise re-raises the exception currently being handled*
<!-- bilingual-en:end -->

当[[函数契约]]要求拒绝某种情况时，可用 `raise ExceptionType(message)` 构造并抛出适当的异常实例。`raise` 也接受异常类，此时通过无参构造得到实例；对象或类必须属于 `BaseException` 体系。消息说明失败原因，异常类型让调用者按类别处理。

<!-- bilingual-en:start -->
When a [[函数契约|function contract]] requires rejection, `raise ExceptionType(message)` constructs and raises a suitable exception instance. `raise` also accepts an exception class, instantiated without arguments; the class or object must belong to the `BaseException` hierarchy. The message explains the failure, while its type lets callers handle the category.
<!-- bilingual-en:end -->

```python
def mean(values):
    if not values:
        raise ValueError("at least one value is required")
    return sum(values) / len(values)
```

这段示例假设 `values` 是数值列表；它只显式检查空列表，不声称验证所有输入类型。处理器若只能记录或补做动作、不能解决失败，可用不带参数的 `raise` 保留当前异常继续传播。没有正在处理的异常时执行裸 `raise` 会产生 `RuntimeError`。若要把底层异常转换为另一种接口异常，使用[[异常链]]表达原因。

<!-- bilingual-en:start -->
The example assumes a numeric list and explicitly checks only emptiness; it is not a complete type validator. A handler that can report or perform an action but cannot resolve the failure can use bare `raise` to propagate the current exception. Bare `raise` without an active exception produces `RuntimeError`. Use [[异常链|exception chaining]] when translating a low-level failure into a different interface exception.
<!-- bilingual-en:end -->
