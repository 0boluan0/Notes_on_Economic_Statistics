# 未处理异常沿活动调用链向外传播而不会自动返回失败语句重试

<!-- bilingual-en:start -->
*An unhandled exception propagates outward through active calls rather than automatically retrying the failed statement*
<!-- bilingual-en:end -->

语句抛出异常后，当前正常路径的剩余语句被跳过；若当前层没有匹配的处理器，就沿活动调用链向外寻找。调用者的 `try` 可以捕获其内部调用的函数所抛出的异常。匹配处理器正常结束后，执行继续到整个 `try` 语句之后，而不是回到原失败语句或其下一行。

<!-- bilingual-en:start -->
After a statement raises an exception, the remaining statements on its normal path are skipped. If the current level has no matching handler, the search moves outward through active calls. A caller's `try` can therefore catch an exception raised inside a function it calls. When the matching handler finishes normally, execution continues after the entire `try` statement, not at the failed statement or its next line.
<!-- bilingual-en:end -->

```python
def inner(events):
    events.append("entered")
    int("cat")
    events.append("unreachable")

events = []
try:
    inner(events)
    events.append("also unreachable")
except ValueError:
    events.append("handled")
events.append("after")
# events == ["entered", "handled", "after"]
```

此前已经完成的副作用仍然存在。重试必须由循环或再次调用显式实现；传播时穿过的[[finally清理|清理分支]]也可能改变最终结果。若异常最终逃出普通脚本的最外层而未处理，脚本通常以 traceback 结束；交互解释器则可返回提示符，不能把局部“未捕获”一概等同于整个宿主进程退出。

<!-- bilingual-en:start -->
Previously completed side effects remain. Retrying requires an explicit loop or another call; [[finally清理|cleanup clauses]] crossed during propagation can also change the outcome. An exception escaping the outermost level of an ordinary script normally ends it with a traceback, whereas an interactive interpreter may return to its prompt. Locally unhandled does not universally mean that the entire host process exits.
<!-- bilingual-en:end -->
