# 执行未装饰的 def 会创建并绑定函数对象而函数体只在调用时运行
<!-- bilingual-en:start -->
*Executing an undecorated `def` creates and binds a function object, while its body runs only when the function is called*
<!-- bilingual-en:end -->

> [!summary] 原子执行规则
> Python 执行普通、未装饰的 `def` 时，会创建函数对象并把函数名绑定到它；缩进的函数体此时不会运行。之后求值调用表达式，才会把实参交给该函数并执行函数体。因此“定义成功”只能说明函数对象已经建立，不能证明函数体对某个输入可以正常完成。
> <!-- bilingual-en:start -->
> Executing an ordinary undecorated `def` creates a function object and binds its name, but does not run the body. The body runs only when a later call applies that function to arguments, so a successful definition does not establish that the body completes correctly for any input.
> <!-- bilingual-en:end -->

```python
def reciprocal(x):
    return 1 / x       # not evaluated yet

reciprocal(0)          # the call executes the body and raises ZeroDivisionError
```

这个边界只把“定义”和“调用”分开，不声称执行 `def` 没有任何其他求值。默认值在定义时求值；装饰器也在定义过程中求值，并把装饰后的返回对象绑定给函数名。类型注解何时求值还受 Python 版本与注解设置影响，不应和函数体的调用时执行混为一谈。

> [!question]- 自检
> 为什么模块加载时执行到 `def reciprocal(x): ...` 没报除零错误，仍不能说明 `reciprocal(0)` 安全？
>
> **答案：** `def` 只创建并绑定函数对象，没有执行函数体；除法直到调用并走到该语句时才发生。
