# 溢出与下溢位于浮点范围的两端且后果不同

<!-- bilingual-en:start -->
*Overflow and underflow occur at opposite ends of floating-point range with different consequences*
<!-- bilingual-en:end -->

> [!summary] 原子区分
> **溢出（overflow）**发生在舍入后的结果绝对值大于格式可表示的最大有限值；**下溢（underflow）**涉及结果小到落入最小正规数以下并伴随微小性与精度损失。前者越过“大数端”，后者进入“近零端”，不能都概括为“数太大”。
>
> <!-- bilingual-en:start -->
> **Overflow** occurs when a rounded result's magnitude exceeds the largest finite value of the format. **Underflow** concerns a tiny result below the normal range together with loss of accuracy. Overflow crosses the large-magnitude end; underflow enters the near-zero end. They are not the same generic condition.
> <!-- bilingual-en:end -->

在 IEEE 754 默认处理下，向最近值舍入的溢出通常产生带符号无穷并设置状态标志；下溢结果可以成为次正规数或最终舍入为带符号零。次正规结果并不自动意味着无用，但其相对精度会随接近零而下降。
<!-- bilingual-en:start -->
Under IEEE 754 default handling with round-to-nearest, overflow typically produces a signed infinity and raises a status flag. An underflowing result can become subnormal or eventually round to signed zero. A subnormal result is not automatically useless, but its relative precision decreases toward zero.
<!-- bilingual-en:end -->

语言层不一定把硬件默认结果原样暴露出来。Python 的普通浮点运算、构造器和 `math` 函数在不同异常上可能返回 `inf`、返回 0，或抛出 `OverflowError`/`ValueError`；代码应按具体 API 契约检测，不能仅凭 IEEE 默认规则猜测。
<!-- bilingual-en:start -->
A language need not expose hardware defaults unchanged. Python arithmetic, constructors, and `math` functions can return `inf`, return zero, or raise `OverflowError` or `ValueError` for different exceptional cases. Code must follow the specific API contract rather than infer behavior solely from IEEE defaults.
<!-- bilingual-en:end -->

> [!question]- 回忆与应用
> 一个极小的非零计算结果变成 0，应首先归类为溢出还是下溢？
>
> **答案：** 下溢方向；精确结果落在近零端，经过次正规区或舍入后成为零。
