# Unix文件路径是通过目录层级定位文件的名称序列

在 Unix 文件系统中，路径用 `/` 分隔目录层级中的名称来定位文件；路径也可以只指向目录本身。以 `/` 开头的绝对路径从进程的根目录开始，通常 Shell 命令中的相对路径从当前工作目录开始。`.` 表示当前路径位置的目录，`..` 表示其父目录。
<!-- bilingual-en:start -->
A Unix pathname locates a file through names separated by `/` in a directory hierarchy; it may also name a directory itself. An absolute pathname begins at the process's root directory, while a relative pathname in ordinary shell commands begins at the current working directory. `.` denotes the directory at that point, and `..` its parent.
<!-- bilingual-en:end -->

若当前目录为 `/work/project`，则 `data/input.tsv` 从这里寻找 `data`，而 `/work/project/data/input.tsv` 明确从根开始。改变当前目录后，同一个相对字符串可能指向别处；脚本所在目录并不会自动成为脚本运行时的当前目录。
<!-- bilingual-en:start -->
From `/work/project`, `data/input.tsv` looks for `data` there, whereas `/work/project/data/input.tsv` starts explicitly from the root. Changing the working directory can change the meaning of the same relative string. A script's containing directory does not automatically become its runtime working directory.
<!-- bilingual-en:end -->

路径字符串不等于文件的唯一身份：不同路径可以到达同一个文件，符号链接还会参与解析。不要把删去 `x/..` 这样的纯字符串化简当作对任意含符号链接路径都等价的操作。路径放入 Shell 命令时还要保护参数边界，例如 `"$path"`；文件名内部的空格本身并不非法。
<!-- bilingual-en:start -->
A pathname is not a unique file identity: different paths can reach the same file, and symbolic links participate in resolution. Pure textual removal of a component such as `x/..` need not preserve the meaning of a path involving symbolic links. Shell use additionally requires argument-boundary protection such as `"$path"`; spaces inside a filename are not inherently invalid.
<!-- bilingual-en:end -->
