# 动态数组必须始终同时维护指针、长度与容量不变量
<!-- bilingual-en:start -->
*A dynamic array must maintain pointer, length, and capacity invariants together at all times*
<!-- bilingual-en:end -->

> [!summary] 三元状态
> 动态数组不是一个裸指针，而是一组必须同步成立的状态：`data` 指向当前分配；`length` 是已经构造、允许读写的逻辑元素数；`capacity` 是分配可容纳的元素总数。核心不变量是 `length <= capacity`，且 `capacity > 0` 时 `data` 必须指向至少 `capacity` 个元素的有效分配。
> <!-- bilingual-en:start -->
> A dynamic array is not a bare pointer. `data` identifies the current allocation, `length` counts constructed logical elements, and `capacity` counts allocated element slots. The central invariant is `length <= capacity`, with `data` designating storage for at least `capacity` elements whenever capacity is positive.
> <!-- bilingual-en:end -->

```c
#include <stdbool.h>
#include <stdint.h>
#include <stdlib.h>

struct IntVec {
    int *data;
    size_t length;
    size_t capacity;
};

bool push(struct IntVec *v, int value) {
    if (v == NULL || v->length > v->capacity) return false;
    if ((v->capacity == 0) != (v->data == NULL)) return false;

    if (v->length == v->capacity) {
        size_t next;
        if (v->capacity == 0) {
            next = 4;
        } else {
            if (v->capacity > SIZE_MAX / 2) return false;
            next = v->capacity * 2;
        }
        if (next > SIZE_MAX / sizeof *v->data) return false;

        void *tmp = realloc(v->data, next * sizeof *v->data);
        if (tmp == NULL) return false;
        v->data = tmp;
        v->capacity = next;
    }

    v->data[v->length] = value;
    v->length++;
    return true;
}
```

零初始化的 `struct IntVec v = {0};` 满足本接口选定的唯一空状态：`data == NULL`、`length == 0`、`capacity == 0`。入口检查同时排除“零容量却保留非空指针”和“正容量却没有分配”的矛盾元数据；指针背后是否真有足够大的有效分配仍是调用方必须维护的前置条件，函数无法从裸指针值反查。追加只在 `length == capacity` 时扩容；扩容先检查容量倍增和字节乘法，再用临时指针保持失败原子性。只有目标槽位写入成功后才增加 `length`，因此 `[0, length)` 始终是逻辑元素，而 `[length, capacity)` 只是尚不可读取为元素值的备用空间。
<!-- bilingual-en:start -->
`struct IntVec v = {0};` establishes the empty state. Growth occurs only when length equals capacity, after checking both capacity doubling and byte multiplication. A temporary pointer preserves the old state on failure. Length advances only after the new slot is written, so `[0, length)` remains the logical range and `[length, capacity)` is spare, not readable element state.
<!-- bilingual-en:end -->

任何成功的 `realloc` 都可能使先前借出的元素指针、迭代器式指针和切片失效，即使 `data` 的数值地址没有变化；扩容后应从新的 `data` 和索引重新取得地址。销毁时由唯一所有者 `free(v.data)`，随后把三个字段一起重置为零状态，不能只清指针却留下虚假的长度或容量。
<!-- bilingual-en:start -->
Any successful `realloc` may invalidate previously borrowed element pointers, iterator-like pointers, and slices, even if the numerical address is unchanged. Reacquire addresses from the new `data` and indices. Destruction frees the allocation once and resets all three fields, rather than clearing only the pointer and leaving false length or capacity.
<!-- bilingual-en:end -->

> [!question]- 最小自检
> 为什么扩容成功后先写 `length++`、再写 `data[length-1]` 会让错误处理更脆弱？
>
> **答案：** 在元素真正初始化前，元数据已宣称它属于 `[0,length)`；若写入路径中断，不变量会把未构造槽位伪装成可读元素。先写元素、后提交长度。

## 来源与核验

- [ISO C11 committee draft N1570, 6.5.6, 7.22.3, and 7.22.3.5](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf)：核对数组边界、分配生命周期、`realloc` 的成功与失败路径及旧别名失效。
- [SEI CERT C, MEM35-C](https://wiki.sei.cmu.edu/confluence/spaces/c/pages/87152128/MEM35-C.%2BAllocate%2Bsufficient%2Bmemory%2Bfor%2Ban%2Bobject)：作为工程建议，核对增长大小的范围检查；三元不变量是由这些语言边界导出的数据结构设计。
<!-- bilingual-en:start -->
- [ISO C11 committee draft N1570, 6.5.6, 7.22.3, and 7.22.3.5](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf) was checked for array boundaries, allocated lifetime, `realloc` success and failure, and invalidated old aliases.
- [SEI CERT C MEM35-C](https://wiki.sei.cmu.edu/confluence/spaces/c/pages/87152128/MEM35-C.%2BAllocate%2Bsufficient%2Bmemory%2Bfor%2Ban%2Bobject) was used as engineering guidance for growth-size checks; the three-field invariant is a data-structure design derived from those language boundaries.
