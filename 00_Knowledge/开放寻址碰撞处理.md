# 开放寻址用探测序列在同一数组中处理碰撞

<!-- bilingual-en:start -->
*Open addressing resolves collisions by following a probe sequence within one array*
<!-- bilingual-en:end -->

> [!summary] 原子方法
> 开放寻址不为每个槽另挂一条链。所有条目都存在表数组本身；一次哈希操作为键规定一串候选槽，插入和查找按相同顺序逐个探测。
>
> <!-- bilingual-en:start -->
> Open addressing does not attach a separate chain to each slot. Every entry lives in the table array itself. Hashing defines a sequence of candidate slots for a key, and insertion and lookup follow that sequence in the same order.
> <!-- bilingual-en:end -->

可把探测函数写成 $h(k,i)$，其中 $i=0,1,\ldots,m-1$ 是第几次尝试。插入沿序列前进，直到遇到可用槽；查找沿同一序列前进，直到找到相等键、遇到从未使用过的空槽，或穷尽可能位置。线性探测、二次探测和双重哈希的差别，主要在于如何生成这串位置。
<!-- bilingual-en:start -->
Write the probe function as $h(k,i)$, where $i=0,1,\ldots,m-1$ counts attempts. Insertion advances until it finds a usable slot. Lookup follows the same sequence until it finds an equal key, reaches a slot that has never been used, or exhausts the possible positions. Linear probing, quadratic probing, and double hashing mainly differ in how they generate this sequence.
<!-- bilingual-en:end -->

因为每个槽最多直接保存一个有效条目，开放寻址的表示只能有 $n\le m$。但若还要插入一个此前不存在的新键，就必须至少留有一个可复用槽，所以通常的运行与分析要求有效负载 $\alpha=n/m<1$。负载越接近 1，空槽越难遇到，探测成本上升越快。开放寻址通常有较好的局部性并省去桶指针，但对聚集、哈希分布和负载更敏感。
<!-- bilingual-en:start -->
Because each slot directly holds at most one live entry, an open-addressed representation can contain only $n\le m$ entries. Inserting a previously absent key requires at least one reusable slot, so normal operation and analysis assume a live load $\alpha=n/m<1$. As the load approaches one, empty slots become difficult to find and probe costs rise sharply. The design often has good locality and avoids bucket pointers, but it is more sensitive to clustering, hash quality, and load.
<!-- bilingual-en:end -->

> [!question]- 回忆与辨别
> 开放寻址与拉链法处理同一次碰撞时，条目分别放在哪里？
>
> **答案：** 开放寻址把条目放进同一数组中的另一个探测槽；拉链法把它放进原槽所指向的桶。
