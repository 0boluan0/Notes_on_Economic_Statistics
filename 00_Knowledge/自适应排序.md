# 自适应排序利用输入已有顺序但必须说明顺序度量

<!-- bilingual-en:start -->
*Adaptive sorting exploits existing order under a stated measure*
<!-- bilingual-en:end -->

> [!summary] 原子定义
> 自适应排序的工作量会随输入“接近有序”的程度下降。这个判断必须说明顺序度量，例如逆序对数量 $I$、已有有序段，或每个项目离最终位置的最大距离，而不能只写“近有序时更快”。
>
> <!-- bilingual-en:start -->
> An adaptive sort does less work as its input becomes closer to sorted. The claim must name a presortedness measure, such as inversion count $I$, existing ordered runs, or maximum displacement from final position, rather than merely saying “faster on nearly sorted input.”
> <!-- bilingual-en:end -->

## 自然解释

对标准相邻移动的 insertion sort，每次移动消除一个逆序对，因此其工作可写为 $O(n+I)$；若 $I=O(n)$，运行时间就是线性阶。Python 的 Timsort 则会识别并利用输入中已有的有序结构。

<!-- bilingual-en:start -->
For standard adjacent-move insertion sort, each move removes one inversion, giving $O(n+I)$ work; when $I=O(n)$, the running time is linear. Python's Timsort instead detects and exploits order already present in the input.
<!-- bilingual-en:end -->

> [!warning] 边界
> 自适应性不同于“[[平均情况复杂度|平均情况]]更快”：前者把成本绑定到可陈述的输入结构，后者需要明确输入分布。小规模上常数低、缓存友好，也不是自适应性的定义。
>
> <!-- bilingual-en:start -->
> Adaptivity is not the same as a better [[平均情况复杂度|average case]]. The former relates cost to a stated input structure; the latter requires an input distribution. Low constants or good cache behavior on small inputs do not define adaptivity either.
> <!-- bilingual-en:end -->

> [!question]- 回忆与应用
> “算法在近有序数据上是线性的”还缺什么，才是可检验结论？
>
> **答案：** 缺少“近有序”的度量及成本条件，例如逆序对 $I=O(n)$ 时标准 insertion sort 为 $O(n+I)=O(n)$。
