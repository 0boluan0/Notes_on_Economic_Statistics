# Bash重定向从左向右生效且描述符复制使用复制时的连接

Bash 从左向右处理一个命令的重定向。`2>&1` 把描述符 2 复制到描述符 1 此时指向的连接；它不是设置“以后让 stderr 永远跟随 stdout”的规则。因此改变顺序可能改变输出目的地。
<!-- bilingual-en:start -->
Bash processes a command's redirections from left to right. `2>&1` makes descriptor 2 refer to the connection currently used by descriptor 1. It does not establish a rule that standard error must follow future changes to standard output. Reordering redirections can therefore change destinations.
<!-- bilingual-en:end -->

假设执行前 stdout 与 stderr 都连接终端，`cmd` 会使用这两个通道：
<!-- bilingual-en:start -->
Assume both streams initially connect to the terminal and `cmd` uses both channels:
<!-- bilingual-en:end -->

```bash
cmd > combined.txt 2>&1
cmd 2>&1 > output-only.txt
```

第一种先把 stdout 接到文件，再让 stderr 复制它，所以两者进入 `combined.txt`。第二种先让 stderr 复制原 stdout 的终端连接，再单独改变 stdout，因此只有 stdout 进入 `output-only.txt`。例子涉及写入，应只在临时目录里用已知测试命令代入。
<!-- bilingual-en:start -->
The first form redirects standard output to the file, then duplicates it for standard error: both enter `combined.txt`. The second copies the original terminal connection for standard error before changing standard output, so only standard output enters `output-only.txt`. These forms write files; substitute a known test command only in a temporary directory.
<!-- bilingual-en:end -->

[[Shell管道]]的连接先于命令自身的显式重定向建立。因此 `cmd > file | next` 中，`cmd` 的 stdout 最终接到 `file`，不是同时复制给 `next`；要一份数据去多个目的地，应选择具有复制流职责的工具。
<!-- bilingual-en:start -->
[[Shell管道|Pipeline]] connections are established before a command's explicit redirections. In `cmd > file | next`, `cmd` ultimately writes standard output to `file`, not a duplicate to `next`. Sending copies to multiple destinations requires a tool with that responsibility.
<!-- bilingual-en:end -->

## 来源与核验

- GNU Bash 3.2 本机 `bash(1)`，`REDIRECTION` 与 `Pipelines`；[官方重定向顺序例子](https://www.gnu.org/software/bash/manual/html_node/Redirections.html)：支持从左向右处理、两个相反顺序的连接差异及管道先建立的规则。
<!-- bilingual-en:start -->
The local Bash manual's redirection example establishes left-to-right processing and the two different destinations. Its pipeline section states that the pipe connection precedes explicit command redirections.
<!-- bilingual-en:end -->
