# 预测任务必须先固定预测对象、用途、粒度与输出形式
<!-- bilingual-en:start -->
*A forecasting task must first fix the target, use, granularity, and output form*
<!-- bilingual-en:end -->

> [!summary] 原子任务定义
> 一个可评估的预测任务至少要说明：预测哪个变量、覆盖哪些对象、采用什么时间与聚合粒度、多久更新一次、结果服务什么决定，以及交付点预测、分位数、区间还是完整分布。只说“预测销量”还没有固定任务；门店—周需求和全国—季度总销量不是同一个预测对象。
> <!-- bilingual-en:start -->
> An evaluable forecasting task states the variable, population, temporal and aggregation granularity, update frequency, decision use, and whether the output is a point, quantile, interval, or full distribution. “Forecast sales” alone does not define one task.
> <!-- bilingual-en:end -->

forecast 是对不确定未来的诚实描述，goal 是希望发生什么，plan 是看到 forecast 与 goal 后决定采取什么行动。三者可以联动，但不能为了让计划好看而把预测向目标调高或调低。决策用途的作用，是确定哪些期限、输出和误差真正有代价，而不是预先规定预测必须等于多少。

例如，“为补货预测需求”仍然太宽。较完整的任务可以写成：“每家门店每周更新未来四周需求分布，提供 10%、50%、90% 分位数供补货使用。”具体在什么时点生成、每个 horizon 对应哪个 target time，以及当时能用哪些数据，再由 [[预测时点与信息集]] 固定。

任务定义也决定聚合顺序。直接预测“下月总需求”与先预测每日需求再相加，目标变量和误差分布不同；即使两者期望值偶然接近，也不能把评价结果混用。任务变更后，旧分数只能描述旧任务，不能自动证明新任务上的性能。

> [!question]- 自检
> “明年销售额必须达到一亿元，所以预测一亿元”为什么不是合格的 forecast？
>
> **答案：** 一亿元是 goal。预测应依据当时信息诚实描述未来；计划可以在预测与目标之间选择行动，但不能把目标冒充预测结果。
