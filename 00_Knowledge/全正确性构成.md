# Total correctness
<!-- bilingual-en:end -->
*全正确性*

<!-- bilingual-en:start -->
When we ask a program to calculate an answer, two things can go wrong: it can return the wrong answer, or it can keep running without returning anything. **Total correctness** rules out both failures for the inputs covered by the specification. Every permitted execution must finish, and its final result must be the one the specification requires.
<!-- bilingual-en:end -->
让程序计算一个答案时，可能遇到两类失败：返回了错误答案，或一直运行却什么也不返回。**全正确性**要求：对于规格所涵盖的输入，两种失败都不会发生。每条允许的执行都必须结束，而且最终结果满足规格要求。

<!-- bilingual-en:start -->
The **precondition** says which inputs are allowed. The **postcondition** says what a returned result must satisfy. For example, “input an integer $N\ge0$, return the same number $N$” has a nonnegative-integer precondition and an output requirement $y=N$. Correctness always refers to such a requirement; a program is not simply “correct” without a task and an input scope.
<!-- bilingual-en:end -->
**前置条件**说明允许哪些输入，**后置条件**说明返回的结果必须满足什么。例如，“输入整数 $N\ge0$，返回同一个数 $N$”的前置条件是输入非负整数，输出要求是 $y=N$。正确性总是相对于这样的要求而言；没有任务与输入范围，就无法单独判断程序是否“正确”。

> [!important] Two separate guarantees · 两个独立保证
> <!-- bilingual-en:start -->
> Partial correctness guarantees only that if a process produces a final result, that result satisfies the specification; the process may still run forever. Termination guarantees that the process reaches a final state. Together they yield total correctness: the process finishes, and its result is correct.
> <!-- bilingual-en:end -->
>
> 部分正确性只保证“如果过程产生最终结果，那么该结果满足规格”；它允许过程永远运行。终止性保证过程一定到达最终状态。只有两者同时成立，才能得到“过程一定结束，而且结束时结果正确”的全正确性结论。

## Three programs for the same task
<!-- bilingual-en:end -->
*同一任务，三个程序*

<!-- bilingual-en:start -->
Keep the task $y=N$ for every nonnegative integer input $N$, and use exact integer arithmetic. Consider these three procedures:

| Procedure | Correct whenever it returns? | Must return? |
| --- | --- | --- |
| Start at $(x,y)=(N,0)$; while $x>0$, update to $(x-1,y+1)$; return $y$ | Yes | Yes |
| Repeat a step that does nothing forever; never return | Yes, as a conditional statement about returned results | No |
| Immediately return $N+1$ | No | Yes |
<!-- bilingual-en:end -->
固定任务为：对每个非负整数输入 $N$，输出 $y=N$，并使用精确整数运算。比较三个过程：

| 过程 | 只要返回，结果就正确吗？ | 一定返回吗？ |
| --- | --- | --- |
| 从 $(x,y)=(N,0)$ 开始；当 $x>0$ 时更新为 $(x-1,y+1)$；返回 $y$ | 是 | 是 |
| 永远重复什么也不改变的一步，从不返回 | 是，仅就“若返回则正确”的条件陈述而言 | 否 |
| 立即返回 $N+1$ | 否 | 是 |

<!-- bilingual-en:start -->
For the first procedure, start with $N=3$. Its states are $(3,0),(2,1),(1,2),(0,3)$. The sum $x+y=N$ stays true; when $x=0$, it gives $y=N$. Separately, each step reduces the nonnegative integer $x$ by one, so after exactly $N$ steps the loop exits. With $N=0$, it returns immediately. This is a complete argument for all allowed inputs, not just a test of the four displayed states.
<!-- bilingual-en:end -->
对第一个过程，先看 $N=3$：状态依次为 $(3,0),(2,1),(1,2),(0,3)$。和 $x+y=N$ 始终保持；当 $x=0$ 时，就有 $y=N$。另一方面，每步让非负整数 $x$ 减少一，所以恰好 $N$ 步后退出循环。若 $N=0$，立即返回。这里给出了覆盖所有允许输入的论证，不只是检验所列的四个状态。

<!-- bilingual-en:start -->
The second procedure never produces an incorrect result because it never produces any result. Its partial-correctness condition is therefore true, but useless as a promise to deliver an answer. The third procedure shows the other missing guarantee: finishing quickly does not make the answer correct. Only the first procedure is totally correct for the stated task.
<!-- bilingual-en:end -->
第二个过程永远不会产生错误结果，因为它根本不产生结果，所以“若返回则正确”成立；但这不能承诺交付答案。第三个过程说明另一项保证也不能省：很快结束不代表答案正确。对于规定任务，只有第一个过程全正确。

## What the two proofs must cover
<!-- bilingual-en:end -->
*两个证明必须覆盖什么？*

<!-- bilingual-en:start -->
A [[状态机与可达性|state machine]] describes a process by its possible states and allowed steps. An execution follows those steps from an allowed start. Here a complete execution either continues forever or stops at a state with no next step; a finite observation that was stopped early is only a prefix. We use a program model in which a legitimate terminal state represents a specified return. Errors or other stuck states cannot silently count as successful returns: either the model excludes them and the input conditions justify that exclusion, or their absence must be proved.
<!-- bilingual-en:end -->
[[状态机与可达性|状态机]]用可能状态和允许步骤描述过程；执行从允许的起点出发，沿这些步骤前进。这里完整执行要么无限继续，要么在没有下一步的状态结束；人为提前停止观察得到的只是一段前缀。我们采用的程序模型中，合法终止状态表示规格所要求的返回。错误或其他卡住状态不能悄悄算成成功返回：要么模型将其排除且输入条件足以支持这种排除，要么必须证明它们不会发生。

<!-- bilingual-en:start -->
For **the same allowed inputs and the same execution rules**, partial correctness checks every permitted final result, while termination excludes every infinite execution. If there are several possible branches, exhibiting one successful run proves neither universal guarantee. A branch that returns $N$ and another branch that loops forever give a simple counterexample: a good answer is possible, but total correctness fails. Any restriction on which branches may be chosen must be part of the stated model.
<!-- bilingual-en:end -->
对于**相同的允许输入、相同的执行规则**，部分正确性检查每个允许的最终结果，终止性排除每条无限执行。若存在多个可能分支，展示一条成功执行不能证明任意一项全称保证。例如，一个分支返回 $N$，另一个分支永远循环：虽然可能得到正确答案，全正确性仍不成立。任何对分支选择的限制，都必须写在模型条件里。

<!-- bilingual-en:start -->
The logical combination is simple: choose any allowed input and any complete execution. Termination gives a final result for that execution; partial correctness makes that result satisfy the postcondition. Conversely, a guarantee that every execution finishes correctly supplies both guarantees separately. The scope must match: a termination proof for positive inputs cannot be combined with an output proof for arbitrary integers to certify all integers.
<!-- bilingual-en:end -->
二者结合的逻辑很直接：任取一个允许输入及一条完整执行，终止性保证这条执行产生最终结果，部分正确性保证该结果满足后置条件。反过来，若保证每条执行都结束且结果正确，就分别得到了这两项保证。覆盖范围必须一致：不能把仅适用于正输入的终止证明，与适用于任意整数的输出证明拼接起来，宣称对所有整数都全正确。

## Using an invariant and a termination argument
<!-- bilingual-en:end -->
*怎样使用不变量与终止论证？*

<!-- bilingual-en:start -->
An [[不变量原理|invariant]] is a statement that holds initially and survives every allowed step. It proves the required output only when it is strong enough, together with the exit condition, to imply the postcondition. In the counter example, $x+y=N$ together with $x=0$ gives $y=N$. The weaker invariant “$x,y$ are integers” does not. The full route is [[不变量与部分正确性|initialization, preservation and exit reasoning]]; an arbitrary invariant plus termination is insufficient.
<!-- bilingual-en:end -->
[[不变量原理|不变量]]是初始成立且每步都保持的陈述。只有当它足够强，能够与退出条件一起推出后置条件时，才证明了要求的输出。计数例中，$x+y=N$ 与 $x=0$ 共同给出 $y=N$，但较弱的不变量“$x,y$ 都是整数”做不到。完整路线是[[不变量与部分正确性|初始化、保持性与退出推理]]；任意不变量加终止性并不足够。

<!-- bilingual-en:start -->
In fast exponentiation with a positive real base $a$ and nonnegative integer exponent $b$, $x$ is the current base, $y$ the accumulated factor, and $z$ the remaining exponent. The register invariant is $yx^z=a^b$. If the program stops at $z=0$, this gives $y=a^b$: partial correctness. Separately, each continuing iteration changes the nonnegative integer $z$ to $\lfloor z/2\rfloor<z$, so it cannot continue forever. The brackets mean rounding down. This [[秩函数与终止证明|ranking-function argument]] is one way to prove termination; the definition of total correctness requires termination itself, not a particular proof technique. The linked cards explain the register updates and the two proofs in detail.
<!-- bilingual-en:end -->
对正实数底数 $a$、非负整数指数 $b$ 的快速幂程序，$x$ 是当前底数，$y$ 是已累积因子，$z$ 是剩余指数；寄存器不变量为 $yx^z=a^b$。若程序在 $z=0$ 时停止，就得到 $y=a^b$，这是部分正确性。另一方面，每次继续迭代都把非负整数 $z$ 变成 $\lfloor z/2\rfloor<z$，所以不可能永远继续；括号表示向下取整。这种[[秩函数与终止证明|秩函数论证]]是证明终止的一种方法；全正确性的定义要求终止本身，并不指定必须采用哪种证明技术。链接中的卡片具体解释寄存器更新与这两个证明。

## Boundaries
<!-- bilingual-en:end -->
## 边界

<!-- bilingual-en:start -->
- “Correct if it terminates” does not mean “must terminate”; a loop invariant usually establishes only the former.
- Termination alone does not guarantee correctness; a program may halt quickly with a wrong result.
<!-- bilingual-en:end -->
- “若停止则正确”不是“必定停止”；循环不变式通常只承担前一项。
- 终止本身也不保证答案正确；一个程序可以很快停下并返回错误结果。

<!-- bilingual-en:start -->
In the first statement, the invariant must support the exit reasoning just described. A proof also concerns the arithmetic and step model actually specified: exact-integer reasoning does not automatically cover machine overflow. Likewise, termination says that a run eventually ends; it does not promise a useful time bound or efficient implementation.
<!-- bilingual-en:end -->
第一条中的不变量必须支持前面说明的退出推理。证明也依赖实际规定的运算与步骤模型：精确整数上的论证，不会自动覆盖机器溢出。同样，终止只保证执行最终结束，不自动承诺实用的时间上界或高效实现。

> [!question]- What has been proved? · 已经证明了什么？
> <!-- bilingual-en:start -->
> You have proved that program $A$ always finishes, but have not checked its output. You have proved that program $B$ is correct whenever it returns, but have not proved termination. Has either been proved totally correct? **No.** The evidence for each is missing one obligation. This does not establish that either program is actually incorrect: a missing proof is not a counterexample. If an infinite permitted execution of $B$ is exhibited, however, its total correctness is disproved.
> <!-- bilingual-en:end -->
>
> 已证明程序 $A$ 总会结束，但还没检查输出；已证明程序 $B$ 若返回则结果正确，但尚未证明终止。哪一个已经被证明全正确？**都没有。**目前各缺一个证明义务，但这不代表任一程序实际上一定不正确：缺少证明不等于找到反例。不过，如果确实展示了 $B$ 的一条允许的无限执行，就否定了它的全正确性。
