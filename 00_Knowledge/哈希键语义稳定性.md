# 哈希键在表中期间必须保持哈希与相等语义稳定

<!-- bilingual-en:start -->
*A hash key's hash and equality semantics must remain stable while it is stored*
<!-- bilingual-en:end -->

> [!summary] 原子不变量
> 键被插入后，决定其哈希值和相等性的内容不能再变化。否则查找会按新状态走到另一个位置，却在旧状态决定的位置留下原条目。
>
> <!-- bilingual-en:start -->
> Once a key has been inserted, the content that determines its hash and equality must not change. Otherwise lookup follows a path chosen by the new state while the entry remains where the old state placed it.
> <!-- bilingual-en:end -->

想象一个对象按 `student_id` 哈希。它以编号 17 插入字典后，程序把编号改成 23。下一次查找先计算 23 的哈希并检查相应位置；原条目却仍留在 17 的路径上。即使遍历字典还能看见这个对象，按键查找也可能失败。这不是哈希表“忘记了”对象，而是键破坏了定位不变量。
<!-- bilingual-en:start -->
Imagine an object hashed by `student_id`. It is inserted with ID 17 and later mutated to 23. The next lookup hashes 23 and checks the corresponding path, while the entry still occupies the path selected by 17. Iteration may still reveal the object even though key lookup fails. The table has not forgotten it; the key has broken the location invariant.
<!-- bilingual-en:end -->

## Python 中的可哈希性

Python 因此不允许按内容比较的 `list` 或 `dict` 充当字典键。`tuple` 也不是无条件可哈希：只有其中每个参与哈希的元素都可哈希时才可以。自定义可变类若实现按内容的 `__eq__`，通常也不应实现 `__hash__`；若确实需要作为键，应让参与相等与哈希的身份字段不可变。
<!-- bilingual-en:start -->
Python therefore rejects content-compared `list` and `dict` objects as dictionary keys. A `tuple` is hashable only when all of the elements involved are hashable. A mutable custom class with value-based `__eq__` normally should not implement `__hash__`; if it must serve as a key, the identity fields used by equality and hashing should be immutable.
<!-- bilingual-en:end -->

稳定性也不等于“跨进程得到相同整数”。Python 的 `str` 与 `bytes` 哈希在单次进程内保持不变，但默认加入随机盐，所以重启后可能不同；内置 `hash()` 的结果不应当作可持久化标识。
<!-- bilingual-en:start -->
Stability does not mean “the same integer across processes.” Python keeps `str` and `bytes` hashes constant within one process but salts them by default, so they may differ after a restart; a built-in `hash()` result should not be used as a persistent identifier.
<!-- bilingual-en:end -->

> [!question]- 回忆与辨别
> 一个对象插入字典后仍能在遍历中看见，却再也按键找不到，最先应检查什么？
>
> **答案：** 检查插入后是否修改了参与 `__hash__` 或 `__eq__` 的字段，以及两者是否仍遵守相等键同哈希的契约。

## 来源与核验

- Python 语言参考，[`object.__hash__`](https://docs.python.org/3/reference/datamodel.html#object.__hash__)：核验哈希集合要求键的哈希值保持不变，以及可变、按值比较的类不应实现 `__hash__`。
- Python 标准库，[`dict` 映射类型](https://docs.python.org/3/library/stdtypes.html#mapping-types-dict)：核验包含列表、字典等可变且按值比较内容的对象不能作为字典键。
