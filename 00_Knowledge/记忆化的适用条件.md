# 记忆化有收益须发生重复命中且正确性要求键足以决定可复用结果

<!-- bilingual-en:start -->
*Memoization can benefit only from cache hits, while correctness requires each key to determine a reusable result*
<!-- bilingual-en:end -->

> [!summary] 原子边界
> 记忆化在第一次求出结果后，以代表这次计算状态的键保存结果；以后再次请求仍在缓存中的同一有效键时直接复用。它可能有**性能收益**，至少要真的发生缓存命中，而且省下的重算成本要超过查询、存储与保留缓存的成本；它的**正确性**则要求同一键在缓存有效期内必定对应同一个可复用结果。这是两项不同条件。命中常来自一棵调用树里的重叠子问题，也可以来自多次顶层调用，并非只能出现在递归内部。

朴素 Fibonacci 会多次计算同一个 `fib(k)`，所以按 `k` 缓存可把指数级重复压到每个 $k$ 只求一次：

```python
def fib(n, memo=None):
    """Return F_n for an integer n >= 0."""
    if memo is None:
        memo = {0: 0, 1: 1}
    if n not in memo:
        memo[n] = fib(n - 1, memo) + fib(n - 2, memo)
    return memo[n]
```

这里 `n` 足以决定数学结果，而且单次求值中会反复请求相同的 `k`；在按基本算术为单位成本计数时，每个 $k$ 只需首次求值一次。相反，如果一次普通树遍历不会再次请求同一节点或状态，而且以后也不复用这份缓存，缓存就不会减少节点访问，反而增加字典查询和内存。

“键足以决定结果”要求把所有会改变结果的上下文纳入键或固定在缓存外部。例如函数结果还依赖汇率日期、权限、随机数、可变全局配置或会变化的图，却只按一个节点编号缓存，就可能把旧上下文的答案误用到新上下文。带副作用的函数也不能因为“返回值相同”就随意跳过调用，因为副作用本身可能是契约的一部分。

还要注意两个实现边界：

- 若缓存的是可变对象并把同一个对象直接返回，调用者的原地修改会污染以后命中；可返回不可变值、复制结果或明确所有权。
- 记忆化不会自动解决循环依赖。若 `A` 在结果尚未写入缓存前又递归请求 `A`，仍可能无限递归；需要另行检测“正在计算”状态或重新建模。

> [!question]- 自检
> 路径搜索函数 `best(node)` 的结果还取决于本次禁用的边集合，却只用 `node` 作缓存键。即使不同路径会重复访问同一节点，这个缓存可靠吗？
>
> **答案：** 不可靠。同一节点在不同禁边集合下可能有不同答案；必须把足以决定结果的状态纳入键，或取消这层缓存。
