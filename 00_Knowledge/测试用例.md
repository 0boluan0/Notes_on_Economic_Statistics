# 测试用例是规定前置条件、输入或操作以及预期行为的具体检查场景
<!-- bilingual-en:start -->
*A test case specifies a concrete scenario: preconditions, inputs or actions, and expected behavior.*
<!-- bilingual-en:end -->

用例不只是“一组输入”。要能解释并重跑它，还应说明初始状态、调用或操作，以及用什么[[测试判据]]检查结果。实际结果是执行后得到的证据，不能反过来自动成为预期结果。
<!-- bilingual-en:start -->
A case is more than input data. To interpret and repeat it, identify the initial state, invocation or actions, and the [[测试判据|oracle]] used to check the result. The actual result is evidence obtained during execution, not an automatic definition of the expected result.
<!-- bilingual-en:end -->

例如，若契约规定“判断回文且不修改输入”，一个用例可以是：新建 `x = ['a', 'b']`，执行 `is_pal(x)`，检查结果是 `False`，再检查 `x` 仍为 `['a', 'b']`。后一项不是额外猜测，而是对已声明副作用边界的检查。
<!-- bilingual-en:start -->
For a contract that checks palindromes without mutating its input, one case creates `x = ['a', 'b']`, invokes `is_pal(x)`, checks for `False`, and checks that `x` is still `['a', 'b']`. The last check follows the stated mutation contract rather than inventing a new requirement.
<!-- bilingual-en:end -->

涉及共享列表时，每次重跑都要恢复所声明的起始状态，否则前一次执行留下的修改会改变下一次测试的问题。多个用例组成测试集；增加用例时应能说清它补查了哪一种行为。
<!-- bilingual-en:start -->
Restore the declared initial state before rerunning a case involving mutable lists; otherwise earlier mutations change the next experiment. A collection of cases forms a test suite, and each added case should have an identifiable testing purpose.
<!-- bilingual-en:end -->
