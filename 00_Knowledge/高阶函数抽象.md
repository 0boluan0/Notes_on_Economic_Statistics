# 高阶函数通过接收或返回函数把固定计算框架与可替换行为分开
<!-- bilingual-en:start -->
*Higher-order functions separate a fixed computational framework from replaceable behavior by accepting or returning functions*
<!-- bilingual-en:end -->

> [!summary] 原子抽象模式
> 高阶函数至少接收一个函数作为实参，或返回一个函数作为结果。它可以把稳定的遍历、重试、聚合或迭代改进框架写一次，再由传入的 predicate、transform 或 update 函数决定变化部分。抽象成立的前提是行为参数具有清楚而兼容的契约；“能传函数”本身不保证组合正确。
> <!-- bilingual-en:start -->
> A higher-order function accepts at least one function as an argument or returns a function as its result. It can write a stable traversal, retry, aggregation, or iterative-improvement framework once while a supplied predicate, transform, or update determines the varying behavior. The abstraction works only when those behavior parameters have clear, compatible contracts.
> <!-- bilingual-en:end -->

```python
def count_matching(predicate, values):
    count = 0
    for value in values:
        if predicate(value):
            count += 1
    return count
```

这里固定的是“逐项检查并计数”，可替换的是“什么算匹配”。若只出现一个一次性的简单条件，直接循环可能更清楚；高阶抽象的价值来自稳定、可命名、会重复出现的计算模式，不是把每个调用都改写得更抽象。

> [!question]- 自检
> `count_matching` 为什么不需要知道“偶数”的定义？它仍需知道传入函数的什么契约？
>
> **答案：** 偶数判断被行为参数替换；框架仍要求 predicate 能接受一个元素并返回可作真值判断的结果，且副作用符合调用者预期。
