# return 把值交给调用者而 print 只产生可见输出副作用
<!-- bilingual-en:start -->
*`return` gives a value to the caller, whereas `print` only produces a visible output side effect*
<!-- bilingual-en:end -->

> [!summary] 原子边界
> 普通函数执行 `return expression` 会结束当前调用，并让调用表达式求值为该结果；省略表达式或执行到函数体末尾则返回 `None`。`print(value)` 把文本写到输出流，但 `print` 调用本身返回 `None`。屏幕上看到了数字，不等于调用者获得了这个数字用于后续组合。
> <!-- bilingual-en:start -->
> In an ordinary function, `return expression` ends the current call and makes the call expression evaluate to that result; an empty return or reaching the end yields `None`. `print(value)` writes text to an output stream, while the `print` call itself returns `None`. Seeing a number on screen does not mean the caller received that number for further composition.
> <!-- bilingual-en:end -->

```python
def displayed_product(x, y):
    print(x * y)

result = displayed_product(3, 4)  # prints 12; result is None
```

打印可以是函数契约中有意的副作用，例如命令行界面；问题只在于把输出副作用误当作返回通道。普通函数的 `return` 规则也不能无条件外推到 generator 与 async generator：包含 `yield` 的函数具有不同的暂停和完成语义。

还要保留 `finally` 边界：若 `return` 穿过 `try/finally`，`finally` 会先执行；其中新的 `return` 或异常可以替换原先待交付的返回值。因此“`return expression` 把该值交给调用者”隐含后续没有其他控制转移覆盖它。

> [!question]- 自检
> 为什么 `print(displayed_product(3, 4))` 会先显示 `12`，再显示 `None`？
>
> **答案：** 内层函数打印 `12`，但没有显式返回值，所以调用结果是 `None`；外层 `print` 再显示这个调用结果。
