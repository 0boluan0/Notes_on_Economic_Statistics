# 最好情况复杂度是在同一规模的合法输入中取最小资源成本

<!-- bilingual-en:start -->
*Best-case complexity takes the minimum resource cost over valid inputs of the same size*
<!-- bilingual-en:end -->

固定算法、成本模型与规模，最好情况复杂度是规模为 $n$ 的合法输入中最小的资源成本。设相应输入集合为非空的 $I_n$，且最小值存在，则

<!-- bilingual-en:start -->
For a fixed algorithm, cost model and size measure, best-case complexity is the smallest resource cost among valid inputs of size $n$. For a nonempty input set $I_n$ with an attained minimum:
<!-- bilingual-en:end -->

$$
T_{\mathrm{best}}(n)=\min_{x\in I_n}T(x).
$$

逐项查找、找到即返回的线性搜索，在 $n\ge1$ 且第一个元素就是目标时只需一次相等比较。在访问与比较均为常数成本的模型下，最好时间是 $\Theta(1)$，尽管[[最坏情况复杂度]]为 $\Theta(n)$。这个最好结论取决于确有提前返回；总要扫完整个列表的实现没有同样的最好情况。

<!-- bilingual-en:start -->
A linear search that returns on a match needs one equality test when $n\ge1$ and the first element is the target. With constant-cost access and comparison, its best-case time is $\Theta(1)$ even though its [[最坏情况复杂度|worst-case time]] is $\Theta(n)$. This relies on early return; an implementation that always scans the entire list does not have the same best case.
<!-- bilingual-en:end -->

最好情况不代表通常性能。它也不等同于 [[大Ω记号]]：$\Omega$ 表示对已经选定的成本函数取渐近下界，可用于最好、最坏或平均成本中的任何一个。

<!-- bilingual-en:start -->
Best-case cost does not describe typical performance. Nor is it synonymous with [[大Ω记号|Big-Omega]], which gives an asymptotic lower bound on an already selected cost function—best, worst, or average.
<!-- bilingual-en:end -->
