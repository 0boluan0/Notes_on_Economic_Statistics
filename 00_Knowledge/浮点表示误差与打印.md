# 十进制输入的表示误差与打印舍入不是同一件事

<!-- bilingual-en:start -->
*Decimal input representation error is different from display rounding*
<!-- bilingual-en:end -->

> [!summary] 原子区分
> **表示误差**发生在十进制目标值不能被目标二进制格式精确编码时；解析器只能保存一个邻近的二进制有理数。**打印舍入**发生在把已经保存的机器值转换成便于阅读的十进制字符串时。后者改变显示，不会改变内存中的值，也不能修复前者。
>
> <!-- bilingual-en:start -->
> **Representation error** occurs when a target decimal value cannot be encoded exactly in the destination binary format, so parsing stores a nearby binary rational. **Display rounding** occurs later, when that stored machine value is converted to a readable decimal string. Formatting changes the display, not the stored value, and cannot repair representation error.
> <!-- bilingual-en:end -->

在大多数使用 binary64 的 Python 平台上，字面量 `0.1` 保存的精确值是

```text
3602879701896397 / 2**55
```

它略大于数学上的 $1/10$。Python 通常打印最短、又能往返恢复同一浮点值的字符串 `0.1`；这不表示内存里真的存了十进制 $1/10$。可用 `x.as_integer_ratio()` 或 `x.hex()` 检查保存值，而 `format(x, '.2f')` 只决定输出样式。
<!-- bilingual-en:start -->
On most Python platforms using binary64, the exact stored value of the literal `0.1` is `3602879701896397 / 2**55`, slightly larger than mathematical $1/10$. Python normally prints the shortest decimal string that round-trips to the same float, namely `0.1`; this does not mean that decimal $1/10$ was stored. `x.as_integer_ratio()` or `x.hex()` exposes the stored value, whereas `format(x, '.2f')` only controls presentation.
<!-- bilingual-en:end -->

如果业务需要精确十进制金额或精确有理运算，应选择满足该语义的 `decimal.Decimal`、整数最小单位或 `fractions.Fraction`；增加打印位数只是诊断手段，不是更换数值模型。
<!-- bilingual-en:start -->
If the domain requires exact decimal money or exact rational arithmetic, choose a representation with that contract, such as `decimal.Decimal`, integer minor units, or `fractions.Fraction`. Printing more digits is a diagnostic aid, not a change of numerical model.
<!-- bilingual-en:end -->

> [!question]- 回忆与应用
> 把 `0.1` 格式化成 30 位小数，是否提高了后续计算精度？
>
> **答案：** 没有。格式化只生成字符串；原浮点值与它已经包含的表示误差不变。
