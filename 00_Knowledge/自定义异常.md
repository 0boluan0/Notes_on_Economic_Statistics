# 自定义异常是为调用者需要区分的失败情形定义的异常类型

<!-- bilingual-en:start -->
*A user-defined exception is an exception type for a failure condition that callers need to distinguish*
<!-- bilingual-en:end -->

自定义异常是程序自己定义的异常类，用来给特定失败情形提供可按类型识别的名字。一般从 `Exception` 或合适的现有异常类派生；当调用者需要区分某种领域失败，而现有类型不足以表达这个区别时，再增加新类型。消息不同本身不必产生新类。

<!-- bilingual-en:start -->
A user-defined exception is a class created by a program to give a particular failure a type-based identity. Usually it derives from `Exception` or an appropriate existing exception class. Add a new type when callers need a domain distinction that existing types do not express; different messages alone do not require different classes.
<!-- bilingual-en:end -->

```python
class MissingGradeError(Exception):
    pass

def require_grades(grades):
    if not grades:
        raise MissingGradeError("no grades were recorded")
    return grades
```

调用者可用 `except MissingGradeError:` 单独处理缺失成绩，或用 `except Exception:` 覆盖它与其他普通异常。类层级应反映调用者需要区别的失败，而不是“在哪个函数出错”。直接派生 `BaseException` 会绕开普通 `Exception` 处理器，通常不适合业务失败；若无需新类型，已有 `ValueError` 可能已满足契约。

<!-- bilingual-en:start -->
Callers can handle missing grades specifically with `except MissingGradeError:`, or include them with other ordinary exceptions under `except Exception:`. The hierarchy should reflect useful failure distinctions, not merely which function raised them. Directly deriving from `BaseException` bypasses ordinary `Exception` handlers and is generally unsuitable for domain failures. When no new distinction is needed, an existing type such as `ValueError` may already satisfy the contract.
<!-- bilingual-en:end -->
