# 主键以唯一且非空的属性组合标识一行

<!-- bilingual-en:start -->
*A primary key identifies a row with a unique, non-null set of attributes*
<!-- bilingual-en:end -->

> [!summary] 原子定义
> 主键是被选作表中行身份的一列或一组列。其取值组合必须唯一且非空；复合主键要求组合唯一，不要求其中每一列单独唯一。
>
> <!-- bilingual-en:start -->
> A primary key is the column or set of columns chosen as the identity of a table row. Its value combination must be unique and non-null. A composite key requires uniqueness of the combination, not of each component by itself.
> <!-- bilingual-en:end -->

若 `order_items` 的一行表示某订单中的某个商品，可用 `(order_id, product_id)` 作复合主键。同一个 `order_id` 可以出现多次，同一个 `product_id` 也可以出现多次，但同一组合不能重复。若一个订单允许同一商品出现多条独立行，真实粒度已经更细，主键也应加入 `line_number` 或独立行标识。
<!-- bilingual-en:start -->
If one `order_items` row represents a product within an order, `(order_id, product_id)` may be a composite primary key. Each component may repeat, but the pair may not. If a product may occupy several independent lines in one order, the real grain is finer and the key must include a `line_number` or another line identifier.
<!-- bilingual-en:end -->

主键声明不仅建立约束，也把“哪组属性构成行身份”写进模式。它与 `UNIQUE` 加 `NOT NULL` 在允许的数据上可能接近，但一张表只能选一个主键作为主要身份，仍可为其他候选键分别声明唯一且非空的约束。只写普通 `UNIQUE` 时，PostgreSQL 默认允许多个 `NULL`，因此它未必已经表达了一个始终存在的候选身份。
<!-- bilingual-en:start -->
A primary-key declaration both enforces a constraint and records which attributes constitute row identity. It may accept the same data as `UNIQUE` plus `NOT NULL`, but a table selects only one primary key while separately enforcing other candidate keys as unique and non-null. A plain PostgreSQL `UNIQUE` constraint permits multiple nulls by default, so it does not necessarily express an identity that is always present.
<!-- bilingual-en:end -->

> [!question]- 回忆与辨别
> 复合主键 `(student_id, course_id)` 是否意味着每个学生只能选一门课？
>
> **答案：** 不意味着。它只禁止同一学生—课程组合重复；`student_id` 和 `course_id` 各自仍可出现多次。
