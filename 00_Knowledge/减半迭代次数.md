# Counting halving iterations
<!-- bilingual-en:end -->

*减半迭代次数*

<!-- bilingual-en:start -->
Repeated halving asks how many updates are needed to shrink an integer to a stopping value. Each update removes roughly one binary digit, so the count grows slowly: doubling the starting number adds about one update. To get an exact answer, specify both the rounding rule and when the loop stops. Here the [[输入规模|input size parameter]] is the nonnegative integer value $n$.
<!-- bilingual-en:end -->

反复减半要回答的是：把一个整数缩小到停止值，需要执行多少次更新。每次更新大约去掉一个二进制位，所以次数增长很慢：起始数字翻倍，大约只增加一次更新。要得到精确答案，必须同时说清取整规则和停止条件。本卡以非负整数的数值 $n$ 作为 [[输入规模]]。

<!-- bilingual-en:start -->
## Count updates, not displayed states
<!-- bilingual-en:end -->

## 数更新次数，而不是状态个数

```python
m = n
updates = 0
while m > 0:
    m //= 2
    updates += 1
```

<!-- bilingual-en:start -->
Assume $n$ is an integer with $n\ge0$, and interpret division exactly. The operator `// 2` rounds down; `updates` counts executions of the body. The final failed guard test is a check, not another update.
<!-- bilingual-en:end -->

假设 $n$ 是满足 $n\ge0$ 的整数，并按精确整数运算理解除法。`// 2` 向下取整；`updates` 数的是循环体执行次数，最后一次不成立的条件检查不算额外更新。

<!-- bilingual-en:start -->
The notation [[大Θ记号|$\Theta(g(n))$]] describes growth trapped between fixed positive multiples of $g(n)$ for sufficiently large $n$. It gives a growth scale rather than an exact count. A one-sided [[大O记号|$O$ upper bound]] need not be tight.
<!-- bilingual-en:end -->

[[大Θ记号|$\Theta(g(n))$]] 表示当 $n$ 足够大时，增长量被 $g(n)$ 的两个固定正倍数夹住；它描述增长尺度，不是精确次数。单侧的 [[大O记号|$O$ 上界]] 未必紧确。

<!-- bilingual-en:start -->
Starting from integer $m_0=n\ge1$, repeatedly apply $m_{t+1}=\lfloor m_t/2\rfloor$ while $m_t>0$. The exact iteration count is $\lfloor\log_2 n\rfloor+1$; it is zero for $n=0$. This counts iterations, not unconditional running time.
<!-- bilingual-en:end -->

从整数 $m_0=n\ge1$ 开始，只要 $m_t>0$ 就执行一次 $m_{t+1}=\lfloor m_t/2\rfloor$，总迭代次数恰为 $\lfloor\log_2 n\rfloor+1$。若 $n=0$ 则执行零次。该结论数的是迭代次数，不是无条件的运行时间。

<!-- bilingual-en:start -->
Since $m_t=\lfloor n/2^t\rfloor$, reaching zero first means finding the least integer $t$ with $2^t>n$. This gives the expression above and asymptotic count $\Theta(\log(n+1))$. For $n=8$, the states are $8,4,2,1,0$, requiring four updates. Stopping at $m\le1$ changes the exact count.
<!-- bilingual-en:end -->

因为 $m_t=\lfloor n/2^t\rfloor$，第一次变为零等价于 $2^t>n$，所以最小整数 $t$ 就是上述表达式，渐近为 $\Theta(\log(n+1))$。例如 $n=8$ 时状态是 $8,4,2,1,0$，执行四次更新。若终止条件改为 $m\le1$，精确次数也会改变，不能原样套用。

<!-- bilingual-en:start -->
Uniformly $\Theta(1)$ work per iteration is sufficient to infer logarithmic time directly from logarithmically many iterations. [[二分查找|Binary search]] uses this mechanism under constant-time random access and comparison. Copying the current interval on each round requires [[循环成本求和|summing loop costs]] or a [[分治成本模型|divide-and-conquer cost model]]; see [[切片二分成本|slicing binary-search costs]].
<!-- bilingual-en:end -->

若每轮总工作为统一的 $\Theta(1)$，则可直接由对数轮数推出对数时间；这是一个充分的成本条件。[[二分查找]]在常数时间随机访问与比较模型下使用这个机制；若每轮复制当前区间，必须改用[[循环成本求和]]或[[分治成本模型]]，具体见[[切片二分成本]]。

## Why the floor formula survives every update
<!-- bilingual-en:end -->

## 为什么每轮取整仍可合成一个公式

<!-- bilingual-en:start -->
For a nonnegative real $u$, write $\lfloor u\rfloor=2q+r$, with $r\in\{0,1\}$. Then $2q+r\le u<2q+r+1$, so $q\le u/2<q+1$ and $\lfloor\lfloor u\rfloor/2\rfloor=\lfloor u/2\rfloor$. This identity proves $m_t=\lfloor n/2^t\rfloor$ by induction. For $n\ge1$, let $k=\lfloor\log_2 n\rfloor$, meaning $2^k\le n<2^{k+1}$. After $k$ updates the state is 1; one more update gives 0.
<!-- bilingual-en:end -->

对非负实数 $u$，写成 $\lfloor u\rfloor=2q+r$，其中 $r\in\{0,1\}$。由 $2q+r\le u<2q+r+1$ 得到 $q\le u/2<q+1$，因此 $\lfloor\lfloor u\rfloor/2\rfloor=\lfloor u/2\rfloor$。这个恒等式用归纳法证明 $m_t=\lfloor n/2^t\rfloor$。对 $n\ge1$，令 $k=\lfloor\log_2 n\rfloor$，即 $2^k\le n<2^{k+1}$；执行 $k$ 次后状态是 1，再执行一次才到 0。

> [!example] Four updates, five states · 四次更新，五个状态
> <!-- bilingual-en:start -->
> For $n=8$, the states are $8\to4\to2\to1\to0$. There are five states but four arrows. For $n=1$, the only update is $1\to0$; for $n=0$, the initial guard is already false.
> <!-- bilingual-en:end -->
>
> 当 $n=8$ 时有 $8\to4\to2\to1\to0$：五个状态、四个箭头。$n=1$ 时只更新一次 $1\to0$；$n=0$ 时初始条件已经不成立。

<!-- bilingual-en:start -->
If the same floor-halving update instead runs only while `m > 1`, the count is $\lfloor\log_2 n\rfloor$ for $n\ge1$, and zero for $n=0$. Changing the stopping test has removed the final $1\to0$ update. A [[二分查找|binary-search implementation]] may also discard the tested midpoint; its own interval recurrence determines its exact count.
<!-- bilingual-en:end -->

若更新仍是向下取整减半，但条件改成 `m > 1`，则 $n\ge1$ 时恰为 $\lfloor\log_2 n\rfloor$ 次，$n=0$ 时仍是零次；改变条件后，最后的 $1\to0$ 更新被删掉了。[[二分查找]]的实现还可能同时丢弃刚检查的中点，精确次数应由它自己的区间递推决定。

<!-- bilingual-en:start -->
The unit-cost assumption is a [[算法成本模型|cost-model choice]]. Python integers can grow beyond a machine word, so the theorem alone does not prove that division, comparison or copying a large integer is constant-time. The count remains exact even when the time assigned to each update changes.
<!-- bilingual-en:end -->

常数成本是假定的 [[算法成本模型]]。Python 整数可以超过一个机器字，因此本定理本身不能证明大整数的除法、比较或复制都花常数时间；即使每轮所计时间改变，更新次数仍然准确。
