# 递归定义必须给出基本情况和由较小同类实例构造答案的递归步骤

<!-- bilingual-en:start -->
*A recursive definition needs base cases and recursive cases that build the answer from smaller instances of the same kind*
<!-- bilingual-en:end -->

> [!summary] 原子定义
> 只看到“函数体里出现自己的名字”还不足以得到一份可用的递归规格。规格要用两类规则完整描述约定输入域：**基本情况**直接给出无需再递归的实例答案；**递归步骤**把其余实例化成一个或多个沿良基关系更小的同类实例，再说明怎样用子结果构造当前答案。基本情况回答“在哪里直接停下”，递归步骤回答“较小问题的答案怎样成为当前问题的答案”。

以有限嵌套列表求和为例，可以把输入域定义成“数，或由同类对象组成的有限列表”：

```python
def nested_sum(value):
    if isinstance(value, (int, float)):
        return value
    return sum(nested_sum(item) for item in value)
```

数字是直接可解的基本情况；列表分支逐个求子对象的和，再把子结果相加。空列表也被列表分支覆盖，因为 `sum([]) == 0`。这里稳定的是数据定义与组合规则，不是某一种 Python 写法。

有几个容易混淆的边界：

- 基本情况可以有多个，递归步骤也可以产生多个子调用；关键是它们共同覆盖约定的输入域。
- “调用了更小输入”只说明有递归形状；若当前层漏掉必要工作，函数仍会终止却算错。例如查找列表时只递归检查尾部而不检查头元素。
- 递归定义本身不自动证明程序终止。还要单独证明每条递归路径都沿一个良基关系下降。
- 对自引用容器或无限惰性结构，上面的“有限嵌套列表”前提不再成立，不能照搬这份终止论证。

> [!question]- 自检
> 一个函数对 `n == 0` 返回 0，其余情况直接返回 `f(n - 1)`，却没有把当前的 `n` 纳入结果。它已经是正确的递归求和了吗？
>
> **答案：** 不是。它有基本情况，也会在非负整数上终止，但递归步骤没有说明如何由较小问题的答案构造当前总和；它最终对所有输入都返回 0。
