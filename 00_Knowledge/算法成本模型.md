# 算法成本模型规定计数的资源单位及基本操作的成本

<!-- bilingual-en:start -->
*A cost model specifies resource units and the costs of primitive operations*
<!-- bilingual-en:end -->

算法成本模型规定分析中计量什么资源、把什么当作基本操作，以及每项操作收取多少成本。只有模型与[[输入规模]]明确后，“执行一步”或“常数时间”才有确定含义；一行程序可以包含多个操作或一次随输入增长的操作。

<!-- bilingual-en:start -->
A cost model specifies the resource being measured, the primitive operations, and the cost charged to each. “One step” and “constant time” become meaningful only after the model and [[输入规模|input size]] are fixed. One source-code line may perform several operations or one operation whose cost grows with the input.
<!-- bilingual-en:end -->

例如，字长为 $w$ 的 word-RAM 模型可把模型规定的、作用于常数个机器字的算术、比较与内存访问计为 $O(1)$；寻址 $n$ 个位置通常要求 $w\ge\lceil\log_2 n\rceil$。这不意味着任意长整数乘法也只花一步。Python 整数的表示长度会增长；若按位操作计费，就必须把长度及相应算术成本纳入分析。

<!-- bilingual-en:start -->
For example, a word-RAM with word length $w$ may charge $O(1)$ for its specified arithmetic, comparisons and memory accesses on a constant number of words. Addressing $n$ locations normally requires $w\ge\lceil\log_2 n\rceil$. This does not make multiplication of arbitrarily large integers a single constant-cost step. Python integers can grow in representation length; a bit-cost analysis must include that length and the corresponding arithmetic costs.
<!-- bilingual-en:end -->

同样，列表索引、切片、成员测试与扩容不能凭语法都记为一步。若切片复制 $k$ 个固定大小引用，其复制工作为 $\Theta(k)$；一次列表成员测试要计算实际检查了多少元素及每次相等比较的成本。动态容器还要区分单次操作的最坏成本与[[摊还复杂度]]。

<!-- bilingual-en:start -->
Likewise, syntax alone does not make indexing, slicing, membership tests and resizing unit-cost operations. Copying a slice of $k$ fixed-size references takes $\Theta(k)$ copying work. List membership requires counting the examined elements and the cost of each equality test. Dynamic containers also require distinguishing a single operation's worst-case cost from [[摊还复杂度|amortized complexity]].
<!-- bilingual-en:end -->
