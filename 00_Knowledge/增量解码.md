# 增量解码复用前缀状态并以前一个已选 token 计算下一个 token 的分布

<!-- bilingual-en:start -->
*Incremental decoding reuses prefix state and processes the previously selected token to predict the next one*
<!-- bilingual-en:end -->

**增量解码**（incremental decoding）是在已有前缀状态上继续生成的过程。对使用 [[KV cache]] 的标准 decoder-only 自回归路径，每一步只把尚未处理的最新 token 作为新输入，计算它的逐层状态，并用它的最终表示预测下一个 token。新输入的 KV 在本步加入缓存；本步刚选出的输出要到下一步才成为输入。

<!-- bilingual-en:start -->
**Incremental decoding** continues generation from an existing prefix state. In standard decoder-only autoregressive generation with a [[KV cache|KV cache]], each step processes the latest unprocessed token, computes its layer-wise state, and uses its final representation to predict the next token. The input token's KV is added during this step; the newly selected output becomes an input only in the next step.
<!-- bilingual-en:end -->

## 三个输出需要几次后续前向

<!-- bilingual-en:start -->
*How many subsequent forward passes produce three outputs?*
<!-- bilingual-en:end -->

提示为 $x_1,x_2,x_3$，输出为 $y_1,y_2,y_3$。以下缓存长度在该行计算与 token 选择完成后读取；假设没有裁剪、驱逐或提前缓存命中。

<!-- bilingual-en:start -->
Let the prompt be $x_1,x_2,x_3$ and the outputs be $y_1,y_2,y_3$. Cache lengths below are measured after each computation and token selection, with no truncation, eviction, or prefix-cache hit.
<!-- bilingual-en:end -->

| 操作 | 新输入 | 本次选择的输出 | 已计算 KV 的位置 |
|---|---|---|---|
| [[预填充]] | $x_1,x_2,x_3$ | $y_1$ | $x_1,x_2,x_3$：3 个 |
| 第 1 次增量前向 | $y_1$ | $y_2$ | 提示与 $y_1$：4 个 |
| 第 2 次增量前向 | $y_2$ | $y_3$ | 提示与 $y_1,y_2$：5 个 |

<!-- bilingual-en:start -->
Prefill selects $y_1$ while caching three prompt positions. Processing $y_1$ selects $y_2$ and grows the cache to four positions. Processing $y_2$ selects $y_3$ and grows it to five. The final selected token $y_3$ has not yet acquired KV state.
<!-- bilingual-en:end -->

因此，提示长 $P$、实际生成 $N\ge1$ 个 token 时，基本路径是一次预填充，加 $N-1$ 次增量前向。刚选择最后输出而尚未继续前向时，缓存包含 $P+N-1$ 个位置。若 $N=1$，预填充已完成所需预测，没有后续增量前向。

<!-- bilingual-en:start -->
For prompt length $P$ and $N\ge1$ generated tokens, the basic path consists of one prefill followed by $N-1$ incremental forward passes. Immediately after selecting the final output, the cache contains $P+N-1$ processed positions. If $N=1$, prefill already supplies the required prediction, with no subsequent incremental forward pass.
<!-- bilingual-en:end -->

## 计算时间与请求时间

<!-- bilingual-en:start -->
*Computation time and request time*
<!-- bilingual-en:end -->

令 $C_{\mathrm{pf}}(P)$ 表示预填充及首次选择耗时，$C_{\mathrm{inc}}(P+j)$ 表示追加第 $j$ 个输出作为输入后、总上下文为 $P+j$ 的一次前向及选择耗时。只对这条顺序计算路径求和得到

<!-- bilingual-en:start -->
Let $C_{\mathrm{pf}}(P)$ include prefill and first-token selection. Let $C_{\mathrm{inc}}(P+j)$ include one forward pass and selection after adding output $j$ as an input, giving context length $P+j$. Summing only this sequential computation path gives
<!-- bilingual-en:end -->

$$
C_{\mathrm{model}}
=C_{\mathrm{pf}}(P)+\sum_{j=1}^{N-1}C_{\mathrm{inc}}(P+j).
$$

这个式子没有自动计入排队、传输或步骤之间的调度停顿；用户等待由[[请求完成延迟]]的实际事件边界测量。[[首Token延迟]]和[[Token间隔]]分别观察首输出之前与后续输出之间的等待。

<!-- bilingual-en:start -->
This sum does not automatically include queueing, transmission, or scheduling gaps between steps. User waiting is measured through the event boundaries of [[请求完成延迟|request completion latency]]. [[首Token延迟|Time to first token]] and [[Token间隔|inter-token latency]] distinguish the initial wait from subsequent gaps.
<!-- bilingual-en:end -->

这里的 $N$ 必须说明是否计入 EOS 或被接口隐藏的停止 token。一次验证可以接受多个候选的 speculative decoding、多个分支的 beam search 不遵守本卡“一次后续前向选择一个输出”的计算次数；它们需另列执行时间轴。

<!-- bilingual-en:start -->
The count $N$ must specify whether it includes EOS or stop tokens hidden by the API. Speculative decoding can accept several candidates in one verification, while beam search manages multiple branches. Their execution counts require separate timelines rather than the one-output-per-forward baseline used here.
<!-- bilingual-en:end -->

## 来源与核验

<!-- bilingual-en:start -->
*Sources and verification*
<!-- bilingual-en:end -->

- [Kwon et al. (2023), PagedAttention](https://arxiv.org/html/2309.06180v1#S2.SS2)，§2.2：支持增量阶段以 $x_{n+t}$ 预测 $x_{n+t+1}$，仅新增当前输入位置的 KV。$N-1$ 与缓存长度由该索引关系直接推出。
  <!-- bilingual-en:start -->
  Section 2.2 specifies prediction of $x_{n+t+1}$ from input $x_{n+t}$ while adding only the current input's KV. The $N-1$ count and cache lengths follow from this indexing.
  <!-- bilingual-en:end -->
- [Hugging Face Transformers v4.57.1, Caching](https://huggingface.co/docs/transformers/v4.57.1/cache_explanation)，Attention matrices、Cache storage implementation 中的生成循环：核对最后位置 logits 选出的 token 成为下一轮输入，而非本轮已缓存位置。
  <!-- bilingual-en:start -->
  The attention explanation and generation loop verify that the token selected from the final logits becomes the next iteration's input rather than an already cached position.
  <!-- bilingual-en:end -->
