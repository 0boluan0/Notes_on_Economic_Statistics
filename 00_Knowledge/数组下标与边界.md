# 数组下标等价于指针加法再解引用且不提供边界检查
<!-- bilingual-en:start -->
*Array subscripting is pointer addition followed by indirection, and it performs no bounds check*
<!-- bilingual-en:end -->

> [!summary] 等价式与前提
> C 把 `E1[E2]` 定义为 `*((E1) + (E2))`：一边必须是指向完整对象类型的指针，另一边必须是整数。数组表达式通常先转换为首元素指针，整数再按元素而不是按原始字节移动，最后 `*` 访问目标元素。语法等价式没有携带数组长度，也不会自动检查索引。
> <!-- bilingual-en:start -->
> C defines `E1[E2]` as `*((E1) + (E2))`: one operand is a pointer to a complete object type and the other is an integer. An array expression normally converts to its first-element pointer, pointer addition selects an element, and `*` accesses it. No length or automatic bounds check is added.
> <!-- bilingual-en:end -->

```c
int subscript_example(void) {
    int a[4] = {10, 20, 30, 40};
    int x = a[2];       // 等价于 *(a + 2)，得到 30
    int *mid = &a[2];
    int y = mid[-1];    // 等价于 *(mid - 1)，仍在同一数组内，得到 20
    return x + y;
}
```

合法范围由基准指针所关联的真实数组对象决定，而不是由索引是否“看起来非负”决定。对首元素指针 `a`，可访问元素是 `a[0]` 到 `a[3]`；`a[4]` 会试图解引用 one-past 指针，行为未定义。相反，从数组中部开始的 `mid[-1]` 仍落在同一数组内，所以可以成立。
<!-- bilingual-en:start -->
The real array object, not the apparent sign of the index, determines validity. From the first-element pointer, `a[0]` through `a[3]` are accessible; `a[4]` attempts to dereference a one-past pointer and is undefined. A negative index from a middle pointer can remain within the same array.
<!-- bilingual-en:end -->

函数接收 `const int *values, size_t n` 时，`values[i]` 的类型可以完全正确，但调用契约仍必须保证至少有 `n` 个可读元素，并让循环只取 `0 <= i < n`。编译成功最多证明表达式类型可组合，不能证明长度实参与真实对象一致。
<!-- bilingual-en:start -->
For a function receiving `const int *values, size_t n`, the type of `values[i]` may be correct while the call is still invalid. The contract must provide at least `n` readable elements and restrict access to `0 <= i < n`; compilation cannot prove that the length matches the object.
<!-- bilingual-en:end -->

> [!question]- 最小自检
> 长度为 4 的数组为什么能形成 `a + 4`，却不能读取 `a[4]`？
>
> **答案：** `a + 4` 是允许形成的末尾后一位指针；`a[4]` 还会按定义对它求 `*`，而 one-past 指针不能解引用。
