# 回归测试在程序修改后重新检查既有行为以发现新引入或再次出现的缺陷
<!-- bilingual-en:start -->
*Regression testing rechecks existing behavior after a change to detect newly introduced or recurring defects.*
<!-- bilingual-en:end -->

回归描述测试的目的，不是一个与[[单元测试]]、[[集成测试]]并列的层级。单个函数的检查和多组件的检查，都可以在后续修改后作为回归测试重跑。
<!-- bilingual-en:start -->
Regression describes a purpose, not a level alongside [[单元测试|unit]] and [[集成测试|integration testing]]. Checks of either individual functions or combined components can be rerun for regression protection.
<!-- bilingual-en:end -->

修复回文函数把所有列表都判断为回文的问题时，保留 `['a', 'b']` 应返回 `False` 的失败例，也继续运行 `['a', 'b', 'a']` 应返回 `True` 的既有检查。只把实现改成“永远返回 `False`”会让前者通过，却破坏后者。
<!-- bilingual-en:start -->
After fixing a palindrome checker that accepts every list, retain the failing case `['a', 'b']`, which should produce `False`, and rerun the existing case `['a', 'b', 'a']`, which should produce `True`. Replacing the implementation with “always return `False`” passes the first but breaks the second.
<!-- bilingual-en:end -->

若需求本身改变，应先审查哪些旧期望仍然有效；回归保护的是仍然承诺的行为，不是把旧实现的每个偶然输出永久冻结。自动化便于重跑，但不能代替对判据有效性的检查。
<!-- bilingual-en:start -->
When requirements change, review which old expectations remain valid. Regression protects behavior that is still promised, not every accidental output of the old implementation. Automation makes rerunning easier but does not validate the oracle itself.
<!-- bilingual-en:end -->
