# 用sort与uniq统计文本频数时先聚拢完整值再计数排名

<!-- bilingual-en:start -->
*A sort-and-uniq frequency workflow groups complete values before counting and ranking them*
<!-- bilingual-en:end -->

若输入已经满足“一行一个完整值，值内没有换行”的契约，可以先排序使相同值相邻，再用 `uniq -c` 计算频数。最后再按计数排序是另一项职责；第一次排序解决分组，第二次排序解决展示或排名。

<!-- bilingual-en:start -->
For input satisfying the contract of one complete value per line with no embedded newline, sorting first makes equal values adjacent, and `uniq -c` computes their frequencies. Sorting the counts afterward serves a separate purpose: the first sort establishes groups, while the second determines display or ranking order.
<!-- bilingual-en:end -->

```bash
(
    export LC_ALL=C
    printf '%s\n' 'alice smith' 'bob jones' 'alice smith' 'amy lee' |
        sort |
        uniq -c |
        sort -k1,1nr -k2
)
```

结果依次是 `alice smith` 出现 `2` 次、`amy lee` 出现 `1` 次、`bob jones` 出现 `1` 次。第二次排序只把第一字段当作降序数值键；`-k2` 把其余整段作为升序文本次键，因此同频时顺序明确，名字中的空格仍被保留。计数输出的前导空白不属于名字。

<!-- bilingual-en:start -->
The result reports `alice smith` with count `2`, then `amy lee` and `bob jones` with count `1` each. The final sort uses only the first field as a descending numeric key; `-k2` uses the remaining text as an ascending secondary key. Frequency ties therefore have an explicit order, and spaces within names remain intact. Leading count padding is not part of the name.
<!-- bilingual-en:end -->

此例的名字没有前导空白；如果下游要再提取完整值，不能简单只取第二字段。应按已知计数输出格式剥去计数前缀，或直接使用能保留独立“键—计数”字段的表示。取前若干名还需说明同频边界政策：固定输出若干行与保留截止频数的全部并列项不是同一目标。

<!-- bilingual-en:start -->
Names in this example have no leading whitespace. A downstream stage extracting complete values must not simply take the second field: remove the count prefix according to its known format, or use a representation that keeps key and count as distinct fields. A top-k result also needs a tie policy: returning a fixed number of rows differs from retaining every item tied at the cutoff frequency.
<!-- bilingual-en:end -->

频数只描述实际送入管道的记录；若上游只传了样本，结果就是样本频数，不能当成全量统计。输入筛选、坏记录处理和整个管道的成功状态都属于结果可信度的前提。

<!-- bilingual-en:start -->
Frequencies describe only records actually supplied to the pipeline. If the input is a sample, the result is a sample frequency table, not a full-population count. Input selection, malformed-record handling, and successful completion of the complete pipeline are prerequisites for trusting the result.
<!-- bilingual-en:end -->
