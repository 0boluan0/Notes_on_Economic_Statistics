# 伪随机复现要求固定生成器算法、初始化方式与随机调用协议，并验证所用软件实现的流兼容条件
<!-- bilingual-en:start -->
*Pseudorandom reproducibility requires a fixed generator algorithm, initialisation, and random-call protocol together with verified stream-compatibility conditions for the software implementation*
<!-- bilingual-en:end -->

> [!summary] seed 只是重放协议的一部分
> 相同 seed 只有在生成算法、初始化规则、调用数量与顺序、并行分流，以及软件声明的流兼容条件都满足时，才足以重放同一伪随机流；固定 seed 本身不验证模型或程序正确。
> <!-- bilingual-en:start -->
> Reusing a seed reproduces a stream only when the generator, initialisation, number and order of calls, parallel-stream allocation, and the implementation's documented compatibility conditions all match. A fixed seed does not validate the model or program.
> <!-- bilingual-en:end -->

一份可重放记录至少应包含：

- bit generator 或 PRNG 算法及初始化参数；
- 库、语言和相关生成器版本；
- 使用了哪些分布变换，以及调用的数量与顺序；
- 并行 worker 如何从根状态获得子流；
- 会改变状态消耗或结果汇总的输入顺序与数值环境。

<!-- bilingual-en:start -->
A replay record should identify the bit generator and initialisation, relevant software versions, distribution-transform calls and their order, parallel substream allocation, and any input or numerical ordering that changes state consumption or aggregation.
<!-- bilingual-en:end -->

某些库只承诺底层均匀输出在兼容 seeder 下保持一致，不保证每个高层分布函数跨版本逐位相同。即使随机位完全相同，浮点归约或任务调度顺序变化也可能改变最终结果。
<!-- bilingual-en:start -->
Some libraries guarantee compatibility only for a core uniform stream, not every high-level distribution transform. Identical random bits can still lead to different final values when floating-point reduction or scheduling order changes.
<!-- bilingual-en:end -->

在 Python 的兼容 seeder 与 `random()` 承诺下，下面两个对象以同一 seed 开始并遵守相同调用顺序，所以输出相同：

```python
import random

a = random.Random(7)
b = random.Random(7)

assert [a.random(), a.random()] == [b.random(), b.random()]
```

若让 `b` 先多调用一次，随后比较的是序列中的不同位置：

```python
a = random.Random(7)
b = random.Random(7)
_ = b.random()
assert a.random() != b.random()
```

<!-- bilingual-en:start -->
The self-check demonstrates replay under a compatible core generator and identical call protocol. One extra call advances the state, so later position-by-position outputs no longer match.
<!-- bilingual-en:end -->

> [!question]- 可核验自检
> 两次运行 seed 相同，但一次在中途新增了一个随机抽样的诊断步骤。能否期待后续路径逐条相同？
>
> **答案：** 不能。新增调用改变了状态消耗顺序；除非诊断使用独立子流或恢复相同状态协议。
> <!-- bilingual-en:start -->
> No. The extra random call changes state consumption unless the diagnostic uses a separate substream or the original state protocol is restored.
> <!-- bilingual-en:end -->

## 来源与核验

- Python Software Foundation, [`random` — Generate pseudo-random numbers, “Notes on Reproducibility”](https://docs.python.org/3/library/random.html#notes-on-reproducibility)：核对兼容 seeder、核心 `random()` 序列与多线程边界。
- NumPy Developers, [Random Generator compatibility policy](https://numpy.org/doc/stable/reference/random/compatibility.html)：核对 bit generator、软件 build 与跨版本逐位兼容边界。
