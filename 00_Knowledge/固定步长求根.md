# Fixed-step root search
<!-- bilingual-en:end -->

*固定步长求根*

<!-- bilingual-en:start -->
Imagine looking for a zero of a function by marking equally spaced numbers on a number line and testing those marks in order. **Fixed-step root search** does exactly that: it chooses a finite set of candidate inputs before seeing their function values. It is an application of [[枚举验证|exhaustive verification]], whose conclusion is limited to the candidates actually covered. The quantity tested is the [[求根残差|residual]] $|f(x)|$: how much of the equation $f(x)=0$ remains unsatisfied when $x$ is substituted.
<!-- bilingual-en:end -->

想象在数轴上每隔一段距离画一个刻度，再依次检查这些刻度是不是方程的近似解。**固定步长求根**就是这样做的：它先选好有限个候选输入，再计算函数值。这是 [[枚举验证]] 的一种应用，结论只能覆盖实际检查的候选。检查的量是 [[求根残差|残差]] $|f(x)|$，也就是把 $x$ 代回 $f(x)=0$ 后还剩多大的方程缺口。

<!-- bilingual-en:start -->
Fixed-step root search specifies an interval $[a,b]$, a step $h>0$, and a residual tolerance $\tau>0$, generates a finite grid from $a$ at spacing $h$, and checks $|f(x)|\le\tau$ point by point. The first grid point that passes is an acceptable candidate; if the grid is exhausted without one, the algorithm must return an explicit no-hit status.
<!-- bilingual-en:end -->

固定步长求根先给定搜索区间 $[a,b]$、步长 $h>0$ 和残差容差 $\tau>0$，再从 $a$ 开始按间隔 $h$ 生成有限网格，并依次检查 $|f(x)|\le\tau$。第一个通过检查的网格点就是一个可接受候选；若网格耗尽仍无候选通过，算法必须返回明确的“未命中”状态。

<!-- bilingual-en:start -->
Throughout the mathematical description, $a,b$ are finite real numbers with $a\le b$, the indices are integers, and arithmetic and residual tests are exact. An actual program must additionally establish what its rounded candidates and computed function values mean; that implementation issue is treated below.
<!-- bilingual-en:end -->

以下数学描述假设 $a,b$ 是有限实数且 $a\le b$，下标取整数，运算和残差判定都是精确的。实际程序还必须说明舍入后的候选点和计算出来的函数值究竟代表什么；后文再处理这一层。

<!-- bilingual-en:start -->
## What the grid actually contains
<!-- bilingual-en:end -->

## 搜索对象是有限网格

<!-- bilingual-en:start -->
With the convention that the scan starts at $a$ and never steps beyond $b$, its candidate set is $G_h=\{a+jh:0\le j\le\lfloor(b-a)/h\rfloor\}$. At each grid point it evaluates the [[求根残差|residual]] $|f(x)|$ and returns the first value no larger than $\tau$. This certifies a small equation defect, not automatically a small distance to a true root; [[残差控制根误差|additional conditions]] are required for that conversion.
<!-- bilingual-en:end -->

按“从 $a$ 起步且不越过 $b$”的约定，候选集合是

$$
G_h
=
\left\{
a+jh:
j=0,1,\ldots,
\left\lfloor\frac{b-a}{h}\right\rfloor
\right\}.
$$

对每个 $x\in G_h$ 计算 [[求根残差|残差]] $|f(x)|$。若它不超过 $\tau$，算法返回 $x$；否则继续到下一个网格点。这个输出说明候选代回方程后的缺口不超过 $\tau$，并不自动说明它离真根多近；把残差换成位置误差需要 [[残差控制根误差|额外条件]]。

<!-- bilingual-en:start -->
Here $\lfloor u\rfloor$ means the greatest integer no larger than $u$. The left endpoint $a$ is always checked. The right endpoint $b$ is checked only if $(b-a)/h$ is an integer; otherwise the last mark is strictly before $b$. If $a=b$, or if $h>b-a$, the grid contains only $a$. Appending $b$ deliberately is a possible variant, but changes the candidate set being promised.
<!-- bilingual-en:end -->

这里 $\lfloor u\rfloor$ 表示不超过 $u$ 的最大整数。左端点 $a$ 总会被检查；只有 $(b-a)/h$ 恰好为整数时，右端点 $b$ 才在网格中，否则最后一个刻度位于 $b$ 左侧。若 $a=b$，或 $h>b-a$，网格就只有 $a$ 一个点。也可以主动把 $b$ 补进候选，但那是另一种明确规定的网格。

<!-- bilingual-en:start -->
For a minimal example, solve $x^2-2=0$ on $[0,2]$ with $h=0.1$ and $\tau=0.05$. At $x=1.4$, the residual is $|1.4^2-2|=0.04\le0.05$, so the method returns $1.4$ with a residual-tolerance success status. It is not the exact root; it is the grid candidate accepted by the stated rule.
<!-- bilingual-en:end -->

一个最小例子是求 $x^2-2=0$，取 $[a,b]=[0,2]$、$h=0.1$、$\tau=0.05$。扫描到 $x=1.4$ 时，

$$
|1.4^2-2|=0.04\le0.05,
$$

所以返回 $1.4$ 及“满足残差容差”的状态。它不是精确根；本方法返回的是按既定规则验收的网格候选。

<!-- bilingual-en:start -->
The final few checks before acceptance make the two parameters visible:
<!-- bilingual-en:end -->

接受之前的几个检查点，可以直接看出两个参数各自负责什么：

<!-- bilingual-en:start -->
| Candidate $x$ | Residual $\lvert f(x)\rvert$ | Test against $\tau=0.05$ |
|---|---|---|
| $1.2$ | $0.56$ | Reject |
| $1.3$ | $0.31$ | Reject |
| $1.4$ | $0.04$ | Accept and stop |
<!-- bilingual-en:end -->

| 候选 $x$ | 残差 $\lvert f(x)\rvert$ | 与 $\tau=0.05$ 比较 |
|---|---|---|
| $1.2$ | $0.56$ | 拒绝 |
| $1.3$ | $0.31$ | 拒绝 |
| $1.4$ | $0.04$ | 接受并停止 |

<!-- bilingual-en:start -->
The step $h=0.1$ is a spacing in the **input**. The tolerance $\tau=0.05$ is a limit on the **function value**. Their units and roles need not agree. Here the first accepted index is $j=14$, so a scan starting at $j=0$ uses 15 evaluations, not all 21 grid points.
<!-- bilingual-en:end -->

步长 $h=0.1$ 是**输入位置**之间的间隔；容差 $\tau=0.05$ 则限制**函数值**的大小，两者的单位和作用都不必相同。这里第一个通过的下标是 $j=14$，从 $j=0$ 开始一共求值 15 次，不必检查全部 21 个网格点。

<!-- bilingual-en:start -->
## How spacing determines the cost
<!-- bilingual-en:end -->

## 步长同时控制网格密度和成本

<!-- bilingual-en:start -->
The number of grid candidates is:
<!-- bilingual-en:end -->

候选数量为

$$
N_h
=
\left\lfloor\frac{b-a}{h}\right\rfloor+1.
$$

<!-- bilingual-en:start -->
For a work bound, count candidate generation, function evaluation, and residual comparison as uniformly $O(1)$ operations per candidate. The statement below uses that cost model; counting one call to an arbitrarily expensive function is not enough to prove constant work.
<!-- bilingual-en:end -->

要讨论总工作量，先约定每个候选的生成、函数求值和残差比较都有统一的 $O(1)$ 成本。下面的工作量结论采用这个模型；仅仅说“调用函数一次”，不能证明一个任意昂贵的函数只需常数工作量。

<!-- bilingual-en:start -->
The grid contains $N_h=\lfloor(b-a)/h\rfloor+1$ candidates. If each candidate requires one function evaluation and one residual comparison, the worst case costs $N_h$ evaluations, or $O(N_h)$ work. On a fixed interval, roughly halving $h$ roughly doubles both grid density and worst-case cost. The step determines where the algorithm looks; the tolerance determines what counts as acceptance.
<!-- bilingual-en:end -->

若每个候选只需要一次函数求值和一次残差比较，最坏情形需要 $N_h$ 次函数求值，成本为 $O(N_h)$。在区间固定时把 $h$ 大致减半，候选数和最坏求值成本大致翻倍。步长决定在哪里看，容差决定看到什么时算成功；两者不是同一个参数。

<!-- bilingual-en:start -->
The approximate doubling describes a grid with many intervals. For short or degenerate intervals, use the exact floor formula: a one-point grid need not double when the step is halved.
<!-- bilingual-en:end -->

“大致翻倍”描述网格已有许多间隔时的数量级直觉；很短或退化的区间要使用准确的取整公式，一个点的网格在步长减半后未必翻倍。

<!-- bilingual-en:start -->
If evaluating $f$ is expensive, that cost dominates. Repeated floating-point updates with `x += h` can also accumulate rounding error, moving the actual candidates away from the ideal $a+jh$. Generate candidates by index where suitable, or at least use explicit interval and evaluation limits instead of waiting for a floating-point value to equal $b$ exactly.
<!-- bilingual-en:end -->

若 $f$ 本身昂贵，函数求值会主导成本。若用浮点数反复执行 `x += h`，累计舍入还可能让实际候选偏离理想的 $a+jh$。实现时宜按索引构造候选，或至少用明确的区间边界和求值上限控制循环，而不是等待浮点值精确等于 $b$。

> [!warning] A positive step can round to no step · 正步长也可能原地不动
> <!-- bilingual-en:start -->
> With ordinary binary64 arithmetic rounded to nearest, adding `0.1` ten times to `0.0` gives `0.9999999999999999`, whereas `10 * 0.1` gives `1.0`. More seriously, `1.0 + 2**-54 == 1.0`: a positive mathematical increment may leave the stored number unchanged. A loop whose only exit is reaching the next position can then stall.
> <!-- bilingual-en:end -->
>
> 在通常采用最近舍入的 binary64 运算中，从 `0.0` 开始加十次 `0.1` 得到 `0.9999999999999999`，而 `10 * 0.1` 得到 `1.0`。更严重的是 `1.0 + 2**-54 == 1.0`：数学上的正增量可能完全改变不了存储值。若循环只等待位置前进，就可能停滞。

<!-- bilingual-en:start -->
Indexing avoids carrying forward every earlier addition error, but it does not make `a + j*h` exact: multiplication and addition still round, and different indices may produce the same stored value. Even computing $\lfloor(b-a)/h\rfloor$ in floating point can miscount an intended decimal grid. For a claim about that exact grid, use exact input/count arithmetic or verify the generated candidates against it. Otherwise state the actual floating-point grid being searched, enforce a finite index or work limit, and treat invalid evaluations separately. A computed residual needs its own error control before it certifies the mathematical residual.
<!-- bilingual-en:end -->

按下标生成可以避免逐次传递此前所有加法误差，却不能让 `a + j*h` 变成精确运算：乘法和加法仍会舍入，不同下标也可能得到同一个存储值。甚至用浮点数计算 $\lfloor(b-a)/h\rfloor$，也可能把原本想要的十进制网格数错。若要声称覆盖那个精确网格，就应使用精确的输入和计数运算，或另行核对生成点；否则要明确实际搜索的是哪个浮点网格，设定有限下标或工作上限，并单独处理无效求值。计算残差本身也需要误差控制，才能作为数学残差的证据。

## What each exit actually establishes
<!-- bilingual-en:end -->

## 输入、成功状态和失败出口共同构成规格

<!-- bilingual-en:start -->
A reproducible fixed-step search specifies the interval and why the target root is sought there, the positive step and residual tolerance, whether it returns the first acceptable point or all acceptable grid points, and explicit statuses for grid exhaustion, an evaluation cap, domain escape, or non-finite values.
<!-- bilingual-en:end -->

一次可复现的固定步长搜索至少要说明：

- 搜索范围 $[a,b]$，以及为何目标根值得在此处寻找；
- 正步长 $h$ 与残差容差 $\tau$；
- 返回第一个可接受点，还是收集全部可接受网格点；
- 网格耗尽、达到求值上限、越出函数定义域或出现 NaN/overflow 时返回什么状态。

<!-- bilingual-en:start -->
Finite candidates guarantee a finite number of checks only if each required evaluation and decision finishes. `no_grid_hit` is justified after **every candidate has received a valid rejection**. Reaching a work limit early, hitting an undefined function value, or detecting a stalled generator leaves the remaining search unresolved. Such outcomes must not be relabelled as a completed no-hit scan; this is the same coverage-and-decision contract as [[枚举验证|exhaustive verification]].
<!-- bilingual-en:end -->

有限个候选只有在每次必要的求值和判定都能完成时，才能保证有限步检查结束。只有**每个候选都获得有效的拒绝判定**后，才可以报告 `no_grid_hit`。提前达到工作上限、函数在某点无定义、生成器停滞，都表示余下搜索尚未完成，不能冒充一次完整的未命中扫描；这正是 [[枚举验证]] 的覆盖与判定合同。

<!-- bilingual-en:start -->
Grid exhaustion means only that none of the inspected grid points passed the acceptance rule; it does not establish that the interval contains no root. The independent failure boundary and counterexample belong to [[固定步长漏根|fixed-step grid miss]], while [[数值迭代停止条件|numerical stopping criteria]] owns the general success evidence, work limits, and exceptional exits. For a continuous function with a sign-changing bracket, [[二分求根|bisection root-finding]] can instead maintain a root-existence certificate at every iteration.
<!-- bilingual-en:end -->

“网格耗尽”只说明这些网格点没有通过验收，不能直接解释成“区间内没有根”。这种独立失效边界及其反例属于 [[固定步长漏根]]；统一的成功证据、工作上限和异常出口见 [[数值迭代停止条件]]。若函数连续且已经找到端点异号区间，[[二分求根]] 可以改用每轮都保留根存在证书的括区间不变量。

> [!question]- Halving the step · 步长减半
> <!-- bilingual-en:start -->
> On a fixed interval, what changes when $h$ is halved while $\tau$ is unchanged?
>
> **Answer:** The grid becomes roughly twice as dense and the worst-case number of evaluations roughly doubles, while every candidate is still tested by $|f(x)|\le\tau$. Denser sampling improves the chance of a hit, but a guaranteed hit still requires additional assumptions.
> <!-- bilingual-en:end -->
>
> 在固定区间 $[a,b]$ 上把 $h$ 减半但保持 $\tau$ 不变，算法的候选与验收规则分别怎样变化？
>
> **答案：** 网格大致加密一倍，最坏函数求值次数也大致翻倍；每个候选仍由同一个条件 $|f(x)|\le\tau$ 验收。网格更密提高命中机会，但是否一定命中仍需额外条件，不能只由“减半”推出。

<!-- bilingual-en:start -->
Here “improves the chance” refers to increased coverage, not a probability model. In exact arithmetic, with the same starting point and interval, $G_h\subseteq G_{h/2}$: an old accepted point survives refinement. This does not say that one halving must create a hit if there was none; [[固定步长漏根|the grid-miss boundary]] explains the additional coverage argument.
<!-- bilingual-en:end -->

这里“提高命中机会”指覆盖增加，并未引入概率模型。在精确算术中，起点和区间不变时有 $G_h\subseteq G_{h/2}$，所以原来已经合格的点不会因这次加密而消失。但这不代表原来未命中时，只减半一次就一定成功；所需的进一步覆盖论证见 [[固定步长漏根]]。
