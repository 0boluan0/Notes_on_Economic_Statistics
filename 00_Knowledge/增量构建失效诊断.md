# 无变更仍重建或小改动触发全量重建时先查依赖边与不稳定输出
<!-- bilingual-en:start -->
*When an unchanged build reruns or a small edit triggers a full rebuild, inspect dependency edges and unstable outputs first*
<!-- bilingual-en:end -->

> [!summary] 原子诊断
> 先做 null build：完整构建成功后，不改任何声明输入立即再运行一次。若仍执行配方，检查 phony target 是否错误地成为真实目标先决条件、生成物是否每次写入时间戳/build ID、配方是否改写源码树，以及目标时间是否始终早于先决条件。
> <!-- bilingual-en:start -->
> Start with a null build: immediately rerun a successful complete build without changing any declared input. If recipes still execute, inspect whether a phony target was made a prerequisite of a real target, generated files embed a fresh timestamp or build ID, recipes rewrite the source tree, or target times remain older than prerequisites.
> <!-- bilingual-en:end -->

若只改一个叶端文件却几乎全部重建，沿失效传播方向追踪它使哪些下游目标过期：某个共享聚合目标或过宽 prerequisite 可能把无关目标都连进来。相反，应该重建却没重建，则优先怀疑漏边或时间戳没有反映真实内容变化。
<!-- bilingual-en:start -->
If changing one leaf file rebuilds almost everything, trace which downstream targets it invalidates in the direction of change propagation: a shared aggregate target or overly broad prerequisite may connect unrelated targets. Conversely, if a required rebuild does not happen, suspect a missing edge or timestamps that fail to reflect the real content change.
<!-- bilingual-en:end -->

## 边界

“第二次什么都不做”适用于期望增量、无外部变更的构建入口。显式 `clean`、始终执行的检查任务、网络查询或刻意生成当前时间的目标有不同契约；诊断前先确认目标本来是否承诺增量。
<!-- bilingual-en:start -->
“The second run does nothing” applies to an entry point intended to be incremental with no external changes. Explicit `clean`, always-run checks, network queries, or targets deliberately producing the current time have different contracts. Confirm that the target promises incrementality before diagnosing it.
<!-- bilingual-en:end -->

> [!question]- 自检
> 每次构建都把当前时间写入 `version.h`，而所有对象文件依赖它。为什么一条很小的源代码改动可能变成全量重编译？
>
> **答案：** `version.h` 每次都变新，并作为共享先决条件把失效传播到全部对象文件。
