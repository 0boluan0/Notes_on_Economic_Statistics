# 注意力读取是按查询与键的匹配程度加权汇总值的计算

<!-- bilingual-en:start -->
*An attention read aggregates values using weights determined by query-key compatibility*
<!-- bilingual-en:end -->

注意力读取接受一个查询（query）和若干键—值对（key–value pairs），根据查询与各个键的匹配程度，为对应的值分配权重并求和。这里讨论 Transformer 使用的归一化软注意力：权重非负且和为 1，输出是这些值的加权平均。

<!-- bilingual-en:start -->
An attention read takes a query and a set of key–value pairs. Compatibility between the query and each key determines the weight assigned to the corresponding value, and the weighted values are summed. The normalized soft attention considered here uses nonnegative weights that sum to one, producing a weighted average of the values.
<!-- bilingual-en:end -->

$$
o(q)=\sum_{j=1}^{n_k}\alpha_j(q,K)v_j,
\qquad \alpha_j\ge0,
\qquad \sum_{j=1}^{n_k}\alpha_j=1.
$$

权重记为 $\alpha_j(q,K)$，因为归一化后一个候选的权重也取决于同组其他候选的分数；它不是只由一对 $q,k_j$ 单独决定的绝对量。

<!-- bilingual-en:start -->
The notation $\alpha_j(q,K)$ emphasizes that a normalized weight also depends on the scores of the other candidates. It is not an absolute quantity determined by the pair $q,k_j$ alone.
<!-- bilingual-en:end -->

## 查询、键和值各自做什么

<!-- bilingual-en:start -->
*The roles of queries, keys, and values*
<!-- bilingual-en:end -->

查询是发起本次读取的表示；键提供每个候选如何被匹配的表示；值提供真正进入加权和的内容。可以把这三者理解为“用什么去找”“怎样被找到”和“找到后读什么”。这些是计算角色，训练不会预先给它们分配固定的自然语言含义。

<!-- bilingual-en:start -->
The query initiates a read, each key supplies a representation used for matching a candidate, and each value supplies the content entering the weighted sum. The roles can be understood as what to search with, how a candidate is matched, and what is read from it. These are computational roles, without predetermined meanings in natural language.
<!-- bilingual-en:end -->

匹配函数可以有不同形式。[[缩放点积注意力]]使用查询与键的缩放点积打分，再由 [[Softmax]] 归一化；“点积”是这种注意力的具体选择，而“按匹配程度汇总值”是这里的通用读取结构。

<!-- bilingual-en:start -->
Compatibility functions can take different forms. [[缩放点积注意力|Scaled dot-product attention]] scores queries and keys through scaled dot products and normalizes the scores with [[Softmax]]. The dot product is a particular scoring choice within the broader structure of compatibility-weighted value aggregation.
<!-- bilingual-en:end -->

## 一次读取的最小例子

<!-- bilingual-en:start -->
*A minimal read*
<!-- bilingual-en:end -->

设两个候选的值为 $v_1=(2,0)$、$v_2=(0,4)$，查询—键匹配已给出权重 $\alpha=(3/4,1/4)$，那么

<!-- bilingual-en:start -->
Suppose two candidates have values $v_1=(2,0)$ and $v_2=(0,4)$, with query–key matching already producing weights $\alpha=(3/4,1/4)$. The read is then
<!-- bilingual-en:end -->

$$
o=\tfrac34(2,0)+\tfrac14(0,4)=(1.5,1).
$$

若只把 $v_1$ 改成 $(6,0)$，并保持查询、键及匹配规则不变，权重仍是 $(3/4,1/4)$，输出却变成 $(4.5,1)$。因此键参与“分配多少权重”，值决定“这些权重汇总什么内容”。这个例子固定的是一次读取的输入；它没有假设真实模型中改变一个 token 后只会改变 V。

<!-- bilingual-en:start -->
If only $v_1$ changes to $(6,0)$ while the query, keys, and matching rule stay fixed, the weights remain $(3/4,1/4)$ but the output becomes $(4.5,1)$. Keys participate in assigning weights; values supply the content being combined. This example holds the inputs to a single read fixed as stated. It does not assume that changing a token in a real model would affect only V.
<!-- bilingual-en:end -->
