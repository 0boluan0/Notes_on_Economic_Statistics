# 脚本幂等性要求相同条件下重复应用不再改变指定目标状态
<!-- bilingual-en:start -->
*A script is idempotent when repeated application under the same conditions does not further change the specified target state.*
<!-- bilingual-en:end -->

先声明输入、前提与要观察的状态。把一次成功操作记作 $F$，在没有中间外部改动的适用状态上，幂等要求 $F(F(s))=F(s)$。它不是仅仅“重复运行不会报错”或“没有破坏文件”。
<!-- bilingual-en:start -->
Specify inputs, assumptions, and the state being observed. If a successful operation is $F$, idempotency requires $F(F(s))=F(s)$ on applicable states without intervening external changes. This is stronger than merely not reporting errors or not corrupting files.
<!-- bilingual-en:end -->

例如，确保某目录存在可以以“目录存在”作为目标状态；但每运行一次就追加同一配置行，会持续产生重复项，不幂等。日志条数、修改时间等是否计入状态也要说明，不能只挑方便的一项观察结果来宣称整段脚本幂等。
<!-- bilingual-en:start -->
Ensuring a directory exists can target the state “directory exists.” Appending the same configuration line on every run instead accumulates duplicates and is not idempotent. State whether log counts and modification times are included; one convenient observation does not establish idempotency of the whole script.
<!-- bilingual-en:end -->

幂等不等于原子性或自动恢复：一次运行失败在中途时，重跑是否安全仍取决于部分状态、外部副作用和并发。[[dotfiles配置管理]]的安装脚本应检查已有目标及冲突，而不能把“命令带 `-f`”当作幂等证明。
<!-- bilingual-en:start -->
Idempotency is not atomicity or automatic recovery. After a partial failure, safe retries still depend on intermediate state, external effects, and concurrency. A [[dotfiles配置管理|dotfile installation]] script should inspect existing destinations and conflicts rather than treating a force flag as proof of idempotency.
<!-- bilingual-en:end -->

## 来源与核验

[Ansible official glossary, Idempotency](https://docs.ansible.com/projects/ansible/latest/reference_appendices/glossary.html#term-Idempotency)：支持一次与无中间操作的重复应用具有相同结果。$F(F(s))=F(s)$ 和脚本例子是该定义的显式状态化表达，不宣称任意 Shell 命令或 Ansible 任务自动幂等。
<!-- bilingual-en:start -->
[Ansible official glossary: Idempotency](https://docs.ansible.com/projects/ansible/latest/reference_appendices/glossary.html#term-Idempotency) defines equality of one application and repetition without intervening actions. The state equation and examples make that definition explicit without claiming automatic idempotency for arbitrary shell commands or Ansible tasks.
<!-- bilingual-en:end -->
