# 邻接表按邻居存稀疏图而邻接矩阵按点对存边
<!-- bilingual-en:start -->
*Adjacency lists store neighbors; adjacency matrices store all vertex pairs*
<!-- bilingual-en:end -->

> [!summary] 原子区分
> **邻接表（adjacency list）**为每个顶点 $u$ 存它的 outgoing neighbors $Adj(u)$，总空间在常见实现中是 $\Theta(|V|+|E|)$。**邻接矩阵（adjacency matrix）**给每一对已编号顶点留一个格子，simple unweighted digraph 中以 $A_{ij}=1$ 表示 $i\to j$，空间是 $\Theta(|V|^2)$。
> <!-- bilingual-en:start -->
> An **adjacency list** stores the outgoing neighbors $Adj(u)$ of every vertex and normally occupies $\Theta(|V|+|E|)$ space. An **adjacency matrix** reserves one entry for every ordered pair of numbered vertices; in a simple unweighted digraph, $A_{ij}=1$ records $i\to j$, using $\Theta(|V|^2)$ space.
> <!-- bilingual-en:end -->

选择表示法会改变基本操作的成本。邻接表能用 $\Theta(\deg^+(u))$ 时间枚举 $u$ 的实际邻居，适合 sparse graph；矩阵无论实际邻居多少，都要扫一整行才能枚举，成本 $\Theta(|V|)$，但查询指定边 $(u,v)$ 是否存在只需读取一个格子，成本 $\Theta(1)$。
<!-- bilingual-en:start -->
The representation changes operation costs. An adjacency list enumerates the actual neighbors of $u$ in $\Theta(\deg^+(u))$ time and is well suited to sparse graphs. A matrix scans an entire row in $\Theta(|V|)$ time to enumerate neighbors, but tests a specified edge $(u,v)$ by reading one entry in $\Theta(1)$ time.
<!-- bilingual-en:end -->

## 同一个名称下的不同编码
<!-- bilingual-en:start -->
*Different encodings under the same name*
<!-- bilingual-en:end -->

- 无向 simple graph 的 matrix 对称；digraph 不必对称。
- multigraph 可让 $A_{ij}$ 存平行边条数，而不是布尔值；weighted graph 可存权重，但“没有边”与合法权重 $0$ 必须用不同表示。
- adjacency list 中的邻居顺序通常不是图的数学结构，却会影响 BFS/DFS 最终选择哪一个同样合法的 parent tree。
<!-- bilingual-en:start -->

**1.** The adjacency matrix of an undirected simple graph is symmetric; a digraph matrix need not be.<br>
**2.** A multigraph matrix may store the number of parallel edges rather than a Boolean. A weighted graph may store weights, but “no edge” must remain distinguishable from a legitimate zero weight.<br>
**3.** Neighbor order in an adjacency list is usually not part of the mathematical graph, but it can change which equally valid parent tree BFS or DFS returns.<br>
<!-- bilingual-en:end -->

> [!question]- 回忆与应用
> 一张有一百万个顶点、每点平均十个 outgoing neighbors 的图，若主要操作是从一个点逐邻居搜索，为什么邻接矩阵通常不合适？
>
> **答案：**矩阵需要约 $10^{12}$ 个格子，且处理一个顶点要扫描一百万个候选邻居；邻接表只存约一千万条实际邻接项，逐点搜索的工作量随实际边数增长。
> <!-- bilingual-en:start -->
> A graph has one million vertices and about ten outgoing neighbors per vertex. Why is an adjacency matrix usually unsuitable when the main operation is neighbor-by-neighbor search?
>
> **Answer:** The matrix needs about $10^{12}$ entries and scans one million candidates per processed vertex. An adjacency list stores only about ten million actual adjacency entries, so search work scales with the edges that exist.
> <!-- bilingual-en:end -->
