# 归并排序由对半递归与线性归并得到 n log n

<!-- bilingual-en:start -->
*Merge sort gets n log n from recursive halving and linear merging*
<!-- bilingual-en:end -->

> [!summary] 原子命题
> 标准 top-down merge sort 把长度 $n$ 的序列分成两半，递归排序两半，再线性归并，因此满足 $T(n)=2T(n/2)+\Theta(n)$，解为 $T(n)=\Theta(n\log n)$。递归树每层总工作为 $\Theta(n)$，共有 $\Theta(\log n)$ 层。
>
> <!-- bilingual-en:start -->
> Standard top-down merge sort splits a length-$n$ sequence in half, recursively sorts both halves, and merges them linearly. Thus $T(n)=2T(n/2)+\Theta(n)=\Theta(n\log n)$. Each recursion-tree level performs $\Theta(n)$ total work, and there are $\Theta(\log n)$ levels.
> <!-- bilingual-en:end -->

## 自然解释

标准版本不因输入已经有序而省去递归与归并，所以最好和最坏时间都是 $\Theta(n\log n)$。普通数组实现可复用一个 $\Theta(n)$ 临时缓冲区，并另有 $\Theta(\log n)$ 递归栈；若归并在相等键时左侧优先，整个排序稳定。

<!-- bilingual-en:start -->
The standard version does not skip recursion or merging merely because the input is already sorted, so both best- and worst-case running times are $\Theta(n\log n)$. An ordinary array implementation can reuse one $\Theta(n)$ temporary buffer and also has a $\Theta(\log n)$ recursion stack. The whole sort is stable if merging takes the left item first on equal keys.
<!-- bilingual-en:end -->

> [!warning] 边界
> “merge sort 天生稳定且需要线性空间”说得过满。稳定性由平局规则决定；链表、外部排序、bottom-up 或复杂的原地归并变体有不同空间与访问代价。Python 示例中的切片和新列表是该实现的分配方式，不是所有 merge sort 必须逐字复制的定理。实现递归区间时可用半开区间 `[lo, hi)`：两个子区间必须不重叠地覆盖父区间，归并时每个项目恰好输出一次。
>
> <!-- bilingual-en:start -->
> “Merge sort is inherently stable and always needs linear space” is too broad. Stability depends on the tie rule, while linked-list, external, bottom-up, and sophisticated in-place merge variants have different space and access costs. Slices and new lists in a Python demonstration are properties of that implementation, not universal merge-sort theorems. Half-open ranges `[lo, hi)` make the recursive partition auditable: both child ranges must cover the parent without overlap, and merging must emit every item exactly once.
> <!-- bilingual-en:end -->

> [!question]- 回忆与应用
> 为什么递归调用有两个，却不是 $\Theta(2^n)$？
>
> **答案：** 每次调用把问题规模减半；第 $j$ 层虽有 $2^j$ 个子问题，但每个规模约为 $n/2^j$，该层总工作仍为 $\Theta(n)$。
