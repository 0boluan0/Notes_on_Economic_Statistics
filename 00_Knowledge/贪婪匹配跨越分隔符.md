# 贪婪的任意字符重复可能吞掉本想保留的分隔标记

<!-- bilingual-en:start -->
*Greedy repetition of arbitrary characters can consume delimiters that were meant to be preserved*
<!-- bilingual-en:end -->

在课程所用的常规 `sed` 匹配中，`.*` 允许任意长度的字符段；当后面的分隔标记重复出现时，匹配可以延伸到最后一个可用标记。因而“删除某标记以前的内容”不自动等于“删除第一次出现该标记以前的内容”。

<!-- bilingual-en:start -->
In the ordinary `sed` matching used in the course, `.*` admits a character sequence of arbitrary length. When a following delimiter appears repeatedly, the match can extend to the last usable occurrence. Removing the prefix through a delimiter therefore does not automatically mean removing the prefix through its first occurrence.
<!-- bilingual-en:end -->

```bash
printf '%s\n' 'tag first tag second' | sed 's/.*tag //'
```

结果是 `second`，不是 `first tag second`。默认替换第一次匹配并不能解决它：这里第一次匹配本身已经覆盖 `tag first tag `。行首、行尾锚点约束匹配位置，也不会自动限制内部 `.*` 跨越哪些字段。

<!-- bilingual-en:start -->
The result is `second`, not `first tag second`. Replacing only the first match does not solve the problem: that first match already spans `tag first tag `. Anchors constrain where a match starts or ends; they do not automatically prevent an internal `.*` from crossing field boundaries.
<!-- bilingual-en:end -->

修正要来自格式契约：若字段确实禁止某分隔字符，可以用排除该字符的字符类；若需要引号、转义或嵌套结构，则考虑格式解析器。最短匹配语法是否可用要检查具体引擎与版本，不能机械地把 `.*` 改成 `.*?` 并宣称对所有 `sed` 都可移植。

<!-- bilingual-en:start -->
The repair must follow the format contract. If a field really excludes a delimiter character, a negated character class can express that restriction; quoted, escaped, or nested structures may require a format parser. Minimal-match syntax depends on the engine and version: mechanically changing `.*` to `.*?` does not establish portability across all `sed` implementations.
<!-- bilingual-en:end -->
