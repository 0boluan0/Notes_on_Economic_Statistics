# 高精度求和能减少累积舍入但不能保证数学精确

<!-- bilingual-en:start -->
*Accurate summation reduces accumulated rounding but does not guarantee mathematical exactness*
<!-- bilingual-en:end -->

> [!summary] 原子方法
> 顺序求和把当前部分和反复舍入，微小项可能在加入巨大部分和时丢失。改变求和顺序、补偿求和或 Python 的 `math.fsum` 可以保留更多中间信息，从而降低累计舍入；它们改善的是求和算法，不会把输入变成精确实数。
>
> <!-- bilingual-en:start -->
> Sequential summation repeatedly rounds the running total, so a small term can disappear when added to a huge partial sum. Reordering, compensated summation, or Python's `math.fsum` can retain more intermediate information and reduce accumulated rounding. They improve the summation algorithm; they do not turn the inputs into exact real numbers.
> <!-- bilingual-en:end -->

```python
import math

values = [1e16, 1.0, -1e16]
total = 0.0
for value in values:
    total += value

print(total)             # 0.0 with ordinary binary64 step-by-step addition
print(math.fsum(values)) # 1.0
```

显式逐项累加先把 `1.0` 加到 `1e16`，该增量被舍去；`math.fsum` 跟踪多个中间部分和，在这里恢复了数学和。Python 3.12 起，内置 `sum` 对浮点输入也改用更高精度、通常更可交换的算法，因此这个三项例子不再能稳定地区分 `sum` 与 `fsum`。`math.fsum` 仍进一步追踪丢失位；Python 文档同时记录极少数平台上的末位双重舍入边界。
<!-- bilingual-en:start -->
Explicit step-by-step accumulation first adds `1.0` to `1e16`, losing the increment. `math.fsum` tracks multiple intermediate partial sums and recovers the mathematical total here. Since Python 3.12, built-in `sum` also uses a higher-accuracy, usually more commutative algorithm for floats, so this three-item input no longer reliably distinguishes `sum` from `fsum`. `math.fsum` goes further in tracking lost digits, while Python documents a rare platform-dependent last-bit double-rounding boundary.
<!-- bilingual-en:end -->

`math.fsum` 仍不能修复输入采集时已有的表示或测量误差，也不能让超出浮点范围的中间值自动安全，更不能解决目标和本身因大量正负抵消而病态的问题。若误差界很重要，应同时检查数据尺度、和的条件性及所需精度。
<!-- bilingual-en:start -->
`math.fsum` cannot repair representation or measurement error already present in the inputs, automatically make out-of-range intermediates safe, or cure an ill-conditioned sum dominated by cancellation. When error bounds matter, inspect data scale, conditioning of the sum, and required precision as well.
<!-- bilingual-en:end -->

> [!question]- 回忆与应用
> `math.fsum(values)` 与高精度基准一致一次，能否证明所有类似输入都精确？
>
> **答案：** 不能。它是更准确的求和算法，但仍受输入误差、格式范围、舍入环境和问题条件性约束。
