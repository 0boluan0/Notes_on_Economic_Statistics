# except 按书写顺序选择首个匹配异常类型或其基类的处理器

<!-- bilingual-en:start -->
*except selects the first handler whose type matches the exception class or a base class*
<!-- bilingual-en:end -->

普通 `try/except` 按书写顺序检查处理器；异常实例的类等于处理器指定类，或实际继承自该类时，便匹配并只进入首个匹配处理器。捕获基类会覆盖其派生异常，反方向不成立。应把需要区别处理的具体类型放在宽泛基类之前。

<!-- bilingual-en:start -->
Ordinary `try/except` checks handlers in source order and enters only the first matching one. A match occurs when the exception instance has the specified class or inherits from it. Catching a base class includes its derived exceptions, but not conversely. Put specific types before broader bases when they need distinct responses.
<!-- bilingual-en:end -->

```python
try:
    int("cat")
except ValueError as exc:
    result = "invalid value"
except Exception:
    result = "other error"
# result == "invalid value"
```

`except (ValueError, TypeError):` 可以共享一个处理器。`except` 后应给异常类或这些类的元组，不是 `ValueError("message")` 这样的实例；实例属于 `raise` 的用法。交换上例两处理器的顺序会让 `Exception` 先匹配，具体分支失去机会。这里讨论普通 `except`，不讨论异常组的 `except*`。

<!-- bilingual-en:start -->
`except (ValueError, TypeError):` shares a handler between types. The handler header expects exception classes or a tuple of them, not an instance such as `ValueError("message")`; instances belong in `raise`. Reversing the example's handlers lets `Exception` match first and prevents the specific branch from running. This rule concerns ordinary `except`, not exception-group handling with `except*`.
<!-- bilingual-en:end -->
