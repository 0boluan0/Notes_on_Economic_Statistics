# 类适合集中管理状态身份或不变量而简单数据与行为应先考虑更轻表示
<!-- bilingual-en:start -->
*Classes fit centralized state, identity, or invariants, while simple data and behavior should first consider lighter representations*
<!-- bilingual-en:end -->

> [!summary] 原子适用边界
> 当多个操作需要围绕同一份长期状态、对象身份、行为接口或不变量协作时，类能把责任集中起来。若只是临时聚合少量数据、执行无状态变换或只有一个简单表示，tuple、dict、普通函数或既有抽象往往更直接。抽象应由需要解决的问题证明，而不是由“面向对象”标签证明。
> <!-- bilingual-en:start -->
> A class can centralize responsibility when several operations coordinate around persistent state, object identity, a behavioral interface, or invariants. If the task only groups a little temporary data, performs stateless transformations, or has one simple representation, a tuple, dictionary, ordinary function, or existing abstraction is often more direct. The problem should justify the abstraction, not the label “object-oriented.”
> <!-- bilingual-en:end -->

`@dataclass` 适合字段为主的数据载体：默认可生成 `__init__`、`__repr__` 和逐字段的 `__eq__`，减少样板；默认相等比较还要求两个对象具有完全相同的类型。它不会仅凭类型注解自动验证值，也不会自动设计业务不变量；`frozen=True` 只模拟字段只读，不是对嵌套可变对象的深冻结。若状态规则复杂，仍需显式方法与校验。

```python
from dataclasses import dataclass

@dataclass(frozen=True)
class Point:
    x: float
    y: float
```

> [!question]- 回忆与应用
> 一个只保存 `x`、`y` 且没有额外不变量的记录，为什么未必需要手写完整类？
>
> **答案：** 轻量表示或 dataclass 已能表达字段和常用协议；手写类只有在额外状态、身份、行为或不变量值得集中管理时才增加价值。
