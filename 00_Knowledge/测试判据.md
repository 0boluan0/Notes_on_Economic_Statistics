# 测试判据是确定预期行为并据此判断实际测试结果是否可接受的依据
<!-- bilingual-en:start -->
*A test oracle supplies the expected behavior against which an actual result is judged.*
<!-- bilingual-en:end -->

判据可以来自明确规格、可独立计算的例子或有根据的参照结果。检查代码把这个依据落实为比较或条件判断；“程序跑完了”只检查正常结束，不自动检查返回值、对象修改或输出内容。
<!-- bilingual-en:start -->
An oracle may come from a specification, an independently calculated example, or a justified reference result. Checking code turns that basis into comparisons or conditions. Merely finishing execution checks normal completion, not automatically the returned value, mutation, or output content.
<!-- bilingual-en:end -->

判据也不一定是一份精确答案。若平方根函数的规格只要求 `x - eps <= r*r <= x + eps`，这一不等式就能检查返回值是否满足精度要求；不能另把 `r == 1.41421356237` 当作 `x = 2` 时唯一合法的浮点答案。
<!-- bilingual-en:start -->
An oracle need not supply one exact answer. If a square-root specification requires only `x - eps <= r*r <= x + eps`, that inequality checks the promised accuracy. It does not justify demanding `r == 1.41421356237` as the sole acceptable floating-point answer for `x = 2`.
<!-- bilingual-en:end -->

若规格还要求非负结果，就必须另检查 `r >= 0`；不能把未检查的承诺算作已经通过。规格不清或判据自身写错时，应先澄清依据，而不是改期望值让当前实现通过。
<!-- bilingual-en:start -->
If nonnegative output is also promised, check `r >= 0` as well; an unchecked promise has not been verified. When requirements are ambiguous or the oracle is faulty, clarify the basis rather than changing expectations merely to make the current implementation pass.
<!-- bilingual-en:end -->
