# 相等键必须具有相同哈希值

<!-- bilingual-en:start -->
*Equal keys must have equal hashes*
<!-- bilingual-en:end -->

> [!summary] 原子不变量
> 哈希集合要求满足相等契约：若 $a=b$，则必须有 $h(a)=h(b)$。否则，逻辑上相同的键可能被送往不同查找路径，字典或集合便无法把它们稳定地视为同一键。
>
> <!-- bilingual-en:start -->
> Hashed collections require an equality contract: if $a=b$, then $h(a)=h(b)$. Otherwise logically equal keys may be sent down different lookup paths, so a dictionary or set cannot reliably treat them as the same key.
> <!-- bilingual-en:end -->

设一个自定义对象的 `__eq__` 只比较学生编号，但 `__hash__` 同时混入姓名。两份对象只要编号相同就被判为相等；若姓名不同，它们却可能产生不同哈希值。字典先按哈希选择位置，因而可能把第二份对象当成另一个键，破坏“相等键代表同一个条目”的语义。
<!-- bilingual-en:start -->
Suppose a custom object's `__eq__` compares only a student number while `__hash__` also incorporates the name. Two objects with the same number compare equal, yet different names may produce different hashes. Because a dictionary uses the hash to choose a lookup path first, it may treat the second object as a separate key and violate the meaning that equal keys denote the same entry.
<!-- bilingual-en:end -->

这条契约只限制被判为相等的键，并不要求不相等的键具有不同哈希值。后一种情况是碰撞，由哈希表继续比较完整键处理；详见 [[哈希碰撞与完整键比较|碰撞后的完整键比较]]。
<!-- bilingual-en:start -->
The contract constrains keys that compare equal; it does not require unequal keys to have different hashes. Unequal keys with a shared hash are a collision, which the table resolves by comparing complete keys; see [[哈希碰撞与完整键比较|complete-key comparison after collisions]].
<!-- bilingual-en:end -->

> [!question]- 回忆与辨别
> 自定义键的 `__eq__` 使用哪些字段，`__hash__` 至少必须满足什么条件？
>
> **答案：** 任何被 `__eq__` 判为相等的两份对象都必须得到相同哈希值；哈希可以碰撞，所以不要求不同对象一定有不同哈希值。
