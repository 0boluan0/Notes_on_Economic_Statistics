# 投机解码用草稿提出候选，再由目标模型验收和修正，以一次验证推进多个生成位置

<!-- bilingual-en:start -->
*Speculative decoding proposes draft candidates and uses a target model to accept and correct them, allowing one verification round to advance several generation positions.*
<!-- bilingual-en:end -->

投机解码（speculative decoding）是先提出候选 token，再由目标模型检查候选前缀的自回归生成方法。本卡具体定义 Leviathan 等人的**严格单草稿链算法**：草稿按自己的分布提出一段候选，目标计算相应条件概率，通过概率验收和必要的修正保持指定目标采样器的输出分布。这一保证属于该算法及其条件，不能仅凭“投机解码”这个名称推给所有变体。

<!-- bilingual-en:start -->
Speculative decoding is an autoregressive generation method that proposes candidate tokens before a target model checks their prefixes. This note defines **Leviathan et al.'s strict single-draft-chain algorithm**: a draft samples a candidate sequence, the target evaluates the relevant conditional probabilities, and probabilistic acceptance with correction preserves the specified target sampler's output distribution. That guarantee belongs to this algorithm under its conditions; the name alone does not establish it for every speculative variant.
<!-- bilingual-en:end -->

## 两个模型各自负责什么

<!-- bilingual-en:start -->
*The roles of the two models.*
<!-- bilingual-en:end -->

令 $h$ 为已提交的前缀，$p(v\mid h)$ 为目标采样器对下一 token $v$ 的分布，$q(v\mid h)$ 为草稿实际使用的提议分布，$\gamma$ 为本轮提出的候选数。[[语言模型输出头]]提供词表 logits 和基础概率；这里的 $p,q$ 还应包含实际采样设置的作用，具体见 [[投机分布保持边界]]。

<!-- bilingual-en:start -->
Let $h$ be the committed prefix, $p(v\mid h)$ the target sampler's next-token distribution, $q(v\mid h)$ the distribution actually used to propose draft tokens, and $\gamma$ the number of candidates proposed in a round. A [[语言模型输出头|language-model output head]] supplies vocabulary logits and base probabilities; $p$ and $q$ here also incorporate the actual sampling settings, as specified in [[投机分布保持边界|the distribution-preservation boundary]].
<!-- bilingual-en:end -->

草稿负责便宜地提出可能被接受的续写，目标负责提供最终必须符合的条件分布。草稿常是较小模型，也可以是低成本的 n-gram 提议机制；“参数更少”不是定义所要求的条件。经典算法在同一个 token 样本空间上比较 $p$ 和 $q$，不能直接拿不同 tokenizer 的 token ID 做概率比或相减。

<!-- bilingual-en:start -->
The draft cheaply proposes continuations likely to be accepted, while the target defines the conditional distribution that the output must follow. A draft is often a smaller model, but a low-cost n-gram proposal can also serve this role; fewer parameters are not a defining requirement. The classical algorithm compares $p$ and $q$ over the same token sample space, so probabilities for unrelated token IDs from different tokenizers cannot be divided or subtracted directly.
<!-- bilingual-en:end -->

## 为什么一轮可能推进多个位置

<!-- bilingual-en:start -->
*Why a round can advance multiple positions.*
<!-- bilingual-en:end -->

假设草稿依次提出 $x_1,x_2,x_3$。这些输入已经确定，目标可以对下面四个前缀计算下一 token 分布：

<!-- bilingual-en:start -->
Suppose the draft sequentially proposes $x_1,x_2,x_3$. With these inputs already known, the target can evaluate the next-token distributions for four prefixes:
<!-- bilingual-en:end -->

$$
h,\qquad h+x_1,\qquad h+x_1+x_2,\qquad h+x_1+x_2+x_3.
$$

Transformer 对已知候选位置的计算可以并行组织；候选是否能成为真实输出，则仍要沿前缀顺序验收。如果三个候选全部通过，还能利用第四个分布再抽一个 token；如果较早拒绝，就在该位置修正。额度充足且未遇结束 token 时，一轮因此能输出 $1$ 到 $\gamma+1$ 个 token。[[投机前缀验收]]给出完整提交顺序，[[投机采样修正]]说明为什么修正后仍服从目标分布。

<!-- bilingual-en:start -->
A Transformer can organize computations over the known candidate positions in parallel, while acceptance still follows prefix order. If all three candidates pass, the fourth distribution supplies one additional token; an earlier rejection instead triggers correction at that position. With sufficient output allowance and no end token, a round therefore emits between $1$ and $\gamma+1$ tokens. [[投机前缀验收|Speculative prefix acceptance]] specifies the full commitment order, and [[投机采样修正|speculative sampling correction]] establishes the target-distribution guarantee.
<!-- bilingual-en:end -->

这里的“一轮验证”没有预设耗时等于普通单 token 的 [[增量解码]]。草稿计算、验证时的张量形状和协调开销都要付出时间；它们是否被多交付的 token 摊薄，由 [[投机加速条件]]决定。

<!-- bilingual-en:start -->
A verification round is not assumed to take the same time as ordinary single-token [[增量解码|incremental decoding]]. Draft computation, verification tensor shapes, and coordination all incur costs. [[投机加速条件|The speculative speedup condition]] determines whether the additional emitted tokens amortize those costs.
<!-- bilingual-en:end -->

  <!-- bilingual-en:start -->
