# 请求完成延迟是从请求起点到约定完成事件的总经过时间

<!-- bilingual-en:start -->
*Request completion latency is the elapsed time from a specified request start to its defined completion event*
<!-- bilingual-en:end -->

**请求完成延迟**是请求从开始到完成共经过多久，常称端到端延迟（end-to-end latency，E2E）。必须声明两个事件：客户端通常从发送请求计到接收最终响应；服务端的接收起点、最终 token 事件则覆盖另一段系统范围。

<!-- bilingual-en:start -->
**Request completion latency**, often called end-to-end latency (E2E), is the total elapsed time from a request's start to its completion. Both events must be specified: clients commonly measure request sending to final-response receipt, while server arrival and final-token events cover a different system boundary.
<!-- bilingual-en:end -->

令 $s$ 为所选请求起点，$f$ 为完成事件，则定义为 $\mathrm{E2E}=f-s$。这段等待覆盖两事件之间实际经过的时间，而不只是一组 GPU kernel 的时间和。

<!-- bilingual-en:start -->
For starting event $s$ and completion event $f$, the definition is $\mathrm{E2E}=f-s$. It covers the time actually elapsed between those events, not merely a sum of GPU-kernel runtimes.
<!-- bilingual-en:end -->

## 什么时候能由 TTFT 和 TPOT 恢复总时间

<!-- bilingual-en:start -->
*When TTFT and TPOT reconstruct the total time*
<!-- bilingual-en:end -->

若 $t_1,t_N$ 是同一观测点的首、末 token 时刻，使用[[首Token延迟]]的 $t_1-s$ 及[[平均输出Token时间]]的 $(t_N-t_1)/(N-1)$，对 $N>1$ 有

<!-- bilingual-en:start -->
Let $t_1,t_N$ mark the first and final tokens at one observation point. Using [[首Token延迟|TTFT]] as $t_1-s$ and [[平均输出Token时间|TPOT]] as $(t_N-t_1)/(N-1)$, for $N>1$ we obtain
<!-- bilingual-en:end -->

$$
\mathrm{E2E}
=\mathrm{TTFT}+(N-1)\mathrm{TPOT}+(f-t_N).
$$

只有完成事件恰是末 token 事件，即 $f=t_N$，尾项才消失。若 $N=1$，直接写 $\mathrm{E2E}=\mathrm{TTFT}+(f-t_1)$，不把未定义的 TPOT 乘以零。

<!-- bilingual-en:start -->
The trailing term vanishes only when completion is the final-token event, $f=t_N$. For $N=1$, write $\mathrm{E2E}=\mathrm{TTFT}+(f-t_1)$ directly rather than multiplying undefined TPOT by zero.
<!-- bilingual-en:end -->

例如首 token 在发送后 120 ms 出现，输出共3个，后续 TPOT 为45 ms，则末 token 在210 ms出现。若协议完成帧在220 ms收到，请求E2E为220 ms，末 token 后的10 ms也属于这一完成口径。

<!-- bilingual-en:start -->
For example, TTFT of 120 ms, three output tokens, and subsequent TPOT of 45 ms place the final token at 210 ms. If the protocol completion frame arrives at 220 ms, request E2E is 220 ms, including the final 10 ms under that completion convention.
<!-- bilingual-en:end -->

## 总时间不等于任意耗时报告相加

<!-- bilingual-en:start -->
*Total latency is not an arbitrary sum of reported durations*
<!-- bilingual-en:end -->

[[增量解码]]的前向次数可以解释执行路径，却不能代替事件计时。计算、通信、CPU处理可能重叠；有些统计又互相包含。因此只有把区间切为同一时间轴上互不重叠、完整覆盖的片段，才能直接相加重建 E2E。比较两种系统也必须采用相同起止事件。

<!-- bilingual-en:start -->
The forward-pass count in [[增量解码|incremental decoding]] explains execution but does not replace event timing. Computation, communication, and CPU processing may overlap, and reported intervals may include one another. Direct addition reconstructs E2E only for non-overlapping intervals that fully partition the same timeline. System comparisons also require matching start and end events.
<!-- bilingual-en:end -->
