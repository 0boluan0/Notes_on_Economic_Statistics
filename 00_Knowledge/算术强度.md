# 算术强度是一次计算的算术操作数与指定存储层级读写字节数之比
<!-- bilingual-en:start -->
*Arithmetic intensity is the ratio of arithmetic operations to bytes transferred at a specified memory level*
<!-- bilingual-en:end -->

算术强度（arithmetic intensity）衡量搬运一字节数据能支撑多少算术工作。设一次计算完成 $F$ 次浮点操作，在选定的存储边界上读写 $D$ 字节，则

<!-- bilingual-en:start -->
Arithmetic intensity measures how much arithmetic work is performed per byte transferred. If a computation performs $F$ floating-point operations and transfers $D$ bytes across a specified memory boundary, then
<!-- bilingual-en:end -->

$$I=\frac FD\quad\text{FLOP/byte}.$$

这里分子是操作**数量**，不是每秒操作数；分母是累计搬运量，不是模型文件大小或峰值显存占用。同一块数据从显存反复读入，可能被计多次；在片上缓存命中的读取，则未必再次跨越显存边界。因此必须注明正在统计 HBM、L2 还是其他层级，并说明是理想流量估计还是实际观测。

<!-- bilingual-en:start -->
The numerator counts operations, not operations per second. The denominator is cumulative traffic, not file size or peak memory occupancy. Repeated device-memory reads may count repeatedly, whereas an on-chip cache hit need not cross that boundary. State the memory level and whether traffic is estimated or measured.
<!-- bilingual-en:end -->

例如，构造一次 $2\times10^9$ FLOP 的计算：若读写 $10^9$ byte，则 $I=2$ FLOP/byte；若通过复用把相同计算的流量降到 $10^8$ byte，则 $I=20$ FLOP/byte。操作数未变，数据搬运却摊到了更多计算上。[[批量复用权重]]和 [[FlashAttention]] 分别展示跨输入复用权重与分块减少中间结果往返的方式。

<!-- bilingual-en:start -->
For a constructed computation of $2\times10^9$ FLOPs, transferring $10^9$ bytes gives an intensity of 2 FLOP/byte. Reducing traffic to $10^8$ bytes raises it to 20 without changing the operation count. [[批量复用权重|Batched weight reuse]] and [[FlashAttention]] illustrate two ways to obtain more work from data movement.
<!-- bilingual-en:end -->

强度较高并不单独证明程序快。要和同一精度、同一存储层级的计算能力及带宽一起看，见 [[Roofline模型]]；线程不足、同步和启动延迟也可能使程序达不到估计上界。

<!-- bilingual-en:start -->
Higher intensity alone does not prove lower runtime. The [[Roofline模型|Roofline model]] also requires compute capacity and bandwidth at matching precision and memory level. Insufficient parallelism, synchronization, and launch latency can keep performance below that bound.
<!-- bilingual-en:end -->
