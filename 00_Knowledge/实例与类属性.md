# 实例属性属于单个对象而类属性由未遮蔽它的实例共享
<!-- bilingual-en:start -->
*Instance attributes belong to one object, while class attributes are shared by instances that do not shadow them*
<!-- bilingual-en:end -->

> [!summary] 原子状态区别
> 类体中的赋值通常建立类属性；`self.name = value` 通常在当前实例上建立或更新实例属性。读取时，实例自己的普通属性会遮蔽同名类属性；写 `obj.name = ...` 不会替其他实例修改类属性。若把本应逐实例独立的可变容器放在类上，所有未遮蔽它的实例就会别名到同一对象。
> <!-- bilingual-en:start -->
> Assignment in a class body normally creates a class attribute, while `self.name = value` normally creates or updates an attribute on the current instance. On reads, an ordinary instance attribute shadows a class attribute of the same name; assigning `obj.name = ...` does not update the class for other instances. If a mutable container that should be per-instance is placed on the class, every instance that has not shadowed it aliases the same object.
> <!-- bilingual-en:end -->

```python
class WrongNotebook:
    pages = []                 # one shared list

    def add(self, page):
        self.pages.append(page)

a = WrongNotebook()
b = WrongNotebook()
a.add("A")
b.pages                       # ["A"]

class Notebook:
    def __init__(self):
        self.pages = []        # one list per instance
```

共享的常量、配置默认值或全类计数器可以合理地放在类属性中；问题不在“类属性可变”本身，而在共享语义是否符合设计。描述器可能拦截实例赋值，因此这里的写入规则是普通属性的默认情形。

若多个实例意外共享容器，还要区分两条不同路径：容器写成类属性属于本卡；构造器把可变对象写成默认参数则属于[[默认参数求值|可变默认参数共享]]。两者都表现为别名，却发生在不同绑定阶段。

> [!question]- 回忆与应用
> 两个实例为什么会意外看到同一张新增页面？
>
> **答案：** 它们都从类上读取同一个可变列表；`append` 修改共享对象，并没有为调用实例自动创建新列表。
