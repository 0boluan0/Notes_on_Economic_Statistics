# Bash命令替换以命令的标准输出替换表达式并删除末尾换行

Bash 的 `$(command)` 是命令替换：在子 Shell 环境中执行内部命令，用其标准输出替换整个表达式，并删除输出末尾的所有换行。内部换行不在这一步删除；stderr 不会自动成为替换结果，退出状态也不是被插入的文本。
<!-- bilingual-en:start -->
Bash `$(command)` is command substitution: it executes the command in a subshell environment, replaces the expression with its standard output, and removes all trailing newlines. Internal newlines are not removed at this step. Standard error is not automatically captured, and the exit status is not the substituted text.
<!-- bilingual-en:end -->

```bash
value=$(printf 'a\n\n')
printf '<%s>\n' "$value"
```

输出为一行 `<a>`，不是保留两个尾换行的文本。赋值右侧不做通常的字段分割；把命令替换直接放进普通参数位置时，`"$(command)"` 才保护结果不再被字段分割和文件名展开。
<!-- bilingual-en:start -->
The result is one line, `<a>`; the two trailing newlines are gone. Ordinary assignment values do not undergo word splitting. In an ordinary argument position, `"$(command)"` protects the result from subsequent word splitting and pathname expansion.
<!-- bilingual-en:end -->

因此 `for file in $(ls)` 不能可靠枚举任意文件名：文件名中的空白可能被分开，通配符可能再次匹配，尾换行也不能保真。应使用[[文件名安全传参]]。命令替换适合取得文本值，不适合作为保持任意字节流不变的容器。
<!-- bilingual-en:start -->
Consequently, `for file in $(ls)` is not a reliable enumeration of arbitrary filenames: whitespace can split names, wildcards can expand again, and trailing newlines are not preserved. Use [[文件名安全传参|safe filename argument handling]]. Command substitution captures textual values; it is not a container that preserves arbitrary byte streams unchanged.
<!-- bilingual-en:end -->
