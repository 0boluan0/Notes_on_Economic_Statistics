# 软件测试是设计并执行检查以发现软件缺陷和评价其行为是否符合要求的活动
<!-- bilingual-en:start -->
*Software testing designs and performs checks to reveal defects and assess whether behavior meets requirements.*
<!-- bilingual-en:end -->

本课聚焦动态测试：在选定输入与条件下运行程序，把返回值、状态变化或失败方式与[[函数契约]]比较。测试回答“这次行为是否符合要求”；已经观察到不符合要求后，解释并修复原因是[[调试]]的责任。
<!-- bilingual-en:start -->
This course focuses on dynamic testing: execute a program under selected inputs and conditions, then compare its result, state changes, or failure behavior with the [[函数契约|function contract]]. Testing asks whether an observed behavior meets the requirement; [[调试|debugging]] explains and repairs a known failure.
<!-- bilingual-en:end -->

例如，回文判断函数对 `['a', 'b']` 应返回 `False`；若实际返回 `True`，这个用例暴露了缺陷。只测 `['a', 'b', 'a']` 并得到 `True`，却不能区分正确实现和“永远返回 `True`”的实现。
<!-- bilingual-en:start -->
A palindrome checker should return `False` for `['a', 'b']`; returning `True` exposes a defect. Passing `['a', 'b', 'a']` alone cannot distinguish a correct implementation from one that always returns `True`.
<!-- bilingual-en:end -->

未穷尽所声明的行为范围时，测试全部通过不构成“所有情况均正确”的证明。增加输入数量也不会无条件给出“程序正确的概率”；仍要检查选例方式和[[测试判据]]是否有发现错误的能力。
<!-- bilingual-en:start -->
Passing tests does not prove correctness over an unexhausted behavioral domain. More inputs do not, without further assumptions, determine a probability that the program is correct; both case selection and the [[测试判据|test oracle]] must be capable of detecting errors.
<!-- bilingual-en:end -->
