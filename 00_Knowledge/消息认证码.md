# 消息认证码用共享秘密密钥校验消息完整性与持钥来源
<!-- bilingual-en:start -->
*A message authentication code uses a shared secret key to verify message integrity and key-holder origin*
<!-- bilingual-en:end -->

> [!summary] 它是什么
> 消息认证码（MAC）把消息和共享秘密密钥送入生成算法，得到一段较短的 tag。验证方用同一秘密密钥、消息和 tag 检查结果；在算法与密钥假设成立时，验证成功说明消息未被不持钥者修改，并且 tag 来自某个持钥者。
> <!-- bilingual-en:start -->
> A message authentication code takes a message and a shared secret key and produces a short tag. A verifier checks the message and tag with the same secret key. Under the algorithm and key assumptions, successful verification indicates that the message was not modified by a party without the key and that some key holder generated the tag.
> <!-- bilingual-en:end -->

HMAC、KMAC 和 CMAC 都是 MAC 构造，但内部基础不同。HMAC 用密码学 hash 与密钥构造 MAC；它不是把 `key || message` 随意拼接后再做一次普通 hash。选择具体方案时应使用标准构造和成熟库，而不是从原语名称自行组合。
<!-- bilingual-en:start -->
HMAC, KMAC, and CMAC are MAC constructions with different foundations. HMAC constructs a MAC from a cryptographic hash and a key; it is not an arbitrary hash of `key || message`. A concrete scheme should come from a standard construction and mature library rather than an improvised combination of primitives.
<!-- bilingual-en:end -->

MAC 认证消息但不加密消息，明文仍可见。它的“来源”也只到持有共享密钥的集合为止；若要判断集合内究竟是谁生成 tag，需要另看 [[MAC 的来源边界]]。
<!-- bilingual-en:start -->
A MAC authenticates but does not encrypt the message, so plaintext remains visible. Its origin claim reaches only the set of shared-key holders; deciding which holder generated a tag requires the separate [[MAC 的来源边界|MAC origin boundary]].
<!-- bilingual-en:end -->

> [!question]- 自检
> 验证方收到消息、tag 和共享密钥后，MAC 验证究竟在检查什么？
>
> **答案：** 它检查这条消息与 tag 是否能由同一秘密密钥按约定算法产生，从而排除没有密钥者的篡改或伪造；它不解密消息，也不区分共享密钥的不同持有者。

## 来源与核验

- [NIST Message Authentication Codes project](https://csrc.nist.gov/Projects/message-authentication-codes)：核对 MAC 从消息生成、用于保证消息完整性与来源认证，并要求发送方和接收方建立秘密密钥；页面同时列出 HMAC、KMAC 与 CMAC。
- [NIST FIPS 198-1, *The Keyed-Hash Message Authentication Code*](https://csrc.nist.gov/pubs/fips/198-1/final)：核对 HMAC 使用密码学 hash 与共享秘密密钥提供消息认证；截至 2026-09-01，该 FIPS 仍列为 final，NIST 已提出日后迁移到 SP 800-224，但尚未完成替代。
