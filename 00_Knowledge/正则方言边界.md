# 使用正则表达式前必须确定工具、方言和选项的语义

<!-- bilingual-en:start -->
*Regular-expression syntax depends on the tool, dialect, and options*
<!-- bilingual-en:end -->

相同字符在不同匹配模式中可能含义不同。`grep` 默认使用 BRE，`grep -E` 使用 ERE，`grep -F` 则按固定字符串匹配而不解释正则元字符。ERE 中的 `+`、`?`、`|` 和圆括号有组合意义；BRE 不能简单照抄这套写法。

<!-- bilingual-en:start -->
The same characters can have different meanings in different matching modes. `grep` defaults to BRE, `grep -E` uses ERE, and `grep -F` matches fixed strings without interpreting regular-expression metacharacters. In ERE, `+`, `?`, `|`, and parentheses have compositional roles; their spelling cannot simply be copied into BRE.
<!-- bilingual-en:end -->

```bash
printf '%s\n' 'a+b' 'aaab' | grep -F 'a+b'
printf '%s\n' 'a+b' 'aaab' | grep -E 'a+b'
```

第一条输出字面量 `a+b`，第二条输出包含“一个或多个 `a` 后接 `b`”的 `aaab`。GNU BRE 把 `\+`、`\?`、`\|` 当作扩展运算符；不能由 GNU 的行为推断任意 BRE 实现都这样处理。需要这些 ERE 功能时，显式选择已确认支持的 ERE 模式更清楚。

<!-- bilingual-en:start -->
The first command outputs literal `a+b`; the second outputs `aaab`, which contains one or more `a` characters followed by `b`. GNU BRE treats `\+`, `\?`, and `\|` as extended operators, but that does not establish the behavior of every BRE implementation. Explicitly selecting a supported ERE mode makes the intended syntax clearer.
<!-- bilingual-en:end -->

还要分开三个解释层：[[Shell引用|Shell 引号]]决定传给程序的参数，正则引擎解释模式，`sed` 的替换部分另有 `&`、`\1` 等规则。Shell 的文件名通配符也不是正则表达式。课程所用 GNU/BSD `sed -E` 已广泛部署，但它成为 POSIX 标准选项是在 2024 版；该版还引入了最短重复等新规则，不能据此假定旧机器已经实现。

<!-- bilingual-en:start -->
Keep three interpretation layers separate: [[Shell引用|Shell quoting]] determines the argument passed to a program, the regex engine interprets the pattern, and a `sed` replacement has its own rules for `&`, `\1`, and related syntax. Shell filename patterns are not regular expressions either. GNU/BSD `sed -E` is widely deployed, but it became a POSIX option in the 2024 edition. That edition also introduced minimal-repetition rules, which should not be assumed on older installations.
<!-- bilingual-en:end -->
