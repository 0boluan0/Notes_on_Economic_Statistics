# 本地 Git 仓库不能替代独立异地备份

<!-- bilingual-en:start -->
*A local Git repository cannot replace an independent off-site backup*
<!-- bilingual-en:end -->

> [!summary] 原子边界
> Git 只保护已经进入对象数据库且仍可恢复的内容；同一磁盘上的 working tree 与 `.git` 会一起遭遇硬件损坏、误删或勒索软件。备份还要求独立故障域、保留策略和经过验证的恢复过程。
>
> <!-- bilingual-en:start -->
> Git can protect only content that entered its object database and remains recoverable. A working tree and `.git` directory on the same disk share exposure to hardware failure, deletion, or ransomware. Backup additionally requires an independent failure domain, retention policy, and tested restoration process.
> <!-- bilingual-en:end -->

Git 很擅长回答“哪些提交来自哪些提交”和“两个快照有什么差异”，却不会自动覆盖：

- 尚未提交或被 `.gitignore` 排除的文件；
- 仓库之外的数据库、凭据、系统配置与外部服务状态；
- 只存在于某个仓库的 reflog，以及未被传输 refs 纳入可达图的本地对象；
- 被所有同步副本共同删除或被强制改写的历史；
- 仓库所在设备本身的损坏或丢失。

<!-- bilingual-en:start -->
Git excels at ancestry and snapshot comparison, but it does not automatically cover uncommitted or ignored files; external databases, credentials, and service state; local-only reflogs and objects not reachable from the refs transferred to another copy; history deleted or force-rewritten across every synchronized copy; or loss of the device holding the repository.
<!-- bilingual-en:end -->

把所需 refs 推送到独立远程，至少会增加一份从这些 refs 可达的对象副本；但是否构成合格备份仍取决于权限隔离、不可变或分代保留、地理/账户独立性和恢复演练。最小验证不是“远程页面能打开”，而是能在另一个干净位置恢复仓库及其必要的外部状态。
<!-- bilingual-en:start -->
Pushing the required refs to an independent remote adds a copy of the objects reachable from those refs, but whether it is an adequate backup still depends on permission isolation, immutable or versioned retention, geographic or account independence, and restore testing. The minimum proof is not that a remote page opens, but that the repository and its required external state can be restored in a clean location.
<!-- bilingual-en:end -->

> [!question]- 回忆与辨别
> 项目每天 commit，但从不 push，也不做系统备份。硬盘损坏后 Git 能否恢复？
>
> **答案：** 不能；对象数据库与工作区都在同一故障域，硬盘损坏会同时带走它们。

## 来源与核验

- Git 官方文档，[`gitdatamodel`](https://git-scm.com/docs/gitdatamodel)：核验 Git 保护的是对象数据库中的 commit、tree 与 blob，并以 references 定义可达位置。
- Git 官方文档，[`git-reflog`](https://git-scm.com/docs/git-reflog)：核验本地恢复线索会过期且只记录本地引用移动，支持其不能充当永久异地备份的边界结论。
- [*Pro Git: Getting a Git Repository*](https://git-scm.com/book/en/v2/Git-Basics-Getting-a-Git-Repository)：核验 clone 获得远程仓库中几乎全部数据的独立副本；备份要求则是据此作出的系统设计判断。
