# 函数形参数组会调整为指针而可访问边界必须由接口另行表达
<!-- bilingual-en:start -->
*An array parameter is adjusted to a pointer, so the interface must express accessible bounds elsewhere*
<!-- bilingual-en:end -->

> [!summary] 原子边界
> 在函数参数声明中，写成“某类型的数组”的形参会调整为指向该元素类型的指针。`void f(int a[10])` 并不会把十个 `int` 复制进函数，也不会让函数从 `a` 的类型恢复调用者数组长度；在参数类型层面它仍是 `int *`。
> <!-- bilingual-en:start -->
>
> &nbsp;
> In a function parameter declaration, a parameter written as an array of some type is adjusted to a pointer to that element type. `void f(int a[10])` neither copies ten integers into the function nor lets the function recover the caller's array length from `a`'s type; at the parameter-type level it is still `int *`.
> <!-- bilingual-en:end -->

```c
#include <stdbool.h>
#include <stddef.h>

bool contains_zero(const int values[], size_t n) {
    for (size_t i = 0; i < n; i++) {
        if (values[i] == 0) {
            return true;
        }
    }
    return false;
}
```

这里 `n` 不是可有可无的装饰，而是接口契约的一部分：调用方承诺 `values` 指向至少 `n` 个可读元素，函数只访问 `[0,n)`。长度也可以由哨兵、固定协议或把指针与长度封装在结构体中表达；关键不是“必须多传一个整数”，而是不能从已经调整的指针形参反推出调用者数组长度。函数内部对参数 `values` 使用 `sizeof values / sizeof values[0]` 得到的是指针大小相关结果，最多偶然等于某个元素个数，绝不是可靠的调用者数组长度。
<!-- bilingual-en:start -->
Here `n` is not optional decoration but part of the interface contract: the caller promises that `values` designates at least `n` readable elements, and the function accesses only `[0,n)`. A sentinel, a fixed protocol, or a structure that carries pointer and length can express the boundary instead; the essential rule is not “always pass another integer” but “do not infer the caller's array length from an adjusted pointer parameter.” Inside the function, `sizeof values / sizeof values[0]` is based on the pointer size and can at most coincide accidentally with an element count; it is not a reliable caller-array length.
<!-- bilingual-en:end -->

## `static` 下界仍不是运行时长度对象

在参数中写 `int a[static 10]` 表达：每次调用时，实参必须提供对一个至少含十个元素的数组首元素的访问。若函数定义中的可变下界表达式实际被求值，每次求值都必须为正；函数原型作用域中的非常量数组大小则按 `*` 处理，不能依赖其中的副作用。这个写法给实现更多契约信息，却仍调整为指针，也不会自动携带一个可查询的长度；违反最小元素承诺是违反语言要求，而不是触发自动边界检查。普通的 `int a[10]` 没有这项 `static` 最小下界保证。
<!-- bilingual-en:start -->
Writing `int a[static 10]` as a parameter requires every call to provide access to the first element of an array of at least ten elements. If a variable bound in the function definition is actually evaluated, each evaluation must be positive; a nonconstant array size at function-prototype scope is instead treated as `*`, so its side effects must not be relied upon. The spelling gives the implementation a stronger contract, but the parameter is still adjusted to a pointer and carries no queryable length; violating the minimum-element requirement violates the language requirement rather than triggering automatic bounds checking. Plain `int a[10]` supplies no such `static` minimum-bound guarantee.
<!-- bilingual-en:end -->

## 边界

形参数组调整是函数声明语境中的专门规则，不能推广成“数组等于指针”。真正数组对象、普通表达式转换、`sizeof` 和一元 `&` 的区别，以及字符串字面量初始化这一例外，统一见[[数组到指针转换|数组对象与数组到指针转换]]。本原子只保留一个直接后果：函数体中的参数 `a` 已是指针，所以 `sizeof a` 得到调整后指针类型的大小，而不是调用者数组的总字节数。
<!-- bilingual-en:start -->
Array-parameter adjustment is a special function-declaration rule and must not be generalised into “an array is a pointer.” The distinct array object, ordinary expression conversion, `sizeof`, unary `&`, and string-literal initialisation boundary are treated in the dedicated array-conversion atom. The direct consequence retained here is that parameter `a` is already a pointer inside the function, so `sizeof a` sees the adjusted pointer type rather than the caller's complete array.
<!-- bilingual-en:end -->

> [!question]- 自检
> 为什么 `void print_all(int a[100])` 仍不能在函数内可靠地推断调用者确实传了 100 个元素？
>
> **答案：** 参数声明调整为 `int *`；方括号中的普通 `100` 不成为运行时长度。可访问边界必须由长度参数、哨兵、固定协议或更高层数据结构另行表达并验证。
