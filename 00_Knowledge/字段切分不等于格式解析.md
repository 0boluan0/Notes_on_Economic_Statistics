# 按分隔符切字段不能自动解析带引号、转义或嵌套的数据格式

<!-- bilingual-en:start -->
*Delimiter-based field splitting does not automatically parse quoted, escaped, or nested formats*
<!-- bilingual-en:end -->

按分隔符切分只执行给定的切分规则，不自动理解字段内部的引号或转义。例如 `awk -F ','` 会把 `Alice,"hello, world"` 切成三个字段，而按通常 CSV 引号规则，这其实是两个字段。外层 Shell 引号只能保护命令参数，不能替数据补上 CSV 解析语义。

<!-- bilingual-en:start -->
Delimiter splitting applies its specified separator rule; it does not automatically understand quoting or escaping inside fields. For example, `awk -F ','` splits `Alice,"hello, world"` into three fields, whereas ordinary CSV quoting makes it a two-field record. Shell quoting protects command arguments; it does not add CSV parsing semantics to the data.
<!-- bilingual-en:end -->

```python
import csv

print(next(csv.reader(['Alice,"hello, world"'])))
# ['Alice', 'hello, world']
```

若输入契约明确规定字段不能含 TAB 或换行，按 TAB 分隔的逐行文本可以用相应的 `awk -F` 程序处理；若允许这些字符出现在带引号字段中，就必须采用理解该格式的解析器。解析器同样需要正确的方言设置，以及字段数、类型与业务范围检查。

<!-- bilingual-en:start -->
A line-oriented tab-delimited format can be processed by an appropriate `awk -F` program when its contract excludes tabs and newlines inside fields. If quoted fields may contain those characters, use a parser that understands the format. A parser still requires the correct dialect and checks on field counts, types, and domain constraints.
<!-- bilingual-en:end -->

字段编号也不是通用语义：日志中的 `$9` 只有在已核实的具体布局中才可能表示状态码。类似地，从 `2 alice smith` 使用 `awk '{print $2}'` 只能得到 `alice`，不能保留完整名字 `alice smith`。下游排序和计数无法挽回上游丢失的内容。

<!-- bilingual-en:start -->
Field numbers are not universal meanings: `$9` denotes a status code only under a verified, specific log layout. Likewise, `awk '{print $2}'` on `2 alice smith` yields only `alice`, not the complete name `alice smith`. Downstream sorting and counting cannot recover information lost upstream.
<!-- bilingual-en:end -->
