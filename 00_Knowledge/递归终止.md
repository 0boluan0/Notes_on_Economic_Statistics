# 递归终止要求所有递归调用沿共同良基关系严格下降并覆盖基本情况

<!-- bilingual-en:start -->
*Recursive termination requires every recursive call to descend along a common well-founded relation and every reachable bottom form to be handled directly*
<!-- bilingual-en:end -->

> [!summary] 原子证明义务
> 要证明递归一定结束，应给每个尚未完成的调用赋一个秩 $r(x)$，使它落在不存在无限严格下降链的集合中；非负整数是最常见的选择。随后逐一检查：当前输入若不属于直接停止的情况，它产生的**每一个**递归子调用 $y$ 都满足 $r(y)<r(x)$，而所有可能到达且不能再下降的形态都有直接处理分支。

例如对 $b\ge 0$ 的 Euclidean algorithm：

```python
def gcd(a, b):
    if b == 0:
        return abs(a)
    return gcd(b, a % b)
```

当 `b > 0` 时，Python 的非负余数满足 $0\le a\bmod b<b$，所以可取秩 $r(a,b)=b$。每一步严格下降，最终只能到达 `b == 0`。这比“参数看起来变小了”更强，因为它同时固定了论域、比较关系和所有分支的检查对象。

常见漏洞包括：

- 只检查主分支，而遗漏某个可能保持原规模或增大规模的递归调用。
- 度量虽然偶尔下降，却可能在不同调用之间反复回升；终止需要沿每条调用边严格下降。
- 基本情况写在代码里，却位于不可达的值上。例如从正整数不断加 1，永远到不了 `0`。
- 多参数或互递归并不要求只看一个整数；可以用字典序元组，或对“当前函数名与参数”一起定义良基秩。

终止与答案正确仍是两个问题。严格下降只能保证调用结束；递归步骤是否保留规格，要用归纳、不变量或其他正确性论证另证。

> [!question]- 自检
> `f(n)` 的一个分支调用 `f(n - 1)`，另一个分支调用 `f(n + 1)`；代码也写了 `n == 0` 的基本情况。能用秩 $r(n)=n$ 证明它在所有非负输入上终止吗？
>
> **答案：** 不能。第二个分支使秩增大，而且可能永远不进入 `n == 0`。必须排除该分支、换成真正共同下降的良基秩，或承认目前没有终止证明。
