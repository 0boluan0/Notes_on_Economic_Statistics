# 一元 & 取得地址而实际求值的一元 * 只能间接访问有效指针
<!-- bilingual-en:start -->
*Unary `&` obtains an address, while an actually evaluated unary `*` may indirect only through a valid pointer*
<!-- bilingual-en:end -->

> [!summary] 两个表达式运算符
> 对可取地址的对象左值 `x`，一元 `&x` 产生指向 `x` 的指针值。对指向有效对象的指针 `p`，一元 `*p` 产生指代该对象的左值；读取 `*p` 读取对象，给 `*p` 赋值则写对象。声明中的 `*` 用来构造指针类型，表达式中的一元 `*` 才是间接访问，不能因字形相同而混为一步。
> <!-- bilingual-en:start -->
> For an addressable object lvalue `x`, unary `&x` produces a pointer to `x`. For a pointer `p` that validly designates an object, unary `*p` produces an lvalue designating that object. The asterisk in a declaration constructs a pointer type; unary `*` in an expression performs indirection.
> <!-- bilingual-en:end -->

```c
void indirection_example(void) {
    int n = 7;
    int *p = &n;  // 声明中的 *；表达式中的 &
    int copy = *p;
    *p = 9;
    (void) copy;
}
```

执行后 `copy` 是 `7`，`n` 是 `9`。`p` 仍只是一个被复制和读取的指针值；真正修改 `n` 的是最后一行通过 `*p` 得到 `n` 的左值后写入。
<!-- bilingual-en:start -->
After execution, `copy` is `7` and `n` is `9`. The pointer value itself is merely read; the last line modifies `n` through the lvalue produced by `*p`.
<!-- bilingual-en:end -->

“类型正确”不等于“可解引用”。实际求值 `*p` 时，`p` 必须是适合所需类型和对齐要求、并指向仍在生命周期内对象的有效值；空指针、未初始化得到的未确定指针、对象寿命结束后的旧指针都不能用于这种访问。写入还要求该对象能通过这条访问路径修改，例如不能通过 `const int *` 写 `int`。
<!-- bilingual-en:start -->
Correct static type is not enough. When `*p` is actually evaluated, `p` must validly designate a live object with suitable type and alignment. Null, indeterminate, and lifetime-expired pointer values cannot support that access; writing additionally requires a modifiable access path.
<!-- bilingual-en:end -->

有一个重要的语义边界：标准把 `&*p` 规定为好像两个运算符都被删掉，二者并不实际求值，所以即使 `p` 是空指针，这个表达式也只是得到原指针值，并没有访问空地址。相反，单独求值 `*p` 或读取 `*p` 仍要求有效指针。这个例外不能拿来为真实解引用开脱。
<!-- bilingual-en:start -->
There is a precise boundary: in `&*p`, the two operators cancel semantically and no indirection is evaluated, even if `p` is null. An evaluated `*p` still requires a valid pointer; the cancellation rule does not legitimise a real dereference.
<!-- bilingual-en:end -->

> [!question]- 最小自检
> 为什么在 `int *p;` 之后、尚未给 `p` 赋确定值时求值 `*p`，即使通过语法检查也不成立？
>
> **答案：** `p` 的类型虽然是 `int *`，其自动对象却未初始化，保存的是未确定值；实际解引用不满足有效指针前提。
