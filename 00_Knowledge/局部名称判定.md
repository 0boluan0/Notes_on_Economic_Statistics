# 函数块内出现名称绑定会使该名称默认为局部并可能触发先读后绑错误
<!-- bilingual-en:start -->
*A binding anywhere in a function block makes that name local by default and can cause a read-before-bind error*
<!-- bilingual-en:end -->

> [!summary] 原子作用域规则
> 若函数代码块内存在对某名称的绑定操作，Python 默认把该块中对此名称的使用都解释为局部变量，除非用 `global` 或 `nonlocal` 声明改变目标。判定依据是整个代码块，不是运行时先走到哪一行；因此在首次局部绑定之前读取该名称，会抛出 `UnboundLocalError`，而不会临时退回同名外层绑定。
> <!-- bilingual-en:start -->
> If a function block contains a binding operation for a name, Python treats uses of that name in the block as local unless `global` or `nonlocal` redirects the binding. The whole block determines this classification, not the path executed first, so reading the name before its first local binding raises `UnboundLocalError` rather than temporarily falling back to an outer binding.
> <!-- bilingual-en:end -->

```python
x = 10

def increment():
    print(x)  # x is already classified as local for this block
    x += 1   # binding operation
```

“绑定操作”不只包括普通赋值，还包括形参、import、循环 target 等能建立名称绑定的语法。读取一个在函数块内从未绑定的名称，才会继续按外层作用域解析。局部名称遮蔽外层同名绑定并不修改外层对象；是否共享对象还要另看这些绑定实际指向什么。

整块扫描只针对“当前代码块”：嵌套的另一个函数体或类体是独立代码块，其内部赋值不会倒过来把外层函数的同名名称判为局部。判断作用域时应先标出代码块边界，再在每块内找绑定语法。

> [!question]- 自检
> 为什么把 `x += 1` 放在 `if False:` 内，也可能让同一函数更早的 `print(x)` 报 `UnboundLocalError`？
>
> **答案：** 局部名称由整个代码块中的绑定语法判定，不取决于该分支运行时是否执行。
