# Topological order
<!-- bilingual-en:end -->
*拓扑序*

<!-- bilingual-en:start -->
A **topological order** arranges all vertices of a directed graph in one list so that every arrow points from an earlier entry to a later entry. For tasks, it answers a basic question: in what sequence can we perform them one at a time while respecting the stated prerequisite edges? The list is the result; **topological sorting** is the task of finding such a list or determining that none exists.
<!-- bilingual-en:end -->
**拓扑序**把有向图的全部顶点排成一个列表，使每条箭头都从较早位置指向较晚位置。对任务而言，它回答一个基本问题：按什么顺序逐项执行，才能遵守给定的先修边？列表是结果；**拓扑排序**则是寻找这种列表、或判定不存在这种列表的任务。

<!-- bilingual-en:start -->
## Read a proposed order edge by edge
<!-- bilingual-en:end -->
*逐条边检查一个候选顺序*

<!-- bilingual-en:start -->
Suppose $A$ and $B$ are two preparations, $C$ combines their results, and $D$ uses that combined result. The [[图模型语义|edge meaning]] is “prerequisite first”: $A\to C$, $B\to C$, and $C\to D$. The list $(A,B,C,D)$ respects every edge. So does $(B,A,C,D)$, because no requirement fixes the relative order of $A$ and $B$. The list $(A,C,B,D)$ fails: the edge $B\to C$ would point backward in it.
<!-- bilingual-en:end -->
设 $A,B$ 是两项准备工作，$C$ 合并它们的结果，$D$ 再使用合并结果。[[图模型语义|边的含义]]是“前置任务先做”，边为 $A\to C$、$B\to C$、$C\to D$。列表 $(A,B,C,D)$ 遵守每条边，$(B,A,C,D)$ 也遵守，因为没有要求固定 $A,B$ 的相对顺序。$(A,C,B,D)$ 则不合法，其中 $B\to C$ 会朝列表前方指去。

<!-- bilingual-en:start -->
## Include each vertex exactly once
<!-- bilingual-en:end -->
*每个顶点恰好出现一次*

<!-- bilingual-en:start -->
Let $G=(V,E)$ be a finite [[图类型的建模边界|directed graph]], with $n=|V|$ vertices. A topological order is a list $(v_1,\ldots,v_n)$ containing **every vertex exactly once**, subject to this rule: whenever there is an edge $v_i\to v_j$, its indices satisfy $i<j$. Equivalently, let $\operatorname{pos}(v)$ denote the position assigned to vertex $v$; all positions $1,\ldots,n$ are used exactly once, and
<!-- bilingual-en:end -->
设 $G=(V,E)$ 是有限[[图类型的建模边界|有向图]]，顶点数为 $n=|V|$。拓扑序是**包含每个顶点恰好一次**的列表 $(v_1,\ldots,v_n)$，并满足：只要存在边 $v_i\to v_j$，下标就必须有 $i<j$。等价地，用 $\operatorname{pos}(v)$ 表示顶点 $v$ 在列表中的位置；位置 $1,\ldots,n$ 各使用一次，且

$$u\to v\text{ is an edge}\quad\Longrightarrow\quad\operatorname{pos}(u)<\operatorname{pos}(v).$$

<!-- bilingual-en:start -->
This strict inequality disallows ties. A layer number shared by several vertices can be useful for parallel scheduling, but it is not yet a list position: the vertices in a layer still have to be put in some order. Omitting an isolated vertex or repeating a vertex also fails the definition, even if all checked edges point forward.
<!-- bilingual-en:end -->
这里使用严格不等式，所以位置不能并列。供多个顶点共用的层数可以帮助并行调度，却还不是列表位置：同一层内的顶点仍要排出先后。遗漏孤立顶点或重复某个顶点也不符合定义，即使已经检查的所有边都朝向列表后方。

<!-- bilingual-en:start -->
Checking the edges also checks every positive-length [[游走路径与环|directed path]]. Along $u=x_0\to x_1\to\cdots\to x_k=v$, positions increase at each step, so $\operatorname{pos}(u)<\operatorname{pos}(v)$. Conversely, each non-loop edge is a one-edge path; a self-loop is excluded separately by the strict position inequality. On a DAG there are no self-loops, so the MIT MCS definition can equivalently require each vertex to come before every other vertex reachable from it.
<!-- bilingual-en:end -->
检查边也就检查了每条正长度的[[游走路径与环|有向路径]]。沿着 $u=x_0\to x_1\to\cdots\to x_k=v$，位置每一步都严格增加，所以 $\operatorname{pos}(u)<\operatorname{pos}(v)$。反过来，每条非自环边都是一步路径；自环则由严格的位置不等式单独排除。在 DAG 中没有自环，因此 MIT MCS 的定义也可以等价地要求：每个顶点都排在从它可达的其他顶点之前。

> [!warning] A list need not be a path · 列表不必是一条路径
> <!-- bilingual-en:start -->
> In $(A,B,C,D)$ above, $A$ and $B$ are consecutive even though there is no edge $A\to B$. A topological order lists vertices; it does not claim that consecutive entries are joined by edges. Nor does placing $A$ before $B$ create a new prerequisite relation. Another valid list may reverse them.
> <!-- bilingual-en:end -->
> 上例 $(A,B,C,D)$ 中，$A,B$ 在列表里相邻，却没有边 $A\to B$。拓扑序是在列举顶点，并没有声称相邻项必有边相连。把 $A$ 写在 $B$ 前也没有创造一条新的依赖关系；另一份合法列表可以颠倒二者。

## Existence and boundary cases
<!-- bilingual-en:end -->
*存在性与边界情形*

<!-- bilingual-en:start -->
A directed cycle prevents a topological order: following its arrows would require positions to increase strictly and finally return to the starting position. A self-loop already requires the impossible inequality $\operatorname{pos}(v)<\operatorname{pos}(v)$. The converse for finite graphs—that a [[有向无环图|DAG]] has a topological order—is proved in [[DAG 与拓扑序等价|the equivalence theorem]]. The [[Kahn 拓扑排序与环证书|Kahn algorithm]] and [[DFS 逆完成序拓扑排序|reverse DFS finishing order]] give specific construction methods under their stated conditions.
<!-- bilingual-en:end -->
有向环会阻止拓扑序存在：沿环的箭头，位置必须严格增加，最后却又回到起始位置。一个自环就已经要求不可能的不等式 $\operatorname{pos}(v)<\operatorname{pos}(v)$。有限图中的反向结论——[[有向无环图|DAG]] 一定有拓扑序——见[[DAG 与拓扑序等价|等价定理]]的证明。[[Kahn 拓扑排序与环证书|Kahn 算法]]与[[DFS 逆完成序拓扑排序|DFS 逆完成顺序]]则在各自条件下提供具体构造方法。

<!-- bilingual-en:start -->
The graph need not be connected. An isolated vertex can be inserted anywhere into a valid order of the other vertices. With no edges, every listing of all vertices exactly once is valid. Under the explicitly allowed empty-graph convention, there is one topological order of the empty graph: the empty list. Repeated parallel arrows impose the same position inequality more than once and do not change which lists satisfy it.
<!-- bilingual-en:end -->
图不必连通。一个孤立顶点可以插入其他顶点合法顺序的任意位置。若没有边，凡是把全部顶点恰好列一次的排列都合法。若明确允许空图，则空图恰有一个拓扑序：空列表。重复的同向平行边只是重复要求同一个位置不等式，不改变哪些列表符合条件。

<!-- bilingual-en:start -->
A topological order need not be unique, as the two valid lists in the example show; [[拓扑序的线性扩张|the linear-extension distinction]] develops that freedom further. Positions are order numbers, not starting times or durations. Even a valid order does not by itself minimize completion time or account for limited workers. The meaning of an edge must also be kept fixed: if arrows mean “depends on” instead of “must precede,” execution follows the reverse of the edge-respecting list.
<!-- bilingual-en:end -->
拓扑序不必唯一，例中的两个合法列表已经说明这一点；[[拓扑序的线性扩张]]进一步讨论这种自由度。位置是顺序编号，不是开始时间或持续时间。合法顺序本身也不会自动使工期最短，或自动考虑人手限制。同时还要固定边的含义：如果箭头表示“依赖于”，而不是“必须先于”，实际执行次序就应当与沿边要求的列表相反。
