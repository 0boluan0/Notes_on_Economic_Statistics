# 排序算法
<!-- bilingual-en:start -->
*Sorting Algorithms*
<!-- bilingual-en:end -->

> [!summary] 快速恢复
> **它解决什么：** 按比较规则重排元素，并依据输入规模、已有顺序、稳定性、内存与写入成本选择算法。
> **具体锚点：** insertion sort 在近有序小数组上只移动少量元素，merge sort 则为任意输入提供稳定的 $\Theta(n\log n)$ 时间。
> **核心难点：** “更快”必须说明输入分布、最坏/平均情形、稳定性和额外空间；比较次数不是唯一成本。
> **为什么重要：** 排序常是搜索、去重、分组和展示的前置步骤，错误的算法选择会把后续流水线拖慢。
> **继续：** 先写清排序键、稳定性与内存要求，再比较候选算法。
> <!-- bilingual-en:start -->
> **Problem addressed:** Reorder elements under a comparison rule and select an algorithm from input size, existing order, stability, memory, and write cost.
> **Concrete anchor:** Insertion sort moves few elements in a small, nearly sorted array, while merge sort gives stable $\Theta(n\log n)$ time for arbitrary input.
> **Central difficulty:** “Faster” must specify input distribution, worst or average case, stability, and auxiliary space; comparisons are not the only cost.
> **Why it matters:** Sorting often precedes search, deduplication, grouping, or display, so a poor choice can dominate the whole pipeline.
> **Continue with:** State the key, stability requirement, and memory budget before comparing candidates.
> <!-- bilingual-en:end -->

## 选择、冒泡与插入
<!-- bilingual-en:start -->
*Selection, Bubble, and Insertion Sort*
<!-- bilingual-en:end -->

selection sort O(n²) 比较且交换少；bubble sort O(n²) 并交换相邻，适合教学不常实用；insertion sort 最坏 O(n²)、对小/近有序数据好，常作为混合算法基例。
<!-- bilingual-en:start -->
Selection sort makes O(n²) comparisons but relatively few swaps. Bubble sort makes O(n²) work through adjacent swaps and is mainly pedagogical. Insertion sort is O(n²) in the worst case but effective for small or nearly sorted input, so hybrid algorithms often use it as a base case.
<!-- bilingual-en:end -->

## merge sort
<!-- bilingual-en:start -->
*Merge Sort*
<!-- bilingual-en:end -->

分半、递归排序、线性合并，时间 Theta(n log n)，稳定但通常需额外空间。比较排序一般下界 Omega(n log n)，依赖比较模型和任意键顺序。
<!-- bilingual-en:start -->
Merge sort divides the sequence, sorts each half recursively, and merges in linear time. It runs in Theta(n log n), is stable, and normally needs auxiliary space. The general Omega(n log n) lower bound for comparison sorting assumes the comparison model and arbitrary key order.
<!-- bilingual-en:end -->

## 选择标准
<!-- bilingual-en:start -->
*Selection Criteria*
<!-- bilingual-en:end -->

稳定排序保持相等键的原顺序；原地性限制额外存储；自适应算法利用已有顺序。实际选择还受数据移动成本、缓存局部性和语言内置实现影响，生产代码通常先用经过验证的标准库排序。
<!-- bilingual-en:start -->
A stable sort preserves the original order of equal keys, an in-place algorithm limits auxiliary storage, and an adaptive algorithm exploits existing order. Data-movement cost, cache locality, and the language's built-in implementation also matter; production code should normally begin with the verified standard-library sort.
<!-- bilingual-en:end -->

## Worked example：昂贵写入时为什么选 selection sort
<!-- bilingual-en:start -->
*Worked Example: Why Selection Sort Can Win When Writes Are Expensive*
<!-- bilingual-en:end -->

若比较便宜而写入外部存储极贵，selection sort 的 $\Theta(n^2)$ 比较但 O(n) swaps 可能优于频繁移动元素的 insertion sort。只按渐近比较次数选算法会漏掉实际基本操作成本。
<!-- bilingual-en:start -->
If comparisons are cheap but writes to external storage are very expensive, selection sort's $\Theta(n^2)$ comparisons but O(n) swaps can outperform insertion sort's frequent movement. Choosing solely from asymptotic comparison count misses the actual primitive-operation cost.
<!-- bilingual-en:end -->

## 失败诊断
<!-- bilingual-en:start -->
*Failure Diagnosis*
<!-- bilingual-en:end -->

- 相同键顺序被打乱：确认业务是否要求稳定，并检查实现是否在相等时也交换。
  <!-- bilingual-en:start -->
  Equal-key order changes: determine whether the requirement needs stability and whether the implementation swaps equal elements.
  <!-- bilingual-en:end -->
- 递归排序漏元素：明确半开区间，验证每个元素恰好进入一个子问题并在合并时恰好输出一次。
  <!-- bilingual-en:start -->
  A recursive sort loses elements: use explicit half-open intervals and verify that each element enters one subproblem and is emitted exactly once during merge.
  <!-- bilingual-en:end -->
- 小数组标准库更快：常数、原生实现和自适应策略可主导小 n，这不否定增长阶。
  <!-- bilingual-en:start -->
  The standard library wins on small arrays: constants, native code, and adaptive strategies can dominate small n without contradicting asymptotic growth.
  <!-- bilingual-en:end -->

*Minimum Self-Check*

### merge sort 的主要取舍是什么？
<!-- bilingual-en:start -->
*What is the central trade-off of merge sort?*
<!-- bilingual-en:end -->

> [!answer]- 答案
> 稳定且保证 n log n 时间，但通常需要额外合并空间和数据复制。
> <!-- bilingual-en:start -->
> It is stable and guarantees n log n time, but normally requires auxiliary merge space and data copying.
> <!-- bilingual-en:end -->

### 近有序小数组为何常用 insertion sort？
<!-- bilingual-en:start -->
*Why is insertion sort often used for a small, nearly sorted array?*
<!-- bilingual-en:end -->

> [!answer]- 答案
> 逆序对少时移动量小，循环简单且常数低；最坏 O(n²) 仍要求规模受控。
> <!-- bilingual-en:start -->
> Few inversions mean little movement, and the simple loops have low constants; its O(n²) worst case still requires a controlled input size.
> <!-- bilingual-en:end -->

### “稳定排序”保证什么，不保证什么？
<!-- bilingual-en:start -->
*What does a stable sort guarantee, and what does it not guarantee?*
<!-- bilingual-en:end -->

> [!answer]- 答案
> 它保持相等键元素的相对顺序；不保证原地、低内存或某个时间复杂度。
> <!-- bilingual-en:start -->
> It preserves the relative order of elements with equal keys; it does not guarantee in-place operation, low memory use, or a particular time bound.
> <!-- bilingual-en:end -->
