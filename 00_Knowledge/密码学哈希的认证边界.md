# 普通密码学 hash 能检测变化，但不能认证可被攻击者一同替换的数据
<!-- bilingual-en:start -->
*An unkeyed cryptographic hash detects change but cannot authenticate data that an attacker can replace together with its digest*
<!-- bilingual-en:end -->

> [!summary] 原子边界
> 普通 hash 没有秘密输入，任何人都能为任意消息重新计算摘要。因此，比较摘要能否成为完整性证据，取决于“预期摘要”是否来自攻击者不能同步改写的可信来源；hash 计算正确本身不提供来源认证。
> <!-- bilingual-en:start -->
> An ordinary hash has no secret input, so anyone can compute a digest for any message. Digest comparison becomes integrity evidence only when the expected digest comes from a trusted source that the attacker cannot replace at the same time. Correct hash computation alone does not authenticate origin.
> <!-- bilingual-en:end -->

若网站把安装包和 SHA-256 值放在同一个可篡改页面上，比较可以发现偶然传输损坏，却不能单独证明发布者身份：攻击者改包后也能重算摘要。若摘要来自独立可信渠道，或摘要本身受 MAC、数字签名或已认证连接保护，比较才接到可信锚点上。
<!-- bilingual-en:start -->
If a website publishes an installer and its SHA-256 value on the same attacker-writable page, comparison can detect accidental corruption but cannot by itself authenticate the publisher: an attacker can alter the package and recompute the digest. Comparison becomes anchored when the expected digest arrives through an independent trusted channel or is protected by a MAC, digital signature, or authenticated connection.
<!-- bilingual-en:end -->

> [!question]- 自检
> 从镜像站下载文件、从发布者独立签名的页面取得摘要，与从同一被攻陷网页取得文件和摘要，有何关键差别？
>
> **答案：** 前者把预期摘要放在独立信任路径上；后者允许攻击者同时替换文件和摘要，比较只能证明两者彼此匹配，不能证明来源。

## 来源与核验

- [NIST FIPS 180-4, *Secure Hash Standard*](https://csrc.nist.gov/pubs/fips/180-4/upd1/final)：核对消息摘要可检测消息自生成摘要后是否改变，但该标准没有给普通摘要加入秘密来源认证。
- [NIST Message Authentication Codes project](https://csrc.nist.gov/Projects/message-authentication-codes)：以 MAC 需要发送者与接收者建立秘密密钥，交叉核对普通公开摘要缺失的认证锚点。
- [MIT Missing Semester, “Hash functions”](https://missing.csail.mit.edu/2020/security/#hash-functions)：核对从独立官方来源取得预期摘要后再验证下载文件的教学例子。
