# 临时目录安全创建先用mktemp创建私有工作区并检查结果
<!-- bilingual-en:start -->
*Safe temporary-directory creation uses mktemp to create a private workspace and checks the result before use.*
<!-- bilingual-en:end -->

需要临时工作区时，用 `mktemp -d` 实际创建唯一目录并取得路径，不要只拼接固定名称或 `$$` 后缀猜测“尚未使用”的路径。可预测名称会引入抢占或符号链接竞争；只生成名称而不创建的 `mktemp -u` 不能提供同样保护。
<!-- bilingual-en:start -->
Use `mktemp -d` to create a unique directory and obtain its path rather than guessing an unused fixed name or PID-based suffix. Predictable names introduce preemption or symlink races. Generating a name without retaining its creation, as with `mktemp -u`, does not provide the same protection.
<!-- bilingual-en:end -->

```bash
cli_tmp=$(mktemp -d) || exit 1
printf 'Temporary directory: %s\n' "$cli_tmp"
```

这段脚本在创建失败时停止；成功后仍须把 `"$cli_tmp"` 当作一个参数引用，后续写入限制在已创建目录内。GNU 与 BSD 的模板、`-t`、`-p` 选项并不完全相同，迁移具体写法前查本机手册。
<!-- bilingual-en:start -->
The script stops if creation fails. After success, quote `"$cli_tmp"` as one argument and restrict temporary writes to that directory. GNU and BSD templates and `-t`/`-p` options differ, so check the local manual before moving a particular form between platforms.
<!-- bilingual-en:end -->

临时目录也需要明确生命周期。可为已确认属于本次运行的资源设计退出清理，但 trap 无法在 `SIGKILL` 或断电时保证运行；不得以空值、未核对变量或宽泛目录作为递归清理目标。创建成功、业务完成与清理完成是三个不同结果。
<!-- bilingual-en:start -->
Give temporary directories an explicit lifecycle. Cleanup may be arranged for resources confirmed to belong to this run, but traps cannot guarantee execution after `SIGKILL` or power loss. Never derive recursive cleanup from an empty value, unverified variable, or broad directory. Creation, task completion, and cleanup are separate outcomes.
<!-- bilingual-en:end -->

## 来源与核验

[GNU Coreutils, mktemp invocation](https://www.gnu.org/software/coreutils/manual/html_node/mktemp-invocation.html)：支持安全创建、可预测名称竞争与目录模式；本机 macOS `mktemp(1)` 全文核对 BSD 选项和 `-u` 风险。
<!-- bilingual-en:start -->
[GNU Coreutils: mktemp invocation](https://www.gnu.org/software/coreutils/manual/html_node/mktemp-invocation.html) supports safe creation, predictable-name races, and directory mode. The complete installed macOS `mktemp(1)` was checked for BSD options and `-u` risks.
<!-- bilingual-en:end -->

[OpenBSD signal(3)](https://man.openbsd.org/signal.3)：支持不可捕获信号的清理边界；限制清理目标是本卡补充的安全操作条件。
<!-- bilingual-en:start -->
[OpenBSD signal(3)](https://man.openbsd.org/signal.3) supports the uncatchable-signal boundary; restricting cleanup targets is an explicit safety condition added here.
<!-- bilingual-en:end -->
