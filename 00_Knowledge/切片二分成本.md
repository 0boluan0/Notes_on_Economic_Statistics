# 递归二分若每层复制保留的半个列表，最坏总复制成本是线性而非对数
<!-- bilingual-en:start -->
*Recursive binary search that copies the retained half-list at each level has linear, not logarithmic, worst-case copying cost*
<!-- bilingual-en:end -->

在有序的随机访问数组上，[[二分查找]]只需对数次数的比较；但若递归时用 Python 列表切片 `L[:half]` 或 `L[half:]` 创建新的子列表，复制也要付费。在复制 $k$ 个元素引用花费 $\Theta(k)$、比较和索引为常数成本的模型下，**这一切片实现的最坏运行时间为 $\Theta(n)$**，其中 $n$ 是原列表长度。
<!-- bilingual-en:start -->
[[二分查找|Binary search]] on a sorted random-access array needs only logarithmically many comparisons. A recursive implementation that constructs each sublist with Python slices such as `L[:half]` or `L[half:]` must also pay for copying. If copying $k$ references costs $\Theta(k)$ and indexing and comparison have constant cost, **this slicing implementation takes $\Theta(n)$ worst-case time**, where $n$ is the original list length.
<!-- bilingual-en:end -->

## 沿着实际走过的一条分支求和
<!-- bilingual-en:start -->
*Sum the costs along the one branch actually visited*
<!-- bilingual-en:end -->

先取 $n=2^k$，考虑一直搜索到单元素列表的情形。各层复制的长度依次是 $n/2,n/4,\ldots,1$，由[[几何和]]，总复制量为

$$
\frac n2+\frac n4+\cdots+1=n-1.
$$

比较与调用开销另有 $\Theta(\log n)$，合起来仍为 $\Theta(n)$。一般整数 $n$ 只增加取整项，不改变阶数。第一层就复制约半个原列表，也直接给出线性下界。
<!-- bilingual-en:start -->
For $n=2^k$, follow a search that reaches a singleton. The copied lengths are $n/2,n/4,\ldots,1$, whose [[几何和|geometric sum]] is $n-1$. Comparisons and call overhead add $\Theta(\log n)$, so the total remains $\Theta(n)$. Rounding for arbitrary integer $n$ does not change the order. The first slice alone copies about half of the input and supplies a linear lower bound.
<!-- bilingual-en:end -->

把“$\log n$ 层”乘以“每层最多 $n$”只能得到较松的 $O(n\log n)$ 上界，不能据此写成 $\Theta(n\log n)$：后面的列表已经越来越短。
<!-- bilingual-en:start -->
Multiplying "$\log n$ levels" by "at most $n$ per level" gives the loose upper bound $O(n\log n)$, not the tight bound $\Theta(n\log n)$: the later lists are progressively shorter.
<!-- bilingual-en:end -->

## 同一算法思想，换一种表示成本就不同
<!-- bilingual-en:start -->
*The same search idea can have different representation costs*
<!-- bilingual-en:end -->

传递原列表与 `low, high` 索引而不切片，可以让每层的其他工作保持常数，得到最坏 $\Theta(\log n)$ 时间。递归索引版还保留 $\Theta(\log n)$ 个常数大小调用帧；迭代索引版可用 $\Theta(1)$ [[辅助空间]]。切片递归版沿活跃调用链保留的子列表总长为 $\Theta(n)$，所以其峰值辅助空间也是线性；不是把整棵调用树的累计分配量当成峰值。
<!-- bilingual-en:start -->
Passing the original list with `low, high` indices avoids copying and keeps the other work at each level constant, giving $\Theta(\log n)$ worst-case time. Recursive index-based search retains $\Theta(\log n)$ constant-size frames; an iterative index-based version uses $\Theta(1)$ [[辅助空间|auxiliary space]]. Along the active path, recursive slicing retains sublists of total length $\Theta(n)$, so its peak auxiliary space is linear. Peak space is not cumulative allocation over a whole call tree.
<!-- bilingual-en:end -->
