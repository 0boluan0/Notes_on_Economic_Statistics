# Slicing in binary search
<!-- bilingual-en:end -->

*二分查找中的切片成本*

<!-- bilingual-en:start -->
A shorter search interval is not free if each recursive call first makes a new list. Think of crossing out half the entries versus photocopying the half you keep: both reduce the number of candidates, but only one copies the candidates again. This card counts that extra work for ordinary Python list slicing.
<!-- bilingual-en:end -->

如果每次递归都先创建一个新列表，那么缩小搜索区间也要花费时间。可以想成“划掉一半”与“把保留的一半重新复印”：两者都减少候选，后者还要再次复制候选。本卡计算普通 Python 列表切片带来的这项额外工作。

<!-- bilingual-en:start -->
A slice copies references into a new list; it does not recursively copy each element object. We count one unit per copied reference and use constant-size frame/index bookkeeping, as specified by the [[算法成本模型|cost model]]. Calls are assumed to finish normally, with consistent comparisons and enough resources for recursion and allocation.
<!-- bilingual-en:end -->

切片把元素引用复制到新列表，并不会递归复制每个元素对象。本卡按每个被复制引用计一单位，并按 [[算法成本模型]] 假设调用帧和索引记账占常数大小；还假设比较一致、调用正常完成，且递归与分配资源足够。

<!-- bilingual-en:start -->
## Which implementation is being counted?
<!-- bilingual-en:end -->

## 先确定被分析的具体实现

<!-- bilingual-en:start -->
MIT Lecture 23 uses `half = len(L)//2`, then recurses into `L[:half]` if `L[half] > e`, or `L[half:]` otherwise. It has no equality return at the midpoint: even if `L[half] == e`, it keeps searching the right slice until the list has length one. Each call follows exactly one branch. Empty and singleton lists return directly without a slice.
<!-- bilingual-en:end -->

MIT 第 23 讲先计算 `half = len(L)//2`，若 `L[half] > e` 就递归 `L[:half]`，否则递归 `L[half:]`。该版没有“中点相等就返回”的分支：即使 `L[half] == e`，也继续搜索右切片直到列表只剩一个元素。每次调用只沿一条分支进行；空列表和单元素列表直接返回，不创建切片。

<!-- bilingual-en:start -->
The notation [[大Θ记号|$\Theta(g(n))$]] describes growth trapped between fixed positive multiples of $g(n)$ for sufficiently large $n$. It gives a growth scale rather than an exact count. A one-sided [[大O记号|$O$ upper bound]] need not be tight.
<!-- bilingual-en:end -->

[[大Θ记号|$\Theta(g(n))$]] 表示当 $n$ 足够大时，增长量被 $g(n)$ 的两个固定正倍数夹住；它描述增长尺度，不是精确次数。单侧的 [[大O记号|$O$ 上界]] 未必紧确。

<!-- bilingual-en:start -->
[[二分查找|Binary search]] on a sorted random-access array needs only logarithmically many comparisons. A recursive implementation that constructs each sublist with Python slices such as `L[:half]` or `L[half:]` must also pay for copying. If copying $k$ references costs $\Theta(k)$ and indexing and comparison have constant cost, **this slicing implementation takes $\Theta(n)$ worst-case time**, where $n$ is the original list length.
<!-- bilingual-en:end -->

在有序的随机访问数组上，[[二分查找]]只需对数次数的比较；但若递归时用 Python 列表切片 `L[:half]` 或 `L[half:]` 创建新的子列表，复制也要付费。在复制 $k$ 个元素引用花费 $\Theta(k)$、比较和索引为常数成本的模型下，**这一切片实现的最坏运行时间为 $\Theta(n)$**，其中 $n$ 是原列表长度。

<!-- bilingual-en:start -->
## Sum the costs along the one branch actually visited
<!-- bilingual-en:end -->

## 沿着实际走过的一条分支求和

<!-- bilingual-en:start -->
In the following geometric calculation take an integer $k\ge1$. The empty and singleton cases are handled directly by the base cases and have no copied sublist.
<!-- bilingual-en:end -->

下面的几何求和取整数 $k\ge1$。空列表和单元素列表由基本情形直接处理，不复制子列表。

<!-- bilingual-en:start -->
For $n=2^k$, follow a search that reaches a singleton. The copied lengths are $n/2,n/4,\ldots,1$, whose [[几何和|geometric sum]] is $n-1$. Comparisons and call overhead add $\Theta(\log n)$, so the total remains $\Theta(n)$. Rounding for arbitrary integer $n$ does not change the order. The first slice alone copies about half of the input and supplies a linear lower bound.
<!-- bilingual-en:end -->

先取 $n=2^k$，考虑一直搜索到单元素列表的情形。各层复制的长度依次是 $n/2,n/4,\ldots,1$，由[[几何和]]，总复制量为

$$
\frac n2+\frac n4+\cdots+1=n-1.
$$

比较与调用开销另有 $\Theta(\log n)$，合起来仍为 $\Theta(n)$。一般整数 $n$ 只增加取整项，不改变阶数。第一层就复制约半个原列表，也直接给出线性下界。

<!-- bilingual-en:start -->
Multiplying "$\log n$ levels" by "at most $n$ per level" gives the loose upper bound $O(n\log n)$, not the tight bound $\Theta(n\log n)$: the later lists are progressively shorter.
<!-- bilingual-en:end -->

把“$\log n$ 层”乘以“每层最多 $n$”只能得到较松的 $O(n\log n)$ 上界，不能据此写成 $\Theta(n\log n)$：后面的列表已经越来越短。

<!-- bilingual-en:start -->
## The same search idea can have different representation costs
<!-- bilingual-en:end -->

## 同一算法思想，换一种表示成本就不同

<!-- bilingual-en:start -->
The following storage comparison refers to worst-case completed searches as the input length grows. Count only new reference slots and active call frames, exclude the original input, and use the fixed-size unit assumptions above.
<!-- bilingual-en:end -->

下面的存储比较讨论输入长度增长时、正常完成搜索的最坏情况。只计新引用槽位与尚未返回的调用帧，排除原始输入，并使用前面固定大小的计量假设。

<!-- bilingual-en:start -->
Passing the original list with `low, high` indices avoids copying and keeps the other work at each level constant, giving $\Theta(\log n)$ worst-case time. Recursive index-based search retains $\Theta(\log n)$ constant-size frames; an iterative index-based version uses $\Theta(1)$ [[辅助空间|auxiliary space]]. Along the active path, recursive slicing retains sublists of total length $\Theta(n)$, so its peak auxiliary space is linear. Peak space is not cumulative allocation over a whole call tree.
<!-- bilingual-en:end -->

传递原列表与 `low, high` 索引而不切片，可以让每层的其他工作保持常数，得到最坏 $\Theta(\log n)$ 时间。递归索引版还保留 $\Theta(\log n)$ 个常数大小调用帧；迭代索引版可用 $\Theta(1)$ [[辅助空间]]。切片递归版沿活跃调用链保留的子列表总长为 $\Theta(n)$，所以其峰值辅助空间也是线性；不是把整棵调用树的累计分配量当成峰值。

<!-- bilingual-en:start -->
## Check the shrinking lengths
<!-- bilingual-en:end -->

## 核对逐层缩小的长度

> [!example] Eight inputs, seven copied references · 八个输入，七次引用复制
> <!-- bilingual-en:start -->
> For a list of length 8, the official slicing version creates lists of lengths 4, 2 and 1. Thus it copies $4+2+1=7$ references, whether the target equals the first midpoint or is absent. These are three slice operations, not seven recursive calls.
> <!-- bilingual-en:end -->
>
> 对长度为 8 的列表，官方切片版创建长度为 4、2、1 的列表，因此复制 $4+2+1=7$ 个引用。目标等于第一个中点或根本不存在时都如此。这是三次切片，不是七次递归调用。

<!-- bilingual-en:start -->
For arbitrary $n\ge2$, let $m_t$ be the current list length. Each retained length is at most $\lceil m_t/2\rceil$, hence $m_t\le\lceil n/2^t\rceil$. It reaches a singleton within $\lceil\log_2 n\rceil$ slices. The total copied length is bounded above by $\sum_{t=1}^{\lceil\log_2 n\rceil}(n/2^t+1)<n+\lceil\log_2 n\rceil=O(n)$. The first slice contains at least $\lfloor n/2\rfloor$ references, giving a matching lower bound.
<!-- bilingual-en:end -->

一般 $n\ge2$ 时，记当前列表长度为 $m_t$。每次保留长度至多为 $\lceil m_t/2\rceil$，因此 $m_t\le\lceil n/2^t\rceil$；最多经过 $\lceil\log_2 n\rceil$ 次切片就到单元素。总复制长度至多为 $\sum_{t=1}^{\lceil\log_2 n\rceil}(n/2^t+1)<n+\lceil\log_2 n\rceil=O(n)$；第一次切片至少复制 $\lfloor n/2\rfloor$ 个引用，又给出相同阶的下界。

<!-- bilingual-en:start -->
For this particular official version, the first slice is unavoidable when $n\ge2$, so even its best case has linear copying cost as $n$ grows. A different version that returns immediately on midpoint equality can have a constant-time best case before any slice; its worst case still pays linear copying. An empty or singleton input has constant overhead, so $\Theta(n+1)$ is a convenient bound including these small cases.
<!-- bilingual-en:end -->

对这份官方版本，只要 $n\ge2$ 就必定进行第一次切片，所以随 $n$ 增长，最好情况的复制成本也是线性的。若另一版本在中点相等时立即返回，则可能在任何切片之前就结束，最好情况是常数时间，但最坏情况仍支付线性复制成本。空输入或单元素输入只有常数开销；若统一涵盖这些小规模情形，可写为 $\Theta(n+1)$。

<!-- bilingual-en:start -->
The previous space paragraph applies the definition of [[辅助空间|auxiliary space]] to the live parent-and-child lists in this one-branch implementation. It does not define a general rule equating total copies with peak storage. Keep those two measurements separate when comparing another implementation.
<!-- bilingual-en:end -->

前面的空间段落把 [[辅助空间]] 的定义应用于本实现中仍存活的父子列表；它并没有定义“累计复制量等于峰值空间”的一般规则。比较其他实现时，应继续区分这两项度量。

<!-- bilingual-en:start -->
The course slide first multiplies a logarithmic number of levels by the original input size. This supplies a loose upper bound. Its later linear conclusion uses the shrinking lists; the geometric calculation above is the tight argument.
<!-- bilingual-en:end -->

课件先把对数层数乘以原始输入长度，这只能得到较松的上界；后面的线性结论使用了列表逐层缩小的事实，前述几何求和才给出紧确论证。
