# 密码学哈希把任意长度消息确定性地映射为固定长度摘要
<!-- bilingual-en:start -->
*A cryptographic hash deterministically maps an arbitrary-length message to a fixed-length digest*
<!-- bilingual-en:end -->

> [!summary] 它是什么
> 密码学哈希函数接收一段消息，确定性地产生固定长度摘要。同一输入和算法总得到同一摘要；输入哪怕只改一位，摘要通常也会明显改变。摘要比原文短得多，所以它是内容的紧凑指纹，不是原文的可逆压缩。
> <!-- bilingual-en:start -->
> A cryptographic hash function takes a message and deterministically produces a fixed-length digest. The same input under the same algorithm yields the same digest, while even a one-bit change will normally alter the digest substantially. The digest is a compact fingerprint, not a reversible compression of the message.
> <!-- bilingual-en:end -->

实际安全还要求区分三种攻击目标：给定摘要找输入是原像问题；给定一份特定消息找另一份同摘要消息是第二原像问题；让攻击者自由寻找任意同摘要消息对是碰撞问题。三者问的对象不同，不能用“hash 很难破解”一句话代替。
<!-- bilingual-en:start -->
Practical security distinguishes three attack goals. Finding an input for a given digest is a preimage problem; finding a different input matching one specified message is a second-preimage problem; finding any pair of distinct messages with the same digest is a collision problem. They ask different questions and should not be collapsed into the phrase “the hash is hard to break.”
<!-- bilingual-en:end -->

最小例子是下载后重算文件摘要：若本地摘要与先前保存的预期摘要不同，文件一定发生了变化；若二者相同，只能在所用算法的碰撞抗性与预期摘要的可信来源边界内，把它作为内容未变的证据。
<!-- bilingual-en:start -->
A minimal example is recomputing a downloaded file's digest. A mismatch proves that the file changed. A match is evidence that it did not change only within the collision-resistance assumption and the trust boundary of the expected digest.
<!-- bilingual-en:end -->

> [!question]- 自检
> “找到任意两份同摘要消息”和“给定这份文件，再找一份同摘要文件”为什么不是同一个问题？
>
> **答案：** 前者允许攻击者自由选择两边，是碰撞问题；后者固定了其中一份输入，是第二原像问题。攻击自由度不同，安全强度也不能混用。

## 来源与核验

- [NIST Hash Functions project](https://csrc.nist.gov/Projects/hash-functions)：核对 hash 将任意长度消息映射为固定长度摘要，并分别定义碰撞、原像与第二原像抗性。
- [NIST FIPS 180-4, *Secure Hash Standard*](https://csrc.nist.gov/pubs/fips/180-4/upd1/final)：核对消息摘要用于检测消息自生成摘要后是否改变；NIST 已决定修订该标准，本卡不据此推荐具体算法寿命。
