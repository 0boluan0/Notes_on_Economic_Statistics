# 异常链是异常对象之间保存隐式上下文或显式原因的联系

<!-- bilingual-en:start -->
*Exception chaining links exception objects through implicit context or explicit cause*
<!-- bilingual-en:end -->

异常链（exception chaining）是异常对象之间保存上下文或原因的联系。处理旧异常时又抛出新异常，Python 通常把旧异常记为新异常的 `__context__`；`raise NewError(...) from exc` 则显式把 `exc` 记为 `__cause__`。显式原因也可以引用先前保存的异常对象，无需此刻正在处理它。这让接口可以换一种异常类型表达失败，同时保留底层诊断线索。

<!-- bilingual-en:start -->
Exception chaining links exception objects through context or cause. When a new exception is raised while another is being handled, Python normally stores the earlier one as `__context__`. `raise NewError(...) from exc` explicitly records `exc` as `__cause__`; this can be a previously saved exception object, with no currently active handler. An interface can thus translate the failure's type while preserving its underlying diagnostic evidence.
<!-- bilingual-en:end -->

```python
def parse_count(text):
    try:
        return int(text)
    except ValueError as exc:
        raise ValueError("count must be an integer") from exc
```

新消息属于当前接口；原始转换失败仍是显式原因。`raise ... from None` 抑制默认 traceback 中旧上下文的显示，不删除仍可访问的 `__context__`，也不是恢复成功。只有确实想简化面向调用者的诊断时才选择隐藏，并确保新异常保留所需信息。

<!-- bilingual-en:start -->
The new message belongs to the current interface, while the conversion failure remains its explicit cause. `raise ... from None` suppresses the old context in default traceback display; it does not erase the accessible `__context__` or make the operation successful. Hide it only as a deliberate diagnostic choice, preserving the information callers need in the replacement exception.
<!-- bilingual-en:end -->
