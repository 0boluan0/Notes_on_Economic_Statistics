# 实例属性查找按数据描述器、实例字典、类的 MRO 与非数据描述器的优先级解析
<!-- bilingual-en:start -->
*Instance attribute lookup follows the precedence of data descriptors, instance storage, the class MRO, and non-data descriptors*
<!-- bilingual-en:end -->

> [!summary] 原子查找规则
> 对普通实例读取 `obj.name` 时，默认 `object.__getattribute__` 先在 `type(obj)` 的 MRO 中寻找同名**数据描述器**，再检查实例自己的 `__dict__`，然后取 MRO 中的非数据描述器或普通类属性。若这些步骤最终抛出 `AttributeError`，点号读取的外层回退才可能调用 `type(obj).__getattr__`。所以“先实例、再类”只适用于没有数据描述器介入的简化情形。
> <!-- bilingual-en:start -->
> For an ordinary instance read `obj.name`, the default `object.__getattribute__` first looks through `type(obj)`'s MRO for a data descriptor, then checks the instance's own `__dict__`, and then uses a non-data descriptor or ordinary class attribute found through the MRO. If those steps ultimately raise `AttributeError`, the outer dot-lookup fallback can then call `type(obj).__getattr__`. Thus “instance first, then class” is only a simplified rule when no data descriptor intervenes.
> <!-- bilingual-en:end -->

`property` 是常见数据描述器，因此即使实例字典里出现同名键，属性读取仍由 property 控制。普通类中由 `def` 创建的函数是非数据描述器：若实例已有同名普通属性，它会遮蔽方法；否则函数在读取时可绑定为方法。类若自定义 `__getattribute__`，则可以改写整套默认流程；`__getattr__` 本身不在 `object.__getattribute__` 内部，而是在它以 `AttributeError` 失败后提供回退。

```python
class Box:
    @property
    def value(self):
        return 10

b = Box()
b.__dict__["value"] = 99
b.value                    # 10: the data descriptor wins
```

> [!question]- 回忆与应用
> 为什么 `obj.__dict__["x"]` 中有键 `x`，仍不能保证 `obj.x` 返回这个值？
>
> **答案：** 类及其 MRO 中的同名数据描述器优先于实例字典；自定义 `__getattribute__` 也可能改变默认查找。
