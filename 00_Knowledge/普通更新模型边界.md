# 普通更新模型要求周期IID且每次更新实现概率重置
<!-- bilingual-en:start -->
*An ordinary renewal model requires iid cycles and a genuine probabilistic reset at every renewal*
<!-- bilingual-en:end -->

> [!summary] 建模边界
> “发生了一次更换、维修或回返”不自动等于“更新”。普通更新模型要求每次更新后的未来周期：
> 1. 与此前周期独立；
> 2. 与其他周期同分布；
> 3. 由已经选定的间隔定义完整描述。
>
> 也就是说，系统在更新时刻必须回到与初始状态概率等价的状态，而不只是标签看起来相同。
> <!-- bilingual-en:start -->
> A replacement, repair, or return is an ordinary renewal only when the next cycle is independent of the past and has the same distribution as every other cycle. The system must reset probabilistically, not merely return to the same label.
> <!-- bilingual-en:end -->

逐项诊断可以区分相邻模型：

- 只有第一周期分布不同：是 **delayed renewal process**，不是从 $t=0$ 起的普通更新过程；
- 奇数、偶数周期交替使用不同分布：可建模为 alternating renewal，而非 IID 周期；
- 不完全维修后“虚拟年龄”保留：以后寿命依赖维修史，需要 generalized renewal、virtual-age 或 semi-Markov 模型；
- 季节、日历时间或共同环境改变所有寿命：间隔可能不同分布或相互依赖；
- 下一状态与停留时间共同依赖当前状态：更接近 Markov renewal / semi-Markov，而非单一 IID 间隔序列。

条件独立也不一定足够。例如给定一个长期隐藏环境 $Z$ 时，各周期寿命独立，但所有周期共享同一个 $Z$；边际上它们通常相关，因此不是普通更新过程。必须检查无条件的跨周期独立性，或把 $Z$ 纳入状态。

> [!example] “修好如新”与“勉强修复”
> 每次故障后换上同型号全新部件，寿命可合理近似 IID；若只是修到能运行，累计磨损仍影响下一次寿命，即使界面仍显示“正常”，也没有真正重置。

> [!question]- 自检
> 首台设备来自旧库存，之后每次都换成同一型号新设备。全部故障间隔是否从一开始就是普通更新过程？
>
> **答案：** 通常不是；第一间隔可有不同分布，形成 delayed renewal。首台更换之后的后续间隔才可能构成普通更新序列。
