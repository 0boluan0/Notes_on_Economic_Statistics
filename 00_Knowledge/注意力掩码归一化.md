# 注意力掩码必须在允许的 key 上重新归一化，并为每个有效 query 保留至少一个 key
<!-- bilingual-en:start -->
*Attention masking must normalize over allowed keys and retain at least one key for each valid query*
<!-- bilingual-en:end -->

对使用 [[Softmax]] 权重的注意力，掩码后的每一有效 query 行仍应在允许的 key 上构成概率分布。设第 $i$ 行的允许集合为 $J_i$，未掩码分数 $s_{ij}$ 有限，则要求 $J_i\ne\varnothing$，并计算

$$
a_{ij}=\begin{cases}
\displaystyle\frac{\exp(s_{ij})}{\sum_{\ell\in J_i}\exp(s_{i\ell})},&j\in J_i,\\[6pt]
0,&j\notin J_i.
\end{cases}
$$

<!-- bilingual-en:start -->
For attention using [[Softmax|softmax]] weights, each valid query row must remain a probability distribution over its allowed keys. Let $J_i$ be the allowed set for row $i$, with finite unmasked scores $s_{ij}$. The displayed definition requires $J_i\ne\varnothing$ and normalizes only over that set.
<!-- bilingual-en:end -->

[[因果注意力掩码|先把禁止位置的 logits 设为 $-\infty$]] 再做 softmax，直接得到上式。也可以先对全部分数做 softmax，得到 $p_{ij}$，再将禁止位置置零并重新归一化。在精确算术下，只要允许集合非空，两种方式相同：

$$
a_{ij}
=\frac{\mathbf1[j\in J_i]p_{ij}}
{\sum_{\ell\in J_i}p_{i\ell}}.
$$

<!-- bilingual-en:start -->
[[因果注意力掩码|Setting forbidden logits to $-\infty$]] before softmax produces this distribution directly. Alternatively, compute softmax over all scores to obtain $p_{ij}$, zero the forbidden entries, and renormalize. In exact arithmetic, the two procedures agree whenever the allowed set is nonempty.
<!-- bilingual-en:end -->

例如分数为 $(\log2,\log3,\log5)$，第三个 key 被屏蔽。对全部分数做 softmax 得 $(0.2,0.3,0.5)$；仅将第三项置零会留下 $(0.2,0.3,0)$，总和只有 $0.5$。重新归一化才得到 $(0.4,0.6,0)$，与先掩码再 softmax 相同。

<!-- bilingual-en:start -->
For scores $(\log2,\log3,\log5)$ with the third key masked, the original softmax is $(0.2,0.3,0.5)$. Zeroing the third entry alone leaves $(0.2,0.3,0)$, whose sum is only $0.5$. Renormalization produces $(0.4,0.6,0)$, matching masking before softmax.
<!-- bilingual-en:end -->

若整行 key 都被屏蔽，分母为零，数学上没有这行的归一化注意力分布。实现可以另行约定忽略这个无效 query、返回零输出或报错，但必须明确处理；“全零权重”不满足概率行和为一的定义。实际浮点计算还需避免上溢、下溢；先掩码并在允许集合内稳定计算 softmax，通常更直接。

<!-- bilingual-en:start -->
If every key in a row is masked, the denominator is zero and no normalized attention distribution is defined for that row. An implementation may explicitly ignore the invalid query, return a zero output, or raise an error; all-zero weights are not a probability row. Floating-point code must also handle overflow and underflow. Masking first and computing a stable softmax over allowed keys is usually the direct approach.
<!-- bilingual-en:end -->
