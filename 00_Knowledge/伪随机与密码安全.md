# Pseudorandomness and cryptographic security
<!-- bilingual-en:end -->

*伪随机与密码安全*

<!-- bilingual-en:start -->
A simulation and a password-reset service may both need numbers that look random, but they ask different questions. The simulation needs inputs suitable for its probability calculation; the reset service needs a token that someone else cannot feasibly guess. **Statistical suitability for simulation does not establish cryptographic security.** A [[伪随机数生成器|pseudorandom number generator (PRNG)]] produces output from an algorithm and an internal state: stored information that determines how the calculation continues.
<!-- bilingual-en:end -->

模拟程序和密码重置服务都可能需要看起来随机的数字，但它们提出的问题不同。模拟需要适合概率计算的输入；重置服务需要别人难以猜中的令牌。**适合模拟的统计性质，并不能证明密码学安全。** [[伪随机数生成器]]（PRNG）通过算法和内部状态产生输出；状态就是决定计算如何继续的已存信息。

<!-- bilingual-en:start -->
For a simulation, we inspect matters such as unwanted dependence, distributional behaviour, period and speed. The period is the number of steps before a state cycle repeats. [[伪随机复现|Reproducibility]] is also useful: recording the initialisation and call protocol lets us rerun a numerical experiment. For a secret token, making that sequence reconstructible by an outsider would defeat its purpose.
<!-- bilingual-en:end -->

模拟中要检查不希望出现的依赖、分布表现、周期和速度。周期指状态循环再次重复前经历的步数。[[伪随机复现|可复现性]]也很有用：记录初始化与调用协议后，可以重跑一次数值试验。但秘密令牌若能被外人按同样过程重建，就失去了用途。

<!-- bilingual-en:start -->
## A balanced sequence can be predictable
<!-- bilingual-en:end -->

*分布看着均衡，下一项仍可能可预测*

> [!example] Eight equally visited states · 八个均匀走访的状态
> <!-- bilingual-en:start -->
> Reuse the small machine from the [[伪随机数生成器|PRNG definition]]: start at $S_0=1$ and update $S_{t+1}=(5S_t+1)\bmod8$, where “mod 8” means take the remainder after division by $8$. Its next eight states are $6,7,4,5,2,3,0,1$. Each value occurs once, so a frequency count over this cycle is perfectly balanced. Yet knowing the rule and current state $6$ gives the next state exactly: $(5\cdot6+1)\bmod8=7$. Uniform counts did not hide the rule. This deliberately tiny example illustrates the distinction; it is not a recommended simulation generator.
> <!-- bilingual-en:end -->
>
> 沿用[[伪随机数生成器|定义卡]]的小机器：从 $S_0=1$ 开始，按 $S_{t+1}=(5S_t+1)\bmod8$ 更新，“mod 8”表示除以 $8$ 取余数。之后八个状态是 $6,7,4,5,2,3,0,1$，每个值恰好出现一次，整个周期的频数完全均衡。但知道规则和当前状态 $6$，就能准确算出下一状态为 $7$。频数均匀并没有隐藏规则。这只是刻意缩小的辨析例子，不是推荐用于模拟的生成器。

<!-- bilingual-en:start -->
A longer period or a larger battery of statistical tests can provide useful evidence about numerical behaviour. It cannot, by itself, certify resistance to an adversary who uses the algorithm, observed outputs and other available information. NIST explicitly separates statistical testing from cryptanalysis: security analysis of how the construction could be distinguished or predicted.
<!-- bilingual-en:end -->

更长周期、更多统计测试，可以为数值表现提供有用证据，却不能单独认证生成器能够抵抗利用算法、已见输出及其他可用信息的对手。NIST 明确区分统计测试与密码分析；后者研究构造能否被辨认、预测等安全问题。

## Deterministic does not mean automatically insecure
<!-- bilingual-en:end -->

*确定性本身不等于不安全*

<!-- bilingual-en:start -->
Cryptographic generators can also be deterministic between reseeds. Their security claim relies on a suitable construction, secret state and enough unpredictable input, under a stated computational threat model. NIST calls such a construction a **deterministic random bit generator (DRBG)**. Entropy here describes uncertainty in the input; a long seed string with a publicly known value does not provide corresponding secret uncertainty. Merely changing the seed of a simulation generator does not give it a cryptographic design.
<!-- bilingual-en:end -->

密码学生成器在两次重新播种之间也可以是确定的。安全主张依赖适当的构造、秘密状态和足够不可预测的输入，并有明确的计算能力与信息获取假设。NIST 称这种构造为**确定性随机比特生成器（DRBG）**。这里的熵描述输入的不确定性；很长但公开已知的种子字符串，不会因此提供相应的秘密不确定性。仅仅给模拟生成器换个种子，并不会把它变成密码学构造。

> [!warning] What happens if the state is exposed? · 状态暴露以后呢？
> <!-- bilingual-en:start -->
> If the complete current state, algorithm and subsequent calls are known, and no new unknown input enters, a deterministic continuation can be computed. “Cryptographic” does not remove that fact. NIST distinguishes **backtracking resistance**, protecting previously unseen past outputs after a state compromise, from **prediction resistance**, protecting future outputs after compromise through effective reseeding with fresh entropy. These are specific guarantees with conditions; they do not promise protection against arbitrary partial or complete state exposure.
> <!-- bilingual-en:end -->
>
> 如果完整当前状态、算法和后续调用都已知，而且没有新未知输入进入，确定性的后续计算就能够被算出。“密码学”不会消除这个事实。NIST 区分**回溯抵抗**与**预测抵抗**：前者关注状态泄露后，先前未见过的过去输出能否仍受保护；后者借助带新熵的有效重新播种，保护泄露之后的未来输出。这些是有条件的具体保证，不能概括成“任意部分或全部状态暴露都没关系”。

## Choose the interface for the task
<!-- bilingual-en:end -->

*按任务选择接口*

<!-- bilingual-en:start -->
In Python, the default `random.Random` generator uses Mersenne Twister and the official documentation excludes cryptographic use. It is appropriate to use a documented simulation generator and recorded initialisation for a reproducible experiment. For password-reset tokens or similar application secrets, Python directs us to `secrets`, which uses the operating system's security-oriented randomness source. For example, `secrets.token_urlsafe(32)` requests a URL-safe token from 32 random bytes; its encoded text is not necessarily 32 characters long. For cryptographic keys, use the key-generation interface of the relevant cryptographic library, which handles that algorithm's key format and requirements.
<!-- bilingual-en:end -->

Python 默认的 `random.Random` 使用 Mersenne Twister，官方文档明确排除密码学用途。可复现试验可以使用有文档依据的模拟生成器，并记录初始化。密码重置令牌等应用秘密应按 Python 文档使用 `secrets`，它调用操作系统面向安全的随机源。例如，`secrets.token_urlsafe(32)` 请求用 32 个随机字节生成 URL 安全令牌；编码后的文本不一定是 32 个字符。密码学密钥则应使用对应密码库的密钥生成接口，让它处理该算法的格式与要求。

<!-- bilingual-en:start -->
A security-oriented generator does not, in turn, certify a simulation model, sampling transformation or standard-error calculation. Conversely, a perfectly replayable experiment does not certify token security. The useful question is which property the application needs and which evidence supports that property.
<!-- bilingual-en:end -->

面向安全的生成器也不会反过来认证模拟模型、抽样变换或标准误计算。可完美复现的试验同样不能认证令牌安全。关键是应用需要哪一种性质，以及有什么证据支持这项性质。

> [!question] Check the claim · 检查这项主张
> <!-- bilingual-en:start -->
> A generator has a huge period and passes standard statistical tests. Is that sufficient evidence to use it for password-reset tokens? No: those facts do not establish the required security construction, secret initialisation or resistance under the relevant threat model. Use an appropriate security API rather than treating the test result as certification.
> <!-- bilingual-en:end -->
>
> 某生成器周期极长且通过常用统计测试，这是否足以支持用它生成密码重置令牌？不够：这些事实没有证明所需的安全构造、秘密初始化或相应威胁模型下的抵抗能力。应使用适当的安全接口，不能把统计测试结果当成安全认证。

## 来源与核验

<!-- bilingual-en:start -->
- Python Software Foundation, [`random`, introduction and bookkeeping](https://docs.python.org/3/library/random.html), and [`secrets`, introduction and token generation](https://docs.python.org/3/library/secrets.html): the default Mersenne Twister/security distinction, state replay, operating-system source and token API.
- NIST, [SP 800-22 Rev. 1a, official abstract](https://csrc.nist.gov/pubs/sp/800/22/r1/upd1/final): statistical tests do not replace cryptanalysis; only this boundary is used here, not a claim that a particular test suite certifies security.
- NIST, [SP 800-90A Rev. 1, §§8.6.3–8.6.6 and 8.8, printed pp. 18–19 and 23–24](https://doi.org/10.6028/NIST.SP.800-90Ar1): entropy/seed privacy and distinct state-compromise guarantees. The eight-state arithmetic is a direct example.
<!-- bilingual-en:end -->

- Python 官方 `random` 的导言、状态保存接口及 `secrets` 的导言、令牌接口：核对默认生成器的用途边界、状态复现、操作系统随机源与调用含义。
- NIST SP 800-22 Rev. 1a 官方摘要：核对统计测试不能代替密码分析；本卡不声称该测试套件能够认证安全。
- NIST SP 800-90A Rev. 1 第 8.6.3–8.6.6、8.8 节，印刷第 18–19、23–24 页：核对熵、种子保密、回溯抵抗和带新熵重新播种的预测抵抗。八状态算例为直接计算。
