# 必须执行的输入验证与副作用不能依赖可能被优化删除的 assert

<!-- bilingual-en:start -->
*Required input validation and side effects cannot depend on assert statements that optimization may remove*
<!-- bilingual-en:end -->

Python 的 `-O` 优化会删除 `assert` 语句，包括条件与消息的求值。因此，只要[[函数契约]]要求某检查在运行时始终执行，就不能只用断言承担它；外部输入格式、允许范围和安全约束应采用正常控制流，例如显式判断并[[主动抛出异常|抛出适当异常]]。

<!-- bilingual-en:start -->
Python's `-O` optimization removes `assert` statements, including evaluation of their conditions and messages. If a [[函数契约|function contract]] requires a runtime check to execute regardless of assertion settings, an assertion cannot be its sole implementation. Validate external formats, permitted ranges, and security constraints using ordinary control flow, such as an explicit condition and [[主动抛出异常|an appropriate exception]].
<!-- bilingual-en:end -->

```python
def positive_count(text):
    count = int(text)
    if count <= 0:
        raise ValueError("count must be positive")
    return count
```

解析成功不保证范围正确，见[[输入解析边界]]。也不要把必要动作写进 `assert save_result()`：优化后保存动作本身就消失。断言可以补充内部正确性检查，但删除它们不应改变程序实现契约所需的行为。

<!-- bilingual-en:start -->
Successful parsing does not establish a valid range; see [[输入解析边界|input-parsing boundaries]]. Likewise, do not put a required action inside `assert save_result()`: optimization removes the save itself. Assertions can supplement internal correctness checks, but removing them should not remove behavior needed to implement the contract.
<!-- bilingual-en:end -->

*Sources and verification*

- [Python Command Line, -O](https://docs.python.org/3/using/cmdline.html#cmdoption-O)；[Python Language Reference §7.3, assert statement](https://docs.python.org/3/reference/simple_stmts.html#the-assert-statement)：核对优化删除整条断言而非仅隐藏报错。用 `compile(..., optimize=0/1)` 实测断言条件副作用分别存在和消失；显式验证在两种模式下保持拒绝非正数。
  <!-- bilingual-en:start -->
  These sections establish that optimization removes the entire statement rather than merely hiding errors. Execution with `compile(..., optimize=0/1)` confirmed that a condition's side effect disappears under optimization, while explicit validation still rejects nonpositive values in both modes.
  <!-- bilingual-en:end -->
- [[03_Computer_Science/03_MIT 6.100L/MIT 6.100L-finger-exercises/mit6_100l_ex13_sol.pdf#page=1|MIT 6.100L Finger Exercise 13，PDF pp. 1–2]]：核对契约明确要求某些非法类型抛 `ValueError`；“输入非空”是另列前提，答案没有自动验证全部前提。该例支持区分规格条件与实际执行检查，不把断言当作完整验证器。
  <!-- bilingual-en:start -->
  This exercise explicitly requires `ValueError` for certain invalid element types; nonemptiness is a separate precondition that the solution does not comprehensively validate. It supports distinguishing specification assumptions from executable checks, rather than treating assertions as complete validators.
