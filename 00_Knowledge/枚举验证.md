<!-- bilingual-en:start -->
# Exhaustive enumeration
<!-- bilingual-en:end -->

*枚举验证*

<!-- bilingual-en:start -->
To search by **exhaustive enumeration**, list the possible answers and test them systematically. Suppose the permitted answers are the integers 0 through 5 and you want a number whose square is 16. Try 0, 1, 2, 3, then 4; the test succeeds at 4. The useful guarantee comes from knowing which possibilities the search covers and what the test actually checks.
<!-- bilingual-en:end -->

用**枚举验证**找答案，就是列出可能的答案，再有系统地逐一检验。例如，允许的答案是 0 到 5 的整数，目标是找到平方等于 16 的数：依次试 0、1、2、3，再试 4，就在 4 处通过检查。方法的保证来自两件事：搜索覆盖了哪些可能，以及检查规则究竟检验什么。

<!-- bilingual-en:start -->
A **candidate** is one possible answer, before we know whether it works. The **candidate set** is the collection of answers we agree to consider. A [[命题与谓词|predicate]] is a condition with a true/false result after an input is supplied: here $P(c)$ means “$c^2=16$”. The letter $P$ names the test, while $c$ is the candidate being tested. A working implementation must be able to finish that test for each candidate.
<!-- bilingual-en:end -->

**候选**是在尚未确定是否正确时考虑的一个答案；**候选集合**收集了我们约定要考察的答案。[[命题与谓词|谓词]]是在代入输入后得到真或假的条件：这里 $P(c)$ 表示“$c^2=16$”。$P$ 是检查规则的名字，$c$ 是当前候选。实际实现还必须能够完成对每个候选的检查。

> [!important] What an exhaustive result means · 穷尽的结论范围
> <!-- bilingual-en:start -->
> Exhaustive enumeration first specifies a finite candidate set $C$ and a validity predicate $P$, then generates every candidate systematically and applies the same predicate to each one. If any solution is enough, it returns the first $c$ satisfying $P(c)$; if every candidate fails, it reports that no solution exists inside this candidate set.
> <!-- bilingual-en:end -->
>
> 枚举验证先明确一个有限候选集合 $C$ 和判断规则 $P$，再系统生成其中每个候选，并对每个候选运行同一个谓词。若只求任意一个解，就返回第一个满足 $P(c)$ 的候选；若全部候选都不满足，就报告“这个候选集合内没有解”。

<!-- bilingual-en:start -->
## Why candidate coverage and the test both matter
<!-- bilingual-en:end -->

## 完备性需要候选空间、生成器和检验规则同时成立

<!-- bilingual-en:start -->
Let $C=\{c_1,\ldots,c_N\}$ be the candidate set and let $P(c)$ test whether a candidate is valid. Completeness requires three things at once: $C$ covers every eligible candidate, the generator visits every element of $C$ in finite time, and $P$ is correct. Returning at the first success finds one solution; listing every solution requires continuing until the set is exhausted.
<!-- bilingual-en:end -->

设候选集合为

$$
C=\{c_1,c_2,\ldots,c_N\},
$$

目标是找一个满足 $P(c)=\mathrm{true}$ 的候选。基本算法是：

```text
for c in C:
    if P(c):
        return c
return not_found
```

“完备”依赖三个条件：$C$ 覆盖题目允许的全部候选；循环确实能在有限时间内访问每个 $c\in C$；$P$ 对每个候选的判断正确。若只要求找到任意一个解，遇到第一个通过者即可返回；若要列出全部解，就必须继续到候选耗尽。

<!-- bilingual-en:start -->
A returned candidate is justified only if the test is sound: a “true” result must mean the stated requirement really holds. A no-solution result needs more: every eligible candidate must be covered, no candidate may be silently skipped, and each test must terminate with the right answer. A finite set alone is not enough if the generator keeps repeating one element or a test runs forever. This is the same separation between keeping a claim true and eventually finishing used in [[循环不变量与终止|loop invariants and termination]].
<!-- bilingual-en:end -->

返回一个候选是否可信，首先取决于检查是否可靠：“真”必须真的表示规定条件成立。要报告无解，还需要完整覆盖允许的候选、没有悄悄跳过元素，并且每次检查都在有限时间内给出正确答案。如果生成器一直重复一个元素，或某次检查永远不结束，候选集合有限也不能保证程序完成。这与[[循环不变量与终止]]中“保持论断成立”和“最终结束”的区分一致。

<!-- bilingual-en:start -->
The generator must also **finish after finitely many actual visits**. Merely ensuring that each distinct candidate eventually appears is insufficient: the sequence $0,1,0,1,\ldots$ visits every member of $C=\{0,1\}$ promptly but never reports exhaustion. With no passing candidate, that loop never reaches `not_found`. Repetition is allowed only if the complete visit schedule still ends.
<!-- bilingual-en:end -->

生成器本身还必须**在有限次实际访问之后结束**。只保证每个不同候选最终都会出现还不够：序列 $0,1,0,1,\ldots$ 很快就访问了 $C=\{0,1\}$ 的每个成员，却永远不会报告耗尽。如果没有候选通过，这个循环就永远到不了 `not_found`。可以有重复访问，但完整的访问安排仍须最终结束。

<!-- bilingual-en:start -->
In the pseudocode, `return c` ends the search immediately after one success; `return not_found` is reached only after the `for` loop has finished normally. An empty candidate set performs no tests and correctly has no satisfying element. A timeout, exception, or interrupted scan is a different outcome: it says that the search was not completed, not that the remaining candidates would all fail.
<!-- bilingual-en:end -->

伪代码中的 `return c` 会在第一次成功后立即结束搜索；只有 `for` 循环正常走完，才会执行 `return not_found`。空候选集合不作任何检查，其中确实没有满足条件的元素。超时、异常或中途打断则是另一种结果：搜索尚未完成，不能据此说剩余候选都会失败。

<!-- bilingual-en:start -->
## One answer, all answers, or no answer
<!-- bilingual-en:end -->

*一个答案、全部答案与没有答案*

> [!example] The same test, different questions · 相同检查，不同问题
> <!-- bilingual-en:start -->
> Let $C=\{-3,-2,-1,0,1,2,3\}$ and let $P(c)$ mean $c^2=4$. If candidates are visited in the displayed order, the first-success algorithm returns $-2$. That satisfies “find any answer”, but not “list all answers”: continuing the scan also finds $2$. If instead the requirement is $c^2=5$, none of the seven integer candidates passes. This proves there is no answer in $C$; it does not prove that the real equation has no solution.
> <!-- bilingual-en:end -->
>
> 令 $C=\{-3,-2,-1,0,1,2,3\}$，$P(c)$ 表示 $c^2=4$。按写出的顺序检查时，第一次成功就返回的算法会得到 $-2$，满足“找任意一个答案”；但若要求“列出全部答案”，就必须继续，才能再找到 $2$。若把要求改成 $c^2=5$，这七个整数候选都不通过，证明的是 $C$ 内没有答案，并不证明对应的实数方程无解。

<!-- bilingual-en:start -->
The claim about all eligible answers also depends on the declared domain. Searching only nonnegative candidates can be complete for a requested nonnegative square root; it is incomplete for all real roots of $x^2=4$. Likewise, several successful examples do not justify an arbitrary rule: exhaustive checking establishes a statement only for the finite domain that was actually covered.
<!-- bilingual-en:end -->

“所有允许的答案”取决于事先声明的范围。若只求非负平方根，仅搜索非负候选可以完整；若要求 $x^2=4$ 的所有实根，这样做就不完整。同样，几个成功例子不能证明任意范围的规律；穷尽检查支持的是实际完整覆盖的有限范围。

## Coverage has a cost
<!-- bilingual-en:end -->

*覆盖需要付出成本*

<!-- bilingual-en:start -->
In the worst case, finding the last solution or establishing that none exists takes $N$ tests. If generation and testing cost at most $T_G$ and $T_P$ per candidate, the total cost is $O(N(T_G+T_P))$. Exhaustive enumeration guarantees coverage, not speed; pruning is valid only when it cannot remove a feasible solution.
<!-- bilingual-en:end -->

最坏情形下，找到最后一个解或证明“没有候选通过”都需要 $N$ 次检验。若生成一个候选和检验它的成本分别至多为 $T_G$ 与 $T_P$，总成本为

$$
O\!\left(N(T_G+T_P)\right).
$$

因此 exhaustive enumeration 的优点是覆盖保证，不是效率保证。缩小候选空间、避免重复生成或从约束推出部分变量，会减少成本，但不能以漏掉合法候选为代价。

<!-- bilingual-en:start -->
Here $N$ counts candidates visited once, and the per-candidate costs must be finite. If an implementation generates duplicates, count its actual visits rather than assuming they equal the number of distinct candidates. The displayed bound describes the scan; fixed setup and returning from an empty scan add constant overhead, giving $O(1+N(T_G+T_P))$ in that model. A cheap-looking predicate may itself be expensive, so state the [[算法成本模型|cost model]] before comparing searches.
<!-- bilingual-en:end -->

这里 $N$ 对应每个候选访问一次，单次生成与检查成本还必须有限。若实现重复生成候选，应按实际访问次数计费，不能假定它等于不同候选的数量。上式描述扫描部分；固定初始化及空扫描的返回另有常数开销，在该模型中总成本可写为 $O(1+N(T_G+T_P))$。看起来简短的检查规则也可能很贵，因此比较搜索时应先说明[[算法成本模型]]。

<!-- bilingual-en:start -->
Safe pruning is a proof about omitted candidates. In the course’s nonnegative integer square-root search, once $c^2>x$, every larger nonnegative integer also has a square greater than $x$. That monotonicity justifies ending the remaining scan. Stopping merely because a convenient number of attempts has been made supplies no such proof. [[二分查找|Binary search]] gains efficiency from stronger ordered-comparison information that justifies eliminating whole groups.
<!-- bilingual-en:end -->

安全剪枝需要说明为何被省略的候选都不可能成功。课程的非负整数平方根搜索中，一旦 $c^2>x$，更大的非负整数的平方也一定超过 $x$；这个单调性论证允许结束剩余扫描。仅仅因为已经试了一个方便的次数，就没有这样的证明。[[二分查找]]利用更强的有序比较信息，才能有依据地一次排除一组候选。

<!-- bilingual-en:start -->
## A finite grid covers only its sampled points
<!-- bilingual-en:end -->

*有限网格只覆盖采样点*

<!-- bilingual-en:start -->
A [[固定步长求根|fixed-step root search]] over a continuous interval merely replaces the problem by enumeration on a finite grid; this card's finite-set conclusion does not extend to the whole real interval. Even when the interval contains a root, the grid can miss the entire residual-acceptance region; see [[固定步长漏根|fixed-step grid miss]].
<!-- bilingual-en:end -->

连续区间上的 [[固定步长求根]] 只是把问题改成有限网格枚举；它不能由本卡的有限集合结论推到整个实数区间。即使区间内有根，网格仍可能完全错过残差接受区域，见 [[固定步长漏根]]。

> [!question]- Interpret an exhausted search · 自检
> <!-- bilingual-en:start -->
> A program checks every element of $C'$ and none satisfies $P$. What else is required before declaring the original problem unsolvable?
>
> **Answer:** $C'$ must cover every candidate allowed by the original problem, and $P$ must be correct. If eligible candidates were omitted, exhausting $C'$ proves only that no solution lies inside $C'$.
> <!-- bilingual-en:end -->
>
> 程序系统检查了集合 $C'$ 的每个元素，且都不满足 $P$。要据此断言原问题无解，还必须确认什么？
>
> **答案：** 必须确认 $C'$ 覆盖原问题允许的全部候选，而且谓词 $P$ 的判断正确；若漏掉合法候选，穷尽 $C'$ 只能证明 $C'$ 内无解。
>
