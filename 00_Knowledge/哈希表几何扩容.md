# 几何扩容把重哈希成本摊到多次更新

<!-- bilingual-en:start -->
*Geometric resizing spreads rehashing cost across many updates*
<!-- bilingual-en:end -->

> [!summary] 原子性能结论
> 扩容时通常要为现有 $n$ 个条目重新计算槽位并搬移，单次容量管理成本是 $\Theta(n)$。若容量每次按固定比例增长，这种昂贵操作之间会隔着线性数量的普通更新，因此容量管理部分的摊还成本可保持常数阶；这并不自动证明碰撞处理也是常数成本。
>
> <!-- bilingual-en:start -->
> Resizing normally recomputes slots and relocates all $n$ existing entries, so one resize has $\Theta(n)$ capacity-management cost. If capacity grows by a fixed factor, a linear number of ordinary updates separates expensive rebuilds, keeping the amortized capacity-management cost constant. This does not by itself prove that collision resolution is constant-time.
> <!-- bilingual-en:end -->

假设容量依次为 $1,2,4,8,\ldots$。做到 $n$ 个条目以前，所有重建搬移量构成几何级数

$$
1+2+4+\cdots < 2n.
$$

只看数组分配、槽位计算和搬移，再把每次普通插入的容量管理工作视为常数，总工作量仍是 $\Theta(n)$，所以容量管理的摊还成本为 $\Theta(1)$。若再有随机哈希与受控负载，使普通碰撞处理具有期望常数成本，才能得到整个更新的“期望摊还 $O(1)$”。这不否认触发扩容的那一次操作很慢；摊还分析讨论操作序列，期望分析才讨论随机选择或输入分布。
<!-- bilingual-en:start -->
Suppose capacities are $1,2,4,8,\ldots$. Before the table reaches $n$ entries, all rebuild work forms the geometric sum above, which is less than $2n$. Counting array allocation, slot computation, relocation, and constant ordinary capacity-management work gives $\Theta(n)$ total, hence $\Theta(1)$ amortized capacity-management cost per insertion. Only after a randomized-hashing and controlled-load assumption supplies expected constant collision-resolution cost can the whole update be called expected amortized $O(1)$. The operation that triggers a resize can still be slow: amortized analysis concerns an operation sequence, whereas expectation concerns randomness or an input distribution.
<!-- bilingual-en:end -->

支持缩容时还要留出迟滞区间：若扩容和缩容使用同一临界点，条目数在边界附近来回变化会反复重建。常见思路是在较高负载扩容、在明显更低的负载才缩容，让下一次重建前仍需经过足够多次更新。
<!-- bilingual-en:start -->
Shrinking also needs hysteresis. If growth and shrinkage use the same threshold, a table whose size oscillates near that boundary may rebuild repeatedly. A common design grows at a higher load and shrinks only at a substantially lower one, ensuring enough updates occur before another rebuild.
<!-- bilingual-en:end -->

> [!question]- 回忆与辨别
> 扩容某一次要搬动 $n$ 个条目，为什么仍能说插入是摊还 $O(1)$？
>
> **答案：** 因为容量按比例增长后，两次扩容之间要发生与当前规模同阶的普通插入；几何级数保证一串 $n$ 次插入的总搬移量仍是 $O(n)$。这只证明容量管理部分的摊还界，碰撞成本还需单独的随机性与负载条件。
