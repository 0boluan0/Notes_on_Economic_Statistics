# 错误最早暴露的阶段只能缩小排查范围而不能证明根因所在
<!-- bilingual-en:start -->
*The earliest stage that exposes a failure narrows the search but does not prove where the root cause lies*
<!-- bilingual-en:end -->

> [!summary] 原子判断
> 先问“程序走到了哪一步”，可以迅速排除一批不可能的原因：语法或类型不兼容通常在编译时暴露；缺少可链接定义通常在链接时暴露；非法输入、越界和错误状态常在运行时暴露。但报错位置是**发现问题的位置**，不一定是**制造问题的位置**。
> <!-- bilingual-en:start -->
>
> &nbsp;
> First ask how far the program got. Syntax or incompatible types are usually exposed during compilation, missing linkable definitions during linking, and invalid inputs, bounds violations, or bad states during execution. Yet the reporting location is where the problem was detected, not necessarily where it was created.
> <!-- bilingual-en:end -->

## 一套够用的排查顺序

1. **编译未通过：** 先修第一条有意义的诊断，并同时查看它指向的声明和调用。后续几十条错误可能只是解析已经偏离后的连锁反应。
2. **链接未通过：** 核对函数或对象是否真正有定义、定义所在目标文件是否参加链接、名称与类型是否一致。
3. **程序已运行但结果错误或崩溃：** 用最小输入重现，再检查前置条件、对象生命周期、数组边界和算术范围。

“能编译”只说明实现接受了这个翻译单元；它既不证明链接一定成功，也不证明程序对所有输入都有定义良好的行为。
<!-- bilingual-en:start -->
1. **Compilation failed:** Fix the first meaningful diagnostic and inspect both the referenced declaration and the call. Many later errors may only be cascades after parsing went off course.
2. **Linking failed:** Check that a function or object really has a definition, that its object file participates in the link, and that names and types agree.
3. **The program ran but crashed or produced a wrong result:** Reproduce with the smallest input, then inspect preconditions, object lifetimes, array bounds, and arithmetic ranges.

“It compiles” means only that the implementation accepted the translation unit. It proves neither that linking will succeed nor that execution is well-defined for every input.
<!-- bilingual-en:end -->

## 边界

编译器有时会在链接期优化时才发现问题，也可能只给出警告而仍生成程序；越界等未定义行为还可能暂时看似正常。因此按阶段诊断是缩小搜索空间的方法，不是把所有故障机械归类的定理。
<!-- bilingual-en:start -->
A compiler may discover a problem only during link-time optimisation, may issue only a warning and still produce a program, or may let undefined behaviour such as an out-of-bounds access appear to work. Stage-based diagnosis narrows the search space; it is not a theorem that mechanically classifies every fault.
<!-- bilingual-en:end -->

> [!question]- 自检
> 链接器在 `main` 的调用处报告 `undefined reference to mean`。为什么不能只盯着这一行调用？
>
> **答案：** 调用处只是链接器需要该符号的位置；根因也可能是定义文件没参与链接、定义名称不同，或声明与定义不一致。

## 来源与核验

- [GCC, Overall Options](https://gcc.gnu.org/onlinedocs/gcc/Overall-Options.html)：核对各构建阶段及链接并非编译的同义词。
- [GCC, Warning Options](https://gcc.gnu.org/onlinedocs/gcc/Warning-Options.html)：核对诊断、警告与错误的边界。
- [ISO C11 committee draft N1570, 5.1.1.3 and 3.4.3](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf)：核对必须诊断的情形与未定义行为不要求诊断的区别。
<!-- bilingual-en:start -->
- [GCC, Overall Options](https://gcc.gnu.org/onlinedocs/gcc/Overall-Options.html) was checked for distinct build stages and the fact that linking is not synonymous with compilation.
- [GCC, Warning Options](https://gcc.gnu.org/onlinedocs/gcc/Warning-Options.html) was checked for the boundary among diagnostics, warnings, and errors.
- [ISO C11 committee draft N1570, 5.1.1.3 and 3.4.3](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf) was checked for diagnosable violations versus undefined behaviour for which no diagnostic is required.
<!-- bilingual-en:end -->
