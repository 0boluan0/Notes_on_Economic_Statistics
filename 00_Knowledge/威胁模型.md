# 威胁模型用资产、保护目标、攻击者能力与信任边界限定安全主张
<!-- bilingual-en:start -->
*A threat model bounds a security claim by its assets, protection goals, adversary capabilities, and trust boundaries*
<!-- bilingual-en:end -->

> [!summary] 它是什么
> 威胁模型是针对一个具体系统或决策写下的安全问题边界：保护什么，想保留机密性、完整性还是可用性，攻击者能读、改或调用什么，哪些组件和身份暂时可信，以及失败会造成什么影响。只有这些条件明确后，某项控制是否有效才可检验。
> <!-- bilingual-en:start -->
> A threat model records the boundary of a concrete security question: what is being protected, whether confidentiality, integrity, or availability is required, what an adversary can read, modify, or invoke, which components and identities are provisionally trusted, and what failure would cost. Only then can a control be tested against the claim.
> <!-- bilingual-en:end -->

例如，同一份下载文件面对不同攻击者，需要不同证据。若只担心磁盘随机损坏，重新计算 hash 并与先前保存的摘要比较可能足够；若攻击者能同时替换文件和网页上的摘要，这个检查就不能认证发布者。SHA-256 的计算没有改变，改变的是攻击能力与可信渠道。
<!-- bilingual-en:start -->
The same downloaded file needs different evidence against different adversaries. If the concern is accidental disk corruption, recomputing a hash and comparing it with a previously retained digest may suffice. If an attacker can replace both the file and the digest on the website, that check cannot authenticate the publisher. SHA-256 has not changed; the adversary and trusted channel have.
<!-- bilingual-en:end -->

威胁模型不是无限罗列所有危险。它只需把本次判断的范围和假设写到足以反驳：新入口、权限或依赖出现后，旧结论要重新检查，不能自动覆盖新的攻击面。
<!-- bilingual-en:start -->
A threat model is not an endless catalogue of every danger. It makes the present scope and assumptions explicit enough to challenge. New interfaces, privileges, or dependencies require the old conclusion to be checked again rather than extended automatically.
<!-- bilingual-en:end -->

> [!question]- 自检
> “数据库已加密”为什么还不足以证明客户数据安全？
>
> **答案：** 还不知道攻击者能否控制应用、读取解密后的数据、取得密钥或滥用合法权限，也不知道目标是防泄露、篡改还是不可用。必须先补全资产、目标、能力和信任边界。

## 来源与核验

- [NIST SP 800-154, *Guide to Data-Centric System Threat Modeling*（Initial Public Draft）](https://csrc.nist.gov/pubs/sp/800/154/ipd)：核对威胁建模是一种面向特定数据、应用或系统的风险评估，会同时建模攻击面与防御面；截至 2026-09-01 仍为草案，因此本卡只采用其通用定义，不把它当成强制规范。
- [OWASP Threat Modeling Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Threat_Modeling_Cheat_Sheet.html)：核对系统模型、数据流、信任边界、威胁识别、缓解与复查共同构成可重复的威胁建模过程。
- [NIST SP 800-160 Vol. 1 Rev. 1, *Engineering Trustworthy Secure Systems*](https://csrc.nist.gov/pubs/sp/800/160/v1/r1/final)：交叉核对保护需求、系统边界、安全约束与验证证据必须共同限定系统安全结论。
