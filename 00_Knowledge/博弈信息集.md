# 博弈中的信息集把同一行动者无法区分且具有相同可选行动的决策节点归在一起
<!-- bilingual-en:start -->
*An information set groups decision nodes that belong to the same mover, cannot be distinguished by that mover, and offer the same available actions*
<!-- bilingual-en:end -->

> [!summary] 它回答“轮到我时，我究竟知道自己在哪儿吗？”
> 一个信息集中的实际节点已经由历史决定，但行动者无法凭当时可得信息判断是哪一个。因此，他必须在这些节点上作出同一项选择。信息集不是“概念上相似的节点合集”，而是[[扩展式博弈]]对行动时可观察信息的正式编码。
> <!-- bilingual-en:start -->
> The actual history determines one node, but the mover cannot tell which node within the information set has been reached. The same choice must therefore apply at every node in that set. Information sets encode observability, not visual similarity.
> <!-- bilingual-en:end -->

## 为什么同一集合中的节点必须共享行动者和行动

令 $\mathcal I_i$ 是玩家 $i$ 的信息划分。每个信息集 $I\in\mathcal I_i$ 是一组由玩家 $i$ 行动的非终端历史。若 $h,h'\in I$，则必须有

$$
P(h)=P(h')=i,
\qquad
A(h)=A(h')=:A(I).
$$

第一项保证玩家知道现在是不是轮到自己；第二项保证玩家不会从“屏幕上出现了不同按钮”反推出实际节点。若两个节点的可行动作不同，它们就不能被建模为同一信息集。

信息集还构成决策节点的划分：每个玩家决策节点属于且只属于一个信息集。画图时常用虚线连起同一集合中的节点，但虚线只是表示法，真正的对象是这项划分。

## 单点与非单点信息集

- **单点信息集**只有一个节点。玩家知道自己位于哪段具体历史。
- **非单点信息集**有多个节点。玩家知道自己位于这个集合，却无法区分其中的具体历史。

单点并不等于玩家知道世界的一切。例如，玩家可能准确知道已发生的行动，却不知道对手的收益参数。信息集只编码模型里与当次行动有关的历史辨识；收益与类型是否共同已知属于[[完全与完美信息|完全信息]]问题。

## 信息集如何约束策略与子博弈

一项纯策略必须在每个信息集选一个行动，而不是给同一信息集中的每个节点各写一个行动。若玩家在同一信息集的左节点写“上”、右节点写“下”，这不是可行策略，因为玩家行动时根本不知道自己应执行哪一条指令。

信息集也限制哪些续局能独立分析。候选续局若只包含某个信息集的一部分，就等于让分析者在续局开头知道行动者本人不知道的信息，因此不是合法子博弈，详见[[子博弈判定]]。

> [!example] 看不见前一步的后行动者
> 玩家 1 先选 $L$ 或 $R$，玩家 2 随后行动，但看不见玩家 1 的选择。玩家 2 的两个决策节点应在同一信息集。若两个节点都提供 $U,D$，玩家 2 只有“总选 $U$”和“总选 $D$”两项纯策略，不能写“见 $L$ 选 $U$、见 $R$ 选 $D$”。

> [!question]- 自检
> 两个节点都由玩家 2 行动，而且玩家 2 无法区分它们；但左节点可选 $U,D$，右节点可选 $U,M,D$。能否直接把它们画进同一信息集？
>
> **答案：** 不能。同一信息集必须有相同的可行动作。若现实确有这种界面差异，玩家会从可选菜单识别节点；模型必须重写行动集合或信息结构。
