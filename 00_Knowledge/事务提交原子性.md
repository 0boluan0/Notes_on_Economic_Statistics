# 事务把多条语句作为一个全成或全不成的提交单位

<!-- bilingual-en:start -->
*A transaction makes multiple statements one all-or-nothing commit unit*
<!-- bilingual-en:end -->

> [!summary] 原子定义
> transaction（事务）把若干数据库操作包成一个原子提交单位：`COMMIT` 让全部事务性更改共同生效，`ROLLBACK` 使本事务尚未提交的事务性更改不生效。原子性回答的是“这一组受事务管理的状态改变能否只完成一半”。
>
> <!-- bilingual-en:start -->
> A transaction bundles database operations into one atomic commit unit. `COMMIT` makes its transactional changes effective together; `ROLLBACK` prevents its uncommitted transactional changes from taking effect. Atomicity answers whether this transaction-managed state transition can be only partly completed.
> <!-- bilingual-en:end -->

## 自然解释

转账若包含“甲账户减 100”和“乙账户加 100”，两条语句必须同成同败。否则在第二条前崩溃，就会留下钱已扣但未到账的中间状态。`BEGIN ... COMMIT` 把它们声明为一个事务；中途发现条件不成立时用 `ROLLBACK` 撤销整组未提交更改。

<!-- bilingual-en:start -->
A transfer contains “subtract 100 from Alice” and “add 100 to Bob.” The statements must succeed or fail together; a crash between them must not leave money debited but not credited. `BEGIN ... COMMIT` declares the group as one transaction, while `ROLLBACK` cancels its uncommitted changes when a condition fails.
<!-- bilingual-en:end -->

PostgreSQL 中，即使没有显式 `BEGIN`，单条语句也在隐式事务中执行。显式 transaction block 的价值在于把多条语句放进同一个原子边界，而不是让单条 SQL 第一次获得原子性。

<!-- bilingual-en:start -->
In PostgreSQL, even a statement without explicit `BEGIN` runs inside an implicit transaction. An explicit transaction block extends the atomic boundary across several statements; it does not make a single SQL statement atomic for the first time.
<!-- bilingual-en:end -->

> [!warning] 边界
> 数据库 rollback 不会自动撤销事务外的副作用，例如已经发出的邮件、第三方 API 调用或写入普通文件。PostgreSQL sequence 的取值变化也是特例：它对其他事务立即可见，并且事务 abort 后不会回滚。跨系统一致性还需要幂等、outbox 或补偿等额外设计。
>
> <!-- bilingual-en:start -->
> A database rollback does not automatically undo effects outside the transaction, such as sent email, third-party API calls, or ordinary file writes. PostgreSQL sequence changes are another explicit exception: they become visible immediately and are not rolled back if the transaction aborts. Cross-system consistency requires additional designs such as idempotency, an outbox, or compensation.
> <!-- bilingual-en:end -->

> [!question]- 回忆与应用
> 一个程序先更新订单，再单独更新库存，但只给第二条语句开事务。它能保证两者同成同败吗？
>
> **答案：** 不能。原子边界必须同时包住两个共同定义业务状态的更新。

## 来源与核验

- PostgreSQL 18, [*Transaction Isolation*](https://www.postgresql.org/docs/current/transaction-iso.html)：说明 sequence 变更不遵循普通事务回滚规则。
