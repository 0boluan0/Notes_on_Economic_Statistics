# 隔离级别限制并发事务可观察的历史而不自动表达业务规则

<!-- bilingual-en:start -->
*Isolation levels restrict observable concurrent histories rather than express business rules*
<!-- bilingual-en:end -->

> [!summary] 原子定义
> isolation（隔离）规定并发事务可以观察到哪些中间或交错结果。SQL 标准用 dirty read、nonrepeatable read、phantom read 和 serialization anomaly 等现象区分级别；最强的 Serializable 要求成功提交的总体效果等价于某个串行顺序。
>
> <!-- bilingual-en:start -->
> Isolation specifies which intermediate or interleaved results concurrent transactions may observe. The SQL standard distinguishes levels using phenomena such as dirty reads, nonrepeatable reads, phantom reads, and serialization anomalies. Serializable requires the effect of committed transactions to match some serial order.
> <!-- bilingual-en:end -->

## 自然解释

两个事务可以物理上同时运行，只要其成功结果仍符合级别允许的历史。隔离越强，不是简单地“把所有东西都锁住”，而是排除更多不可接受的交错；实现可能使用锁、MVCC snapshot、冲突检测或它们的组合。

<!-- bilingual-en:start -->
Transactions may physically run at the same time as long as their successful outcome fits a history allowed by the level. Stronger isolation does not simply mean “lock everything”; it excludes more unacceptable interleavings, using locks, MVCC snapshots, conflict detection, or combinations thereof.
<!-- bilingual-en:end -->

选择级别必须从不变量反推。若两条语句各自正确却组合后可能产生 write skew，仅仅“不读未提交数据”就不够；要么让约束直接拒绝坏状态，要么加合适锁，要么使用能检测该异常并要求重试的级别。

<!-- bilingual-en:start -->
Choose isolation from the invariant backward. If individually correct statements can combine into write skew, merely avoiding uncommitted reads is insufficient. Encode a rejecting constraint, take suitable locks, or use a level that detects the anomaly and requires retry.
<!-- bilingual-en:end -->

> [!warning] 边界
> 同名 isolation level 在不同数据库上的实际保证可以比 SQL 标准最低要求更强，甚至实现方式不同。下面的 Read Committed 和 Repeatable Read 原子明确指 PostgreSQL，不能无条件搬到别的产品。
>
> <!-- bilingual-en:start -->
> The same isolation-level name can provide stronger guarantees than the SQL minimum or use a different implementation across database products. The Read Committed and Repeatable Read atoms below are PostgreSQL-specific and must not be copied unconditionally to another system.
> <!-- bilingual-en:end -->

> [!question]- 回忆与应用
> “事务之间互相看不到任何东西”是 isolation 的准确解释吗？
>
> **答案：** 不是。隔离级别允许不同程度的并发可见性；关键是哪些历史和异常被允许，以及成功结果是否满足所需不变量。
