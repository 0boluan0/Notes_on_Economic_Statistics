# 构建系统决定如何生成目标而包管理器决定外部依赖从哪里来
<!-- bilingual-en:start -->
*A build system determines how to produce targets, while a package manager locates and selects external dependencies*
<!-- bilingual-en:end -->

> [!summary] 原子边界
> 构建系统管理项目内部的转换关系：哪些输入经过哪些规则得到哪些目标。包管理器管理外部组件：去哪个 registry、Git repository 或本地路径取得包，以及允许、解析并安装哪个版本。
> <!-- bilingual-en:start -->
> A build system manages transformations inside a project: which rules turn which inputs into which targets. A package manager manages external components: which registry, Git repository, or local path supplies a package, and which permitted version is resolved and installed.
> <!-- bilingual-en:end -->

这个区别能定位失败层。`No rule to make target` 指向构建图或输入声明；“找不到满足版本范围的包”指向依赖解析；下载失败又可能只是网络或 registry 可用性问题。
<!-- bilingual-en:start -->
The distinction locates the failing layer. `No rule to make target` points to the build graph or input declaration; “no package satisfies this version range” points to dependency resolution; a download failure may instead concern network or registry availability.
<!-- bilingual-en:end -->

## 边界

职责不同不代表必须使用两个程序。Cargo 等工具同时提供包管理和构建入口，Make 也能在配方中调用下载命令；判断时应看它此刻解决的问题，而不是只看工具名称。
<!-- bilingual-en:start -->
Different responsibilities do not require separate executables. Tools such as Cargo provide both package-management and build entry points, and Make recipes can call download commands. Classify the role by the question being answered, not merely by the tool's name.
<!-- bilingual-en:end -->

> [!question]- 自检
> `Cargo.toml` 的版本要求无法解析，与 `rustc` 编译源文件报语法错，分别先查哪一层？
>
> **答案：** 前者先查包管理/依赖解析，后者先查构建过程中的编译步骤。
