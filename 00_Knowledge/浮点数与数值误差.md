# 浮点数与数值误差
<!-- bilingual-en:start -->
*Floating-Point Numbers and Numerical Error*
<!-- bilingual-en:end -->

> [!summary] 快速恢复
> **它解决什么：** 在计算机不能精确表示所有实数时，理解误差从哪里产生，并把数值结果控制在可接受范围内。
> **具体锚点：** `0.1 + 0.2` 可能不精确等于 `0.3`，因为二进制浮点无法有限表示多数十进制小数。
> **核心难点：** 不能把机器浮点当作实数；比较与停止条件要使用来自问题尺度的绝对或相对容差。
> **为什么重要：** 数值程序的正确性是“误差在可接受范围内”，而非纸笔代数式完全相等。
> **继续：** 先识别表示、舍入与 cancellation，再进入 [[数值求根：二分法与 Newton–Raphson]]。
> <!-- bilingual-en:start -->
> **Problem addressed:** Understand where numerical error comes from when a computer cannot represent every real number exactly, and keep results within an acceptable error bound.
> **Concrete anchor:** `0.1 + 0.2` may not equal `0.3` exactly because most decimal fractions have no finite binary floating-point representation.
> **Central difficulty:** Machine floating-point values are not real numbers; comparisons and stopping rules need absolute or relative tolerances derived from the problem scale.
> **Why it matters:** Correctness in numerical software means that error is bounded acceptably, not that machine values satisfy paper algebra exactly.
> **Continue with:** Identify representation, rounding, and cancellation errors, then move to [[数值求根：二分法与 Newton–Raphson|Numerical Root-Finding: Bisection and Newton–Raphson]].
> <!-- bilingual-en:end -->

## 浮点表示
<!-- bilingual-en:start -->
*Floating-Point Representation*
<!-- bilingual-en:end -->

浮点数近似为符号、尾数和指数，范围与精度有限。舍入误差可累积，减去两个近数产生 catastrophic cancellation。比较用 `math.isclose` 或问题尺度容差，并区分绝对和相对误差。
<!-- bilingual-en:start -->
A floating-point value approximates a sign, significand, and exponent with finite range and precision. Rounding error can accumulate, while subtracting close values causes catastrophic cancellation. Compare with `math.isclose` or a scale-aware tolerance, distinguishing absolute from relative error.
<!-- bilingual-en:end -->

绝对容差适合接近零的量，relative tolerance 适合跨尺度比较；两者都必须来自问题允许误差，而不是随手写一个很小的常数。
<!-- bilingual-en:start -->
An absolute tolerance suits values near zero, while a relative tolerance handles changing scale. Both should come from the problem's acceptable error rather than an arbitrary tiny constant.
<!-- bilingual-en:end -->

## Worked example：求和顺序影响结果
<!-- bilingual-en:start -->
*Worked Example: Summation Order Changes the Result*
<!-- bilingual-en:end -->

把很小的数逐个加到巨大数上，增量可能低于当前表示间距而被舍去；先汇总小量或使用 `math.fsum` 可降低误差。
<!-- bilingual-en:start -->
Adding tiny values one by one to a huge value can lose each increment when it falls below the representable spacing at that magnitude. Summing small values first or using `math.fsum` can reduce the error.
<!-- bilingual-en:end -->

```python
import math

values = [1e16, 1.0, -1e16]
print(sum(values))
print(math.fsum(values))
```

## 失败诊断
<!-- bilingual-en:start -->
*Failure Diagnosis*
<!-- bilingual-en:end -->

- `==` 偶发失败：检查值是否经过浮点运算，并选择与量纲和尺度一致的容差。
  <!-- bilingual-en:start -->
  `==` fails intermittently: determine whether floating-point operations produced the values and choose a tolerance consistent with units and scale.
  <!-- bilingual-en:end -->
- 误差突然放大：查找近数相减、长链求和、溢出/下溢和病态问题，而不只增加小数位显示。
  <!-- bilingual-en:start -->
  Error suddenly grows: inspect subtraction of close values, long summations, overflow or underflow, and ill-conditioning rather than merely printing more digits.
  <!-- bilingual-en:end -->
- 结果稳定但错误：稳定复现只说明舍入路径确定，仍需与解析特例或高精度基准比较。
  <!-- bilingual-en:start -->
  A result is stable but wrong: reproducibility only shows a deterministic rounding path; compare against an analytic case or higher-precision reference.
  <!-- bilingual-en:end -->

## 最小自检
<!-- bilingual-en:start -->
*Minimum Self-Check*
<!-- bilingual-en:end -->

### 为什么浮点数不宜用 `==` 判断迭代收敛？
<!-- bilingual-en:start -->
*Why is `==` unsuitable for deciding convergence of a floating-point iteration?*
<!-- bilingual-en:end -->

> [!answer]- 答案
> 舍入使理论相等值可能有微小差异，也可能迭代在两个近值间循环；应使用与问题尺度匹配的容差。
> <!-- bilingual-en:start -->
> Rounding can leave theoretically equal values slightly different or make an iteration alternate between nearby values; use a tolerance matched to the problem scale.
> <!-- bilingual-en:end -->

### 什么时候相对误差比绝对误差更合适？
<!-- bilingual-en:start -->
*When is relative error more appropriate than absolute error?*
<!-- bilingual-en:end -->

> [!answer]- 答案
> 当允许误差应随量值大小缩放时；接近零时还需绝对容差避免分母失去意义。
> <!-- bilingual-en:start -->
> When acceptable error should scale with magnitude; near zero, an absolute tolerance is also needed because relative error becomes unstable.
> <!-- bilingual-en:end -->

### 为什么显示更多小数位不能修复 cancellation？
<!-- bilingual-en:start -->
*Why does printing more decimal places not repair cancellation?*
<!-- bilingual-en:end -->

> [!answer]- 答案
> 信息已在运算时因舍入丢失，格式化只能显示存下来的近似值，不能恢复被消去的有效数字。
> <!-- bilingual-en:start -->
> Information was lost during arithmetic rounding; formatting only displays the stored approximation and cannot recover cancelled significant digits.
> <!-- bilingual-en:end -->
