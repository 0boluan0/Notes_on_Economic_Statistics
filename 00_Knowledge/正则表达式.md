# 正则表达式是描述字符串匹配模式的表达式

<!-- bilingual-en:start -->
*A regular expression describes a pattern for matching strings*
<!-- bilingual-en:end -->

正则表达式（regular expression，regex）用普通字符、元字符及组合规则描述字符串模式，供程序搜索、筛选或替换匹配内容。表达式本身不是完整命令；“匹配后输出什么”和“逐行还是跨行搜索”由使用它的工具及选项决定。

<!-- bilingual-en:start -->
A regular expression uses ordinary characters, metacharacters, and composition rules to describe a string pattern for searching, filtering, or replacement. It is not a complete command: the consuming tool and its options determine what is output and whether matching operates on individual lines or across lines.
<!-- bilingual-en:end -->

在下面明确采用 ERE、`C` locale 的逐行例子中，`[0-9]` 匹配一个 ASCII 数字，`+` 表示前一项出现至少一次，`^` 与 `$` 约束行首和行尾。只有 `a12` 被输出；没有锚点的 `a[0-9]+` 也能匹配 `xa12y` 内的子串。

<!-- bilingual-en:start -->
In this line-oriented example using ERE and the `C` locale, `[0-9]` matches an ASCII digit, `+` repeats the preceding item at least once, and `^` and `$` constrain the beginning and end of the line. Only `a12` is output; without anchors, `a[0-9]+` also matches a substring of `xa12y`.
<!-- bilingual-en:end -->

```bash
printf '%s\n' 'a12' 'xa12y' 'a' | LC_ALL=C grep -E '^a[0-9]+$'
```

不要把某个工具的符号解释推广到所有正则引擎：BRE、ERE 和其他引擎的语法及匹配规则存在差异，见[[正则方言边界]]。例如 `.` 对换行的处理依赖接口；`grep` 默认逐行搜索时，行尾换行不属于被匹配的行内容。

<!-- bilingual-en:start -->
Do not generalize one tool's syntax to every regular-expression engine: BRE, ERE, and other engines differ in syntax and matching rules; see [[正则方言边界|regular-expression dialect boundaries]]. For example, whether `.` can match a newline depends on the interface. In ordinary line-oriented `grep`, the terminating newline is not part of the matched line contents.
<!-- bilingual-en:end -->
