# 版本要求描述可选范围而不是已经选中的精确版本
<!-- bilingual-en:start -->
*A dependency version requirement describes an admissible range, not the exact version already selected*
<!-- bilingual-en:end -->

> [!summary] 原子区别
> manifest 中的版本字符串通常是交给 resolver 的约束。以 Cargo 为例，`"1.2.3"` 是 `>=1.2.3, <2.0.0`，`~1.2.3` 是 `>=1.2.3, <1.3.0`，`1.2.*` 也是 `>=1.2.0, <1.3.0`；比较符与逗号还能直接组成范围交集。
> <!-- bilingual-en:start -->
> A version string in a manifest is usually a constraint given to a resolver. In Cargo, `"1.2.3"` means `>=1.2.3, <2.0.0`, `~1.2.3` means `>=1.2.3, <1.3.0`, and `1.2.*` means `>=1.2.0, <1.3.0`; comparison operators and commas can express an explicit intersection of ranges.
> <!-- bilingual-en:end -->

因此依赖 `"1.3.7"` 时，Cargo 可以选择兼容且不低于 1.3.7 的版本，但 **1.3.0 不满足下界**。解析器从所有直接与传递约束共同允许的候选中作出具体选择；manifest 本身没有记录这次究竟选了哪一个候选。
<!-- bilingual-en:start -->
Thus, with a Cargo requirement of `"1.3.7"`, the resolver may choose a compatible version no lower than 1.3.7, but **1.3.0 violates the lower bound**. The resolver selects a concrete candidate satisfying all direct and transitive constraints; the manifest alone does not record which candidate was selected this time.
<!-- bilingual-en:end -->

Cargo 也允许用 `=1.2.3` 把允许集合收缩成一个版本；这仍是交给 resolver 的**约束**，不是包含传递依赖、来源，以及 Git 依赖具体 commit 的完整解析结果。
<!-- bilingual-en:start -->
Cargo also permits `=1.2.3`, which narrows the admissible set to one version. It is still a **constraint** given to the resolver, not the complete resolution state containing transitive dependencies, sources, and concrete commits for Git dependencies.
<!-- bilingual-en:end -->

## 边界

范围语法由生态系统定义。不能看到裸 `1.2.3` 就跨 npm、Cargo、Python 等工具断言它是精确 pin 或同一 caret 范围；SemVer 本身也只定义版本号含义，不定义 resolver 语法。
<!-- bilingual-en:start -->
Range syntax is ecosystem-specific. A bare `1.2.3` must not be assumed to mean an exact pin or the same caret range across npm, Cargo, Python, and other tools. SemVer itself defines version-number meaning, not resolver syntax.
<!-- bilingual-en:end -->

1.0.0 以前更要区分两层：SemVer 说 `0.y.z` 的公开 API 不应视为稳定，Cargo 却为解析定义了更具体的默认范围，例如 `0.2.3` 表示 `>=0.2.3, <0.3.0`。这是 Cargo 的选版规则，不是 SemVer 对 `0.2.x` 的兼容保证。
<!-- bilingual-en:start -->
Before 1.0.0, the two layers must be separated even more carefully. SemVer says that the public API of `0.y.z` should not be considered stable, while Cargo defines a more specific default resolution range: for example, `0.2.3` means `>=0.2.3, <0.3.0`. That is Cargo's selection rule, not a SemVer compatibility guarantee for `0.2.x`.
<!-- bilingual-en:end -->

> [!question]- 自检
> Cargo manifest 写 `lib = "1.3.7"`，解析到 1.6.1 与 1.3.0 时，哪个满足默认要求？
>
> **答案：** 1.6.1 满足 `>=1.3.7,<2.0.0`；1.3.0 低于下界，不满足。
