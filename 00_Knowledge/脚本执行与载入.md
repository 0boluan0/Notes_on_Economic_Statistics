# 通常执行脚本使用独立环境而载入脚本使用当前Shell环境

从现有 Bash 通常调用 `bash file` 或 `./file` 时，脚本在独立执行环境中运行；通过 `. ./file` 或 Bash 的 `source ./file` 载入时，文件中的命令在当前 Shell 环境中运行。本区别不把 `exec` 替换当前 Shell 的调用方式算作普通子进程执行。
<!-- bilingual-en:start -->
When invoked normally from an existing Bash as `bash file` or `./file`, a script runs in a separate execution environment. Sourcing it with `. ./file` or Bash `source ./file` executes its commands in the current shell environment. This distinction excludes using `exec` to replace the current shell from the ordinary child-execution case.
<!-- bilingual-en:end -->

假设临时练习目录中的 `change.sh` 只包含 `shell_value=changed`，在独立练习 Bash 中比较：
<!-- bilingual-en:start -->
Suppose `change.sh` in a temporary practice directory contains only `shell_value=changed`. Compare these calls in an isolated practice Bash:
<!-- bilingual-en:end -->

```bash
shell_value=before
bash ./change.sh
printf '%s\n' "$shell_value"
source ./change.sh
printf '%s\n' "$shell_value"
```

两次显示分别为 `before` 与 `changed`。同理，普通子进程中的 `cd` 不改变父 Shell 的当前目录；载入文件中的 `cd` 则改变正在执行它的环境。载入代码还可能改变函数、选项或直接 `exit`，所以它不是只读的“导入数据”。
<!-- bilingual-en:start -->
The outputs are `before` and `changed`. Likewise, a normal child's `cd` does not change the parent shell's directory, whereas a sourced `cd` changes the environment executing it. Sourced code can also change functions or options, or call `exit`; it is not a read-only data import.
<!-- bilingual-en:end -->

`( … )`、`$( … )`、后台命令及 Bash 3.2 的管道阶段也建立子 Shell 环境；在其中调用函数或 `source`，改变仍局限于那个子环境。环境隔离只限制这些 Shell 状态回传，不阻止子进程修改共享文件、发网络请求或产生其他外部副作用。
<!-- bilingual-en:start -->
Parenthesized commands, `$( … )`, background commands, and Bash 3.2 pipeline stages also use subshell environments. A function or `source` call inside one changes that environment. Isolation limits propagation of shell state; it does not prevent shared-file changes, network requests, or other external side effects.
<!-- bilingual-en:end -->
