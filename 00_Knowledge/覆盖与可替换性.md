# 子类覆盖只有保持基类契约时才允许调用者安全替换基类对象
<!-- bilingual-en:start -->
*A subclass override permits safe substitution only when it preserves the base-class contract*
<!-- bilingual-en:end -->

> [!summary] 原子行为边界
> 子类定义同名属性会在 MRO 中覆盖基类版本，但“查找到子类方法”只说明 dispatch 成功，不说明设计正确。若调用者只依赖基类契约，换成子类后仍应满足可接受的输入、承诺的结果、异常与副作用边界，并保持基类不变量；这就是可替换性的核心直觉。
> <!-- bilingual-en:start -->
> A same-named subclass attribute overrides the base implementation in the MRO, but successful dispatch does not establish a correct design. A caller that relies only on the base contract should still receive valid input acceptance, promised results, exception and side-effect boundaries, and preserved base invariants after a subclass is substituted. This is the core intuition of substitutability.
> <!-- bilingual-en:end -->

子类通常不应加强前置条件，例如基类允许所有非负金额，子类却只接受整数；也不应削弱后置条件，例如基类承诺成功后返回新余额，子类却改成只打印。Python 不会自动验证这套语义，需要靠清晰契约与针对基类行为的测试发现破坏。

```python
def apply_deposit(account, amount):
    """account follows the Account deposit contract."""
    return account.deposit(amount)

# Any subclass used here must preserve that observable contract.
```

> [!question]- 回忆与应用
> 子类方法名字和参数数量都与父类相同，为什么仍可能不可替换？
>
> **答案：** 可替换性约束可观察行为；子类仍可能加强输入限制、改变返回/异常/副作用或破坏不变量。
