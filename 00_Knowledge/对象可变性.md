# 对象类型决定其自身能否在身份不变时被原地修改
<!-- bilingual-en:start -->
*An object's type determines whether the object itself supports in-place change while its identity remains fixed*
<!-- bilingual-en:end -->

> [!summary] 原子边界
> Python 对象同时具有身份、类型和值。可变对象允许自身在身份不变时改变；不可变对象不允许这种原地改变。内置的 **list**、**dict**、**set** 是可变类型；数字、**str**、**tuple** 是不可变类型。

必须把三种变化分开：

1. **名称重新绑定：** **x = x + 1** 让名称 **x** 指向另一个对象；
2. **容器槽改变：** **a[0] = value** 改写可变容器保存的引用；
3. **槽中对象改变：** **a[0].append(value)** 不换槽，却修改槽所指向的列表。

对容器来说，不可变性固定的是它直接保存的引用，因而排除第二种变化；第三种变化发生在另一个被引用对象上，并不等于外层容器被原地改写。不可变性也不保证每次运算都创建一个全新身份。实现可以安全复用同值不可变对象；程序不应靠整数、字符串或元组的偶然身份判断值语义。

~~~python
a = [1, 2]
before = id(a)
a.append(3)
assert id(a) == before

n = 1
n = n + 1          # 名称 n 改绑；整数 1 没有被改成 2
~~~

## 增强赋值先运算再回写目标

**x += y** 不是在所有类型上都等于“原地修改”。解释器只求值目标一次，随后按类型尝试增强运算，并把结果赋回原目标：列表常会修改原对象并回写同一对象，元组等不可变对象则通常产生结果后改绑名称。若目标是容器槽，原地运算甚至可能已经改变槽中对象，而最后的槽回写才失败：

~~~python
t = ([],)
try:
    t[0] += [1]
except TypeError:
    pass

assert t == ([1],)   # 内层列表已改变；元组槽回写失败且不会回滚前一步
~~~

> [!question]- 自检
> **x += y** 是否一定表示原地修改？
>
> **答案：** 不一定。它先尝试类型的 in-place 协议；可变列表通常原地扩展，不可变元组则产生结果并改绑名称。必须结合对象类型判断。
