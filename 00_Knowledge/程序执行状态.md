# 手工追踪程序必须同时记录名称绑定、当前求值和下一控制位置
<!-- bilingual-en:start -->
*A program trace must track name bindings, current evaluation, and the next control position together*
<!-- bilingual-en:end -->

> [!summary] 原子执行模型
> Python 解释器按控制流执行语句，并在环境中创建或改变名称绑定。要解释一次运行，至少同时追踪：当前环境里名称指向什么、正在求值哪个表达式、控制接下来会进入哪条语句。最终输出只是这条状态路径的结果，不能反推中间过程必然正确。
> <!-- bilingual-en:start -->
> Python executes statements along a control path while creating or changing name bindings in an environment. A trace therefore tracks the current bindings, the expression being evaluated, and the statement that receives control next. Final output is only the result of that state path and cannot establish that the intermediate process was correct.
> <!-- bilingual-en:end -->

声明式描述说明结果应满足什么性质；命令式过程说明如何一步步得到结果。算法是求解方法，Python 程序是该方法在特定语言与运行环境中的一个实现；同一算法可以有不同实现，同一段代码也可能因输入走不同路径。

```python
x = 2          # bind x to 2
if x > 0:      # evaluate the guard
    y = x + 1  # next control position depends on the guard
```

只写“最后 `y` 是 3”没有说明为什么该分支会运行，也无法诊断条件、绑定或求值的错误。可靠 trace 应在每个分支点写出实际条件值，并在每次赋值后更新环境，而不是把名称当成会自动联动的代数变量。

> [!question]- 回忆与应用
> 两个程序给出相同最终输出，为什么仍不能据此断定它们执行了同一算法或同一路径？
>
> **答案：** 不同控制路径和中间状态可以收束到相同输出；必须检查语句顺序、条件结果和状态变化。
