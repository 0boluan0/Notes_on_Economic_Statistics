# 实测计时描述具体运行而渐近分析描述指定成本模型下的增长界

<!-- bilingual-en:start -->
*Timing describes specific runs; asymptotic analysis describes growth bounds under a cost model*
<!-- bilingual-en:end -->

实测计时观察某个实现、机器、运行环境和输入上的实际耗时；渐近分析在声明的[[算法成本模型]]与输入情形下证明成本随规模增长的界。二者回答不同问题，可以相互检验与补充，但不能把一次计时当成普遍复杂度证明。

<!-- bilingual-en:start -->
Timing observes elapsed time for a particular implementation, machine, environment and input. Asymptotic analysis proves growth bounds under a stated [[算法成本模型|cost model]] and input case. They answer different questions and can complement each other; one timing is not a general complexity proof.
<!-- bilingual-en:end -->

渐近阶较低不保证所有规模上都更快。例如两个模型成本分别为 $1000n$ 和 $n^2$，前者在 $0<n<1000$ 时更大，却最终增长更慢。真实计时还受常数、缓存、解释器、系统负载及所选输入影响；“最终更好”不能省掉实际使用规模。

<!-- bilingual-en:start -->
A lower asymptotic order need not be faster at every size. The model costs $1000n$ and $n^2$ illustrate this: the first is larger for $0<n<1000$ but eventually grows more slowly. Actual timings also depend on constants, caching, the interpreter, system load and selected inputs. “Eventually better” does not remove the need to consider practical sizes.
<!-- bilingual-en:end -->

比较实现时，应固定要比较的任务与计时范围，在多个有意义的规模和输入上重复测量并报告环境；再用操作计数解释趋势。有限测量可以发现实现或模型不吻合，却不能单独证明所有足够大输入上的界。重复计时的样本均值也不自动等于[[平均情况复杂度]]：后者需要指定输入分布。

<!-- bilingual-en:start -->
Compare implementations using the same task and timing scope, repeated measurements at meaningful sizes and inputs, and a reported environment; then use operation counts to explain trends. Finite measurements can reveal a mismatch between implementation and model, but cannot alone prove a bound for all sufficiently large inputs. A sample mean of repeated timings is not automatically [[平均情况复杂度|average-case complexity]], which requires an input distribution.
<!-- bilingual-en:end -->
