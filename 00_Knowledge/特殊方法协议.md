# 特殊方法把自定义对象接入 Python 协议而隐式调用通常从类型而非实例查找
<!-- bilingual-en:start -->
*Special methods integrate custom objects with Python protocols, while implicit calls usually look on the type rather than the instance*
<!-- bilingual-en:end -->

> [!summary] 原子协议边界
> `__repr__`、`__str__`、`__len__`、`__iter__`、`__eq__` 等特殊方法让解释器把自定义对象接入显示、长度、迭代和比较协议。实现者必须满足对应协议的返回值与行为契约；名字像双下划线并不自动产生正确语义。对 `len(obj)`、运算符等隐式调用，Python 通常在 `type(obj)` 上查找特殊方法，而不会采用实例字典里临时塞入的同名函数。
> <!-- bilingual-en:start -->
> Special methods such as `__repr__`, `__str__`, `__len__`, `__iter__`, and `__eq__` let the interpreter integrate a custom object with display, length, iteration, and comparison protocols. Implementers must satisfy each protocol's return-value and behavioral contract; a double-underscore name alone does not create correct semantics. For implicit calls such as `len(obj)` and operators, Python normally looks up the special method on `type(obj)` rather than using a same-named function inserted into the instance dictionary.
> <!-- bilingual-en:end -->

```python
class Batch:
    def __init__(self, items):
        self.items = list(items)

    def __len__(self):
        return len(self.items)

b = Batch([1, 2, 3])
len(b)                     # 3
```

相等和哈希不是一个孤立的“运算符重载”技巧：若自定义 `__eq__`，还要遵守[[哈希相等性契约|相等键同哈希]]并考虑[[哈希键语义稳定性|键状态稳定性]]。对象身份与值相等的区别保留在[[对象身份与值相等]]，不在本卡重复。

> [!question]- 回忆与应用
> 为什么给单个实例执行 `obj.__len__ = lambda: 5` 通常不会让 `len(obj)` 变成 5？
>
> **答案：** 隐式特殊方法调用通常绕过实例字典，直接从对象的类型及其继承链查找协议实现。
