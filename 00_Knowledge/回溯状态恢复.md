# 递归回溯若共享可变状态就必须在探索下一分支前恢复进入时不变量

<!-- bilingual-en:start -->
*Recursive backtracking over shared mutable state must restore the entry invariant before exploring the next branch*
<!-- bilingual-en:end -->

> [!summary] 原子不变量
> 回溯常按“选择—探索—撤销”运行：先把一个候选选择写入当前状态，递归探索由此产生的分支，再撤销这次修改，使下一个候选从与本层入口相同的状态出发。若多个分支共享同一可变对象，恢复不是清理习惯，而是分支正确性的必要不变量。

对一组**互异且可哈希**的候选生成排列时，可以原地维护 `path`；`set` 的枚举次序不作保证，因此这里只承诺枚举全部排列，不承诺输出顺序：

```python
def visit(path, remaining):
    if not remaining:
        emit(tuple(path))
        return
    for choice in tuple(remaining):
        path.append(choice)          # choose
        remaining.remove(choice)
        visit(path, remaining)       # explore
        remaining.add(choice)        # unchoose
        path.pop()
```

在每次循环进入下一候选前，应重新满足：“`path` 恰好记录从根到当前层的选择，`remaining` 恰好包含尚未使用的候选”。若漏掉 `pop()` 或 `add()`，后一分支就从前一分支残留的状态起跑，输出会漏解、重复或携带非法选择。

边界取决于状态传递方式：

- 若每个子调用收到独立副本，返回时天然丢弃子分支修改，可以没有显式 `unchoose`，代价是复制时间与空间。
- 若找到一个解后立即返回，并且契约就是保留该解，成功路径可以有意不恢复；但所有继续探索或向普通调用者返回的路径仍必须满足约定状态。
- 修改与撤销之间可能抛异常时，可用 `try/finally` 保证恢复，否则异常处理后共享状态仍可能损坏。

栈帧独立只能保护局部名称，不能保护它们共同引用的 `path` 或 `remaining`。判断是否要撤销，应看对象身份与函数契约，而不是看变量名是否局部。

> [!question]- 自检
> 两个递归分支都接收同一个列表 `path`。第一分支 `append('A')` 后返回，却未 `pop()`；第二分支随后 `append('B')`。第二分支看到的路径是什么，问题出在哪里？
>
> **答案：** 它会看到包含残留 `'A'` 的路径，再加入 `'B'`。第二分支没有从本层入口状态开始，分支之间发生了污染。
