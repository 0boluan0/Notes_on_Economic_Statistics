# Coverage of a byte-level tokenizer
<!-- bilingual-en:end -->

*字节级分词器为什么能表示陌生字符*

<!-- bilingual-en:start -->
A byte-level tokenizer that includes all 256 single-byte values can always represent the UTF-8 bytes of valid input text. A merged token for a whole character or word can shorten its representation. The base byte entries already provide coverage. This property concerns representability. Semantic competence depends on the model and its training data.
<!-- bilingual-en:end -->

一个收录全部 256 种单字节值的分词器，可以表示任意合法 UTF-8 文本的字节序列。某个字或词拥有整体词元时可以编码得更短。即使没有整体表项，也能回到基础字节。可表示性（coverage）回答能否编码，是否理解该词则取决于模型及其训练。

## Decoding across a character boundary
<!-- bilingual-en:end -->

*跨越字符边界解码*

<!-- bilingual-en:start -->
A [[00_Knowledge/词元编号|token ID]] addresses bytes in this tokenizer’s vocabulary. Token boundaries may fall inside a UTF-8 character. Reassemble the byte sequence before decoding it as text. Inspect a single token through its bytes when a standalone text decode produces a replacement character.
<!-- bilingual-en:end -->

一个[[00_Knowledge/词元编号|词元编号]]在该词表中对应一段字节。词元边界可以落在一个 UTF-8 字符内部。先拼回字节，再作文本解码。如果单个词元打印出替换字符 `�`，可以检查这个词元究竟包含哪些字节。

<!-- bilingual-en:start -->
In the GPT-2 encoding, the three UTF-8 bytes 232, 140 and 182 produce the IDs 164, 234 and 114 for one Chinese character. The three IDs decoded together restore the original character. The English string `hello` has five UTF-8 bytes and one GPT-2 token.
<!-- bilingual-en:end -->

以“茶”为例，UTF-8 字节是 232、140、182，GPT-2 的词元编号却是 164、234、114。三个 ID 一起解码恢复一个“茶”字。反过来，`hello` 有 5 个 UTF-8 字节，在同一词表中只有 1 个词元。
