# 元组固定直接包含的对象引用但其中的可变对象仍可改变
<!-- bilingual-en:start -->
*A tuple fixes its directly contained object references, while mutable objects referenced by those slots may still change*
<!-- bilingual-en:end -->

> [!summary] 原子边界
> 元组创建后，不能增加、删除或替换它的槽，也不能对槽做赋值。这个保证停在元组边界：若某个槽引用列表、字典或其他可变对象，该对象内部仍可改变。

~~~python
row = ([1, 2], "fixed")
row[0].append(3)    # 合法：修改列表
# row[0] = [9]      # TypeError：试图替换元组槽

assert row == ([1, 2, 3], "fixed")
~~~

因此“元组不可变”不等于“从元组出发可到达的整个对象图都不可变”。需要稳定快照时，必须检查嵌套成员，而不是只把外层改成 **tuple**。

## 与可哈希性的关系

元组也不会自动成为字典键。只有当每个元素都可哈希时，元组才可哈希；含列表的元组不可哈希。真正的键约束由 [[哈希键语义稳定性]] 承担，本卡只说明外层不可变边界。

> [!question]- 自检
> 为什么 **([1],)** 的打印结果可能变化，却仍不违反元组不可变性？
>
> **答案：** 元组的唯一槽始终指向同一个列表；变化发生在列表内部，槽本身没有被替换。
