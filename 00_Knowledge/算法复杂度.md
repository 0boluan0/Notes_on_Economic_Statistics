# Algorithmic complexity
<!-- bilingual-en:end -->

*算法复杂度*

<!-- bilingual-en:start -->
**Algorithmic complexity** describes how much work or storage an algorithm requires as its inputs change. The practical question is not just whether a program ran quickly once, but what resource demand its procedure can create on larger or less favourable inputs. A meaningful answer needs the size, the resource, the cost model and the input case.
<!-- bilingual-en:end -->

**算法复杂度**描述算法的工作量或存储需求如何随输入变化。它关心的不只是程序某一次跑得快不快，还包括输入变大或变得不利时，过程可能需要多少资源。有意义的答案要说清规模、资源、成本模型和输入情形。

<!-- bilingual-en:start -->
Algorithm complexity describes the computational resources an algorithm consumes and how consumption varies with input size. A complete statement specifies the [[输入规模|size measure]], [[算法成本模型|cost model]], resource and input case. Time and space are different resources; best, worst and average cases summarize inputs differently.
<!-- bilingual-en:end -->

算法复杂度描述一个算法使用多少计算资源，以及这种消耗怎样随输入规模变化。完整陈述必须指定[[输入规模]]、[[算法成本模型]]、所计资源和输入情形；时间与空间是不同资源，最好、最坏与平均是不同的输入汇总方式。

> [!example] One list length, different amounts of search · 同一列表长度，不同搜索工作量
> <!-- bilingual-en:start -->
> Scan `[4,9,4,12]` from left to right and stop at the first equality. Finding 4 uses one equality test; finding 12 uses four; searching for absent 7 also uses four. The list length is four in every case. Counting equality tests isolates one resource; calling this the running time additionally requires accounting for loop overhead and the cost of each comparison. With fixed-cost operations, a length-$n$ list has worst-case scan time $\Theta(n)$ as $n$ grows: [[大Θ记号|Theta notation]] means growth bounded above and below by positive constant multiples of $n$ for sufficiently large $n$. An empty list has zero equality tests but still some return overhead.
> <!-- bilingual-en:end -->
>
> 从左到右扫描 `[4,9,4,12]`，第一次相等就停止。找 4 只检查一次相等，找 12 检查四次，找不存在的 7 也检查四次；三种情况的列表长度都是四。相等比较次数只隔离了一种资源；若要称为运行时间，还须计算循环开销与每次比较的成本。在基本操作成本固定时，长度为 $n$ 的列表最坏扫描时间随 $n$ 增长为 $\Theta(n)$；[[大Θ记号]]表示在 $n$ 充分大后，成本被 $n$ 的两个正常数倍夹住。空列表的相等比较次数为零，但仍有返回等固定开销。

<!-- bilingual-en:start -->
For example, “early-return linear search on a list of length $n$ has worst-case time $\Theta(n)$ when access and equality tests cost constant time” identifies the algorithm, size, model, resource and case. It does not say that every input takes linear time or that the algorithm uses linear [[辅助空间|auxiliary space]].
<!-- bilingual-en:end -->

例如，“长度为 $n$ 的列表上，找到即停的线性搜索，在访问与相等比较均为常数成本时，最坏时间为 $\Theta(n)$”同时交代了算法、规模、模型、资源与情形。它不等于“每个输入都花线性时间”，也不意味着使用线性[[辅助空间]]。

<!-- bilingual-en:start -->
A cost for one concrete input comes first. [[最好情况复杂度|Best-case]] and [[最坏情况复杂度|worst-case]] functions then compare inputs with the same declared size; [[平均情况复杂度|average-case complexity]] additionally needs a distribution. The [[大Θ记号|Theta notation]] describes the growth of whichever cost function has been chosen. It does not choose the input case for us.
<!-- bilingual-en:end -->

先有具体输入上的成本，再用[[最好情况复杂度]]或[[最坏情况复杂度]]比较同一规模的不同输入；[[平均情况复杂度]]还需要指定分布。[[大Θ记号]]描述的是已经选定的成本函数怎样增长，不会替我们选择输入情形。

<!-- bilingual-en:start -->
[[大O记号|Big-O]], [[大Ω记号|Big-Omega]] and [[大Θ记号|Big-Theta]] describe the asymptotic behavior of a selected cost function; they are not synonyms for algorithm complexity. Randomized execution must identify the randomness behind [[随机算法期望复杂度|expected complexity]], while operation sequences need a separate [[摊还复杂度|amortized analysis]]. [[计时与渐近分析|Timing versus asymptotic analysis]] distinguishes these functions from seconds measured on one machine.
<!-- bilingual-en:end -->

[[大O记号]]、[[大Ω记号]]、[[大Θ记号]]是描述已选定成本函数的渐近工具，不是算法复杂度的同义词。随机运行要说明[[随机算法期望复杂度]]的随机对象；动态结构的操作序列要另行说明[[摊还复杂度]]。算法在某台机器上的实际秒数，则交由[[计时与渐近分析]]区分。
