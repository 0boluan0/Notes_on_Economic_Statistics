# 算法复杂度是在指定规模成本模型与输入情形下描述算法资源消耗的函数

<!-- bilingual-en:start -->
*Algorithm complexity describes resource consumption under a specified size measure, model and input case*
<!-- bilingual-en:end -->

算法复杂度描述一个算法使用多少计算资源，以及这种消耗怎样随输入规模变化。完整陈述必须指定[[输入规模]]、[[算法成本模型]]、所计资源和输入情形；时间与空间是不同资源，最好、最坏与平均是不同的输入汇总方式。

<!-- bilingual-en:start -->
Algorithm complexity describes the computational resources an algorithm consumes and how consumption varies with input size. A complete statement specifies the [[输入规模|size measure]], [[算法成本模型|cost model]], resource and input case. Time and space are different resources; best, worst and average cases summarize inputs differently.
<!-- bilingual-en:end -->

例如，“长度为 $n$ 的列表上，找到即停的线性搜索，在访问与相等比较均为常数成本时，最坏时间为 $\Theta(n)$”同时交代了算法、规模、模型、资源与情形。它不等于“每个输入都花线性时间”，也不意味着使用线性[[辅助空间]]。

<!-- bilingual-en:start -->
For example, “early-return linear search on a list of length $n$ has worst-case time $\Theta(n)$ when access and equality tests cost constant time” identifies the algorithm, size, model, resource and case. It does not say that every input takes linear time or that the algorithm uses linear [[辅助空间|auxiliary space]].
<!-- bilingual-en:end -->

[[大O记号]]、[[大Ω记号]]、[[大Θ记号]]是描述已选定成本函数的渐近工具，不是算法复杂度的同义词。随机运行要说明[[随机算法期望复杂度]]的随机对象；动态结构的操作序列要另行说明[[摊还复杂度]]。算法在某台机器上的实际秒数，则交由[[计时与渐近分析]]区分。

<!-- bilingual-en:start -->
[[大O记号|Big-O]], [[大Ω记号|Big-Omega]] and [[大Θ记号|Big-Theta]] describe the asymptotic behavior of a selected cost function; they are not synonyms for algorithm complexity. Randomized execution must identify the randomness behind [[随机算法期望复杂度|expected complexity]], while operation sequences need a separate [[摊还复杂度|amortized analysis]]. [[计时与渐近分析|Timing versus asymptotic analysis]] distinguishes these functions from seconds measured on one machine.
<!-- bilingual-en:end -->
