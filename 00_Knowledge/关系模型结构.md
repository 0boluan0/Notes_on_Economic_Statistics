# 关系模型用属性定义结构并用元组承载事实

<!-- bilingual-en:start -->
*The relational model uses attributes to define structure and tuples to carry facts*
<!-- bilingual-en:end -->

> [!summary] 原子模型
> 一张关系表的结构由带名称和取值域的属性组成；每个元组在这些属性上给出一组值，表达同一种事实。关系模型先规定“可以说什么”，再保存“已经发生了什么”。
>
> <!-- bilingual-en:start -->
> A relation's structure consists of named attributes with domains. Each tuple supplies one value for every attribute and expresses one fact of the same kind. The relational model first defines what may be stated, then stores the facts that hold.
> <!-- bilingual-en:end -->

设有关系：

$$
\operatorname{Enrollment}(student\_id, course\_id, term, grade)
$$

属性名说明各列的角色，域限制每列可取什么值；一条元组则可以表达“某学生在某学期修读某课程并获得某成绩”。同一关系中的元组必须服从同一个解释，不能让一部分行表示选课、另一部分行突然表示课程本身。
<!-- bilingual-en:start -->
Attribute names state the role of each column, and domains restrict admissible values. A tuple may express that a student took a course in a term and received a grade. Every tuple in the relation must obey the same interpretation; some rows cannot mean enrollments while others suddenly mean courses.
<!-- bilingual-en:end -->

理论上的关系是元组的集合，因此没有内在行序，也不靠“第几行”识别事实。实际 SQL 系统为了方便和性能，允许 `NULL`，而查询结果默认还可能保留重复行。这些是 SQL 的操作语义，不能反过来把关系理解成一张有固定顺序的电子表格。
<!-- bilingual-en:start -->
A relation in the mathematical model is a set of tuples, so it has no intrinsic row order and does not identify a fact by its row number. Practical SQL systems admit `NULL`, and query results may retain duplicates by default. Those operational semantics do not turn a relation into a spreadsheet with a stable physical ordering.
<!-- bilingual-en:end -->

> [!question]- 回忆与辨别
> 为什么“第 17 行”不能成为关系中某个事实的稳定身份？
>
> **答案：** 关系没有内在行序；扫描方式、存储布局和查询计划都可能改变呈现顺序。事实应由属性值及键来识别，而不是由显示位置识别。
