# Summing loop costs
<!-- bilingual-en:end -->

*循环成本求和*

<!-- bilingual-en:start -->
A loop costs the work it actually performs. Counting indentation levels does not tell you how many operations run: an inner loop might have ten iterations, shrink with the outer index, or stop early. Treat a run as a bill with one line for each executed piece of work, then add those lines under a stated [[算法成本模型|cost model]].
<!-- bilingual-en:end -->

循环的成本来自实际完成的工作。只数缩进层级并不能知道执行了多少操作：内层可能固定十次、随外层下标缩短，也可能提前停止。可以把一次运行看成一张账单，为每段实际执行的工作记一笔，再在明确的 [[算法成本模型]] 下求和。

<!-- bilingual-en:start -->
Analyze a loop by determining which iterations execute, how many occur, and the cost of each, then summing them. Include initialization, condition tests and updates in the chosen [[算法成本模型|cost model]]. Sequential blocks add their costs; nested loops require sums over the actual index ranges.
<!-- bilingual-en:end -->

分析循环时，先确定每次迭代是否执行、执行多少次以及每次实际成本，再将这些成本求和；初始化、条件检查与更新也要计入选定的[[算法成本模型]]。顺序执行的代码块成本相加；嵌套循环按实际索引范围逐层求和。

<!-- bilingual-en:start -->
The notation [[大Θ记号|$\Theta(g(n))$]] describes growth trapped between fixed positive multiples of $g(n)$ for sufficiently large $n$. It gives a growth scale rather than an exact count. A one-sided [[大O记号|$O$ upper bound]] need not be tight.
<!-- bilingual-en:end -->

[[大Θ记号|$\Theta(g(n))$]] 表示当 $n$ 足够大时，增长量被 $g(n)$ 的两个固定正倍数夹住；它描述增长尺度，不是精确次数。单侧的 [[大O记号|$O$ 上界]] 未必紧确。

<!-- bilingual-en:start -->
Fix the actual run or the input case before naming its iteration count. With early returns, two inputs of the same size can visit different numbers of items; an [[算法复杂度|algorithmic cost function]] must say whether it describes that run, a best case or a worst case. The sum below counts only iterations that are visited.
<!-- bilingual-en:end -->

为迭代次数命名之前，先固定实际运行或输入情形。存在提前返回时，两个相同规模输入可能访问不同数量的元素；[[算法复杂度|算法成本函数]]必须说明描述的是该次运行、最好情况还是最坏情况。下面的总和只计实际访问的轮次。

<!-- bilingual-en:start -->
With $k(n)$ iterations and body cost $c_i(n)$ at iteration $i$, the body costs $\sum_{i=1}^{k(n)}c_i(n)$. Deriving $O(k(n)g(n))$ by adding per-iteration $O(g(n))$ bounds requires constants and thresholds uniform across the iterations. A matching uniform lower bound gives $\Theta(k(n)g(n))$; see [[渐近界的统一常数|uniform asymptotic constants]].
<!-- bilingual-en:end -->

若共有 $k(n)$ 轮，第 $i$ 轮主体成本为 $c_i(n)$，主体总成本是 $\sum_{i=1}^{k(n)}c_i(n)$。用逐项界推出总和界时，需要对所有这些轮次同时有效的统一常数与起始阈值，才能把“每轮 $O(g(n))$”合并为 $O(k(n)g(n))$；若每轮还有同样统一的 $\Omega(g(n))$ 下界，就得到 $\Theta(k(n)g(n))$。参见[[渐近界的统一常数]]。

<!-- bilingual-en:start -->
For example, if each inner iteration does one constant-cost operation, these two ranges produce different counts:
<!-- bilingual-en:end -->

例如，内层每次做一个常数成本操作，下列两种执行次数不同：

<!-- bilingual-en:start -->
The first has total time $\Theta(nm)$ for $m,n\ge1$; the second has $\Theta(n^2)$ time. The triangular inner loop does not take $\Theta(n)$ iterations on every outer iteration, yet its sum is quadratic. An inner loop of exactly 10 iterations gives only $\Theta(n)$ total time. Early returns, slices and linear membership tests must also enter the analysis.
<!-- bilingual-en:end -->

$$
\sum_{i=0}^{n-1}\sum_{j=0}^{m-1}1=nm,
\qquad
\sum_{i=0}^{n-1}\sum_{j=i}^{n-1}1
=\sum_{i=0}^{n-1}(n-i)
=\frac{n(n+1)}2.
$$

第一种在 $m,n\ge1$ 时总时间为 $\Theta(nm)$；第二种为 $\Theta(n^2)$。三角形循环的内层并非每轮都做 $\Theta(n)$ 次，但求和仍给出平方阶。若内层固定只做 10 次，则总时间仅为 $\Theta(n)$。若有提前返回、切片或线性成员测试，还要把相应控制流程与成本加入求和。

<!-- bilingual-en:start -->
## A body-count table makes the sum concrete
<!-- bilingual-en:end -->

## 先把每轮主体次数写出来

> [!example] A rectangle and a triangle · 矩形与三角形
> <!-- bilingual-en:start -->
> For $n=4,m=3$, a rectangular loop has inner counts $3,3,3,3$, totalling 12. A triangular loop with `range(i,n)` has counts $4,3,2,1$, totalling 10. A fixed ten-element inner list gives at most 40 comparisons if the run visits all four outer items; an early exit can reduce the visited work.
> <!-- bilingual-en:end -->
>
> 当 $n=4,m=3$ 时，矩形循环的内层次数是 $3,3,3,3$，合计 12；使用 `range(i,n)` 的三角形循环是 $4,3,2,1$，合计 10。若内层固定比较十个候选，而且运行访问全部四个外层项，则至多比较 40 次；提前退出会减少实际访问的工作。

<!-- bilingual-en:start -->
The body sum is not automatically the whole runtime. For a normally completed loop with $k$ body executions, there is usually one initialization, $k$ updates and $k+1$ guard checks. Their costs also belong to the total. A body sum of zero for an empty range does not make the program free: it still checks the range or guard and returns.
<!-- bilingual-en:end -->

主体总和不会自动等于整个运行时间。一个正常结束且执行 $k$ 次主体的循环，通常还有一次初始化、$k$ 次更新和 $k+1$ 次条件检查；这些成本也要计入。空范围的主体总和为零，不代表程序没有成本，它仍要检查范围或条件并返回。

<!-- bilingual-en:start -->
With constant-cost range setup, iteration control and inner operations, the rectangular example has full cost $\Theta(1+n+nm)$ for nonnegative integers $n,m$. When $m=0$, it performs no inner body operation but still visits the outer loop $n$ times; when $n=0$, it has only constant setup. The triangular example has full cost $\Theta(1+n^2)$ for $n\ge0$. These boundary-aware forms agree with the inherited growing-input formulas.
<!-- bilingual-en:end -->

若范围建立、循环控制和内层操作都按常数成本计算，矩形例对非负整数 $n,m$ 的完整成本为 $\Theta(1+n+nm)$。当 $m=0$ 时没有内层主体工作，但仍访问外层 $n$ 次；当 $n=0$ 时只有常数设置成本。三角形例对 $n\ge0$ 的完整成本为 $\Theta(1+n^2)$。这些包含边界的写法与前面的增长规模公式一致。

## Use the actual exit path
<!-- bilingual-en:end -->

## 按实际退出路径记账

<!-- bilingual-en:start -->
In the course's `all_digits(nums)`, each visited number is compared with the fixed digits 0 through 9. A match breaks the inner loop; the first non-digit returns `False`. Thus each visited item costs between one and ten comparisons under constant-cost equality. A length-$n$ list of digits makes the procedure visit all $n$ items, yielding linear worst-case time; a nonempty list whose first item is invalid finishes in constant time. The source's linear label is a worst-case statement, not the cost of every input.
<!-- bilingual-en:end -->

课程的 `all_digits(nums)` 把每个访问到的数字与固定候选 0 到 9 比较；命中后跳出内层，遇到第一个非数字便返回 `False`。在常数比较成本模型下，每个已访问项进行一到十次比较。长度为 $n$ 且全部合法的列表会被完整访问，给出线性最坏时间；非空列表若第一项非法，则常数时间就结束。来源的线性标签是最坏情况结论，并非每个输入都花这么多时间。

<!-- bilingual-en:start -->
Before replacing a sum by a product, check whether one bound controls all visited iterations. In the triangular loop, the final inner loop has just one iteration, so there is no common positive multiple of $n$ below every inner count. The [[渐近界的统一常数|uniform-constant condition]] explains why summing the exact lengths is safer here.
<!-- bilingual-en:end -->

把总和换成乘积之前，要检查是否有同一组界控制所有已访问轮次。三角形循环的最后一次内层只有一次迭代，因此不可能用同一个正倍数的 $n$ 下界控制每个内层次数。[[渐近界的统一常数]]说明了为什么这里直接求实际长度之和更合适。
