# 即使所有代码路径都被测试执行过也不能据此证明所有输入都得到正确结果
<!-- bilingual-en:start -->
*Exercising every code path does not prove that every input receives the correct result.*
<!-- bilingual-en:end -->

同一路径可以处理多个不同输入，而错误可能只在其中某个边界出现。以下实现声称返回整数的绝对值，却把判断阈值写成了 `-1`。
<!-- bilingual-en:start -->
A path can process many inputs, with a defect exposed only at a particular boundary. This implementation claims to return an integer's absolute value but uses `-1` as its threshold.
<!-- bilingual-en:end -->

```python
def abs_bug(x):
    if x < -1:
        return -x
    else:
        return x
```

测试 `2` 和 `-2`，两个分支、两条完整路径都走过，结果也都正确。但 `abs_bug(-1)` 返回 `-1`，违反绝对值规格。这里不需要循环或复杂状态，就足以否定“路径全覆盖 ⇒ 程序正确”。
<!-- bilingual-en:start -->
Tests with `2` and `-2` exercise both branches and both complete paths and return correct results. Yet `abs_bug(-1)` returns `-1`, violating the specification. No loop or complex state is needed to refute the implication from complete path coverage to correctness.
<!-- bilingual-en:end -->

因此高[[代码覆盖率]]适合提示结构上的遗漏，不能替代[[分区与边界选例]]或可靠的[[测试判据]]。如果只执行代码而不核对结果，错误返回甚至可以在已有用例中静默通过。
<!-- bilingual-en:start -->
High [[代码覆盖率|code coverage]] can reveal structural gaps, but cannot replace [[分区与边界选例|partition and boundary cases]] or a sound [[测试判据|oracle]]. If execution is not followed by meaningful checking, even an incorrect result in an existing case can pass silently.
<!-- bilingual-en:end -->
