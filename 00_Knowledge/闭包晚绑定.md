# 闭包自由变量在调用时解析所以循环创建的函数可能共享最终绑定
<!-- bilingual-en:start -->
*Closure free variables are resolved at call time, so functions created in a loop may share the final binding*
<!-- bilingual-en:end -->

> [!summary] 原子捕获边界
> 闭包通常保存对定义环境中绑定的访问路径，而不是在函数创建时复制自由变量的当前值。若循环反复改绑同一个名称，循环中创建的多个函数可能都在以后调用时读取这个名称的最终绑定。这个 late-binding 行为同样适用于嵌套 `def`，不是 `lambda` 独有缺陷。
> <!-- bilingual-en:start -->
> A closure normally retains access to a binding in its defining environment rather than copying the free variable's current value when the function is created. If a loop repeatedly rebinds one name, several functions created in that loop may all read its final binding when called later. This late binding also applies to nested `def`; it is not unique to `lambda`.
> <!-- bilingual-en:end -->

```python
functions = [lambda: i for i in range(3)]
[fn() for fn in functions]              # [2, 2, 2]

fixed = [lambda value=i: value for i in range(3)]
[fn() for fn in fixed]                  # [0, 1, 2]
```

第二种写法利用默认参数在定义时求值，把当次 `i` 绑定到各函数自己的形参默认对象；另一种清楚做法是每轮调用工厂函数，创建不同外层 frame。若预期本来就是让所有闭包观察最新配置，late binding 也可能是所需语义，不能一概视为错误。

> [!question]- 自检
> 为什么列表中的三个函数不是分别“记住”0、1、2？工厂函数怎样改变这一点？
>
> **答案：** 它们共享对同一循环名称的晚绑定访问；每次调用工厂会创建新的外层 frame，因此各闭包解析到不同绑定。
