# 好的哈希函数要便宜并控制实际键的碰撞分布

<!-- bilingual-en:start -->
*A useful hash function is cheap and controls collisions for the keys that actually occur*
<!-- bilingual-en:end -->

> [!summary] 原子设计原则
> 在键已经遵守相等与稳定契约的前提下，普通哈希表不要求哈希函数消灭碰撞，而要求它计算便宜，并使实际或可能对抗性的键不长期集中到少数位置。
>
> <!-- bilingual-en:start -->
> Once keys satisfy their equality and stability contracts, an ordinary hash table does not require a hash function to eliminate collisions. It needs a function that is cheap to compute and avoids persistently concentrating real or adversarial keys in a few locations.
> <!-- bilingual-en:end -->

“看起来随机”不是可操作的完整标准。至少要分别检查：

1. **计算成本**：若算一次哈希本身就要做大量工作，$O(1)$ 次槽位访问也不会使总操作便宜。
2. **对实际键的分散**：函数要打破输入中的规律，避免常见前缀、步长或低位模式聚到同一批槽。
3. **对可预测攻击的防护**：输入可由外部控制时，固定且可预测的坏碰撞可能成为拒绝服务路径；随机选择哈希族或加入进程级随机化可以改变风险模型。

<!-- bilingual-en:start -->
“Looks random” is not a complete operational standard. Check the cost of computing the hash, dispersion of patterns in the keys that actually occur, and—when inputs are externally controlled—protection against predictable collision attacks through an appropriate randomized design. Equality and key stability are separate prerequisites rather than distribution criteria.
<!-- bilingual-en:end -->

> [!question]- 回忆与辨别
> 一个哈希函数在随机测试数据上分布均匀，为什么还不能直接判定它适合线上字典？
>
> **答案：** 还要检查实际键模式、计算成本、相等契约，以及外部输入能否有意制造碰撞。测试分布均匀只覆盖其中一部分。
