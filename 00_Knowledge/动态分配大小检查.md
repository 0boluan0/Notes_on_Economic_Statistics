# 动态分配大小必须在乘法前检查可表示性并从目标对象推导元素大小
<!-- bilingual-en:start -->
*A dynamic allocation size must be checked before multiplication and derived from the destination object type*
<!-- bilingual-en:end -->

> [!summary] 两次失败检查
> 分配 `count` 个 `T` 需要先证明数学乘积 `count * sizeof(T)` 能由 `size_t` 表示，再调用分配函数并检查它是否返回空指针。前者防止请求大小在调用前已经无符号回绕，后者处理表示合法但系统无法满足的请求；只检查 `malloc` 返回值漏掉了第一层。
> <!-- bilingual-en:start -->
> Allocating `count` objects of type `T` requires first proving that `count * sizeof(T)` is representable in `size_t`, then calling the allocator and checking for a null result. The first check prevents unsigned wrap before the call; the second handles a representable request that the system cannot satisfy.
> <!-- bilingual-en:end -->

```c
#include <stdint.h>
#include <stdlib.h>

int *allocate_ints(size_t count) {
    int *p;

    if (count == 0 || count > SIZE_MAX / sizeof *p) {
        return NULL;  // 本接口把空数组也定义为失败
    }
    size_t bytes = count * sizeof *p;
    p = malloc(bytes);
    return p;         // 调用者仍须检查 NULL
}
```

检查必须发生在乘法之前。若先写 `size_t bytes = count * sizeof *p;` 再判断 `bytes` 是否太大，回绕可能已经把一个巨大请求变成很小的合法数，`malloc` 甚至可能“成功”，后续却按原 `count` 越界。`SIZE_MAX / sizeof *p` 给出当前元素类型可安全请求的最大个数。
<!-- bilingual-en:start -->
The check must precede multiplication. If a huge mathematical product first wraps into a small `size_t`, `malloc` may even succeed for the undersized request and later accesses based on the original count will overflow the object. `SIZE_MAX / sizeof *p` is the maximum representable element count for this type.
<!-- bilingual-en:end -->

这里的 `p` 指向固定大小的 `int`，所以 `sizeof *p` 的操作数类型不是 VLA，操作数不求值：即使 `p` 还没有保存分配结果，也不会真的解引用它，只使用所指类型。相比手写 `sizeof(int)`，这种写法在指针类型改变时会同步改变元素大小。若所指类型是 VLA，则不能套用“`sizeof` 永不求值”的口号，详见[[数组到指针转换|VLA 的 sizeof 边界]]。加法也要检查：要为 `length + 1` 个字节留终止符时，先确认 `length != SIZE_MAX`。
<!-- bilingual-en:start -->
Here `p` points to fixed-size `int`, so the operand of `sizeof *p` does not have VLA type and is not evaluated: the uninitialised pointer is not dereferenced, and only its pointed-to type is used. The slogan “`sizeof` never evaluates its operand” must not be extended to a VLA pointed-to type. Addition needs the same discipline: before requesting `length + 1` bytes for a terminator, establish that `length != SIZE_MAX`.
<!-- bilingual-en:end -->

`calloc(count, sizeof *p)` 把计数和元素大小分开交给库，避免调用者先做那次乘法，但仍必须检查空返回并给 `count == 0` 规定清楚的接口语义。安全编码建议不替代业务上限：一个可表示却大到耗尽资源的 `count` 仍可能需要更早拒绝。
<!-- bilingual-en:start -->
`calloc(count, sizeof *p)` passes count and element size separately and avoids caller-side multiplication, but a null result and the interface's zero-count policy still need handling. Representability is not a business limit; an enormous but representable request may need earlier rejection.
<!-- bilingual-en:end -->

> [!question]- 最小自检
> 为什么 `p = malloc(count * sizeof *p); if (p == NULL) ...` 仍可能分配得过小？
>
> **答案：** `size_t` 乘法可能在进入 `malloc` 前回绕成较小值；分配函数只看已经回绕的请求，无法恢复原数学乘积。
