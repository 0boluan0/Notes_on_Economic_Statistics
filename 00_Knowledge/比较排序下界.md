# 确定性比较排序最坏需要 n log n 次比较

<!-- bilingual-en:start -->
*Deterministic comparison sorting needs n log n comparisons in the worst case*
<!-- bilingual-en:end -->

> [!summary] 原子定理
> 对 $n$ 个互异项目，若算法只能通过两两比较获得键的相对次序，任何确定性排序算法的最坏情况都需要 $\Omega(n\log n)$ 次比较。比较决策树必须区分 $n!$ 种输入排列，因此至少有 $n!$ 个叶子，树高至少为 $\log_2(n!)=\Omega(n\log n)$。
>
> <!-- bilingual-en:start -->
> For $n$ distinct items, if an algorithm can learn key order only through pairwise comparisons, every deterministic sorting algorithm needs $\Omega(n\log n)$ comparisons in the worst case. Its comparison decision tree must distinguish $n!$ input permutations, so it has at least $n!$ leaves and height at least $\log_2(n!)=\Omega(n\log n)$.
> <!-- bilingual-en:end -->

## 自然解释

比较只能逐步排除候选次序，而任意互异键可能以 $n!$ 种方式到来。标准 merge sort 提供 $O(n\log n)$ 比较上界，所以它在这个模型下达到渐近最优；这并不表示它在所有机器成本或所有输入规模上总是最快。

<!-- bilingual-en:start -->
Comparisons eliminate possible orders step by step, while arbitrary distinct keys may arrive in any of $n!$ permutations. Standard merge sort supplies an $O(n\log n)$ comparison upper bound, so it is asymptotically optimal in this model. That does not make it fastest under every machine cost or input size.
<!-- bilingual-en:end -->

> [!warning] 边界
> 下界只约束一般问题的最坏比较次数，不表示每个输入都要做这么多比较，也不约束写入数或辅助空间。若键是有界整数并允许按数位或数组索引操作，counting/radix/direct-access sort 可绕过比较模型，在额外键域与空间条件下达到线性时间。
>
> <!-- bilingual-en:start -->
> The lower bound concerns worst-case comparisons for the general problem; it does not say every input needs that many comparisons, nor does it bound writes or auxiliary space. With bounded integer keys and digit or array-index operations, counting, radix, or direct-access sorting can leave the comparison model and achieve linear time under additional key-range and space assumptions.
> <!-- bilingual-en:end -->

> [!question]- 回忆与应用
> counting sort 为何不反驳 $\Omega(n\log n)$？
>
> **答案：** 它利用有界整数键直接索引计数结构，不只通过两两比较获知顺序，因此不在该下界的比较模型内。
