# 调用类时由 __new__ 创建实例而 __init__ 只初始化已创建的实例
<!-- bilingual-en:start -->
*Calling a class uses `__new__` to create an instance, while `__init__` only initializes an already-created instance*
<!-- bilingual-en:end -->

> [!summary] 原子创建协议
> 对使用通常元类调用行为的用户类求值 `C(args)` 时，调用先分派到 `type(C)` 的 `__call__`；默认协议再由 `__new__(C, args)` 返回新对象。若结果是 `C` 的实例，Python 随后以它为 `self` 调用该新实例的 `__init__(self, args)`，最后把对象交给调用者。`__init__` 已经收到一个存在的对象，所以只能初始化它，并且必须返回 `None`。
> <!-- bilingual-en:start -->
> Evaluating `C(args)` for a user class with ordinary metaclass call behaviour first dispatches to `type(C).__call__`; the default protocol then has `__new__(C, args)` return the new object. If the result is an instance of `C`, Python calls that new instance's `__init__(self, args)` with the object as `self` and finally returns it to the caller. Because `__init__` receives an object that already exists, it initializes rather than creates it and must return `None`.
> <!-- bilingual-en:end -->

```python
class Ticket:
    def __init__(self, code):
        self.code = code

t = Ticket("A17")       # an object is created, then initialized
```

大多数入门类无需重写 `__new__`；它主要用于不可变类型子类或特殊创建控制。若 `__new__` 返回的不是所请求类的实例，默认协议会跳过 `__init__`；若返回其子类实例，则由该结果对象的实际类型解析初始化方法。自定义元类的 `__call__` 还能改写或绕开这套外层协调。在 `__init__` 中 `return value` 会引发 `TypeError`，但裸 `return` 等价于返回 `None`。

> [!question]- 回忆与应用
> 为什么把 `__init__` 称为“对象创建函数”会误导？
>
> **答案：** 创建对象的是 `__new__`；`__init__` 运行时对象已经存在，它只建立初始状态。
