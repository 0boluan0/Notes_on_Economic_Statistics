# 函数契约规定可观察输入输出与副作用而不锁定具体实现
<!-- bilingual-en:start -->
*A function contract specifies observable inputs, outputs, and side effects without fixing a particular implementation*
<!-- bilingual-en:end -->

> [!summary] 原子接口边界
> 函数契约说明调用者必须提供什么、函数在这些前提下返回什么、可能抛出什么异常，以及会发生哪些可观察副作用。调用者依赖这些承诺，而不依赖内部循环、局部名称或某一版算法；只要契约保持，内部实现可以替换。文档字符串和类型注解能表达契约的一部分，但 Python 默认不会替程序自动验证全部语义前提。
> <!-- bilingual-en:start -->
> A function contract states required inputs, promised results, possible exceptions, and observable side effects. Callers depend on those commitments rather than internal loops, local names, or one algorithm, so an implementation may change while the contract remains stable. Docstrings and annotations can express parts of the contract, but Python does not automatically enforce all semantic preconditions.
> <!-- bilingual-en:end -->

“一个函数只做一件事”是为了让契约可以简短说明和独立测试，不是按行数机械拆分。一个两行包装若没有稳定含义，只增加跳转；相反，一个实现较长但只有一个清楚责任的函数仍可能是合理抽象。是否为纯函数、是否修改传入对象、是否输出日志，都属于调用者需要知道的可观察边界。

若结果只由显式输入决定，且函数不读写外部可变状态、不产生返回通道之外的副作用，同一输入的行为就更容易复现、组合和独立测试。若 I/O、日志或状态更新本就是责任的一部分，不必伪装成纯函数；应在契约中明示副作用的对象、时点和失败边界，并尽量把它隔离在少数接口处。

> [!question]- 自检
> 把 `for` 实现换成等价的 `while` 实现，为什么通常不要求修改调用者？什么变化会要求修改？
>
> **答案：** 循环只是实现细节；若输入前提、返回值、异常或副作用等契约改变，调用者才可能需要调整。
