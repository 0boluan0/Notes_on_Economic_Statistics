# Bash前台管道默认取末段状态而pipefail取最右非零状态

对没有前置 `!` 的 Bash 前台管道，默认退出状态等于最后一段命令的状态。启用 `set -o pipefail` 后，若各段全为 0 则结果为 0，否则取管道排列中最右侧非零状态；“最右”不是最晚结束的进程。前置 `!` 会再对整个结果作逻辑取反。
<!-- bilingual-en:start -->
A foreground Bash pipeline without leading `!` returns its last stage's status by default. With `set -o pipefail`, it returns zero if all stages return zero; otherwise it returns the rightmost nonzero status in pipeline order, not the status of the process that finishes last. Leading `!` then logically negates the result.
<!-- bilingual-en:end -->

```bash
set +o pipefail
false | true
printf 'default=%s\n' "$?"
set -o pipefail
false | true
printf 'pipefail=%s\n' "$?"
```

在独立练习 Bash 中，上面分别显示 0 和 1。若要诊断具体哪段失败，可在管道后立即复制 Bash 的 `PIPESTATUS` 数组；运行另一条命令后再读，就可能已失去原状态。修改选项会影响当前 Shell 后续命令，因此例子应在独立环境中执行。
<!-- bilingual-en:start -->
In an isolated practice Bash, these print 0 and 1 respectively. To diagnose individual stages, copy Bash's `PIPESTATUS` array immediately after the pipeline; another command can overwrite it. Option changes affect later commands in the current shell, so run the example in an isolated environment.
<!-- bilingual-en:end -->

`pipefail` 让上游非零更可见，却不能替你判断非零是否符合契约，也不保证自动中止脚本。下游提前停止读取时，上游还可能因管道关闭收到 SIGPIPE。进程替换的状态也不自动加入外层管道。此页以 Bash 3.2 为实践范围；不能泛称 `pipefail` 永远不属于 POSIX，POSIX.1-2024 已规定它。
<!-- bilingual-en:start -->
`pipefail` exposes upstream nonzero statuses, but does not decide whether they are expected or automatically terminate a script. Early termination of a consumer can also cause upstream SIGPIPE. Process-substitution statuses are not automatically included in the outer pipeline. The practical scope here is Bash 3.2; `pipefail` must not be described as permanently non-POSIX, since POSIX.1-2024 specifies it.
<!-- bilingual-en:end -->

## 来源与核验

- GNU Bash 3.2 本机 `bash(1)`，`Pipelines`、`PIPESTATUS` 与 `set: pipefail`；[官方管道章节](https://www.gnu.org/software/bash/manual/html_node/Pipelines.html)：支持默认状态、最右非零、逻辑取反及逐段状态。
- [POSIX.1-2024 Shell Command Language §2.9.2](https://pubs.opengroup.org/onlinepubs/9799919799/utilities/V3_chap02.html#tag_19_09_02)：支持版本边界中 `pipefail` 已纳入标准；本机 `pipe(2)` 支持读端关闭时写入的 SIGPIPE 条件。
<!-- bilingual-en:start -->
The local Bash manual supports the default, rightmost-nonzero, negation, and per-stage rules. POSIX.1-2024 §2.9.2 supports the standards-version boundary. The local `pipe(2)` manual establishes SIGPIPE when writing after all read ends are closed.
<!-- bilingual-en:end -->
