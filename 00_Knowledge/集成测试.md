# 集成测试检查组合起来的程序组件及其交互是否符合预期
<!-- bilingual-en:start -->
*Integration testing checks whether combined components and their interactions behave as intended.*
<!-- bilingual-en:end -->

它关注组件之间怎样传递数据、调用接口、共享状态和传播失败。组合范围可以是少数组件，也可以扩展到课程例子中的整体程序；应先说明实际接入哪些部件，而不是把“集成”理解成固定大小。
<!-- bilingual-en:start -->
It examines data transfer, interface calls, shared state, and failure propagation across components. The scope can be a small combination or, as in the course example, the whole program. State which components are actually connected rather than assigning “integration” a fixed size.
<!-- bilingual-en:end -->

例如，`parse_age` 接收文本并返回整数，`classify_age` 接收整数并返回分类。两个函数分别测试都正确，但主程序若把原文本而不是解析结果传给 `classify_age`，组合仍会失败。测试这个连接比再给两个独立函数各加一个普通值更直接。
<!-- bilingual-en:start -->
Suppose `parse_age` converts text to an integer and `classify_age` classifies an integer. Both functions may pass individually, yet the combined program fails if it passes the original text to the classifier. Testing that connection addresses the fault more directly than adding ordinary inputs to each isolated function.
<!-- bilingual-en:end -->

替身只能提供它实际模拟的行为证据：如果某接口从未连接到真实组件，测试通过不证明那个真实连接可用。反过来，集成失败也不自动说明所有参与组件都有错；可缩小到接口或单元继续[[调试]]。
<!-- bilingual-en:start -->
A substitute supplies evidence only about the behavior it simulates. Passing without connecting an actual component does not establish that real connection. Conversely, an integration failure does not implicate every participant; narrow the investigation to an interface or unit for further [[调试|debugging]].
<!-- bilingual-en:end -->
