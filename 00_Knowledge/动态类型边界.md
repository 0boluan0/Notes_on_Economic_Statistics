# Python 的对象始终有类型而名称可在运行时改绑不同类型对象
<!-- bilingual-en:start -->
*Python objects always have types while names may be rebound to objects of different types at runtime*
<!-- bilingual-en:end -->

> [!summary] 原子类型边界
> “动态类型”指运行时绑定和检查的方式，不是“程序里没有类型”。每个 Python 对象都有类型，类型决定可用操作；普通名称本身没有一个永久锁定的声明类型，可以先绑定整数对象，后来改绑字符串对象。运算发生时仍会依据实际对象类型执行或拒绝操作。
> <!-- bilingual-en:start -->
> “Dynamically typed” describes how binding and checking occur at runtime; it does not mean that the program has no types. Every Python object has a type that determines its supported operations. An ordinary name has no permanently fixed declared type and may first refer to an integer object and later to a string object. When an operation runs, Python still dispatches or rejects it according to the actual object types.
> <!-- bilingual-en:end -->

```python
x = 3
x = "three"     # the name x is rebound to an object of another type

1 + "1"         # TypeError: dynamic typing does not make every mix valid
```

类型注解可以为静态检查器、IDE 与读者表达预期，但 Python 运行时默认不强制函数或变量注解。第三方框架可以另加运行时验证，不能把那种工具行为误说成 Python 语言本身的默认保证。反过来，没有注解也不意味着对象的类型或运行时检查消失。
<!-- bilingual-en:start -->
Type annotations can communicate expectations to static checkers, IDEs, and readers, but the Python runtime does not enforce function and variable annotations by default. A third-party framework may add runtime validation, but that tool behavior is not the language's default guarantee. Conversely, omitting annotations does not remove object types or runtime checks.
<!-- bilingual-en:end -->

> [!question]- 回忆与应用
> `x = 1; x = "one"` 证明 `x` 没有类型，还是证明了别的事？
>
> **答案：** 它证明名称 `x` 可以改绑不同类型的对象；两个对象分别仍有 `int` 与 `str` 类型。
