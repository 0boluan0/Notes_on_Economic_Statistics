# 拉链法把碰撞条目保存在同一桶中

<!-- bilingual-en:start -->
*Separate chaining stores colliding entries in the same bucket*
<!-- bilingual-en:end -->

> [!summary] 原子方法
> 拉链法让数组的每个槽指向一个能保存多个条目的桶。哈希值决定桶，桶内再比较完整键；碰撞不会覆盖原条目，只会让该桶多一个候选。
>
> <!-- bilingual-en:start -->
> Separate chaining lets each array slot refer to a bucket that can hold multiple entries. The hash chooses the bucket and complete keys are compared inside it. A collision adds another candidate instead of overwriting the existing entry.
> <!-- bilingual-en:end -->

插入键 $k$ 时，先计算 $i=h(k)$，再到桶 $T[i]$ 中查找相等键：若已经存在就更新对应值，否则把新条目加入桶。查找和删除也先定位同一个桶，再在桶内完成。桶可以用链表、动态数组或其他小型字典结构实现；“拉链”描述的是分离碰撞条目的结构思想，并不强制某一种容器。
<!-- bilingual-en:start -->
To insert key $k$, compute $i=h(k)$ and search bucket $T[i]$ for an equal key. Update the value if one exists; otherwise add the new entry. Lookup and deletion locate the same bucket before operating inside it. A bucket may be a linked list, dynamic array, or another small dictionary structure. “Chaining” describes the separated-bucket design, not one compulsory container implementation.
<!-- bilingual-en:end -->

## 成本取决于桶有多长

设表中有 $n$ 个条目和 $m$ 个桶，负载因子为 $\alpha=n/m$。所有桶的算术平均长度恰好是 $\alpha$，但一次操作的成本取决于它实际进入的桶。在通用哈希等随机化假设下，目标桶的期望长度为 $O(1+\alpha)$；当 $m=\Omega(n)$ 时，桶内期望工作量可保持常数阶。若许多键都进入同一桶，单次操作仍可能扫描 $\Theta(n)$ 个条目。拉链法解决的是碰撞后的**正确性**，分布与容量管理才决定性能。
<!-- bilingual-en:start -->
With $n$ entries and $m$ buckets, the arithmetic mean bucket length is exactly $\alpha=n/m$, but one operation pays for the bucket it actually reaches. Under a randomized assumption such as universal hashing, the expected target-bucket length is $O(1+\alpha)$; keeping $m=\Omega(n)$ can therefore keep expected bucket work constant. If many keys land in one bucket, an operation may still scan $\Theta(n)$ entries. Chaining supplies correctness after a collision; distribution and capacity management determine performance.
<!-- bilingual-en:end -->

> [!question]- 回忆与辨别
> 拉链法已经处理了碰撞，为什么查找仍可能是线性时间？
>
> **答案：** 因为所有键仍可能进入同一桶，查找就要扫描一条长度为 $n$ 的链。碰撞可处理不等于碰撞很少。
