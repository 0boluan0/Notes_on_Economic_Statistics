# 静态批处理在一批请求结束前不向该批加入新请求

<!-- bilingual-en:start -->
*Static batching admits no new request into a batch until that batch finishes*
<!-- bilingual-en:end -->

**静态批处理**在本卡指以整条请求为调度单位的批处理：选定一组请求后，执行其生成过程，期间不向该批加入新请求，等这批完成后再启动下一批。关键是批次成员的加入规则；是否保留空行、做 padding 或提前流式返回结果，属于进一步的实现选择。

<!-- bilingual-en:start -->
Here **static batching** means request-level batching: a chosen set runs through generation without admitting additional requests into that batch, and the next batch starts after it finishes. The defining property is admission. Retaining empty rows, padding, and streaming completed outputs early are separate implementation choices.
<!-- bilingual-en:end -->

## 短请求结束后，等待者仍不能补进当前批

<!-- bilingual-en:start -->
*A waiting request cannot fill the current batch after a short request finishes*
<!-- bilingual-en:end -->

考虑两个槽位的一批请求。A还需1次[[增量解码]]迭代，B还需3次，C已在队列等待。若示意实现保留固定槽位，三轮是：

<!-- bilingual-en:start -->
Consider a two-slot batch. A needs one further [[增量解码|incremental-decoding]] iteration, B needs three, and C is waiting. An illustrative implementation that retains fixed slots runs:
<!-- bilingual-en:end -->

| 迭代 | 槽位1 | 槽位2 |
|---|---|---|
| 1 | A | B |
| 2 | 空 | B |
| 3 | 空 | B |

<!-- bilingual-en:start -->
The first iteration runs A and B. After A finishes, its slot remains empty during B's second and third iterations. C can join a later batch only after B finishes.
<!-- bilingual-en:end -->

示意图中有用的请求迭代共4个，占6个槽位机会的 $4/6$；这不是GPU利用率测量。实现也可能移除A的行而不再为它计算，此时不一定有真的padding工作，但C仍不能加入当前批。不同输出长度使后期batch越来越小，或让固定槽位空置。

<!-- bilingual-en:start -->
There are four useful request-iterations across six slot opportunities, or $4/6$; this is not measured GPU utilization. An implementation may remove A's row and avoid computing it, eliminating actual padding work while still refusing C admission. Unequal output lengths can therefore shrink late batches or leave fixed slots unused.
<!-- bilingual-en:end -->

## 调度粒度和传输规则分开看

<!-- bilingual-en:start -->
*Scheduling granularity and response delivery are separate*
<!-- bilingual-en:end -->

静态批次可以一边运行一边发送已生成的token，因此“A必须等B结束才能让客户端看见输出”不是静态批处理定义必然要求的行为。它限制的是C何时进入这一计算批。[[连续批处理]]把重新选成员的机会推进到迭代边界；是否改善[[推理吞吐率]]和响应时间还要看输入长度、设备与调度开销。

<!-- bilingual-en:start -->
A static batch may stream generated tokens while it runs, so withholding A's output until B finishes is not required by the definition. The admission constraint concerns when C can enter the computation batch. [[连续批处理|Continuous batching]] moves membership decisions to iteration boundaries; throughput and latency effects still depend on lengths, hardware, and scheduling overhead.
<!-- bilingual-en:end -->
