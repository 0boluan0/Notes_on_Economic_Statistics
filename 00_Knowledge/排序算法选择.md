# 排序算法选择先固定语义与成本模型再比较候选

<!-- bilingual-en:start -->
*Choose a sorting algorithm only after fixing semantics and the cost model*
<!-- bilingual-en:end -->

> [!summary] 原子规则
> 先固定排序键与次序、是否必须稳定、键域和允许的操作；再写输入规模与已有顺序、需要的最好/期望/最坏保证、辅助空间、递归栈、比较/移动/写入成本；最后才比较候选并用代表性数据测量实现。
>
> <!-- bilingual-en:start -->
> First fix the key and ordering relation, stability requirement, key domain, and allowed operations. Then state input size and existing order, required best/expected/worst guarantees, auxiliary space, recursion stack, and comparison/move/write costs. Only then compare candidates and measure implementations on representative data.
> <!-- bilingual-en:end -->

## 自然解释

- 小而近有序、逆序对少：标准 insertion sort 是合理候选。
- 比较便宜但写入外部介质极贵：经典 selection sort 的平方比较、线性交换可能值得。
- 任意比较键、要求稳定且需要最坏 $\Theta(n\log n)$、可接受线性缓冲：稳定归并实现是直接候选。
- 生产代码通常先采用标准库的已验证排序，再依据契约和基准决定是否替换；只需最小若干项时，还应考虑 partial-sort 接口而非完整排序。

<!-- bilingual-en:start -->
- Small, nearly sorted input with few inversions: standard insertion sort is a reasonable candidate.
- Cheap comparisons but very expensive writes to external media: classic selection sort's quadratic comparisons and linear number of swaps may be worthwhile.
- Arbitrary comparison keys, required stability and worst-case $\Theta(n\log n)$ time, with a linear buffer available: a stable merge implementation is a direct candidate.
- Production code should normally start with a verified standard-library sort and replace it only after checking the contract and benchmarks. If only a few extreme items are needed, consider a partial-sort interface instead of a full sort.
<!-- bilingual-en:end -->

> [!warning] 边界
> Python 保证 `sorted()` 与 `list.sort()` 稳定，并使用能利用已有顺序的 Timsort；`list.sort()` 修改原列表而 `sorted()` 返回新列表。这里的 API “in-place” 不证明常数辅助空间，也不把 Timsort 的实现性质自动推广到其他语言或版本。缓存局部性与常数因子要靠目标环境测量。
>
> <!-- bilingual-en:start -->
> Python guarantees that `sorted()` and `list.sort()` are stable and uses Timsort, which can exploit existing order; `list.sort()` mutates the list while `sorted()` returns a new list. API-level “in-place” does not prove constant auxiliary space, and Timsort's properties must not be projected automatically onto other languages or versions. Cache locality and constants require measurement in the target environment.
> <!-- bilingual-en:end -->

> [!question]- 回忆与应用
> 只知道输入有一百万条记录，能否决定“最佳排序算法”？
>
> **答案：** 不能。还缺键域、稳定性、已有顺序、保证类型、内存与真正昂贵的操作；这些条件可能把候选导向完全不同的算法或标准库接口。
