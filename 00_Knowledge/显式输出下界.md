# 逐项写出的输出表示有多大，算法至少就要完成同阶的写出工作
<!-- bilingual-en:start -->
*An algorithm that explicitly writes its output must do at least work proportional to the size of that representation*
<!-- bilingual-en:end -->

若规定输出要实际写出 $S$ 个字符、引用或其他基本单位，并且一次基本操作至多写出固定数量的单位，那么运行时间至少是 $\Omega(S)$。这条下界来自**指定的输出表示**，不是来自程序有多少层循环或递归。
<!-- bilingual-en:start -->
If the required output explicitly writes $S$ characters, references, or other basic units, and one primitive operation writes at most a fixed number of units, runtime is at least $\Omega(S)$. The bound follows from the **required output representation**, not from the number of loops or recursive levels.
<!-- bilingual-en:end -->

## 输出个数和输出总长度要分开
<!-- bilingual-en:start -->
*Count outputs separately from their total length*
<!-- bilingual-en:end -->

生成全部 $n$ 位二进制串时有 $2^n$ 个结果。若每个结果都作为长度为 $n$ 的字符串写出，字符总数为 $n2^n$，故至少需要 $\Omega(n2^n)$ 次字符写出。只数“有 $2^n$ 个结果”会漏掉每个结果的长度。
<!-- bilingual-en:start -->
There are $2^n$ binary strings of length $n$. Writing every result as an explicit $n$-character string writes $n2^n$ characters and therefore requires $\Omega(n2^n)$ character-writing work. Counting only the $2^n$ results omits their lengths.
<!-- bilingual-en:end -->

类似地，对 $n\ge1$ 个不同元素生成全部子集，并把各子集分别存为元素列表：每个元素恰好出现在一半子集中，因此输出列表内共有 $n2^{n-1}$ 个元素引用。再计 $2^n$ 个列表对象，输出规模仍为 $\Theta(n2^n)$。Lecture 23 的 `gen_subsets` 每层只调用一次自身；指数成本来自不断增长的结果集合与复制，不要求调用树本身分叉。
<!-- bilingual-en:start -->
For $n\ge1$ distinct elements, suppose all subsets are separately stored as explicit element lists. Every element appears in half the subsets, so the lists contain $n2^{n-1}$ element references in total. Adding the $2^n$ list objects still gives output size $\Theta(n2^n)$. Lecture 23's `gen_subsets` makes only one recursive call per level: exponentially growing results and copying cause its cost, even without a branching call tree.
<!-- bilingual-en:end -->

## 改变输出要求，才可能绕开这条下界的前提
<!-- bilingual-en:start -->
*Changing the output requirement changes the premise of the bound*
<!-- bilingual-en:end -->

只返回结果数量、压缩表示或共享结构，并不等于逐项写出所有结果；应重新计算这种表示的大小。生成器可以降低同时保留的结果数量，但如果最终仍要展开并消费全部结果，总写出工作不会因此消失。报告[[辅助空间]]时，还要说明是否把必须返回的输出计入。
<!-- bilingual-en:start -->
Returning a count, compressed representation, or shared structure is not the same task as explicitly writing every result; measure the new representation instead. A generator can reduce simultaneously retained results, but fully expanding and consuming all results still incurs their total writing cost. A report of [[辅助空间|auxiliary space]] must state whether required output storage is included.
<!-- bilingual-en:end -->
