# 表粒度用一句话固定每一行代表的对象或事件

<!-- bilingual-en:start -->
*Table grain states in one sentence what each row represents*
<!-- bilingual-en:end -->

> [!summary] 原子原则
> 粒度回答“一行代表什么”。写查询前先把输入表和目标结果各自的粒度说成一句完整的话，才能判断键、连接和聚合是否改变了问题。
>
> <!-- bilingual-en:start -->
> Grain answers, “What does one row represent?” Before writing a query, state the grain of every input and of the intended result in a complete sentence. Only then can keys, joins, and aggregates be judged against the question.
> <!-- bilingual-en:end -->

`orders` 可以是一行一个订单，`order_items` 可以是一行一个“订单—商品”组合，`daily_sales` 可以是一行一个“日期—门店”组合。这些表可能共享 `customer_id`、`store_id` 或日期等列名，但它们的一行不是同一种东西。列名相似不能代替粒度说明。
<!-- bilingual-en:start -->
`orders` may have one row per order, `order_items` one row per order–product pair, and `daily_sales` one row per date–store pair. These tables may share names such as `customer_id`, `store_id`, or a date column, but their rows do not represent the same thing. Similar column names do not substitute for a grain statement.
<!-- bilingual-en:end -->

最实用的检查是先写：

> 结果中的一行代表一个客户在一个自然月的汇总。

若这句话完整描述了目标粒度，那么 `(customer_id, month)` 就应至多标识一行。如果连接明细后这个组合仍出现多行，要么粒度说明漏掉了一个有意保留的维度，要么查询尚未回到目标粒度；此时直接选择订单级金额或继续求和，都会有重复计数的风险。
<!-- bilingual-en:start -->
A useful check is to write: “One result row represents one customer in one calendar month.” If that sentence fully states the target grain, `(customer_id, month)` should identify at most one row. If the pair still appears several times after a detail join, either the grain statement omitted an intentionally retained dimension or the query has not returned to its target grain; selecting or summing order-level measures at that point risks double-counting.
<!-- bilingual-en:end -->

粒度不是 SQL 关键字，也不等于 `GROUP BY` 列表。它是对数据事实的语义承诺。`GROUP BY` 只是实现某种结果粒度的一种办法；写错分组列仍然可以生成语法合法但问题不同的结果。
<!-- bilingual-en:start -->
Grain is not a SQL keyword and is not identical to a `GROUP BY` list. It is a semantic commitment about the represented facts. Grouping is only one way to construct a result grain; the wrong grouping columns can yield valid SQL that answers a different question.
<!-- bilingual-en:end -->

> [!question]- 回忆与辨别
> 一条查询能运行且每列看起来都合理，为什么仍可能整体错误？
>
> **答案：** 结果可能处在错误粒度。例如目标是一行一个订单，连接商品明细后却变成一行一个订单商品；此时订单级度量会被重复。
