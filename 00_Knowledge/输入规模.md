# 输入规模是描述合法输入大小并作为成本函数自变量的度量

<!-- bilingual-en:start -->
*Input size measures valid inputs and supplies the variables of a cost function*
<!-- bilingual-en:end -->

输入规模是描述一个合法输入有多大的度量；它决定成本函数的自变量。使用 $T(n)$ 前必须说明 $n$ 是列表元素数、字符串长度、整数的编码位数，还是别的量。规模不是固定等于输入的数值，也不必只有一个参数。

<!-- bilingual-en:start -->
Input size measures how large a valid input is and supplies the variables of a cost function. Before writing $T(n)$, specify whether $n$ counts list elements, string characters, encoding bits, or something else. Size need not equal an input's numerical value or be a single parameter.
<!-- bilingual-en:end -->

对非负整数 $N$ 的通常二进制编码，位数为 $b=\lfloor\log_2N\rfloor+1$（$N\ge1$；$N=0$ 用一位）。因此执行 $N$ 轮的算法是按数值 $N$ 线性，却可能按位数 $b$ 指数增长。若输入是两个独立长度为 $m,n$ 的列表，就保留 $T(m,n)$；也可在声明两者关系（如 $m=n$），或明确采用总长度等新规模后，说明怎样合并参数。

<!-- bilingual-en:start -->
For the usual binary encoding of a nonnegative integer $N$, its bit length is $b=\lfloor\log_2N\rfloor+1$ for $N\ge1$, with one bit for zero. An algorithm taking $N$ iterations is linear in the value but can be exponential in its bit length. For two independently sized lists, retain $T(m,n)$, or explain a reduction after declaring a relation such as $m=n$ or a new size measure such as total input length.
<!-- bilingual-en:end -->

仅给元素个数仍可能不够：若元素是任意长整数或字符串，一次比较的成本还取决于元素长度。是否把元素视为一个固定大小的机器字，由[[算法成本模型]]决定；排序时把这些约定汇总在[[排序复杂度口径]]。

<!-- bilingual-en:start -->
Element count alone may be insufficient: comparisons of arbitrarily long integers or strings also depend on their lengths. The [[算法成本模型|cost model]] determines whether an element occupies a fixed-size machine word. For sorting, record these choices in the [[排序复杂度口径|sorting complexity contract]].
<!-- bilingual-en:end -->
