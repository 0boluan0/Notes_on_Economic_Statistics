# 组合用 has-a 委托而继承只适合满足可替换契约的 is-a 关系
<!-- bilingual-en:start -->
*Composition uses has-a delegation, while inheritance fits only an is-a relationship with a substitutable contract*
<!-- bilingual-en:end -->

> [!summary] 原子设计区别
> 若一个对象“拥有”另一个对象，就把成员保存为属性并把工作委托给它；这是 composition（组合）的 has-a 关系。只有子类在语义上真是基类的一种，并能满足完整基类契约时，才用 inheritance（继承）的 is-a 关系。仅想借几行实现不是继承理由。
> <!-- bilingual-en:start -->
> When one object has another, store the member as an attribute and delegate work to it; this is the has-a relationship of composition. Use the is-a relationship of inheritance only when the subclass is genuinely a kind of the base and can satisfy its full contract. Borrowing a few implementation lines is not sufficient reason to inherit.
> <!-- bilingual-en:end -->

```python
class Circle:
    def __init__(self, center, radius):
        self.center = center      # a Circle has a Coordinate
        self.radius = radius

    def contains(self, point):
        return point.distance(self.center) < self.radius
```

组合把依赖限制在成员接口上，通常更容易在运行时替换策略、单独测试各部件并控制耦合。继承能让查找、覆盖和 `super` 自动参与，但也把子类绑定到基类契约和 MRO。默认先问“关系是什么”，而不是把“组合优先”当成无条件口号。

组合也不要求先为单一实现制造工厂或接口层；直接保存已有对象并委托，已经足以表达真实的 has-a 关系，等出现第二种可替换实现时再增加必要抽象。

> [!question]- 回忆与应用
> `Bank` 管理一组 `Account` 时，为什么通常不应让 `Bank(Account)`？
>
> **答案：** 银行 has-a 账户集合，并不是可在任何账户位置替换的账户；应保存成员并委托，而不是伪造 is-a 层级。
