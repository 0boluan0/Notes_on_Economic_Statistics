# 认证解密必须先完成验证，才能把明文交给应用使用
<!-- bilingual-en:start -->
*Authenticated decryption must verify before releasing plaintext for application use*
<!-- bilingual-en:end -->

> [!summary] 原子边界
> AEAD 解密对应用只有两个合格结果：认证成功并返回完整明文，或返回失败。tag 尚未验证时产生的候选字节不能交给解析器、日志、错误分支或业务逻辑，因为它们还没有获得认证保证。
> <!-- bilingual-en:start -->
> AEAD decryption has only two valid outcomes for an application: authentication succeeds and the complete plaintext is returned, or decryption returns failure. Candidate bytes produced before tag verification must not be released to parsers, logs, error branches, or business logic because they have not received the authentication guarantee.
> <!-- bilingual-en:end -->

实现为了流式处理可能在内部先计算候选明文，再在结尾校验 tag；接口仍必须缓冲或隔离这些数据。若应用在最终结果前根据候选内容报不同错误、分配资源或执行命令，攻击者就可能通过未认证数据影响系统，即使库最后返回 `FAIL`。
<!-- bilingual-en:start -->
An implementation may internally compute candidate plaintext before checking the final tag for streaming reasons, but its interface must buffer or isolate those bytes. If the application emits content-dependent errors, allocates resources, or executes commands before the final result, unauthenticated data can influence the system even if the library eventually returns `FAIL`.
<!-- bilingual-en:end -->

这是一条调用契约，不是新的加密算法。选择 GCM 或另一 AEAD 只提供正确使用时的性质；系统还要让 API 结构无法或很难在验证完成前消费明文。
<!-- bilingual-en:start -->
This is an invocation contract, not a new encryption algorithm. Choosing GCM or another AEAD provides its properties only when used correctly; the system should structure the API so that consuming plaintext before verification is impossible or difficult.
<!-- bilingual-en:end -->

> [!question]- 自检
> 程序先把候选明文交给 JSON 解析器，解析后才检查 tag。为什么即使失败时丢弃对象仍有问题？
>
> **答案：** 解析器和它触发的错误、资源分配或副作用已经处理了攻击者可控的未认证数据；“最后丢弃”没有收回先前暴露的攻击面。

## 来源与核验

- [RFC 5116, Section 2, *An Interface and Algorithms for Authenticated Encryption*](https://datatracker.ietf.org/doc/html/rfc5116)：核对认证解密接口只能输出明文或 `FAIL`；本卡把该接口约束落实为应用不得提前消费候选明文。
- [NIST SP 800-38D, Section 7.2](https://nvlpubs.nist.gov/nistpubs/Legacy/SP/nistspecialpublication800-38d.pdf)：以 GCM 的 authenticated decryption 算法交叉核对认证失败必须返回 `FAIL`，而不是向调用者交付未认证明文。
