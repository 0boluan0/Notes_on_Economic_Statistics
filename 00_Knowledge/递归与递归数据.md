# 递归与递归数据
<!-- bilingual-en:start -->
*Recursion and Recursive Data*
<!-- bilingual-en:end -->

> [!summary] 快速恢复
> **它解决什么：** 当问题或数据由“较小的同类结构”组成时，用基本情况和递归步骤直接对应定义。
> **具体锚点：** 嵌套列表的元素可能又是列表；处理一个节点后递归处理子列表比预先猜层数自然。
> **核心难点：** 每次调用必须向基本情况推进；调用栈保存未完成工作，树递归会重复子问题。
> **为什么重要：** 树、文件系统、解析器、分治和搜索的结构天然递归。
> **继续：** 先写规模度量和基本情况，再手画调用树；性能问题区分重复计算与栈深。
> <!-- bilingual-en:start -->
> **Problem addressed:** When a problem or data structure contains smaller instances of the same kind, express the solution directly through a base case and recursive step.
> **Concrete anchor:** An item in a nested list may itself be a list; processing one node and recursively processing its children is more natural than guessing a maximum depth.
> **Central difficulty:** Every call must progress toward a base case; the call stack retains unfinished work, and tree recursion may recompute the same subproblems.
> **Why it matters:** Trees, file systems, parsers, divide-and-conquer algorithms, and search are naturally recursive.
> **Continue with:** State a size measure and base cases, then draw the call tree; distinguish repeated work from excessive stack depth when diagnosing performance.
> <!-- bilingual-en:end -->

## 基本情况与递归步骤
<!-- bilingual-en:start -->
*Base Cases and Recursive Steps*
<!-- bilingual-en:end -->

基本情况直接返回，递归步骤把问题转为严格更小实例并组合答案。证明终止需给 well-founded measure，如整数减小、列表变短或树下降一层；仅“看起来更小”不够。
<!-- bilingual-en:start -->
A base case returns directly. A recursive step converts the problem into strictly smaller instances and combines their answers. A termination argument needs a well-founded measure, such as a decreasing integer, a shorter list, or one level of descent in a tree; “it looks smaller” is not enough.
<!-- bilingual-en:end -->

递归定义基本情况和把问题缩小的递归步骤。线性递归形成链，树递归产生多个子问题，可能指数重复；memoization 可缓存重叠子问题。正确性可用结构/规模归纳证明。
<!-- bilingual-en:start -->
A recursive definition specifies a base case and a recursive step that reduces the problem. Linear recursion forms a chain, while tree recursion creates several subproblems and may duplicate work exponentially; memoization caches overlapping subproblems. Correctness can be proved by induction on structure or size.
<!-- bilingual-en:end -->

## 调用栈
<!-- bilingual-en:start -->
*The Call Stack*
<!-- bilingual-en:end -->

每次调用有独立 frame，保存参数、局部变量和返回位置。递归到底后按后进先出回退。画栈能解释为什么同名局部变量不冲突以及结果怎样组合。
<!-- bilingual-en:start -->
Every call has its own frame containing parameters, local variables, and a return location. After reaching a base case, calls return in last-in, first-out order. Drawing the stack explains why identically named local variables do not conflict and how partial results are combined.
<!-- bilingual-en:end -->

## 数值与非数值递归
<!-- bilingual-en:start -->
*Numeric and Structural Recursion*
<!-- bilingual-en:end -->

factorial、Euclidean algorithm 用整数规模；字符串/列表可拆 first/rest；树处理当前节点和 children。数据结构的递归定义通常直接给算法框架。
<!-- bilingual-en:start -->
Factorial and the Euclidean algorithm recurse on an integer measure; strings and lists can be decomposed into first and rest; a tree algorithm processes the current node and its children. The recursive definition of a data structure often supplies the algorithmic skeleton directly.
<!-- bilingual-en:end -->

## 线性递归、树递归与记忆化
<!-- bilingual-en:start -->
*Linear Recursion, Tree Recursion, and Memoization*
<!-- bilingual-en:end -->

线性递归每层一个子调用，深度 O(n)；树递归多个子调用，节点数可能指数。Fibonacci 的朴素树重复相同子问题，memoization 或迭代降至线性。
<!-- bilingual-en:start -->
Linear recursion makes one subcall per level and may have depth O(n). Tree recursion makes multiple subcalls, so its node count can be exponential. Naive Fibonacci repeatedly solves the same subproblems; memoization or iteration reduces the work to linear time.
<!-- bilingual-en:end -->

## 分治
<!-- bilingual-en:start -->
*Divide and Conquer*
<!-- bilingual-en:end -->

把问题分成若干更小、近独立子问题，递归求解并合并，如 merge sort。复杂度由分支数、子问题规模和合并成本共同决定，可用递归树/Master intuition 分析。
<!-- bilingual-en:start -->
Divide and conquer splits a problem into smaller, nearly independent subproblems, solves them recursively, and combines the results, as in merge sort. Complexity depends jointly on branching factor, subproblem size, and combination cost; a recursion tree or Master-theorem intuition helps analyze it.
<!-- bilingual-en:end -->

## Worked example：汇总嵌套列表
<!-- bilingual-en:start -->
*Worked Example: Sum a Nested List*
<!-- bilingual-en:end -->

对“数字或嵌套列表”定义递归：数字直接返回自身；列表则递归汇总每个元素。规模度量是尚未处理的节点数，每次调用都进入严格更小的子树。
<!-- bilingual-en:start -->
Define recursion over “a number or a nested list”: a number returns itself, while a list recursively sums each element. The size measure is the number of unprocessed nodes, and each call descends into a strictly smaller subtree.
<!-- bilingual-en:end -->

```python
def nested_sum(value):
    if isinstance(value, (int, float)):
        return value
    return sum(nested_sum(item) for item in value)


print(nested_sum([1, [2, 3], [], [4, [5]]]))
```

空列表不需额外特殊分支，因为 `sum([])` 的单位元是 `0`。若输入允许其他类型，接口必须选择拒绝、忽略或转换，不能让失败含义由偶然的 `TypeError` 决定。
<!-- bilingual-en:start -->
An empty list needs no extra branch because `sum([])` uses the additive identity `0`. If other input types are permitted, the interface must deliberately reject, ignore, or convert them rather than letting an accidental `TypeError` define the behavior.
<!-- bilingual-en:end -->

## 递归与迭代选择
<!-- bilingual-en:start -->
*Choosing Between Recursion and Iteration*
<!-- bilingual-en:end -->

Python 栈深有限且无尾调用优化。链式问题用循环常更省内存；树/分治递归更清楚。可用显式 stack 把深递归改迭代。
<!-- bilingual-en:start -->
Python has a finite call-stack limit and no tail-call optimization. A loop often uses less memory for a chain-shaped problem, whereas recursion is usually clearer for trees and divide-and-conquer. An explicit stack can replace recursion when depth is unbounded.
<!-- bilingual-en:end -->

Python 无一般 tail-call optimization，深递归可能溢出；递归适合结构天然递归的问题，迭代有时更简单稳健。
<!-- bilingual-en:start -->
Python does not generally optimize tail calls, so deep recursion can overflow. Recursion fits naturally recursive structure, while iteration is sometimes simpler and more robust.
<!-- bilingual-en:end -->

## 副作用边界
<!-- bilingual-en:start -->
*Boundaries for Side Effects*
<!-- bilingual-en:end -->

递归中共享可变 accumulator 容易跨分支污染。优先返回子结果并组合，或明确 push/pop 回溯不变量。
<!-- bilingual-en:start -->
A shared mutable accumulator can leak state across recursive branches. Prefer returning and combining child results, or state an explicit push/pop invariant for backtracking.
<!-- bilingual-en:end -->

## 失败诊断
<!-- bilingual-en:start -->
*Failure Diagnosis*
<!-- bilingual-en:end -->

- 无限递归：写出每个递归分支的实参，并验证同一个良基度量都严格减小。
  <!-- bilingual-en:start -->
  Infinite recursion: list the arguments of every recursive branch and verify that the same well-founded measure decreases strictly in all of them.
  <!-- bilingual-en:end -->
- 结果漏项：检查基本情况是否过早返回，以及多个子结果是否全部进入组合步骤。
  <!-- bilingual-en:start -->
  Missing results: inspect whether a base case returns too early and whether every child result participates in combination.
  <!-- bilingual-en:end -->
- 运行时间爆炸：先画调用树寻找重复子问题；有重叠时考虑 memoization，无重叠时重新检查分支规模。
  <!-- bilingual-en:start -->
  Exploding runtime: draw the call tree and look for repeated subproblems; use memoization for overlap, otherwise reassess branch sizes.
  <!-- bilingual-en:end -->

## 最小自检
<!-- bilingual-en:start -->
*Minimum Self-Check*
<!-- bilingual-en:end -->

### 递归终止需要证明什么？
<!-- bilingual-en:start -->
*What must be proved to establish recursive termination?*
<!-- bilingual-en:end -->

> [!answer]- 答案
> 每次递归调用的某个良基度量严格减小，且所有路径最终到达覆盖的基本情况。
<!-- bilingual-en:start -->
> [!answer]- Answer
> Some well-founded measure must decrease strictly on every recursive call, and every path must eventually reach a covered base case.
<!-- bilingual-en:end -->

### 朴素 Fibonacci 为什么慢？
<!-- bilingual-en:start -->
*Why is naive Fibonacci slow?*
<!-- bilingual-en:end -->

> [!answer]- 答案
> 调用树反复计算相同的 F(k)，总调用数指数增长；memoization 复用结果。
<!-- bilingual-en:start -->
> [!answer]- Answer
> Its call tree repeatedly computes the same F(k), causing an exponential number of calls; memoization reuses those results.
<!-- bilingual-en:end -->

### 什么时候显式 stack 比递归更合适？
<!-- bilingual-en:start -->
*When is an explicit stack preferable to recursion?*
<!-- bilingual-en:end -->

> [!answer]- 答案
> 数据可能很深、语言递归限制严格，或需要精确控制遍历/暂停状态时。
<!-- bilingual-en:start -->
> [!answer]- Answer
> When data may be very deep, the language imposes a strict recursion limit, or traversal and suspension state must be controlled precisely.
<!-- bilingual-en:end -->

### 树递归何时会变慢，怎样改进？
<!-- bilingual-en:start -->
*When does tree recursion become slow, and how can it be improved?*
<!-- bilingual-en:end -->

> [!answer]- 答案
> 多个分支重复计算相同子问题时呈指数增长；可 memoize、动态规划或重新设计算法。
<!-- bilingual-en:start -->
> [!answer]- Answer
> It grows exponentially when branches repeatedly solve the same subproblems; memoization, dynamic programming, or a redesigned algorithm can remove the duplication.
<!-- bilingual-en:end -->
