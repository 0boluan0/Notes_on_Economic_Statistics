# 选择排序每轮从未定部分选极值扩展已定区

<!-- bilingual-en:start -->
*Selection sort extends a settled region by choosing an extreme item each pass*
<!-- bilingual-en:end -->

> [!summary] 原子不变量
> 升序的经典前向 selection sort 在第 $i$ 轮扫描后缀，找到其中最小项目，再与位置 $i$ 交换。轮末前缀 `A[:i+1]` 已排序，包含整个输入中最小的 $i+1$ 个项目，且前缀每个键都不大于后缀每个键。
>
> <!-- bilingual-en:start -->
> On pass $i$, classic forward selection sort scans the suffix, finds its minimum item, and swaps it with position $i$. At the end of the pass, prefix `A[:i+1]` is sorted, contains the smallest $i+1$ input items, and every prefix key is no greater than every suffix key.
> <!-- bilingual-en:end -->

## 自然解释

经典实现无论输入顺序如何都做 $n(n-1)/2$ 次键比较，因此最好与最坏比较成本都是 $\Theta(n^2)$；但每轮至多一次交换，总交换数至多 $n-1$。当写入远贵于比较时，少交换可能是实际选择理由。

<!-- bilingual-en:start -->
The classic implementation performs $n(n-1)/2$ key comparisons regardless of input order, so both best- and worst-case comparison costs are $\Theta(n^2)$. It performs at most one swap per pass, however, for at most $n-1$ swaps. Few swaps can matter when writes are much more expensive than comparisons.
<!-- bilingual-en:end -->

> [!warning] 边界
> “selection sort 不稳定”描述的是常见的远距离交换实现：一次交换可能让相等键跨越。用平移代替交换可以做出稳定变体，但会增加移动；性质属于具体变体。课程中“发现更小值就立即交换”的展示代码也不是少交换的经典变体。
>
> <!-- bilingual-en:start -->
> “Selection sort is unstable” describes the usual long-distance-swap implementation, where one swap can move equal keys past one another. A stable shifting variant is possible but uses more moves, so the property belongs to the concrete variant. The course's demonstration code that swaps whenever it finds a smaller value is also not the classic few-swap variant.
> <!-- bilingual-en:end -->

> [!question]- 回忆与应用
> 为什么已经有序的输入不会减少经典 selection sort 的比较次数？
>
> **答案：** 每轮仍要扫描完整未定后缀，才能证明当前位置确实应放其最小项目。
