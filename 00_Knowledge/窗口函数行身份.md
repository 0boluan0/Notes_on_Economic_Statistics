# 窗口函数在相关行上计算但保留当前行身份

<!-- bilingual-en:start -->
*Window functions compute across related rows while preserving the current row's identity*
<!-- bilingual-en:end -->

> [!summary] 原子区别
> 普通分组聚合把一组输入行折叠成较少的输出行；窗口函数让窗口输入中的每条当前行访问相关行集合并得到统计量，却不再折叠这些当前行。若查询此前已经 `GROUP BY`，窗口保留的是分组后的行，而不是分组前的原始明细。
>
> <!-- bilingual-en:start -->
> Ordinary grouped aggregation collapses each group into fewer output rows. A window function lets every row in its window input compute over a related set without collapsing those current rows again. If the query has already grouped, the preserved rows are group rows, not the original detail rows.
> <!-- bilingual-en:end -->

```sql
SELECT employee_id,
       department,
       salary,
       AVG(salary) OVER (PARTITION BY department) AS department_avg
FROM employees;
```

结果仍是一行一个员工，同时给每位员工附上所在部门平均薪资。若改用 `GROUP BY department`，结果会变成一行一个部门，员工身份不再保留。
<!-- bilingual-en:start -->
The result remains one row per employee while attaching the department average to each employee. Replacing the window with `GROUP BY department` would produce one row per department and lose individual employee identity.
<!-- bilingual-en:end -->

窗口的 `PARTITION BY` 决定相关行集合，窗口内的 `ORDER BY` 决定排序相关计算；对会读取 frame 的函数，frame 再决定当前行实际看见分区中的哪一段。特别要小心：带窗口 `ORDER BY` 的聚合默认 frame 从分区开头延伸到当前行的最后一个并列行，常产生累计值，而不是“整个分区总值”。并列键对 `rank` 会有意给出相同名次，但 `row_number` 等依赖行内先后的函数若没有额外决定键，次序仍不稳定。
<!-- bilingual-en:start -->
`PARTITION BY` defines the related set, and the window's `ORDER BY` defines ordering-sensitive calculations. For frame-sensitive functions, the frame then determines which part of the partition is visible to the current row. With window ordering, the default frame runs from the partition start through the current row's last peer, so an aggregate commonly becomes cumulative rather than using the whole partition. Peers intentionally share a `rank`, but order-sensitive functions such as `row_number` remain nondeterministic among ties unless further keys break them.
<!-- bilingual-en:end -->

窗口函数看到的是经过 `FROM`、`WHERE`、分组和 `HAVING` 后的虚拟表。因此，要在窗口结果上继续过滤，通常还要包一层子查询或 CTE。
<!-- bilingual-en:start -->
Window functions see the virtual table after `FROM`, `WHERE`, grouping, and `HAVING`. Filtering on a window result therefore normally requires an outer query or CTE.
<!-- bilingual-en:end -->

> [!question]- 回忆与辨别
> 为什么窗口 `AVG(...) OVER (PARTITION BY department)` 能同时显示员工薪资和部门均值？
>
> **答案：** 它跨部门分区计算均值，但不像普通 `GROUP BY` 聚合那样把员工行折叠掉。
