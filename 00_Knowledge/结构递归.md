# 结构递归按数据定义的每个基例与构造器分别处理并组合子结果

<!-- bilingual-en:start -->
*Structural recursion handles every base form and constructor in a recursive data definition and combines the recursive results*
<!-- bilingual-en:end -->

> [!summary] 原子设计模式
> 当数据本身由递归规则生成时，算法最稳的骨架通常直接镜像这些规则：每一种基础对象有一个直接分支；每一种构造器有一个分支，对它包含的递归子对象调用同一过程，再用构造器对应的方式组合子结果。

设算术表达式由数字、加法和乘法生成：

$$e ::= n \mid e_1+e_2 \mid e_1\times e_2.$$

求值器就应分别处理三种形态：数字直接给值；加法递归求两个子表达式并相加；乘法递归求两个子表达式并相乘。若数据定义后来加入一元负号，而算法没有新分支，问题不是“某个测试没覆盖”，而是算法已不再覆盖整个数据域。

列表的 `first/rest` 递归只是结构递归的一种。对树，应处理叶节点和各类内部节点；对嵌套结构，应沿实际子对象下降，而不是预先猜最大层数。结构递归的收益是让覆盖性变得可审计：把数据定义与函数分支并排，就能看见漏掉的基例、构造器或子结果。

算法骨架与证明骨架互相镜像，但不是同一件事：

- 算法用结构递归计算结果。
- 正确性证明用[[结构归纳法|结构归纳]]，假设递归子对象上的结果正确，再证明构造后的对象也正确。
- 终止还依赖“子对象关系”确实良基；带环对象图不能只因为语法长得像树就直接套用。

> [!question]- 自检
> 一种树有 `Leaf(value)`、`Unary(child)` 和 `Binary(left, right)` 三个构造器。遍历函数只处理叶与二叉节点，是否已经覆盖这类树？
>
> **答案：** 没有。`Unary` 是数据定义中的独立构造器，算法必须处理它；相应的结构归纳证明也必须有这一分支。
