# 性能剖析把一次指定工作负载的资源消耗归因到程序的执行位置

<!-- bilingual-en:start -->
*Profiling attributes resource consumption under a specified workload to execution locations*
<!-- bilingual-en:end -->

性能剖析（profiling）通过执行记录或采样，估计程序的哪些函数、代码行或调用路径消耗了资源。它回答“这次工作的钱花在哪里”，而不仅是总共花了多久；因此可以用来定位热点，不必先知道热点才开始剖析。

<!-- bilingual-en:start -->
Profiling uses execution records or samples to attribute resource use to functions, lines or call paths. It helps locate hotspots rather than requiring their location in advance.
<!-- bilingual-en:end -->

先固定要完成的任务和代表性输入，再选指标：响应慢可能在等待 I/O，也可能在计算；内存增长需要内存观测，不能仅凭函数耗时判断。Python 的 `cProfile` 可提供函数级调用与时间统计，读表时须区分[[剖析自身与累计时间]]。

<!-- bilingual-en:start -->
Fix the task and representative input, then choose the metric. Latency may reflect I/O waits or computation; memory growth needs memory measurements. Python's `cProfile` provides function-level statistics with distinct [[剖析自身与累计时间|self and cumulative times]].
<!-- bilingual-en:end -->

热点只是这次工作负载下的候选。比如一个导入工具反复解析同一份配置，剖析发现解析占主要时间；可以提出“移出循环”的假设，但先检查配置是否会在循环内改变，再用[[回归测试]]检查行为，并在相同任务上重新计时。剖析有额外开销，优化收益最终回到[[计时与渐近分析|独立计时与成本分析]]核对。

<!-- bilingual-en:start -->
A hotspot suggests a workload-specific hypothesis. Moving repeated configuration parsing outside a loop requires checking whether the configuration changes. Preserve behavior with [[回归测试|regression tests]], then measure again independently; profiling adds overhead.
<!-- bilingual-en:end -->

## 来源与核验

- MIT [The Missing Semester 2020, Debugging and Profiling](https://missing.csail.mit.edu/2020/debugging-profiling/)，“Profiling”“Resource Monitoring”：支持按资源类型定位热点、工作负载与工具选择。配置解析是应用示例。
- Python [The Python Profilers](https://docs.python.org/3/library/profile.html)，“Introduction”：核对函数统计、剖析开销及其与 benchmarking 的区别。

Missing Semester supports hotspot investigation and resource-specific observations. Python's profiler introduction verifies function statistics, overhead and the benchmarking distinction. Configuration parsing is an application example.
